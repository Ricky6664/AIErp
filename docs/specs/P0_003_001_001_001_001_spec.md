## 3. Schema设计

| Schema名称 | 用途 | 隔离方式 |
|-----------|------|---------|
| `erp_base` | 系统级基础数据（参数、字典、编码规则、菜单等） | Schema级隔离，租户共享 |
| `erp_tenant` | 租户业务数据（约200张业务表） | 行级隔离，tenant_id字段 |
| `public` | PostgreSQL默认Schema | 保留不使用 |

### 3.1 多租户隔离策略

- **erp_base**：存放跨租户共享的系统配置数据。所有租户读取同一份数据，通过应用层控制修改权限。
- **erp_tenant**：存放各租户的业务数据。所有业务表强制包含 `tenant_id BIGINT NOT NULL` 字段，MyBatis-Plus多租户插件自动注入 `WHERE tenant_id = ?` 条件实现行级隔离。
- **联合索引约束**：erp_tenant中所有联合索引必须以 `tenant_id` 为首列，确保多租户查询性能。

## 4. 执行说明

### 4.1 前置条件

- PostgreSQL 15+ 已安装并运行
- 具有超级用户（postgres）权限
- 目标服务器有足够的磁盘空间

### 4.2 执行步骤

```bash
# 以postgres用户执行
psql -U postgres -f db/migration/V20260526001__schema_related.sql
```

### 4.3 幂等性

- `CREATE DATABASE` 使用 `DO $$ ... IF NOT EXISTS` 块包装，重复执行不会报错
- `CREATE SCHEMA IF NOT EXISTS` 保证Schema创建的幂等性
- `ALTER DATABASE SET search_path` 可重复执行

## 6. 技术决策记录

| 决策 | 选项 | 选择 | 原因 |
|------|------|------|------|
| 数据库名 | erp_db | ✅ 采用 | 简洁明确，符合命名规范 |
| 编码 | UTF8 vs LATIN1 | ✅ UTF8 | 支持中文及多语言 |
| 模板 | template0 vs template1 | ✅ template0 | 避免本地化配置污染 |
| Schema数量 | 2个(erp_base + erp_tenant) | ✅ 采用 | 清晰分离共享数据与租户数据 |
| 租户隔离方式 | Schema隔离 vs 行级隔离 | ✅ 行级隔离(tenant_id) | 灵活支持动态租户，无需DDL变更 |
