# base_qty 核心规范 + 计算逻辑 + 校验规则

> 版本：V1.0
> 创建日期：2026-06-01
> 任务编号：P0-003-002-011-001-001
> 用途：定义 base_qty（基础单位换算数量）的核心地位、计算公式、校验规则，作为所有涉及多单位/库存/单据明细模块的开发约束基准。

---

## 1. base_qty 定义与核心地位

### 1.1 术语定义

| 术语 | 英文 | 含义 |
|------|------|------|
| 业务单位 | Unit of Measure (UOM) | 单据明细行上实际选用的计量单位（如"箱""包""kg""个"） |
| 基础单位 | Base Unit | 商品档案中统一维护的基础计量单位（如"个""kg"） |
| 转换比例 | Conversion Rate | 1个业务单位 = N个基础单位，即 `base_qty = qty × conversion_rate` |
| 业务数量 | qty | 按所选业务单位的数量（录入数，用户所见即所得） |
| 基础数量 | base_qty | 换算为商品基础单位的数量（库存增减统一使用的数量） |

### 1.2 核心原理

```
    业务单位数量(qty)  ×  转换比例(conversion_rate)  =  基础单位数量(base_qty)

    示例：
    商品A基础单位="个"，每箱=24个
    → 录入 3箱 → qty=3, conversion_rate=24, base_qty=72个
    → 录入 50个 → qty=50, conversion_rate=1, base_qty=50个
```

### 1.3 base_qty 的核心地位

**base_qty 是库存增减的"唯一真值"。**

- 所有库存表（库存余额/库存流水/货位库存/批次库存/序列号）的 qty 字段，其值均为 base_qty
- 所有出入库计算、成本核算、MRP 运算，一律以 base_qty 为计算基准
- 单据明细行的 qty（业务数量）仅用于显示，不参与库存计算
- 转换比例变动时，已发生单据不受影响（快照机制）

### 1.4 适用场景

| 场景 | base_qty 作用 |
|------|---------------|
| 出入库单 | 明细行入库/出库的库存增减量，统一使用 base_qty |
| 库存余额 | 当前库存量 = SUM(出入库 base_qty) |
| 库存预警 | 安全库存（最低/最高）以 base_qty 表达 |
| 成本计算 | 单位成本 = 总金额 / base_qty（按基础单位计） |
| MRP 运算 | 毛需求/净需求/计划产出量，均以 base_qty 计算 |
| 库位/批次拆分 | doc_detail_location/batch 中的 qty 字段均为 base_qty |

## 2. 计算逻辑

### 2.1 核心公式

```
base_qty = qty × conversion_rate
```

### 2.2 计算时机

| 时机 | 计算方式 | 说明 |
|------|---------|------|
| 前端录入 | 用户选单位后自动计算 | 前端实时展示 base_qty，但不持久化到明细行（明细行存 qty + conversion_rate + base_qty） |
| 后端保存 | Service 层保存前计算 | 确保 base_qty 值正确，防止前端篡改 |
| 明细行查询 | 直接读取字段 | base_qty 为明细行冗余字段，无需实时计算 |

### 2.3 后端计算伪代码

```
// 保存/更新明细行时，确保 base_qty 计算正确
function calcBaseQty(qty, conversionRate):
    return qty.multiply(conversionRate).setScale(8, RoundingMode.HALF_UP)

// 保存时调用
detail.setBaseQty(calcBaseQty(detail.getQty(), detail.getConversionRate()))
```

### 2.4 正向计算与反向计算

| 方向 | 公式 | 使用场景 |
|------|------|---------|
| 正向（业务→基础） | `base_qty = qty × conversion_rate` | 录入保存时 |
| 反向（基础→业务） | `qty = base_qty / conversion_rate` | 盘点差异调整、库存批次拆合 |

### 2.5 边界情况处理

| 情况 | 处理规则 |
|------|---------|
| conversion_rate = 0 | 校验拒绝，转换比例必须 > 0 |
| qty = 0 | 允许（赠品/零金额行），base_qty = 0 |
| base_qty 超过 Decimal(18,8) 范围 | 校验拒绝，防止溢出 |
| 基础单位 = 业务单位 | conversion_rate = 1，base_qty = qty |

## 3. 校验规则

### 3.1 单据明细行校验

```
必须通过校验（否则拒绝保存）：

1. qty ≠ null, qty ≥ 0
2. conversion_rate ≠ null, conversion_rate > 0
3. base_qty ≠ null, base_qty ≥ 0
4. base_qty = qty × conversion_rate（精度误差 ≤ 1e-8 容差）
5. base_qty ≤ 9999999999.99999999（Decimal(18,8) 上限）
```

### 3.2 库位/批次拆分校验

```
启用库位或批次时，辅助属性子表的 qty 校验：

1. 同一 detail_id 的所有 doc_detail_location 记录的 qty 之和
   = 明细行主表的 base_qty
2. 同一 detail_id 的所有 doc_detail_batch 记录的 qty 之和
   = 明细行主表的 base_qty
```

### 3.3 序列号校验

```
启用序列号时，序列号数量校验：

1. doc_detail_serial 记录数 = 明细行主表的 base_qty（取整）
2. base_qty 必须为正整数（序列号管理要求），小数拒绝
```

### 3.4 校验失败处理

| 校验项 | 失败时业务异常码 | 提示信息模板 |
|--------|:---:|------|
| conversion_rate ≤ 0 | BIZ-001 | "转换比例必须大于0，当前值：{value}" |
| base_qty ≠ qty × conversion_rate | BIZ-002 | "基础数量计算不一致，期望={expected}，实际={actual}" |
| 库位 qty 和不等于 base_qty | BIZ-003 | "库位拆分数量合计({sum})与明细行基础数量({base_qty})不一致" |
| 批次 qty 和不等于 base_qty | BIZ-004 | "批次拆分数量合计({sum})与明细行基础数量({base_qty})不一致" |
| 序列号数量不等于 base_qty | BIZ-005 | "序列号数量({serial_count})与明细行基础数量({base_qty})不一致" |

## 4. 数据库存储约定

### 4.1 DDL 类型

```sql
-- 明细行主表中的 base_qty 字段
base_qty DECIMAL(18,8) NOT NULL DEFAULT 0

-- 辅助属性子表中的 qty 字段（实际存储的也是 base_qty）
qty DECIMAL(18,8) NOT NULL DEFAULT 0
```

### 4.2 CHECK 约束

```sql
-- base_qty 非负
ALTER TABLE {detail_table}
  ADD CONSTRAINT ck_{detail_table}_base_qty CHECK (base_qty >= 0);

-- qty（业务数量）非负
ALTER TABLE {detail_table}
  ADD CONSTRAINT ck_{detail_table}_qty CHECK (qty >= 0);

-- conversion_rate 正数
ALTER TABLE {detail_table}
  ADD CONSTRAINT ck_{detail_table}_conversion_rate CHECK (conversion_rate > 0);
```

### 4.3 物理精度 vs 显示精度

| 维度 | 定义 | 值 |
|------|------|:---:|
| 物理精度 | DDL 存储精度（decimal 类型参数） | `decimal(18,8)` |
| 显示精度 | 前端输入框/列表展示的小数位数 | 由系统参数 `system.decimal_places_qty` 控制（默认6位） |
| 计算精度 | 后端 BigDecimal 计算时使用的精度 | `scale=8, RoundingMode.HALF_UP` |

### 4.4 冗余存储说明

| 字段 | 是否冗余 | 原因 |
|------|:---:|------|
| base_qty | 是 | 作为库存增减的计算基准，必须直接可用，避免每次需要 JOIN 商品单位表计算 |
| conversion_rate | 是 | 快照字段，记录业务发生时的转换比例。后续单位比例变更不影响历史单据 |
| unit_id / base_unit_id | 是 | 快照字段，记录业务发生时的单位关系 |

## 5. 与各模块的集成关系

### 5.1 明细从表商品冗余字段模板

所有含商品的明细从表（有 product_id 字段），除 product_id 外，必须冗余存储以下字段：

```sql
-- === 商品快照字段（明细从表强制包含）===
product_code        VARCHAR(50),
product_name        VARCHAR(100),
model               VARCHAR(100),
spec                VARCHAR(100),
brand               VARCHAR(50),
unit_id             BIGINT,
unit                VARCHAR(30),
qty                 DECIMAL(18,8)   NOT NULL DEFAULT 0,
is_multi_unit       BOOLEAN         DEFAULT FALSE,
conversion_rate     DECIMAL(18,8)   NOT NULL DEFAULT 1,
base_unit_id        BIGINT,
base_qty            DECIMAL(18,8)   NOT NULL DEFAULT 0,
```

### 5.2 调用链

```
前端录入 qty → 选择单位(unit_id) → 前端查 conversion_rate → 计算 base_qty 展示
    ↓ 提交
后端接收 → 重新计算 base_qty = qty × conversion_rate
    ↓ 保存
数据库写入 → 冗余 base_qty 字段
    ↓ 出入库执行
库存表 → +base_qty (入库) 或 -base_qty (出库)
```

### 5.3 涉及的库存表

| 表名 | 使用的数量字段 | 字段含义 |
|------|---------------|---------|
| inv_stock_balance | qty | 当前库存余额（base_qty） |
| inv_stock_flow | qty | 库存流水变动量（base_qty，正=入库/负=出库） |
| inv_location_stock | qty | 货位库存（base_qty） |
| inv_batch_stock | qty | 批次库存（base_qty） |
| inv_serial | — | 序列号记录（每个序列号对应 base_qty=1） |

## 6. 并发与一致性

### 6.1 库存扣减

```
扣减库存时，使用乐观锁：

UPDATE inv_stock_balance
SET qty = qty - #{base_qty},
    version = version + 1
WHERE product_id = #{product_id}
  AND warehouse_id = #{warehouse_id}
  AND qty >= #{base_qty}     -- 防超卖
  AND version = #{version}   -- 乐观锁
```

### 6.2 事务保证

```
出入库操作必须放在同一事务内：

@Transactional(rollbackFor = Exception.class)
public void executeStockIn(Long orderId) {
    // 1. 更新单据状态
    // 2. 写入库存流水（inv_stock_flow）
    // 3. 更新库存余额（inv_stock_balance）
    // 4. 更新库位/批次库存（如启用）
    // 任一步失败 → 全部回滚
}
```

## 7. 常见错误示例

| 错误 | 说明 | 正确做法 |
|------|------|---------|
| 直接用 qty 做库存计算 | 业务单位数量不能作为库存增减量 | 必须使用 base_qty |
| conversion_rate 存为 0 | 导致 base_qty=0 或除零错误 | conversion_rate 必须 > 0 |
| base_qty 小数位数与 qty 不一致 | base_qty 在转换后可能产生不同小数位 | 统一用 Decimal(18,8)，由系统参数控制显示精度 |
| 前后端 base_qty 计算不一致 | 前端展示值与后端存储值偏差 | 前端仅展示，后端保存时重新计算 base_qty |
| 单位变更后覆盖历史单据 | 基础单位变动影响历史数据 | 使用快照机制：conversion_rate 冗余在明细行，变更不回溯 |
