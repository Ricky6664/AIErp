## 4. 核心约束规则

### 4.1 字段完整性
- 所有业务表必须完整包含上述10个通用字段
- 字段顺序固定：业务字段 → 扩展字段 → 公共字段
- 10个公共字段排列顺序不可调整

### 4.2 默认值规则
- 时间字段（created_at/updated_at）：DB层设 CURRENT_TIMESTAMP 兜底
- 布尔字段（is_deleted）：必须 NOT NULL DEFAULT FALSE，避免三值逻辑
- 版本号（version）：DEFAULT 1，MyBatis-Plus 乐观锁自动+1
- 人员字段（created_by/updated_by/owner_dept_id/owner_id）：由应用层赋值
- 租户字段（tenant_id）：NOT NULL，由 MyBatis-Plus 多租户插件注入

### 4.3 索引规则
- 每个业务表必须创建租户索引：`CREATE INDEX idx_{table}_tenant_id ON {table}(tenant_id)`
- 业务唯一性字段使用部分唯一索引：`CREATE UNIQUE INDEX uk_{table}_{field}_active ON {table}(tenant_id, {field}) WHERE is_deleted = FALSE`
- 联合索引必须以 tenant_id 为首列

### 4.4 COMMENT 注释
- 所有表必须包含 `COMMENT ON TABLE` 表注释
- 所有业务字段必须包含 `COMMENT ON COLUMN` 列注释
- 10个公共字段使用统一的 COMMENT 模板

### 4.5 外键策略
- 应用层维护外键关系，数据库层不创建 FOREIGN KEY 约束

## 6. 设计要点

- **created_by vs owner_id 分离**：created_by 记录历史创建人（审计字段，永不修改）；owner_id 记录当前数据负责人（数据权限判定字段，可按需变更）
- **数据权限取值链路**：`WHERE owner_dept_id IN (...) AND/OR owner_id IN (...)`，禁止使用 created_by 做数据权限判定
- **软删除部分唯一索引**：使用 `WHERE is_deleted = FALSE` 而非将 is_deleted 纳入联合唯一索引，支持同 code 多次删除后重建
- **数值精度**：所有数值字段 DDL 统一使用 decimal(18,8)，实际显示精度由系统参数动态控制
