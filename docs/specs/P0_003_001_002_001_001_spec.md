## 3. 设计要点

### 3.1 created_by与owner_id分离

| 字段 | 性质 | 修改策略 |
|------|------|---------|
| created_by | 审计字段 | 永不修改，记录历史创建人 |
| owner_id | 权限字段 | 可随业务流转而变更（如数据转办） |

- **数据权限取值链路**：查询时数据权限过滤条件为 `WHERE owner_dept_id IN (用户可见部门) AND/OR owner_id IN (用户可见人员)`，禁止使用created_by做数据权限判定。
- **owner_dept_id与owner_id联动**：当owner_id变更时，owner_dept_id应同步更新为新负责人的部门ID。

### 3.2 软删除规范

- 所有业务表使用逻辑删除（`is_deleted = true`），不执行物理DELETE。
- MyBatis-Plus全局逻辑删除插件自动注入 `WHERE is_deleted = false`。
- 业务唯一性约束采用**部分唯一索引**：`CREATE UNIQUE INDEX uk_{table}_{field}_active ON {table}(tenant_id, {field}) WHERE is_deleted = false`。

### 3.3 多租户隔离

- tenant_id字段不可为空。
- 联合索引必须以tenant_id为首列：`CREATE INDEX idx_{table}_tenant_id ON {table}(tenant_id)`。
- MyBatis-Plus多租户插件自动注入 `WHERE tenant_id = ?`。

### 3.4 乐观锁

- version字段每次更新自动+1。
- MyBatis-Plus自动处理version字段的更新检查和自增。
