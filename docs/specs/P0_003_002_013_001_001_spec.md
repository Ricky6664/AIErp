> 用途：定义数值精度的参数优先级体系、尾差处理规则、系统参数配置，作为所有涉及金额/单价/数量/转换率/税率模块的开发约束基准。

## 1. 核心原则

### 1.1 物理精度与显示精度分离

| 维度 | 定义 | 值 |
|------|------|:---:|
| 物理精度 | DDL 存储精度（decimal 类型参数） | `decimal(18,8)` |
| 显示精度 | 前端输入框/列表展示的小数位数 | 由参数体系动态控制 |

**数据库所有数值字段统一使用 `decimal(18,8)` 存储**，确保物理精度足够不丢失数据。实际显示给用户的小数位数由参数体系动态控制，无需修改 DDL。

### 1.2 适用范围

| 字段类别 | 涵盖字段名模式 | 典型字段 |
|---------|-------------|---------|
| amount（金额） | `*_amount`, `*_total`, `*_balance`, `*_cost` | total_amount, paid_amount, unit_cost |
| price（单价） | `*_price`, `unit_*` | unit_price, purchase_price, sale_price |
| qty（数量） | `qty`, `*_qty`, `base_qty` | qty, base_qty, stock_qty |
| rate（税率/百分比） | `*_rate`, `*_percent`, `*_discount` | tax_rate, discount_rate |
| conversion_rate | `conversion_rate` | conversion_rate |
| ext_num*（扩展） | `ext_num1` ~ `ext_num10` | 用户自定义扩展数值 |

## 2. 精度优先级体系

### 2.1 五级优先级链

```
Level 1（最高优先级）
  └─ 字段级 @DecimalPlaces 注解
      └─ 覆盖所有下级

Level 2
  └─ 表级精度配置
      └─ 覆盖模块级和系统级

Level 3
  └─ 模块级参数 {module}.decimal_places_{category}
      └─ 覆盖系统级

Level 4
  └─ 系统级参数 system.decimal_places_{category}
      └─ 全局兜底

Level 5（最低优先级）
  └─ 代码硬编码默认值
      └─ 仅在上级参数均不存在时使用
```

### 2.2 各级详解

#### Level 1 — 字段级精度注解

在 Entity/DTO 字段上使用自定义注解指定精度，优先级最高。

```java
// 示例：发票金额固定2位，不受任何参数影响
@DecimalPlaces(2)
private BigDecimal invoiceAmount;

// 示例：成本单价固定6位
@DecimalPlaces(6)
private BigDecimal costPrice;
```

**适用场景**：法律法规要求的固定精度（如发票金额必须2位）、特殊业务要求。

#### Level 2 — 表级精度配置

按表+字段配置精度，存储于 `sys_doc_config.field_visibility` JSONB 或专门的精度配置表。

```json
{
  "precision": {
    "sale_order_detail.unit_price": 6,
    "sale_order_detail.qty": 4
  }
}
```

**适用场景**：特定单据类型对精度的特殊要求。

#### Level 3 — 模块级参数

`sys_param` 表中按模块维护的精度参数，命名规范：`{module}.decimal_places_{category}`。

| 参数键 | 默认值 | 说明 |
|--------|:---:|------|
| `sale.decimal_places_price` | 4 | 销售模块单价精度 |
| `sale.decimal_places_amount` | 2 | 销售模块金额精度 |
| `purchase.decimal_places_price` | 4 | 采购模块单价精度 |
| `purchase.decimal_places_amount` | 2 | 采购模块金额精度 |
| `inventory.decimal_places_qty` | 6 | 库存模块数量精度 |

#### Level 4 — 系统级参数

`sys_param` 表中全局精度参数，命名规范：`system.decimal_places_{category}`。

| 参数键 | 默认值 | 说明 |
|--------|:---:|------|
| `system.decimal_places_amount` | 2 | 全局金额显示精度 |
| `system.decimal_places_qty` | 6 | 全局数量/转换率显示精度 |
| `system.decimal_places_price` | 4 | 全局单价显示精度 |
| `system.decimal_places_rate` | 4 | 全局税率/百分比显示精度 |

#### Level 5 — 硬编码默认值

当所有上级配置均不存在时使用的兜底值。

| 类别 | 默认精度 |
|------|:---:|
| amount | 2 |
| price | 4 |
| qty | 6 |
| rate | 4 |
| conversion_rate | 6 |

### 2.3 精度查找算法（伪代码）

```
function getDecimalPlaces(fieldCategory, module, tableName, fieldName):
    // Level 1: 字段级 @DecimalPlaces 注解
    annotation = getFieldAnnotation(fieldName, DecimalPlaces.class)
    if annotation != null:
        return annotation.value()

    // Level 2: 表级精度配置
    tableConfig = getTablePrecisionConfig(tableName, fieldName)
    if tableConfig != null:
        return tableConfig

    // Level 3: 模块级参数
    places = getSysParamValue(module + '.decimal_places_' + fieldCategory)
    if places != null and 0 <= places <= 8:
        return places

    // Level 4: 系统级参数
    places = getSysParamValue('system.decimal_places_' + fieldCategory)
    if places != null and 0 <= places <= 8:
        return places

    // Level 5: 硬编码默认值
    return DEFAULT_PRECISION_MAP[fieldCategory]
```

## 3. 尾差处理规则

### 3.1 尾差定义

多行明细各自按指定精度截断（HALF_UP 舍入）后，各行合计与原始总金额可能产生微小差异。

```
示例（2位精度，3行均摊 10.00）：
  行1: 10.00 / 3 = 3.333... → 截断为 3.33
  行2: 10.00 / 3 = 3.333... → 截断为 3.33
  行3: 10.00 / 3 = 3.333... → 截断为 3.33
  合计: 3.33 + 3.33 + 3.33 = 9.99 ≠ 10.00
  尾差: 10.00 - 9.99 = 0.01
```

### 3.2 尾差处理策略

策略由 `system.tail_diff_strategy` 参数控制：

| 策略 | 值 | 说明 |
|------|:---:|------|
| 末行找平 | `LAST_LINE` | 将差额摊入最后一行（**默认**） |
| 首行找平 | `FIRST_LINE` | 将差额摊入第一行 |
| 均摊 | `AVG_SPREAD` | 将差额均匀分摊到所有行 |
| 拒绝 | `NONE` | 差额超出容差时直接拒绝保存 |

### 3.3 尾差容差阈值

由 `system.tail_diff_tolerance` 控制（默认 `0.00000001`，即 1e-8）。

| 条件 | 处理 |
|------|------|
| \|主表 - 明细合计\| ≤ tolerance | 尾差可接受，按策略自动找平 |
| \|主表 - 明细合计\| > tolerance | 超出容差，拒绝保存并提示用户调整 |

### 3.4 按字段类别的尾差处理

| 字段类别 | 处理方式 | 原因 |
|---------|---------|------|
| amount（金额） | 末行找平 | 金额必须分毫不差 |
| qty / base_qty | 末行找平 | base_qty 合计严格一致 |
| price（单价） | 各行独立，不找平 | 单价各行独立，无合计约束 |
| rate（税率） | 各行独立，不找平 | 税率各行独立计算 |

### 3.5 尾差处理实现（Java 伪代码）

```java
public List<DetailLine> handleTailDiff(
        BigDecimal headerAmount,
        List<DetailLine> details,
        int precision,
        TailDiffStrategy strategy) {

    // 1. 各行截断
    BigDecimal sum = BigDecimal.ZERO;
    for (DetailLine line : details) {
        line.setAmount(line.getAmount().setScale(precision, RoundingMode.HALF_UP));
        sum = sum.add(line.getAmount());
    }

    // 2. 计算尾差
    BigDecimal diff = headerAmount.subtract(sum);

    // 3. 容差判断
    BigDecimal tolerance = getTailDiffTolerance();
    if (diff.abs().compareTo(tolerance) <= 0) {
        return details;  // 尾差可忽略
    }

    // 4. 按策略找平
    switch (strategy) {
        case LAST_LINE:
            DetailLine last = details.get(details.size() - 1);
            last.setAmount(last.getAmount().add(diff));
            break;
        case FIRST_LINE:
            DetailLine first = details.get(0);
            first.setAmount(first.getAmount().add(diff));
            break;
        case AVG_SPREAD:
            BigDecimal perLine = diff.divide(
                BigDecimal.valueOf(details.size()), precision, RoundingMode.HALF_UP);
            // ...均摊逻辑
            break;
        case NONE:
            throw new BusinessException("BIZ-006",
                "明细合计(" + sum + ")与主表金额(" + headerAmount + ")不一致，尾差=" + diff);
    }

    return details;
}
```

## 4. 参数配置

### 4.1 精度参数一览

| 参数键 | 默认值 | 分组 | 预置 | 说明 |
|--------|:---:|------|:---:|------|
| `system.decimal_places_amount` | 2 | system | 是 | 全局金额精度 |
| `system.decimal_places_qty` | 6 | system | 是 | 全局数量精度 |
| `system.decimal_places_price` | 4 | system | 是 | 全局单价精度 |
| `system.decimal_places_rate` | 4 | system | 是 | 全局税率精度 |
| `system.tail_diff_tolerance` | 0.00000001 | system | 是 | 尾差容差阈值 |
| `system.tail_diff_strategy` | LAST_LINE | system | 是 | 尾差策略 |
| `sale.decimal_places_price` | 4 | sale | 是 | 销售单价精度 |
| `sale.decimal_places_amount` | 2 | sale | 是 | 销售金额精度 |
| `purchase.decimal_places_price` | 4 | purchase | 是 | 采购单价精度 |
| `purchase.decimal_places_amount` | 2 | purchase | 是 | 采购金额精度 |
| `inventory.decimal_places_qty` | 6 | inventory | 是 | 库存数量精度 |

### 4.2 参数存储

所有精度参数存储在 `sys_param` 表，按 `tenant_id=0` 作为系统预置参数。

```sql
-- 查询所有精度参数
SELECT param_code, param_value, param_group, remark
FROM sys_param
WHERE param_code LIKE '%.decimal_places_%'
   OR param_code LIKE 'system.tail_diff_%'
ORDER BY param_group, param_code;
```

### 4.3 参数修改

- 系统级参数（`system.*`）和二三级模块参数 `is_readonly=FALSE`，管理员可在后台修改
- 参数值范围：0~8（精度），LAST_LINE/FIRST_LINE/AVG_SPREAD/NONE（尾差策略）
- 修改后**立即生效**，无需重启服务
- 修改精度参数**不影响历史数据**，只影响后续的录入和展示

## 6. 存储层约束

### 6.1 DDL 统一类型

```sql
-- 所有金额/单价/数量/转换率/税率字段统一使用此类型
amount          DECIMAL(18,8) NOT NULL DEFAULT 0
unit_price      DECIMAL(18,8) NOT NULL DEFAULT 0
qty             DECIMAL(18,8) NOT NULL DEFAULT 0
base_qty        DECIMAL(18,8) NOT NULL DEFAULT 0
conversion_rate DECIMAL(18,8) NOT NULL DEFAULT 1
tax_rate        DECIMAL(18,8) NOT NULL DEFAULT 0
```

### 6.2 CHECK 约束

```sql
-- 金额/数量/单价/转换率：非负
ALTER TABLE {table} ADD CONSTRAINT ck_{table}_{field}
    CHECK ({field} >= 0);

-- 税率：范围 0~100
ALTER TABLE {table} ADD CONSTRAINT ck_{table}_tax_rate
    CHECK (tax_rate >= 0 AND tax_rate <= 100);
```

## 7. 常见错误与禁止行为

| 错误 | 说明 | 正确做法 |
|------|------|---------|
| DDL 中使用 decimal(18,6) 或 decimal(18,2) | 物理精度不足，数据丢失 | 统一使用 decimal(18,8) |
| 在前端做尾差找平 | 前端只展示，不可做数据修正 | 后端 Service 层统一处理尾差 |
| 修改历史单据的精度 | 精度变更影响历史数据一致性 | 精度参数只影响后续操作 |
| 跳过精度优先级直接硬编码 | 写死 scale=2，失去灵活性 | 通过 PrecisionService 获取精度 |
| 尾差容差设得过大 | 掩盖真实数据不一致 | 容差固定为 1e-8 |
| 金额字段用 qty 精度 | 金额显示6位小数，不符合财务习惯 | 金额统一使用 amount 类别精度 |
