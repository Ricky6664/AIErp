## I01 — 工作台页面缺少 API 错误处理

| 属性 | 值 |
|------|-----|
| 严重度 | 中 |
| 文件 | `erp-ai-web/src/views/auth/config/workbench/index.vue` |
| 行号 | 216, 262, 286-296 |

**问题描述**：
`fetchData` 调用未包裹 try/catch。当 API 请求失败时：
1. `handleRefresh`（L261-264）只显示"数据已刷新"的成功消息，不检查是否实际成功
2. `onMounted`（L286-296）初始化失败时无任何用户提示，页面保持空白 skeleton 状态
3. `handleDateRangeChange`（L215-217）和 `handleDimensionChange`（L219-247）失败时静默

**修复方案**：
```typescript
// 在 fetchData 包装一层带错误处理的方法
async function safeFetch(params?: WorkbenchQueryParams): Promise<void> {
  try {
    await fetchData(params)
  } catch {
    ElMessage.error('数据加载失败，请稍后重试')
  }
}
```
或在 `useAuthConfigWorkbench` composable 的 `fetchData` 中添加 error ref 供页面消费。

**影响范围**：用户体验 — 网络异常或后端错误时无反馈。

## I02 — KpiCard `clickable` 计算属性始终为 true

| 属性 | 值 |
|------|-----|
| 严重度 | 低 |
| 文件 | `erp-ai-web/src/components/KpiCard/index.vue` |
| 行号 | 62 |

**问题描述**：
```typescript
const clickable = computed(() => !!(props.to || emit))
```
`emit` 是 `defineEmits` 返回的函数，在布尔上下文中始终为 truthy。因此无论 KPI 卡片是否有实际点击行为（`to` 路由或 `@click` 事件），`clickable` 始终为 `true`，导致所有卡片都显示 `cursor: pointer` 和 hover 动效。

**修复方案**：
将 `clickable` 改为仅检查 `props.to`，或添加一个显式的 `clickable` prop：
```typescript
const clickable = computed(() => !!props.to)
```
需要 click 行为时由父组件通过 `@click` 监听并配合 `to` prop。

**影响范围**：UI 体验 — 工作台 4 个 KPI 卡片均显示可点击样式但实际无点击响应。

## I03 — `updateRadarChart` 空数据时旧图表残留

| 属性 | 值 |
|------|-----|
| 严重度 | 低 |
| 文件 | `erp-ai-web/src/composables/useAuthConfigWorkbench.ts` |
| 行号 | 161-162 |

**问题描述**：
```typescript
function updateRadarChart(data: LoginMethodDistItem[]): void {
  if (!radarChartRef.value || data.length === 0) return
  // ...
}
```
当筛选条件变更导致 `loginMethodDistribution` 变为空数组时，函数提前返回，雷达图保留上一次有数据时的旧图表内容，与实际情况不符。

**修复方案**：

```typescript
    radarChartRef.value.setOption({
      title: { text: '暂无数据', left: 'center', top: 'center', textStyle: { color: '#999', fontSize: 14 } }
    }, true) // notMerge=true 清除旧配置
    return
  }
  // ... 正常渲染
}
```

**影响范围**：筛选结果为空时雷达图显示不一致。

## I04 — `fetchData` 缺少竞态处理

| 属性 | 值 |
|------|-----|
| 严重度 | 低 |
| 文件 | `erp-ai-web/src/composables/useAuthConfigWorkbench.ts` |
| 行号 | 47-53 |

**问题描述**：
快速连续切换筛选条件（如快速点击日/周/月维度按钮）时，多个 `fetchData` 请求并发。由于网络延迟不确定，后发起的请求可能先返回，导致最终显示的数据不是最后一次筛选的结果。

**修复方案**：
使用请求序列号或 AbortController 取消前一个请求：
```typescript
let requestId = 0

async function fetchData(params?: WorkbenchQueryParams): Promise<void> {
  const id = ++requestId
  loading.value = true
  try {
    const data = await getAuthConfigWorkbenchApi(params)
    if (id === requestId) {  // 仅最新请求的结果生效
      workbenchData.value = data
    }
  } finally {
    if (id === requestId) {
      loading.value = false
    }
  }
}
```

**影响范围**：快速切换筛选条件时可能出现短暂的数据不一致。
