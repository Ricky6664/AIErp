## I01 [CRITICAL] 后端缺少 GET /auth/captcha 端点

### 问题描述
前端 `getCaptchaApi()` 调用 `GET /api/auth/captcha` 获取验证码图片和 key，但后端 AuthController 中没有对应的端点。`CaptchaService.generateCaptcha()` 存在但未通过 REST 暴露。

### 影响
登录页加载时控制台报 404 错误，验证码图片无法显示，用户无法登录。

### 涉及文件
| 文件 | 角色 |
|------|------|
| `erp-ai-web/src/api/modules/auth.ts:13` | 前端调用方 |
| `erp-ai-web/src/composables/login/useLogin.ts:76` | 前端调用方 |
| `src/main/java/com/erp/auth/controller/AuthController.java` | 需添加端点 |
| `src/main/java/com/erp/auth/service/CaptchaService.java` | 需扩展（生成图片） |
| `src/main/resources/application.yml:85` | 需添加排除路径 |

### 修复方案

**Step 1** — AuthController 添加端点：
```java
@Operation(summary = "获取验证码", description = "生成图形验证码, 返回captchaKey和Base64图片")
@GetMapping("/captcha")
public RT<CaptchaResponse> getCaptcha() {
    CaptchaResponse response = captchaService.generateCaptchaImage();
    return RT.ok(response);
}
```

**Step 2** — CaptchaService 扩展生成图片逻辑（当前只生成文本 code，需生成图片并返回 Base64）：
- 使用 `BufferedImage` + `Graphics2D` 绘制验证码图片
- 存储 code 到 Redis（已有逻辑）
- 返回 `CaptchaResponse { captchaKey, captchaImage: "data:image/png;base64,..." }`

**Step 3** — application.yml 排除路径添加：
```yaml
exclude-paths: /api/auth/login,/api/auth/logout,/api/auth/token/refresh,/api/auth/token/verify,/api/auth/captcha,/api/auth/user-info,...
```

## I02 [CRITICAL] 后端缺少 GET /auth/user-info 端点

### 问题描述
前端 `getUserInfoApi()` 调用 `GET /api/auth/user-info`，在 `userStore.login()` 成功后 via `getInfo()` 调用。后端 AuthController 没有对应端点。

### 影响
登录成功后无法获取用户信息、权限列表、角色列表、菜单树，导致：
- 动态路由无法生成（白屏或停留在登录页）
- 导航栏不显示用户名/头像
- 权限校验无法工作

### 涉及文件
| 文件 | 角色 |
|------|------|
| `erp-ai-web/src/api/modules/auth.ts:25` | 前端调用方 |
| `erp-ai-web/src/stores/modules/user.ts:41` | 前端调用方 |
| `src/main/java/com/erp/auth/controller/AuthController.java` | 需添加端点 |

### 修复方案

AuthController 添加端点：
```java
@Operation(summary = "获取当前用户信息", description = "获取当前登录用户的用户信息/权限/角色/菜单树")
@GetMapping("/user-info")
public RT<UserInfoResponse> getUserInfo() {
    UserInfoResponse response = authService.getUserInfo();
    return RT.ok(response);
}
```

AuthService 添加 `getUserInfo()` 方法，从 Sa-Token Session 获取当前用户 ID，查询 SysUser + 权限 + 菜单树。

## I03 [HIGH] Token 校验 HTTP 方法不匹配

### 问题描述
| 端 | 方法 | 路径 |
|----|------|------|
| 前端 `verifyTokenApi()` | **POST** | `/api/auth/token/verify` |
| 后端 AuthController | **GET** | `/auth/token/verify` |

前端使用 POST，后端定义 GET，导致请求返回 405 Method Not Allowed。

### 影响
Token 校验功能不可用（当前流程中前端未直接调用，但预留功能失效）。

### 涉及文件
| 文件 | 角色 |
|------|------|
| `erp-ai-web/src/api/modules/auth.ts:20` | 需改为 GET |
| `src/main/java/com/erp/auth/controller/AuthController.java:75` | 或改为 POST |

### 修复方案

**方案 A（推荐）** — 前端改为 GET（Token 校验是幂等查询，语义上 GET 更合适）：
```typescript
// erp-ai-web/src/api/modules/auth.ts
export function verifyTokenApi(): Promise<boolean> {
  return request.get('/api/auth/token/verify')
}
```

## I04 [MEDIUM] 前端 LoginResponse 类型不完整

### 问题描述
后端 `LoginResponse` 包含字段：`token, refreshToken, userId, username, nickname, avatar, menuTree, permissions`

前端 `LoginResponse` 类型仅定义：`token, refreshToken?, userId?, username?`

缺少 `nickname, avatar, menuTree, permissions` 类型定义。

### 影响
TypeScript 编译无错误（当前使用 `any` 或仅使用已定义字段），但缺少类型安全：
- 如果前端未来直接使用 login 响应中的 menuTree/permissions（跳过 getInfo 调用），类型不匹配
- 当前 `userStore.login()` 只使用 token/refreshToken，问题未暴露

### 涉及文件
| 文件 | 角色 |
|------|------|
| `erp-ai-web/src/api/types/auth.ts:9-14` | 需补充字段 |

### 修复方案

扩展 LoginResponse 类型以匹配后端实际响应：
```typescript
export interface LoginResponse {
  token: string
  refreshToken?: string
  userId?: number
  username?: string
  nickname?: string
  avatar?: string
  menuTree?: import('@/types/user').MenuTreeNode[]
  permissions?: string[]
}
```

## I05 [LOW] Sa-Token exclude-paths 遗漏

### 问题描述
`application.yml` 中 Sa-Token 排除路径为：
```yaml
exclude-paths: /api/auth/login,/api/auth/logout,/api/auth/token/refresh,/api/auth/token/verify,...
```
缺少 `/api/auth/captcha` 和 `/api/auth/user-info`。

### 影响
即使 I01/I02 修复后添加了 captcha 和 user-info 端点，这些端点仍会被 Sa-Token 拦截（未登录时 401），导致验证码和用户信息接口不可用。

### 修复方案
```yaml
exclude-paths: /api/auth/login,/api/auth/logout,/api/auth/token/refresh,/api/auth/token/verify,/api/auth/captcha,/api/auth/user-info,...
```

## I06 [LOW] 登录响应数据冗余

### 问题描述
后端 `AuthService.login()` 在登录响应中包含 `menuTree` 和 `permissions`，但前端 `userStore.login()` 忽略这些字段，通过额外调用 `getUserInfoApi()` 获取相同数据。造成：
- 一次不必要的网络往返
- 后端额外查询开销

### 修复方案

**方案 A** — 前端直接使用 login 响应（减少 1 次请求）：
- `userStore.login()` 中从 login 响应提取 menuTree/permissions/userInfo
- 移除 `getInfo()` 调用（或保留为刷新用户信息的独立功能）

**方案 B** — 后端 login 响应不包含 menuTree/permissions（保持职责单一）：
- 从 `AuthService.login()` 返回的 LoginResponse 中移除 menuTree 和 permissions
- 保持当前前端流程不变

**推荐方案 A**（性能更优，减少 1 次 HTTP 往返）。
