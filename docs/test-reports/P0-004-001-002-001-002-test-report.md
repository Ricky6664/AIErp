## 3. 测试用例详情

### 3.1 AuthService.logout() — 正常退出 (PASS)

**测试方法**: `shouldLogoutSuccessfully`
**验证内容**:
- 获取当前登录用户ID (`StpUtil.getLoginIdAsLong()`)
- 获取当前Token值 (`StpUtil.getTokenValue()`)
- 更新 `auth_online_device` 状态为"已下线"
- 调用 `StpUtil.logout()` 注销Token
- 清除Redis权限缓存 (`user:permission:{userId}`, `user:menu:{userId}`)
- 异步更新登录日志登出时间 (`LoginLogService.updateLogoutTime`)

**结果**: 全部四步操作依次执行, 设备状态正确更新为"已下线", Token已注销, Redis缓存已清除, 登出时间已异步写入.

### 3.2 AuthService.logout() — Token过期幂等 (PASS)

**测试方法**: `shouldHandleExpiredTokenGracefully`
**验证内容**:
- 当Token已过期或不存在时, `StpUtil.getLoginIdAsLong()` 抛出 `NotLoginException`
- `AuthService.logout()` 捕获异常后不传播, 正常返回
- 不会调用 `StpUtil.logout()`

**结果**: 异常被正确捕获, 无异常传播, 符合幂等退出设计要求.

### 3.3 AuthService.logout() — Redis缓存清除 (PASS)

**测试方法**: `shouldClearRedisPermissionCache`
**验证内容**:
- 退出后验证 `redisTemplate.delete("user:permission:{userId}")` 被调用
- 退出后验证 `redisTemplate.delete("user:menu:{userId}")` 被调用

**结果**: 两个Redis Key均被正确删除, 确保下次登录重新加载权限数据.

### 3.4 AuthService.logout() — 设备状态更新容错 (PASS)

**测试方法**: `shouldNotBlockLogoutWhenDeviceStatusUpdateFails`
**验证内容**:
- 当 `auth_online_device` 查询/更新抛出异常时(如数据库连接异常)
- `updateOnlineDeviceStatus` 方法内部捕获异常, 不阻断退出流程
- Token注销仍正常执行

**结果**: 防御性容错正确, 设备状态更新失败不阻断退出主流程.

### 3.5 AuthController.logout() — 接口正常响应 (PASS)

**测试方法**: `shouldReturnOkOnLogout`
**验证内容**:
- `POST /auth/logout` 调用 `authService.logout()`
- 返回 `RT<Void>` 对象, code=200, message="退出成功", data=null

**结果**: 接口返回格式符合 `RT` 统一响应规范.

### 3.6 AuthController.logout() — 重复退出幂等 (PASS)

**测试方法**: `shouldReturnOkOnRepeatedLogout`
**验证内容**:
- 连续两次调用退出接口
- 两次均返回成功 (code=200)
- `authService.logout()` 被调用两次

**结果**: 接口层幂等, 重复调用不报错.
