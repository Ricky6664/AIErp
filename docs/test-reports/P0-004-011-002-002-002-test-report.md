**验证结论**: 修改密码时，若新密码与最近3次历史密码中任一条匹配，正确抛出 `BusinessException(code=30006)`，且不会写入新的密码历史记录。

### 2.2 核心功能 — 历史密码通过 (3/3 通过)

| 用例 | 结果 |
|------|:---:|
| 新密码与历史密码均不匹配时应接受 | PASS |

**验证结论**: 修改密码成功后，新密码被正确哈希并保存，同时写入密码历史表 `sys_user_password_history`，用户记录得到更新。

### 2.3 边界条件 — 空历史或不足3条 (5/5 通过)

| 用例 | 结果 |
|------|:---:|
| 用户无历史密码记录时应接受任何有效新密码 | PASS |
| selectPasswordHistory返回null时应安全处理 | PASS |
| 仅有1条历史密码且不匹配时应接受 | PASS |
| 仅有1条历史密码且匹配时应拒绝 | PASS |
| 仅有2条历史密码且均不匹配时应接受 | PASS |

**验证结论**: 
- 空列表和 `null` 返回值均安全处理，不会抛出 NPE。
- 少于3条历史记录时，只检查实际返回的记录数，不强制要求3条。

### 2.4 边界条件 — 仅检查最近3条 (2/2 通过)

**验证结论**: 调用 `selectPasswordHistory(userId, 3)` 固定查询最近3条，LIMIT由SQL层保证。

## 四、总结

历史密码校验功能的核心逻辑正确：
1. 修改密码时正确查询最近3次历史密码并进行 BCrypt 比对
2. 匹配时拒绝修改并返回错误
3. 密码修改/重置成功后正确记录到密码历史表
4. 边界条件（空历史、null、不足3条）均有安全处理
5. 参数校验在历史密码查询之前完成，避免不必要的数据库开销
