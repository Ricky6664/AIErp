## I01 [LOW] 菜单管理页面中文硬编码

### 问题描述
菜单管理页面（`erp-ai-web/src/views/system/menu/index.vue`）中所有 UI 文案直接使用硬编码中文字符串，未使用 `$t()` 国际化函数。与其他已国际化的页面（登录页等）不一致。

### 影响
- 页面仅支持中文显示，切换到英文时此处文案不变
- 与项目国际化体系脱节

### 涉及文件
| 文件 | 角色 |
|------|------|
| `erp-ai-web/src/views/system/menu/index.vue` | 需替换硬编码文案为 `$t()` |

### 示例（部分硬编码位置）

| 位置 | 当前值 | 建议 |
|------|-------|------|
| 页面标题 h2 | `菜单管理页面` | `$t('menu.title')` |
| 页面描述 | `管理系统菜单...` | `$t('menu.desc')` |
| 查询按钮 | `查询` | `$t('common.search')` |
| 重置按钮 | `重置` | `$t('common.reset')` |
| 新增菜单按钮 | `新增菜单` | `$t('menu.add')` |
| 确认删除标题 | `删除确认` | `$t('menu.deleteConfirmTitle')` |

### 修复方案

**Step 1** — 在 `erp-ai-web/src/locales/zh-CN/` 下添加菜单管理词条文件 `menu.ts`

**Step 2** — 在 `erp-ai-web/src/locales/en-US/` 下添加对应英文词条

**Step 3** — 将 `index.vue` 模板中所有中文硬编码替换为 `$t('menu.xxx')` 调用

**建议**: 可在后续国际化专项任务（P0-002-005 系列）中统一处理，不作为当前页面的阻塞项。

## I02 [LOW] /tree/current 和 /mobile-tree/current 端点缺少权限注解

### 问题描述
后端 `SysMenuController` 中以下端点未标注 `@SaCheckPermission`，但其他 tree 端点均有权限注解：

| 端点 | 当前 | 同级端点 |
|------|------|---------|
| `GET /api/system/menus/tree/current` | **无注解** | `/tree` 有 `@SaCheckPermission("system:menu:query")` |
| `GET /api/system/menus/mobile-tree/current` | **无注解** | `/mobile-tree` 有 `@SaCheckPermission("system:menu:query")` |

### 影响
`/tree/current` 和 `/mobile-tree/current` 是面向当前登录用户的接口，用于获取当前用户有权限的菜单树。
虽然不标注权限注解可能是有意设计（任何已登录用户都应该能获取自己的菜单树），但与其他类似端点不一致，可能属于遗漏。

### 涉及文件
| 文件 | 行号 | 角色 |
|------|:---:|------|
| `src/main/java/com/erp/system/controller/SysMenuController.java` | 173-178 | 需确认是否需要注解 |
| `src/main/java/com/erp/system/controller/SysMenuController.java` | 196-201 | 同上 |

### 修复方案

**方案 A**（推荐）— 不添加注解，保持现状：
- `/tree/current` 和 `/mobile-tree/current` 的设计意图是任何已登录用户均可获取自己的菜单树
- 这是前端导航渲染的核心接口，不应受权限限制
- 在方法上添加 `// 无需权限注解：所有已登录用户可获取自己的菜单树` 注释说明意图

**方案 B** — 添加注解（如确认应受权限控制）：
```java
@SaCheckPermission("system:menu:query")
```
