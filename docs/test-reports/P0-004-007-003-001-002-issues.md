## I02 — 空值权限检查在 directive 和 composable 间不一致

**文件**: 
- `erp-ai-web/src/directives/permission.ts:13` — `checkPermission()`
- `erp-ai-web/src/composables/usePermission.ts:13` — `hasPermission()`

**描述**: 
- `checkPermission('')` 返回 `true`（显示元素）— 因为 `!value` 为 true
- `usePermission().hasPermission('')` 返回 `false`（无权限）— 因为 `!permissionCode` 为 true

两者对空字符串的处理逻辑相反。

**影响**: 低。实际使用中不会对空字符串调用这些函数（directive 必须绑定具体权限码，composable 调用时传具体权限码）。但如果未来有人错误使用 `v-permission=""`，行为可能与预期不符。

**建议修复**: 统一空值处理语义。推荐将 `checkPermission` 改为：
```typescript
if (!value || (Array.isArray(value) && value.length === 0)) return false
```
使空值统一表示"无权限"而非"无限制"。

## N01 — processMenuData 不传递 parentPath 给子菜单

**文件**: `erp-ai-web/src/utils/menuPipeline.ts`

**描述**: `processMenuData` 对每个菜单项调用 `normalizePath(menu.path)` 但从不传递 `parentPath` 参数。`normalizePath` 函数签名支持 `parentPath`:
```typescript
export function normalizePath(path: string, parentPath?: string): string
```

因此子菜单路径不会被自动拼接父路径。

**实际影响**: 无。后端返回的菜单数据中，`path` 字段已为完整绝对路径（如 `/system/user`），不需要前端拼接。此行为符合当前后端契约。

**建议**: 如果未来后端可能返回相对路径的子菜单，需要修改 `processMenuData` 在递归时传递父路径：
```typescript
processed.children = processMenuData(menu.children.map(child => ({
  ...child,
  path: normalizePath(child.path, menu.path)
})))
```
