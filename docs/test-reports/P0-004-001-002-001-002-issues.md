## 问题清单

### 问题 #1: 设备状态更新异常日志级别偏低

| 属性 | 值 |
|------|-----|
| 严重程度 | 低 — 不影响功能 |
| 发现方式 | 代码审查 |
| 位置 | `AuthService.java:142-143` |

**描述**:
`updateOnlineDeviceStatus()` 方法中, 当数据库查询或更新失败时, 异常被捕获并以 `log.debug` 级别记录。在生产环境中 `debug` 级别日志通常不输出, 导致运维人员无法感知设备状态更新失败。

```java
} catch (Exception e) {
    log.debug("更新在线设备状态失败(可能表未初始化): {}", e.getMessage());
}
```

**建议修复**:
将日志级别从 `debug` 提升为 `warn`, 确保生产环境也能记录异常:

```java
} catch (Exception e) {
    log.warn("更新在线设备状态失败: {}", e.getMessage());
}
```

**是否需要立即修复**: 否, 当前阶段 `auth_online_device` 表功能尚在开发中, debug 级别合理。建议在 P0-004-005(认证配置后端开发) 阶段修复。

### 问题 #2: 无 logout 方法参数校验

| 属性 | 值 |
|------|-----|
| 严重程度 | 低 — 设计如此 |
| 发现方式 | 代码审查 |
| 位置 | `AuthService.java:107` |

**描述**:
`logout()` 方法无任何入参, 完全依赖从当前请求上下文获取用户信息。这种方式在正常情况下没问题, 但如果未来需要支持管理员强制下线其他用户, 则无法复用此方法。当前 `SessionService.forceLogout(String token)` 已经提供了此功能。

**建议**: 无需修改, 当前设计已满足需求。管理员强制下线已通过 `SessionService` 单独实现。
