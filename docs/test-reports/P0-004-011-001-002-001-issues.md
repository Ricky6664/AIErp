## ISSUE-1: 缺少 GET /api/auth/captcha 接口端点

**严重级别**：P0-临界

**发现位置**：
- 前端：`erp-ai-web/src/api/modules/auth.ts:13` — `request.get('/api/auth/captcha')`
- 后端：`src/main/java/com/erp/auth/controller/AuthController.java` — 无对应 `@GetMapping("/captcha")`

**问题描述**：
前端 `getCaptchaApi()` 调用 `GET /api/auth/captcha` 获取验证码图片和 key，但 `AuthController` 中不存在该端点。当前 Controller 仅有 `/auth/login`、`/auth/logout`、`/auth/token/verify`、`/auth/token/refresh` 四个端点。

**影响范围**：
- 前端登录页加载时 `loadCaptcha()` 调用失败
- 捕获异常后 `captchaImage` 设为空字符串
- 用户看到的是占位符而非验证码图片
- 用户仍可手动输入验证码（如果知道的话），但无法看到验证码内容
- 登录时 `captchaKey` 为空字符串，后端 `verifyCaptcha` 会抛出 `CaptchaException`

**修复方案**：
在 `AuthController` 中新增验证码生成端点：

```java
@Operation(summary = "获取图形验证码", description = "生成图形验证码并返回base64图片和唯一标识key")
@GetMapping("/captcha")
public RT<CaptchaResponse> getCaptcha() {
    CaptchaResponse response = captchaService.generateCaptchaImage();
    return RT.ok(response);
}
```

**关联任务**：P0-004-011-001-002-002（后端登录接口改造）

## ISSUE-2: CaptchaService 未生成实际验证码图片

**严重级别**：P1-重要

**发现位置**：
- `src/main/java/com/erp/auth/service/CaptchaService.java:36-43` — `generateCaptcha()` 方法

**问题描述**：
`CaptchaService.generateCaptcha()` 当前实现：
1. 生成 4 位随机文本验证码
2. 存入 Redis
3. 返回 captchaKey（UUID 去横线）

但缺少以下关键步骤：
- 未使用 Java AWT（`BufferedImage` + `Graphics2D`）绘制验证码图片
- 未将图片编码为 Base64 字符串
- 返回类型为 `String`（仅 key），前端期望 `CaptchaResponse { captchaKey, captchaImage }`

**影响范围**：
- 即使 ISSUE-1 修复（添加了 API 端点），也无法向前端返回图片
- 前端 `CaptchaImage` 组件依赖 `captchaImage` (base64 data URI) 显示图片

**修复方案**：
扩展 `CaptchaService`，新增 `generateCaptchaImage()` 方法：

1. 生成随机验证码文本
2. 使用 `BufferedImage` 创建图片（宽 120px × 高 40px）
3. 使用 `Graphics2D` 绘制背景噪点、干扰线、扭曲文字
4. 将 `BufferedImage` 编码为 Base64 PNG
5. 验证码文本存入 Redis（key → code）
6. 返回包含 `captchaKey` 和 `captchaImage`（`data:image/png;base64,...`）的响应对象

**示例代码框架**：
```java
public CaptchaResponse generateCaptchaImage() {
    String captchaKey = UUID.randomUUID().toString().replace("-", "");
    String captchaCode = generateRandomCode(4);
    
    // 存入 Redis
    redisTemplate.opsForValue().set(CAPTCHA_PREFIX + captchaKey, captchaCode, 
                                     CAPTCHA_TTL, CAPTCHA_TTL_UNIT);
    
    // 生成图片
    BufferedImage image = new BufferedImage(120, 40, BufferedImage.TYPE_INT_RGB);
    Graphics2D g2d = image.createGraphics();
    // ... 绘制背景、文字、干扰线 ...
    g2d.dispose();
    
    // Base64 编码
    ByteArrayOutputStream baos = new ByteArrayOutputStream();
    ImageIO.write(image, "png", baos);
    String base64 = Base64.getEncoder().encodeToString(baos.toByteArray());
    
    return new CaptchaResponse(captchaKey, "data:image/png;base64," + base64);
}
```

## ISSUE-3: AuthProperties 配置未注入 CaptchaService

**严重级别**：P2-优化

**发现位置**：
- `src/main/java/com/erp/auth/service/CaptchaService.java:25-27` — 硬编码常量
- `src/main/java/com/erp/auth/config/AuthProperties.java` — 已定义但未使用的配置类
- `src/main/resources/application.yml:87-93` — 已配置但未生效的 YAML

**问题描述**：
`CaptchaService` 使用硬编码常量：
```java
private static final long CAPTCHA_TTL = 5;
// generateRandomCode(4) — 硬编码长度 4
```

而 `AuthProperties.Captcha` 已正确定义了 `ttlMinutes` 和 `codeLength` 配置项，且在 `application.yml` 中有对应配置：
```yaml
auth:
  captcha:
    ttl-minutes: 5
    code-length: 4
```

`AuthPropertiesTest` 已验证了配置校验（`@Min` 约束），但 `CaptchaService` 未注入 `AuthProperties`。

**影响范围**：
- 配置文件中修改验证码 TTL 和长度不会生效
- 运维人员无法通过配置调整验证码行为
- 功能上暂无影响（硬编码值与配置默认值相同）

**修复方案**：
在 `CaptchaService` 中注入 `AuthProperties` 并使用其配置值：

```java
private final AuthProperties authProperties;

// 替换硬编码
long ttl = authProperties.getCaptcha().getTtlMinutes();
int codeLength = authProperties.getCaptcha().getCodeLength();
```
