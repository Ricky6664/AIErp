## Issue #1 — 自定义数据范围未持久化

**级别：P2（一般）**

**描述**：
RoleForm 在数据范围选择"自定义"时，用户勾选的部门树（`customDeptIds`）和选择的人员（`customUserIds`）仅在前端表单中维护，提交时 `baseData` 不含这两个字段。后端通过独立 API `/api/system/role/{id}/data-scopes`（接收 `List<SysRoleDataScope>`）管理自定义数据权限配置。

**定位**：
- `RoleForm.vue` 第 386-394 行 `handleSubmit` — `baseData` 缺少 `customDeptIds`/`customUserIds`
- `RoleForm.vue` 第 316-345 行 `loadRoleDetail` — 未调用 `GET /api/system/role/{id}/data-scopes` 获取已有配置

**修复方案**：
1. `erp-ai-web/src/api/modules/role.ts` 新增：
   - `getRoleDataScopes(roleId)` → `GET /api/system/role/{roleId}/data-scopes`
   - `saveRoleDataScopes(roleId, scopes)` → `POST /api/system/role/{roleId}/data-scopes`
2. `loadRoleDetail` 中调用 `getRoleDataScopes` 回填 `customDeptIds`/`customUserIds`
3. `handleSubmit` 中在 `saveInheritance`/`saveExclusions` 前调用 `saveRoleDataScopes`

## Issue #2 — 后端 pageList 不支持 dataScope 筛选

**级别：P2（一般）**

**描述**：
前端 RoleList.vue 发送 `dataScope` 查询参数用于筛选角色列表，但后端 `SysRoleController.pageList()` 方法仅接受 `roleCode`、`roleName`、`isEnabled` 三个参数，`dataScope` 参数被忽略。

**定位**：
- 前端：`RoleList.vue` 第 210-212 行发送 `params.dataScope`
- 后端：`SysRoleController.java` 第 65-69 行 pageList 方法签名缺少 `dataScope` 参数

**修复方案**：
后端 `pageList` 方法增加 `@RequestParam(required = false) String dataScope` 参数，在 wrapper 中追加 `eq(SysRole::getDataScope, dataScope)`。

## Issue #3 — 关键字搜索使用 AND 逻辑

**级别：P3（提示）**

**描述**：
前端发送 `{ roleName: keyword, roleCode: keyword }`，后端构建 AND 查询条件，导致搜索 `keyword` 时只能匹配 roleCode 和 roleName 同时包含该关键词的角色。

**修复方案**：
后端 pageList 方法中使用 `wrapper.and(w -> w.like(SysRole::getRoleCode, roleCode).or().like(SysRole::getRoleName, roleName))` 替代单独的 AND 条件。

---

## Issue #4 — Route name 依赖后端菜单数据

**级别：P3（提示）**

**描述**：
RoleList.vue 使用 `router.push({ name: 'RoleForm', ... })` 导航，该路由由 `permissionStore.generateRoutes()` 从后端菜单表动态创建。如果后端菜单表没有 `menuName='RoleForm'` 的记录，导航将失败。

**建议**：
确保后端菜单种子数据包含 RoleForm 和 RoleMenuPermission 菜单项，或在部署文档中标注此依赖。

## 补充：关于表单布局方式的说明

任务规格要求使用 `el-dialog`（width=720px）弹窗模式，实际实现使用整页表单布局。此差异在本次验证中标记为已知偏离，不做为 bug 处理，因为：
- 整页表单对于含部门树 + 远程搜索人员的复杂表单体验更好
- 实现方式不影响功能正确性
- 如产品确认需弹窗模式，可后续重构
