## Issue #1 [CRITICAL] 缺少3个REST API端点

**现象**：前端调用的3个API端点在后端均无对应的Controller方法，部门关联功能完全不可用。

| API端点 | HTTP方法 | 前端函数 | 文件:行号 |
|---------|:---:|---------|:---:|
| /api/system/dept/tree | GET | getDeptTree() | system.ts:63 |
| /api/system/user/dept | POST | assignUserDepts() | user.ts:64 |
| /api/system/user/dept/{userId} | DELETE | clearUserDepts() | user.ts:73 |

**根因**：UserDeptService/UserDeptServiceImpl 已实现业务逻辑，但 UserController 中未添加对应的 REST 端点。

**修复方案**：

在 `UserController.java` 中新增3个端点方法：

```java
private final UserDeptService userDeptService;

// 1. GET /api/system/dept/tree — 查询部门树
@Operation(summary = "查询部门树")
@SaCheckPermission("system:user:query")
@GetMapping("/dept/tree")
public RT<List<DeptTreeNode>> getDeptTree() {
    // 从 sys_dept 表查询并构建树形结构
    return RT.ok(deptService.getTree());
}

// 2. POST /api/system/user/dept — 分配用户部门
@Operation(summary = "批量分配用户部门")
@SaCheckPermission("system:user:role-assign")
@PostMapping("/dept")
public RT<Void> assignDepts(@Valid @RequestBody UserDeptAssignDTO dto) {
    userDeptService.assignDepts(dto.getUserId(), dto.getDeptIds(), dto.getPrimaryDeptId());
    return RT.ok();
}

// 3. DELETE /api/system/user/dept/{userId} — 清除用户部门
@Operation(summary = "清除用户所有部门关联")
@SaCheckPermission("system:user:role-assign")
@DeleteMapping("/dept/{userId}")
public RT<Void> clearDepts(@PathVariable Long userId) {
    userDeptService.clearAllDepts(userId);
    return RT.ok();
}
```

**需要新增的文件**：
- `UserDeptAssignDTO.java` — 请求体DTO（userId, deptIds, primaryDeptId）
- `DeptTreeNode.java` — 部门树节点VO（如尚未定义）
- `DeptService.java` / `DeptServiceImpl.java` — 部门查询Service（如尚未定义）

**修复涉及文件**：
- `src/main/java/com/erp/system/controller/UserController.java` — 新增3个方法 + 注入UserDeptService

## Issue #2 [CRITICAL] DetailVO缺少deptIds和primaryDeptId字段

**现象**：前端 UserDeptDialog.vue 第217-218行读取 `user.deptIds` 和 `user.primaryDeptId`，但 SysUserVO.DetailVO 中没有这两个字段，且 UserController.getById() 未从 sys_user_dept 表查询并填充。

**根因**：DetailVO 只包含 SysUser 实体字段（ownerDeptId），未包含关联表 sys_user_dept 的数据。

**修复方案**：

1. 在 `SysUserVO.DetailVO` 中新增字段：
```java
private List<Long> deptIds;       // 用户关联的所有部门ID
private Long primaryDeptId;       // 主部门ID
```

2. 在 `UserController.getById()` 的 `toDetailVO` 方法或调用处，查询并填充部门信息：
```java
// UserController.getById() 中，在现有代码后追加:
vo.setDeptIds(userDeptService.getUserDeptIds(id));
vo.setPrimaryDeptId(userService.getPrimaryDeptId(id));  
// 或通过 UserMapper 查询 sys_user_dept WHERE user_id=? AND is_primary=1
```

**修复涉及文件**：
- `src/main/java/com/erp/system/vo/SysUserVO.java` — DetailVO 新增字段
- `src/main/java/com/erp/system/controller/UserController.java` — getById() 填充部门字段

## Issue #3 [HIGH] assignDepts不处理primaryDeptId

**现象**：UserDeptServiceImpl.assignDepts(userId, deptIds) 方法签名缺少 primaryDeptId 参数，导致前端传来的主部门ID被丢弃。

**根因**：Service接口设计时未考虑 primaryDeptId 的传递。

**修复方案**：

1. 修改 `UserDeptService` 接口：
```java
void assignDepts(Long userId, List<Long> deptIds, Long primaryDeptId);
```

2. 修改 `UserDeptServiceImpl.assignDepts` 实现：
```java
@Override
@Transactional(rollbackFor = Exception.class)
public void assignDepts(Long userId, List<Long> deptIds, Long primaryDeptId) {
    SysUser user = getById(userId);
    if (user == null) {
        throw new BusinessException(ErrorCode.DATA_NOT_FOUND, "用户不存在: id=" + userId);
    }
    baseMapper.deleteUserDepts(userId);
    if (deptIds != null && !deptIds.isEmpty()) {
        baseMapper.insertUserDepts(userId, deptIds);
        // 设置主部门
        if (primaryDeptId != null && deptIds.contains(primaryDeptId)) {
            baseMapper.setPrimaryDept(userId, primaryDeptId);
        }
    }
    // ... 踢出用户逻辑保持不变
}
```

**修复涉及文件**：
- `src/main/java/com/erp/system/service/UserDeptService.java` — 方法签名
- `src/main/java/com/erp/system/service/impl/UserDeptServiceImpl.java` — 方法实现

## Issue #4 [HIGH] insertUserDepts硬编码is_primary=0

**现象**：UserMapper.xml 第151-154行 INSERT 语句中 is_primary 硬编码为 0，无法标记主部门。

**根因**：insertUserDepts 的 SQL 设计为批量等权插入，不支持指定主部门。

**修复方案**：

**方案A（推荐 — 配合 Issue #3 的修复）**：
insertUserDepts 保持批量插入 is_primary=0，之后通过 setPrimaryDept 单独更新主部门标记。此方案的优点是不改变 Mapper 接口签名，逻辑清晰。

**方案B**：
修改 insertUserDepts 传入 primaryDeptId 参数，在 foreach 中使用 CASE WHEN：
```xml
<insert id="insertUserDepts">
    INSERT INTO sys_user_dept (user_id, dept_id, is_primary, create_time)
    VALUES
    <foreach collection="deptIds" item="deptId" separator=",">
        (#{userId}, #{deptId}, 
         CASE WHEN #{deptId} = #{primaryDeptId} THEN 1 ELSE 0 END, 
         NOW())
    </foreach>
</insert>
```
需要同步修改 Mapper 接口和 Service 调用。

**推荐方案A**，因其改动最小且不影响现有 Mapper 签名。

**修复涉及文件**：
- 方案A：无需修改（Issue #3 的修复已覆盖）
- 方案B：`src/main/resources/mapper/system/UserMapper.xml`、`src/main/java/com/erp/system/mapper/UserMapper.java`
