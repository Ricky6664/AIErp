## ISS-01: 前后端响应码不匹配 [CRITICAL] [NEW]

### 问题描述

前端 `request.ts` 响应拦截器判定成功条件为 `code === 0`，但后端 `RT.java` 成功时返回 `code = 200`。这导致所有 API 成功响应都被当作业务错误处理，显示错误提示并 reject Promise。

### 影响范围

- 所有通过 `request.ts` 发送的 API 请求均受影响
- 登录流程完全不可用：login API 调用成功但前端判定为失败
- 用户信息获取、Token 验证等所有后续请求同样失败

### 定位

| 位置 | 文件 | 行号 |
|------|------|:---:|
| 前端 | `erp-ai-web/src/utils/request.ts` | 86 |
| 后端 | `src/main/java/com/erp/common/result/RT.java` | 77 |

### 根因分析

```typescript
// request.ts:83-103
const { code, data, message } = response.data
if (code === 0) {        // ← 期望 0
  return data
}
if (code === 20001) { ... }
if (code === 40001 || code === 40003) { ... }
ElMessage.error(message || '请求失败')  // ← code=200 落在此处
return Promise.reject(new Error(message))
```

```java
// RT.java:76-78
public static <T> RT<T> ok(T data) {
    return new RT<>(200, "success", data, System.currentTimeMillis());
    //               ^^^ 成功码为 200
}
```

### 修复方案

**方案 A（推荐）**: 修改前端 `request.ts`，将 `code === 0` 改为 `code === 200`

```typescript
// request.ts:86
- if (code === 0) {
+ if (code === 200) {
```

**方案 B**: 修改后端 `RT.java`，将成功码从 200 改为 0

```java
// RT.java:77
- return new RT<>(200, "success", data, System.currentTimeMillis());
+ return new RT<>(0, "success", data, System.currentTimeMillis());
```

### 推荐

方案 A（改前端）更合理，因为：
1. HTTP 语义上 200 是标准成功状态码
2. 后端 ErrorCode 枚举也已使用 4xxxx 系列，保持 200=成功 更直觉
3. 后端测试用例（AuthControllerTest）已验证 `assertEquals(200, result.getCode())`，改后端需同步修改 12 个测试断言

## ISS-02: 缺少 GET /auth/captcha 端点 [CRITICAL] [CARRY-OVER]

### 问题描述

前端 `useLogin.ts` 在 mounted 时调用 `loadCaptcha()` → `getCaptchaApi()` → `GET /api/auth/captcha`，但后端 `AuthController` 没有此端点。

### 影响范围

登录页加载时无法获取验证码，captchaImage 始终为空字符串，验证码输入无意义。

### 定位

| 位置 | 文件 | 行号 |
|------|------|:---:|
| 前端调用 | `erp-ai-web/src/composables/login/useLogin.ts` | 77 |
| 前端 API | `erp-ai-web/src/api/modules/auth.ts` | 12-13 |
| 后端服务 | `src/main/java/com/erp/auth/service/CaptchaService.java` | 36-42 |

### 根因分析

`CaptchaService.generateCaptcha()` 仅返回 captchaKey 字符串，未生成图片数据。前端 `CaptchaImage.vue` 期望接收 base64 格式的图片数据（`:src="image"`）。

### 修复方案

1. 在 `AuthController` 或新建 `CaptchaController` 中添加 `GET /auth/captcha` 端点
2. 该端点需生成验证码图片（如使用 Java AWT BufferedImage 绘制，转 base64 返回）
3. 返回格式需匹配前端 `CaptchaResponse` 接口：`{ captchaKey: string, captchaImage: string }`
4. 在 `application.yml` 的 Sa-Token exclude-paths 中添加 `/api/auth/captcha`

## ISS-03: 缺少 GET /auth/user-info 端点 [CRITICAL] [CARRY-OVER]

### 问题描述

前端登录成功后，`userStore.login()` 自动调用 `getInfo()` → `getUserInfoApi()` → `GET /api/auth/user-info`，但后端没有此端点。

### 影响范围

登录成功后无法获取用户信息、权限列表和菜单树，前端路由无法动态生成。

### 定位

| 位置 | 文件 | 行号 |
|------|------|:---:|
| 前端调用 | `erp-ai-web/src/stores/modules/user.ts` | 42 |
| 前端 API | `erp-ai-web/src/api/modules/auth.ts` | 24-25 |

### 修复方案

1. 在 `AuthController` 中添加 `GET /auth/user-info` 端点
2. 该端点从 Sa-Token 会话获取当前登录用户 ID
3. 查询用户信息、权限列表、菜单树
4. 返回格式需匹配前端 `UserInfoResponse` 接口：`{ userInfo, permissions, roles, menuTree }`
5. 在 `application.yml` 的 Sa-Token exclude-paths 中添加 `/api/auth/user-info`

## ISS-04: verifyToken HTTP 方法不匹配 [MEDIUM] [CARRY-OVER]

### 问题描述

前端 `verifyTokenApi()` 使用 `request.post('/api/auth/token/verify')`（POST），后端 `AuthController` 使用 `@GetMapping("/token/verify")`（GET）。

### 影响范围

Token 验证请求返回 405 Method Not Allowed。

### 定位

| 位置 | 文件 | 行号 |
|------|------|:---:|
| 前端 | `erp-ai-web/src/api/modules/auth.ts` | 20-21 |
| 后端 | `src/main/java/com/erp/auth/controller/AuthController.java` | 75 |

### 修复方案

**方案 A（推荐）**: 修改前端，将 POST 改为 GET（GET 方法语义更合适，Token 通过请求头传递无需 Body）

```typescript
// auth.ts:20-22
- export function verifyTokenApi(): Promise<boolean> {
-   return request.post('/api/auth/token/verify')
- }
+ export function verifyTokenApi(): Promise<boolean> {
+   return request.get('/api/auth/token/verify')
+ }
```

方案 B: 修改后端为 @PostMapping（不推荐，GET 语义更合适）
