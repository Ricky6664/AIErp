## 问题 #1：el-table 行类型不匹配（已修复 ✅）

- **严重程度**：中（编译错误）
- **位置**：`erp-ai-web/src/views/auth/config/online-device/index.vue:137`
- **现象**：`vue-tsc` 报错 TS2345 — `Argument of type 'DefaultRow' is not assignable to parameter of type 'OnlineDeviceItem'`
- **原因**：el-table 的 `#default="{ row }"` 插槽中 `row` 类型为 `DefaultRow`，而 `handleKick` 函数参数声明为 `OnlineDeviceItem`
- **修复**：`@confirm="handleKick(row as OnlineDeviceItem)"` — 添加类型断言
- **状态**：✅ 已修复

## 问题 #2：批量强制下线错误处理不完整（待处理）

- **严重程度**：中
- **位置**：`erp-ai-web/src/views/auth/config/online-device/index.vue:291-310`
- **现象**：`handleBatchKick` 函数的 catch 块为空，且 ElMessageBox.confirm 取消操作也走 catch 分支
- **原因**：
  1. `ElMessageBox.confirm` 在用户点击"取消"时 Promise reject，进入 catch
  2. API 调用失败也进入同一个 catch
  3. 两种场景无法区分，API 失败被静默吞掉
- **建议修复**：
  ```ts
  async function handleBatchKick(): Promise<void> {
    if (selectedIds.value.length === 0) return
    try {
      await ElMessageBox.confirm(
        `确定将选中的 ${selectedIds.value.length} 台设备强制下线？`,
        '批量强制下线',
        { confirmButtonText: '确定', cancelButtonText: '取消', type: 'warning' }
      )
    } catch {
      return // 用户取消
    }
    try {
      await batchKickDeviceApi(selectedIds.value)
      ElMessage.success(`已强制下线 ${selectedIds.value.length} 台设备`)
      selectedIds.value = []
      await fetchDeviceList()
    } catch {
      ElMessage.error('批量强制下线失败，请重试')
    }
  }
  ```
- **状态**：⏳ 待后续任务处理

## 问题 #3：API 路径使用复数形式与规格文档不一致（待确认）

- **严重程度**：低
- **位置**：
  - `erp-ai-web/src/api/modules/onlineDevice.ts:6` — `GET /api/system/online-devices/page`
  - `erp-ai-web/src/api/modules/onlineDevice.ts:13` — `POST /api/system/online-devices/{tokenId}/kick`
- **现象**：规格文档（P0-004-010-004-001-001 Section 5.2）使用单数形式 `/api/system/online-device`，实现使用复数形式 `/api/system/online-devices`
- **影响**：如果后端也使用复数形式则无影响；如果后端使用单数形式则接口调不通
- **建议**：与后端 Controller 实际路径对比确认，保持一致
