## 问题 1: 历史密码校验的详细错误消息在前端不可见

| 属性 | 值 |
|------|-----|
| 严重程度 | 中 (功能正常, 用户体验受影响) |
| 影响范围 | `UserServiceImpl.changePassword()` 第163行、第170行 |
| 状态 | 待修复 |

### 问题描述

`changePassword()` 方法中抛出的 `BusinessException` 包含详细错误信息，但由于 `BusinessException` 的消息格式化机制，这些详细信息被丢弃：

```java
// 第163行 - "新密码不能与旧密码相同" 实际被丢弃
throw new BusinessException(ErrorCode.PARAM_DUPLICATE, "新密码不能与旧密码相同");

// 第170行 - "新密码不能与最近3次使用过的密码相同" 实际被丢弃
throw new BusinessException(ErrorCode.PARAM_DUPLICATE, "新密码不能与最近3次使用过的密码相同");
```

`BusinessException(IErrorCode, Object... args)` 构造函数将 `args` 用于替换 `ErrorCode` 消息模板中的 `{}` 占位符。但 `ErrorCode.PARAM_DUPLICATE` 的消息模板为 `"参数值重复"`，不含任何 `{}` 占位符。因此 args 被静默忽略，实际返回给前端的消息始终是 `"参数值重复"`，无法区分"与旧密码相同"还是"与历史密码重复"。

### 预期行为

前端应能获取到具体的原因描述，以便向用户展示有意义的错误提示。

### 建议修复方案

**方案 A** — 修改 ErrorCode 消息模板（推荐）
将 `PARAM_DUPLICATE` 的消息模板改为支持参数化：
```java
PARAM_DUPLICATE(30006, "参数值重复: {}"),
```
这样 `BusinessException(ErrorCode.PARAM_DUPLICATE, "新密码不能与最近3次使用过的密码相同")` 将生成消息 `"参数值重复: 新密码不能与最近3次使用过的密码相同"`。

**方案 B** — 使用自定义消息构造
在 `BaseException` 中增加一个新的构造函数，允许直接传入完整消息而不经过模板替换。
