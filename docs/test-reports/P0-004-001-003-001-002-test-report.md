## 四、已知限制

1. **checkLogin() void静态方法mock限制**: Sa-Token 的 `StpUtil.checkLogin()` 是 void 静态方法，Mockito `MockedStatic.when()` 在注册 stub 时先执行真实方法，导致在无 Sa-Token 上下文的单元测试中无法 stub。Token过期/未登录的错误码区分逻辑（TOKEN_EXPIRED vs UNAUTHORIZED）在 AuthController 层通过 mock AuthService 实例方法间接验证，完整的 Sa-Token 异常类型路径需通过集成测试覆盖。

2. **设备状态更新依赖 AuthOnlineDevice 表**: `updateDeviceLastActiveTime()` 方法依赖数据库查询，测试中通过 mock 验证了容错行为，但端到端验证需要实际数据库环境。

Token校验与刷新核心逻辑全部通过单元测试验证。双Token机制（accessToken + refreshToken）的核心安全特性——refreshToken一次性使用（防重放）、Token平滑替换（旧Token宽松期可用）、新refreshToken 7天TTL存储——均通过 mock 验证。防御性容错（设备状态更新失败不阻断主流程）正常工作。无未解决的阻塞性问题。
