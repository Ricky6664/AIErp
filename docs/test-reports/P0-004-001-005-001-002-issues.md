## 发现问题

### 1. [🟢 建议] LoginLogService 缺少独立单元测试

- **文件**：`src/main/java/com/erp/auth/service/LoginLogService.java`
- **描述**：LoginLogService 没有独立的单元测试。当前的 AuthServiceTest 通过 Mock LoginLogService 来验证调用，但未直接测试 LoginLogService 内部逻辑（如 buildLog 构造、Mapper 写入、异常捕获等）。
- **影响**：LoginLogService 内部的边界条件和异常路径（如数据库连接失败时的日志写入降级）未被独立测试覆盖。
- **修复方案**：编写 `LoginLogServiceTest`，Mock `SysLoginLogMapper`，覆盖：
  - `logSuccess()` 正常写入
  - `logFailure()` 正常写入
  - `updateLogoutTime()` 查找到记录
  - `updateLogoutTime()` 未找到记录（null safe）
  - `asyncWriteLog()` 成功/失败路径
  - Mapper insert 抛异常时 catch 块不向外传播
- **优先级**：低 — 不影响功能正确性，建议在后续模块中补充。

## 已排除的潜在问题

以下场景经分析后确认无问题：

| 场景 | 分析结论 |
|------|---------|
| @Async 方法内部调用 private 方法 | `@Async` 代理拦截 public 方法后，内部调用链全部在异步线程执行，行为正确 |
| updateLogoutTime 读后写无事务 | 日志表为追加型数据，登出时间小延迟无业务影响，无需复杂事务保护 |
| 数据库写失败无补偿 | 已通过 log.error 记录，异步日志写入设计上允许失败不阻断主流程 |
| 并发问题 | 每条日志独立 insert，userId+created_at+status 组合索引即可满足查询，无需锁 |
