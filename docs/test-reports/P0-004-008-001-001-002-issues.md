## 问题 #1: RT响应码不一致（CRITICAL）

**发现位置**:
- 后端: `src/main/java/com/erp/common/result/RT.java:77` — `new RT<>(200, ...)`
- 后端: `src/main/java/com/erp/common/enums/ErrorCode.java:32` — `SUCCESS(0, "操作成功")`
- 前端: `erp-ai-web/src/utils/request.ts:86` — `if (code === 0)`

**现象**: `RT.ok()` 返回 `code: 200`，前端响应拦截器检查 `code === 0` 才认为成功。所有API调用将被当作业务错误处理，前端弹窗报错。

**根因**: `RT.ok()` 硬编码了HTTP风格的成功码200，但 `ErrorCode.SUCCESS` 定义为0，前端也按0判断。后端内部存在架构矛盾。

**影响范围**: 全系统所有API接口，影响面100%。

**修复方案**:

**方案A（推荐）**: 修改 `RT.ok()` 系列方法，使用 `ErrorCode.SUCCESS.getCode()` 替代硬编码200:

```java
// RT.java — 修改3处
public static <T> RT<T> ok(T data) {
    return new RT<>(ErrorCode.SUCCESS.getCode(), "success", data, System.currentTimeMillis());
}
public static <T> RT<T> ok() { return ok(null); }
public static <T> RT<T> ok(String message, T data) {
    return new RT<>(ErrorCode.SUCCESS.getCode(), message, data, System.currentTimeMillis());
}
```

**方案B**: 修改前端 `request.ts`，将 `code === 0` 改为 `code === 200`，同时更新 `ErrorCode.SUCCESS`。不推荐——会与ErrorCode设计意图矛盾。

**修复文件清单**:
- `src/main/java/com/erp/common/result/RT.java`（如选方案A，3行）
- `src/test/java/com/erp/common/result/RTTest.java`（同步更新测试断言）

## 问题 #2: el-tree-select的props类型错误（HIGH）

**发现位置**: `erp-ai-web/src/views/system/user/index.vue:34`

**现象**: `vue-tsc` 报错 `'value' does not exist in type 'TreeOptionProps'`

**根因**: Element Plus 2.14.x 的 `TreeOptionProps` 类型不包含 `value` 属性。节点值标识应通过组件 `node-key` attribute 指定。

**修复方案**:

```html
<!-- 修改前 -->
<el-tree-select
  :props="{ label: 'menuName', value: 'id', children: 'children' }"
  ...
/>

<!-- 修改后 -->
<el-tree-select
  :props="{ label: 'menuName', children: 'children' }"
  node-key="id"
  ...
/>
```

**修复文件清单**:
- `erp-ai-web/src/views/system/user/index.vue`（修改`:props`并添加`node-key="id"`，1-2行）

## 问题 #5: PageResult类型定义不一致（MEDIUM）

**发现位置**:
- 后端: `PageResult.java` — 字段名 `list`
- 前端全局类型: `erp-ai-web/src/types/api.d.ts:8` — 字段名 `records`
- 前端用户API: `erp-ai-web/src/api/modules/user.ts:4-9` — 自定义 `UserPageResult` 字段名 `list`

**现象**: 全局 `PageResult` 类型与后端字段名不一致（`records` vs `list`），用户模块通过自定义接口规避了问题。

**修复方案**: 统一全局 `PageResult` 类型定义，将 `records` 改为 `list`:

```typescript
// api.d.ts
export interface PageResult<T = unknown> {
  list: T[]      // 改为 list（匹配后端）
  total: number
  pageNum: number
  pageSize: number
}
```

同时移除 `user.ts` 中冗余的 `UserPageResult` 接口，直接使用全局 `PageResult<UserListItem>`。

**修复文件清单**:
- `erp-ai-web/src/types/api.d.ts`（改records为list）
- `erp-ai-web/src/api/modules/user.ts`（移除UserPageResult，使用全局PageResult）
- `erp-ai-web/src/views/system/user/index.vue`（调整result.list访问）
