## Bug #1 — 编辑模式未回显部门与角色分配

**严重程度**：高
**文件**：`erp-ai-web/src/views/system/user/UserForm.vue`
**位置**：`loadUserDetail` 函数（第 276-288 行）

### 问题描述

编辑用户时，`loadUserDetail` 仅回显了基础字段（username, nickname, email, mobile, avatar, status），未回显 `deptIds`、`roleIds`、`primaryDeptId`。用户打开编辑对话框后看不到当前已分配的部门和角色，也无法修改。

### 当前代码

```typescript
async function loadUserDetail(id: number): Promise<void> {
  try {
    const user = (await getUserDetail(id)) as unknown as Record<string, unknown>
    formData.value.username = (user.username as string) ?? ''
    formData.value.nickname = (user.nickname as string) ?? ''
    formData.value.email = (user.email as string) ?? ''
    formData.value.mobile = (user.mobile as string) ?? ''
    formData.value.avatar = (user.avatar as string) ?? ''
    formData.value.status = (user.status as string) ?? 'normal'
  } catch {
    ElMessage.error('加载用户详情失败')
  }
}
```

### 修复方案

需要后端 `getUserDetail` API 返回 `deptIds`、`roleIds`、`primaryDeptId` 字段，然后前端补充回显逻辑：

```typescript
async function loadUserDetail(id: number): Promise<void> {
  try {
    const user = (await getUserDetail(id)) as unknown as Record<string, unknown>
    formData.value.username = (user.username as string) ?? ''
    formData.value.nickname = (user.nickname as string) ?? ''
    formData.value.email = (user.email as string) ?? ''
    formData.value.mobile = (user.mobile as string) ?? ''
    formData.value.avatar = (user.avatar as string) ?? ''
    formData.value.status = (user.status as string) ?? 'normal'
    formData.value.deptIds = (user.deptIds as number[]) ?? []
    formData.value.roleIds = (user.roleIds as number[]) ?? []
    formData.value.primaryDeptId = (user.primaryDeptId as number) ?? null
  } catch {
    ElMessage.error('加载用户详情失败')
  }
}
```

同时需要更新 `UserListItem` 类型定义（`erp-ai-web/src/types/user.d.ts`），添加字段：
```typescript
export interface UserListItem {
  // ...existing fields...
  deptIds?: number[]
  roleIds?: number[]
  primaryDeptId?: number
}
```

### 关联 Bug

本修复依赖 Bug #2 同步修复，否则编辑提交也不会包含部门/角色数据。

## Bug #2 — 编辑提交 payload 缺少部门与角色字段

**严重程度**：高
**文件**：`erp-ai-web/src/views/system/user/UserForm.vue`
**位置**：`handleSubmit` 函数（第 304-310 行）

### 问题描述

编辑模式下的提交 payload 仅包含基础字段和可选密码，缺少 `deptIds`、`roleIds`、`primaryDeptId`。即使用户在表单中选择了部门和角色，提交时也不会发送给后端。

### 当前代码

```typescript
if (isEdit.value && props.userId) {
  if (formData.value.password) {
    payload.password = formData.value.password
  }
  await updateUser(props.userId, payload)
}
```

### 修复方案

编辑模式下也应发送部门和角色数据：

```typescript
if (isEdit.value && props.userId) {
  if (formData.value.password) {
    payload.password = formData.value.password
  }
  payload.deptIds = formData.value.deptIds
  payload.roleIds = formData.value.roleIds
  if (formData.value.primaryDeptId) {
    payload.primaryDeptId = formData.value.primaryDeptId
  }
  await updateUser(props.userId, payload)
}
```

## Bug #3 — 批量删除无失败回滚

**严重程度**：中
**文件**：`erp-ai-web/src/views/system/user/index.vue`
**位置**：`handleBatchDelete` 函数（第 287-289 行）

### 问题描述

批量删除使用 `for...of` 串行执行，无错误处理。若删除第 3 个（共 5 个）时失败，前 2 个已被删除且无法回滚，后 2 个也不会执行。

### 当前代码

```typescript
.then(async () => {
  for (const id of selectedIds.value) {
    await deleteUser(id)
  }
  ElMessage.success('批量删除成功')
  // ...
})
```

### 修复方案

使用 `Promise.allSettled` 并发执行，区分成功与失败：

```typescript
.then(async () => {
  const results = await Promise.allSettled(
    selectedIds.value.map((id) => deleteUser(id))
  )
  const failed = results.filter((r) => r.status === 'rejected').length
  const succeeded = results.filter((r) => r.status === 'fulfilled').length
  if (failed === 0) {
    ElMessage.success(`成功删除 ${succeeded} 个用户`)
  } else {
    ElMessage.warning(`成功删除 ${succeeded} 个用户，${failed} 个失败`)
  }
  selectedIds.value = []
  await fetchUserList()
})
```

## 改进建议

### Warn #1 — 部门树数据源使用 getMenuTree
**文件**：`UserForm.vue:262`, `index.vue:187`
**说明**：部门树选择器调用 `getMenuTree()` API，label 属性为 `menuName`。若菜单与部门为不同实体，应使用专用部门树 API。若共用同一 API，建议重命名为更通用的名称（如 `getDeptTree`）。
**建议**：确认后端设计意图后决定是否调整。

### Warn #2 — 多处 catch 静默吞错
**文件**：`UserForm.vue:263-264, 271-273, 323`
**说明**：部门树、角色列表加载失败时静默设置空数组，表单提交失败时完全无处理。虽然提交失败的 toast 可能由请求拦截器统一处理，但应在关键路径添加兜底提示。
**建议**：在 submit catch 中添加 `ElMessage.error('操作失败，请稍后重试')` 作为兜底。

### Warn #3 — 导出功能为占位实现
**文件**：`index.vue:317-319`
**说明**：导出按钮仅显示"导出功能将在后续任务中实现"。这是预期的阶段性实现，后续任务会补充。
**建议**：无需立即处理，后续任务会覆盖。

### Warn #4 — pageSize=999 硬编码
**文件**：`role.ts:13`
**说明**：`getRoleList` 使用 `pageSize: 999` 获取全部角色。若系统角色数超过 999，部分角色将不可见。
**建议**：后续改为使用专用"获取全部角色"接口或后端分页上限提升。

### Warn #5 — 表单初始化无 loading 状态
**文件**：`UserForm.vue:251-258`
**说明**：`initForm` 并行请求部门树和角色列表时无 loading 遮罩，用户会短暂看到空下拉框。
**建议**：添加 `v-loading` 指令到表单或下拉组件，数据加载完成后解除。
