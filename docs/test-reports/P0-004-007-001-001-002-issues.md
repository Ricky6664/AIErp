## 问题列表

### 问题 #1：localStorage 读取无异常保护（低优先级）

| 属性 | 描述 |
|------|------|
| **严重程度** | 🟢 低 |
| **位置** | `erp-ai-web/src/router/guards.ts:16` |
| **发现场景** | 代码审查 |
| **问题描述** | `localStorage.getItem(TOKEN_KEY)` 在极端环境（浏览器隐私模式、存储配额耗尽）下可能抛出 SecurityError 或 QuotaExceededError，当前无 try-catch 保护会导致路由守卫崩溃 |
| **影响范围** | 极少数浏览器极端场景 |
| **修复方案** | 将 `localStorage.getItem` 调用包装在 try-catch 中，异常时视为无 token |
| **状态** | 📋 已记录 — 建议后续统一处理（可抽为安全的 storage 工具函数） |

### 问题 #2：并发导航可能触发重复 getInfo 调用（低优先级）

| 属性 | 描述 |
|------|------|
| **严重程度** | 🟢 低 |
| **位置** | `erp-ai-web/src/router/guards.ts:30-39` |
| **发现场景** | 代码审查 |
| **问题描述** | `isRoutesLoaded` 在 async 调用完成后才设置为 true。如果用户在 getInfo 尚未返回时触发了另一个导航（如浏览器前进后退），`isRoutesLoaded` 仍为 false，会再次调用 `getInfo`，导致并发请求 |
| **影响范围** | 快速连续导航场景，后端短时间内收到重复 /api/auth/user-info 请求 |
| **修复方案** | 增加一个 pending promise 引用：首次进入时缓存 promise，后续并发检查直接 await 同一个 promise，避免重复请求 |
| **状态** | 📋 已记录 — 不影响功能正确性，属性能优化项 |
