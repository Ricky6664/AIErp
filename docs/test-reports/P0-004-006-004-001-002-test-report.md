## 核心功能验证

### 1. Token 刷新主流程（Scenario 1）
- refreshAxios.post('/api/auth/token/refresh', { refreshToken }) 被正确调用
- 刷新成功后将新 token/refreshToken 写入 localStorage（satoken/refresh_token）
- 同步更新 Pinia userStore（token/refreshToken）
- 原请求 config.headers 的 Authorization 和 satoken 均更新

### 2. 防无限循环（Scenario 2）
- 请求 URL 为 `/api/auth/token/refresh` 时，isRefreshRequest 返回 true
- 直接调用 handleRefreshFailure，不发起新的刷新请求
- 抛出错误消息 "刷新Token失败，请重新登录"

### 3. 刷新锁并发控制（Scenario 5）
- isRefreshing 标志位正确工作
- 第一个 401 请求设置 isRefreshing=true 并发起刷新
- 后续 401 请求检测到 isRefreshing=true 后进入 pendingQueue
- 刷新完成后 replayRequests 遍历队列并重放所有请求
- mockRefreshPost 仅被调用 1 次，确认无重复刷新

### 4. 刷新失败降级（Scenario 3, 6）
- handleRefreshFailure 清除 store 中 token/refreshToken/userInfo/permissions/roles/menuTree
- 清除 localStorage 中 satoken 和 refresh_token
- 队列中所有 pending request 收到 reject
- ElMessage.warning 提示用户
- router.replace 跳转到 /login?redirect=原路径

### 5. 边界条件（Scenario 8, 9）
- 已在 /login 页时不执行 router.replace，避免循环跳转
- config.url 为 undefined 时 isRefreshRequest 返回 false，不会误判为刷新请求
