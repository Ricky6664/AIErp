## 发现的问题

### 问题1: MockedStatic void方法mock限制

- **严重程度**: 低（不影响功能正确性，仅影响测试策略）
- **类型**: 测试工具限制
- **描述**: `StpUtil.checkLogin()` 是 void 静态方法，Mockito `MockedStatic.when()` 在注册 stub 时会先执行真实方法，在无 Sa-Token 上下文的单元测试中抛出非预期的 `NotLoginException`，无法在 Service 层单元测试中直接验证 `TOKEN_EXPIRED` vs `UNAUTHORIZED` 错误码区分逻辑
- **影响范围**: AuthServiceTest.VerifyToken 错误路径测试
- **复现步骤**:
  1. 在 `AuthServiceTest` 中尝试 `stpUtilMock.when(() -> StpUtil.checkLogin()).thenThrow(NotLoginException)`
  2. 执行测试
  3. mock未生效，真实 `checkLogin()` 被执行
- **当前缓解措施**: 错误码区分逻辑在 AuthControllerTest 层通过 mock `AuthService` 实例方法验证（实例方法mock无此问题）
- **建议修复**: 
  - 方案A（推荐）: 升级到 Mockito 5.x + `mockito-inline`，验证新版本 MockedStatic 对 void 方法的支持
  - 方案B: 使用 Sa-Token 提供的 `SaMockUtil` 测试工具（如存在）
  - 方案C: 编写集成测试，在真实 Sa-Token 上下文中验证 Token过期/未登录的错误码
- **状态**: ⚠️ 已知限制，暂不阻塞
