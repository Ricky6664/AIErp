## 问题 C1（严重）：BaseEntity 审计字段名与 DDL 列名不匹配

**影响范围**：所有继承 BaseEntity 的实体类（SysUser, SysRole, SysMenu, SysCodeRule 等）

**问题描述**：
- BaseEntity 字段：`createTime`, `updateTime`, `creatorId`, `updaterId`
- MyBatis-Plus `map-underscore-to-camel-case: true` 自动转换为：`create_time`, `update_time`, `creator_id`, `updater_id`
- DDL 实际列名：`created_at`, `updated_at`, `created_by`, `updated_by`

这将导致 SELECT/INSERT/UPDATE 时审计字段映射失败。

**修复方案**：
在 BaseEntity 中为审计字段添加显式 `@TableField` 映射：

```java
@TableField(value = "created_at", fill = FieldFill.INSERT)
private LocalDateTime createTime;

@TableField(value = "updated_at", fill = FieldFill.INSERT_UPDATE)
private LocalDateTime updateTime;

@TableField(value = "created_by", fill = FieldFill.INSERT)
private Long creatorId;

@TableField(value = "updated_by", fill = FieldFill.INSERT_UPDATE)
private Long updaterId;
```

或者将 BaseEntity 字段重命名为 `createdAt`/`updatedAt`/`createdBy`/`updatedBy`（与 DDL 的 snake_case 自然对应），但需要同步修改所有引用和自动填充处理器。

**优先级**：P0 — 阻塞所有数据库操作
**建议修复任务**：在下一个任务或专门修复任务中处理

## 问题 C2（严重）：实体类缺少扩展字段

**影响范围**：SysUser, SysRole, SysMenu（以及所有继承 BaseEntity 的实体）

**问题描述**：
DDL 每张表定义了标准扩展字段：
- `ext_str1` ~ `ext_str10` (VARCHAR)
- `ext_num1` ~ `ext_num5` (DECIMAL)
- `ext_date1` ~ `ext_date3` (DATE)
- `ext_bool1` ~ `ext_bool3` (BOOLEAN)
- `ext_json` (JSONB)

这些字段是项目级的通用扩展机制，但 BaseEntity 和实体类均未包含。

**修复方案**：
将扩展字段添加到 BaseEntity 中（一次修改覆盖所有实体）：

```java
private String extStr1;
private String extStr2;
// ... extStr3~10
private BigDecimal extNum1;
private BigDecimal extNum2;
// ... extNum3~5
private LocalDate extDate1;
private LocalDate extDate2;
private LocalDate extDate3;
private Boolean extBool1;
private Boolean extBool2;
private Boolean extBool3;
private String extJson;
```

注意：`ext_json` 为 JSONB 类型，Java 端使用 String 存储，通过 MyBatis-Plus TypeHandler 或 JSON 序列化处理。

**优先级**：P1 — 扩展字段暂未使用，但应尽快补齐
**建议修复任务**：下一个 BaseEntity 维护任务

## 问题 M1（中等）：SysUser 实体类重复定义

**影响范围**：SysUser 实体映射

**问题描述**：
存在两个 `SysUser` 类：
| 类 | 包路径 | 实现方式 |
|----|--------|---------|
| SysUser | com.erp.auth.entity | 独立实现 Serializable，手动映射所有字段 |
| SysUser | com.erp.system.entity | 继承 BaseEntity，字段使用默认映射 |

两者均标注 `@TableName("sys_user")`，可能导致：
- MyBatis-Plus type-aliases-package 扫描时冲突
- 开发者混淆两个类
- 运行时 mapper 定位到错误的实体

**修复方案**：
1. 保留 `com.erp.system.entity.SysUser`（继承 BaseEntity，符合项目架构）
2. 删除 `com.erp.auth.entity.SysUser`（legacy 类）
3. 将 auth.entity.SysUser 中的 `@TableField` 显式列名映射合并到 BaseEntity 修复中
4. 检查并更新所有引用 auth.entity.SysUser 的代码

**优先级**：P1 — 当前编译通过但存在潜在冲突
**建议修复任务**：在下一个 P0-004 任务中处理

## 问题 m1（建议）：缺少 Lombok @Builder 注解

**影响范围**：SysUser, SysRole, SysMenu

**问题描述**：
任务规格 Section 5.1 要求实体类使用 `@Data/@Builder/@NoArgsConstructor/@AllArgsConstructor`，当前仅使用了 `@Data`。

**修复方案**：
为实体类添加 Lombok 注解：

```java
@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
@EqualsAndHashCode(callSuper = true)
@TableName("sys_user")
public class SysUser extends BaseEntity { ... }
```

注意：`@Builder` 需要配合 `@NoArgsConstructor` 和 `@AllArgsConstructor` 使用。

**优先级**：P2 — 不影响功能，按需添加

## 问题 m2（建议）：缺少 serialVersionUID 显式声明

**影响范围**：SysUser, SysRole, SysMenu

**问题描述**：
BaseEntity 实现了 `Serializable`，但子类未声明 `serialVersionUID`。虽然 Java 会自动生成，但显式声明是最佳实践。

**修复方案**：
为每个实体类添加：
```java
@Serial
private static final long serialVersionUID = 1L;
```

**优先级**：P2 — 不影响功能
