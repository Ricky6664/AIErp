## 问题清单

### 问题 1：缺少验证码图片生成接口 (严重)

| 属性 | 值 |
|------|-----|
| 严重程度 | 🔴 高 |
| 状态 | ⚠️ 待修复 |
| 影响范围 | 前端登录页无法获取验证码图片 |

**描述**：
`AuthController` 中没有 `/auth/captcha` 端点来生成并返回验证码图片。`CaptchaService.generateCaptcha()` 只返回一个 UUID key，不生成实际的图片。前端 `CaptchaImage.vue` 组件期望接收 base64 格式的图片数据，但目前没有后端接口提供此数据。

**修复方案**：
1. 在 `AuthController` 中添加 `GET /auth/captcha` 端点
2. 使用 Java `BufferedImage` 生成验证码图片（含干扰线、噪点）
3. 将图片转为 base64 返回，同时在响应中返回 captchaKey
4. 或直接返回 image/png 二进制流 + captchaKey 通过 header 返回

**关联任务**：P0-004-011-001-002-001（前端登录页验证码组件）、P0-004-011-001-002-002（后端登录接口改造）

### 问题 2：CaptchaService 未使用 AuthProperties 配置 (中等)

| 属性 | 值 |
|------|-----|
| 严重程度 | 🟡 中 |
| 状态 | ⚠️ 待修复 |
| 影响范围 | 配置不可动态调整 |

**描述**：
`CaptchaService` 中硬编码了 TTL（5分钟）和验证码长度（4位），未使用 `AuthProperties` 中已定义的 `captcha.ttlMinutes` 和 `captcha.codeLength` 配置项。

```java
// 当前：硬编码
private static final long CAPTCHA_TTL = 5;
// ... generateRandomCode(4);

// 应改为：使用配置
private final AuthProperties authProperties;
// ... authProperties.getCaptcha().getTtlMinutes()
// ... authProperties.getCaptcha().getCodeLength()
```

**修复方案**：
1. 在 `CaptchaService` 中注入 `AuthProperties`
2. 使用 `authProperties.getCaptcha().getTtlMinutes()` 替代硬编码 TTL
3. 使用 `authProperties.getCaptcha().getCodeLength()` 替代硬编码 codeLength

### 问题 3：generateCaptcha() 不返回验证码文本 (中等)

| 属性 | 值 |
|------|-----|
| 严重程度 | 🟡 中 |
| 状态 | ⚠️ 待修复 |
| 影响范围 | 调用方无法获取验证码明文用于图片渲染 |

**描述**：
`generateCaptcha()` 方法只返回 captchaKey，不返回生成的验证码文本。生成验证码图片时需要使用验证码文本来绘制图片，调用方无法获取。

**修复方案**：
1. 方案A：返回一个包含 key + code 的 DTO/VO 对象
2. 方案B：返回 key，同时将 code 也存入 Redis 的另一个 key 中（不推荐，增加复杂度）
3. 推荐方案A：创建 `CaptchaVO` 包含 `captchaKey` 和 `captchaImage`(base64)，在 service 层完成图片生成和 base64 编码

### 问题 4：Math.random() 非加密安全 (低)

| 属性 | 值 |
|------|-----|
| 严重程度 | 🟢 低 |
| 状态 | 💡 建议改进 |
| 影响范围 | 验证码可预测性略高 |

**描述**：
`generateRandomCode()` 使用 `Math.random()` 生成随机字符。对于验证码场景这不是严重问题，但使用 `SecureRandom` 会更安全。

**修复方案**：
将 `Math.random()` 替换为 `java.security.SecureRandom` 实例。
