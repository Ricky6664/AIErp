## 一、验证概述

本次验证目标: 确认 application.yml 与各 profile(dev/test/staging/prod)配置的继承关系正确, profile 配置可覆盖公共配置, 配置加载顺序正确, 通过 /actuator/env 接口确认配置项已生效且无冲突.

### 验证方法

1. 静态分析: 逐文件比对 application.yml 与各 profile 的配置项, 识别冲突与冗余
2. 编译验证: `mvn compile` 确认 YAML 语法正确
3. 运行时验证: 启动应用(dev profile), 通过 /actuator/env 查询关键配置项的实际生效值
4. 敏感信息检查: grep 扫描所有配置文件中是否存在硬编码密码/密钥

## 二、发现的问题与修复

### 问题 1: logic-delete-field 命名不一致 [已修复]

| 文件 | 原值 | 问题 |
|------|------|------|
| application.yml | `isDeleted` | 实体字段名(camelCase), 正确 |
| application-dev.yml | `is_deleted` | 数据库列名(snake_case), 与 base 不一致 |
| application-test.yml | `is_deleted` | 同上 |
| application-staging.yml | `is_deleted` | 同上 |
| application-prod.yml | `is_deleted` | 同上 |

**影响**: MyBatis-Plus `logic-delete-field` 指定的是实体字段名而非数据库列名. Profile 值 `is_deleted` 会导致框架找不到实体字段, 软删除功能失效.

**修复**: 统一到 application.yml 的公共配置, profiles 移除冗余声明, 继承 base 值 `isDeleted`.

### 问题 2: logic-delete-value / logic-not-delete-value 类型不一致 [已修复]

| 文件 | logic-delete-value | logic-not-delete-value |
|------|:---:|:---:|
| application.yml(原) | `1`(整数) | `0`(整数) |
| profiles | `true`(布尔) | `false`(布尔) |

**影响**: 层级规范定义 is_deleted 字段为布尔语义(true/false), profiles 值更准确. 由于 profile 覆盖 base, 实际生效的是 `true`/`false`, 但 base 值 `1`/`0` 有误导性.

**修复**: application.yml 统一为 `true`/`false`, profiles 移除冗余声明.

### 问题 3: id-type 大小写不一致 [已修复]

| 文件 | 原值 |
|------|------|
| application.yml | `ASSIGN_ID` |
| profiles | `assign_id` |

**影响**: MyBatis-Plus 枚举不区分大小写, 功能正常但风格不统一.

**修复**: profiles 移除冗余声明, 继承 base 值 `ASSIGN_ID`.

### 问题 4: profiles 中 MyBatis-Plus 配置大量冗余 [已修复]

**现象**: 4 个 profile 文件中 `mybatis-plus.mapper-locations`、`type-aliases-package`、`global-config.db-config.*`、`configuration.map-underscore-to-camel-case` 等配置项与 application.yml 完全相同, 造成维护负担.

**修复**: 各 profile 仅保留环境特有的 `configuration.log-impl` 覆盖项:
- dev: `org.apache.ibatis.logging.stdout.StdOutImpl`(控制台输出 SQL)
- test/staging/prod: `org.apache.ibatis.logging.nologging.NoLoggingImpl`(关闭 SQL 日志)

### 问题 5: 无 spring.config.import 声明 [无需修复]

**说明**: 项目采用 Spring Boot 标准 profile 机制(`spring.profiles.active`), 不依赖 `spring.config.import`. Spring Boot 自动按以下顺序加载:
1. `application.yml`(公共基础)
2. `application-{profile}.yml`(profile 覆盖)

此机制等同于 `spring.config.import` 的效果, 无需额外配置.

### 3.4 PropertySource 加载顺序验证

从 /actuator/env 返回的 propertySources 顺序(优先级从高到低):

```
1. server.ports (运行时)
2. commandLineArgs (命令行参数)
3. servletConfigInitParams
4. servletContextInitParams
5. systemProperties (JVM 系统属性)
6. systemEnvironment (操作系统环境变量)
7. random
8. application-dev.yml (Profile 配置)  <-- 高优先级
9. application.yml (公共基础配置)      <-- 低优先级
10. devtools
11. applicationInfo
12. Management Server
```

**结论**: application-dev.yml 优先级高于 application.yml, Profile 配置可正确覆盖公共配置.
