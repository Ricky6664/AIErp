# 全局规范-异步消息规范

> 本文档定义RabbitMQ消息队列的Exchange/Queue命名规则、消息格式标准、死信策略、幂等消费规范，所有涉及异步处理的开发任务必须严格遵守。

---

## 1. RabbitMQ Exchange/Queue命名规则

### 1.1 命名格式

| 资源类型 | 命名格式 | 示例 |
|---------|---------|------|
| Exchange | `erp.{模块}.{事件类型}` | `erp.sale.order` |
| Queue | `erp.{模块}.{消费者}.{事件类型}` | `erp.inv.sale.order_created` |
| Routing Key | `{模块}.{资源}.{操作}` | `sale.order.created` |
| 死信Exchange | `erp.dlx.{模块}` | `erp.dlx.sale` |
| 死信Queue | `erp.dlq.{模块}.{消费者}.{事件类型}` | `erp.dlq.sale.notification.send` |

### 1.2 标准Exchange清单

| Exchange | 类型 | 说明 | 常用Routing Key |
|---------|:----:|------|----------------|
| erp.sale | topic | 销售模块事件 | sale.order.created/updated/audited |
| erp.purchase | topic | 采购模块事件 | purchase.order.created/audited |
| erp.inv | topic | 库存模块事件 | inv.stock.in/out/transfer |
| erp.produce | topic | 生产模块事件 | produce.notice.created/completed |
| erp.subcontract | topic | 委外模块事件 | sub.notice.created/completed |
| erp.ar | topic | 应收模块事件 | ar.receipt.created/write_off |
| erp.ap | topic | 应付模块事件 | ap.payment.created/write_off |
| erp.doc.flow | topic | 单据流转事件 | doc.flow.push/rollback |
| erp.notification | fanout | 全局通知（站内信/邮件/短信） | — |
| erp.audit | topic | 审核状态变更 | audit.approved/rejected |
| erp.system | topic | 系统事件（参数变更/缓存刷新） | system.config.changed |

### 1.3 标准Queue清单

| Queue | 绑定Exchange | Routing Key | 说明 |
|-------|-------------|-------------|------|
| erp.inv.sale.order_audited | erp.sale | sale.order.audited | 销售审核→库存预留 |

## 2. 消息格式标准

### 2.1 统一消息体结构

```json
{
  "eventId": "evt_20240525_001",
  "eventType": "sale.order.audited",
  "timestamp": 1716600000000,
  "tenantId": 1001,
  "sourceModule": "sale",
  "sourceService": "SaleOrderServiceImpl",
  "traceId": "abc-123-def-456",
  "payload": {
    "orderId": 12345,
    "orderNo": "SALE-20240525-0001",
    "customerId": 100,
    "totalAmount": 15000.00,
    "auditStatus": 2,
    "auditorId": 501,
    "auditTime": "2024-05-25T10:30:00"
  }
}
```

### 2.2 消息字段规范

| 字段 | 类型 | 必填 | 说明 |
|------|:----:|:----:|------|
| eventId | String | 是 | 事件唯一ID（UUID或雪花ID），用于幂等去重 |
| eventType | String | 是 | 事件类型（与Routing Key一致） |
| timestamp | Long | 是 | 事件产生时间戳（毫秒） |
| tenantId | Long | 是 | 租户ID（多租户隔离必须） |
| sourceModule | String | 是 | 源模块名称 |
| sourceService | String | 否 | 源服务类名 |
| traceId | String | 否 | 链路追踪ID |
| payload | Object | 是 | 业务数据载体（各模块自定义） |

### 2.3 Java消息基类

```java
@Data
public abstract class BaseEvent {
    private String eventId;
    private String eventType;
    private Long timestamp;
    private Long tenantId;
    private String sourceModule;
    private String traceId;

    protected BaseEvent() {
        this.eventId = IdUtil.getSnowflakeNextIdStr();
        this.timestamp = System.currentTimeMillis();
        this.traceId = MDC.get("traceId");
    }
}

// 销售订单审核事件
@Data
@EqualsAndHashCode(callSuper = true)
public class SaleOrderAuditedEvent extends BaseEvent {
    private Long orderId;
    private String orderNo;
    private Long customerId;
    private BigDecimal totalAmount;
    private Integer auditStatus;

    public SaleOrderAuditedEvent() {
        super();
        this.setEventType("sale.order.audited");
        this.setSourceModule("sale");
    }
}
```

## 3. 死信队列策略

### 3.1 配置规范

```
每个业务Queue配置对应的死信Exchange和死信Queue：
- 业务Queue → 消费失败/超时 → 死信Exchange(erp.dlx.{模块}) → 死信Queue
- 重试次数：最多3次（通过x-death header计数）
- 重试间隔：指数退避（1s → 5s → 30s）
```

| 参数 | 值 | 说明 |
|------|---|------|
| x-dead-letter-exchange | erp.dlx.{模块} | 死信交换机 |
| x-dead-letter-routing-key | dlq.{原routingKey} | 死信路由键 |
| x-message-ttl | 300000 | 消息最大存活时间（5分钟） |
| x-max-length | 10000 | 队列最大消息数 |

### 3.2 死信处理

| 步骤 | 操作 | 说明 |
|:----:|------|------|
| 1 | 消费失败→nack(requeue=true) | 重新入队，最多3次 |
| 2 | 3次失败→进入死信队列 | 自动路由到DLQ |
| 3 | 死信队列→告警通知 | 钉钉/邮件通知运维 |
| 4 | 人工排查→手动重发或丢弃 | 管理后台提供重发/删除操作 |

## 4. 幂等消费规范

### 4.1 幂等实现方式

```java
@Component
public class SaleOrderAuditedConsumer {

    @RabbitListener(queues = "erp.inv.sale.order_audited")
    public void onSaleOrderAudited(Message message, Channel channel) throws IOException {
        SaleOrderAuditedEvent event = JSON.parseObject(
            new String(message.getBody()), SaleOrderAuditedEvent.class);

        // 幂等检查：基于eventId去重
        String deduplicateKey = "erp:mq:consumed:" + event.getEventId();
        Boolean isNew = redisTemplate.opsForValue().setIfAbsent(deduplicateKey, "1", 24, TimeUnit.HOURS);

        if (!Boolean.TRUE.equals(isNew)) {
            // 重复消息，直接ACK
            channel.basicAck(message.getMessageProperties().getDeliveryTag(), false);
            return;
        }

        try {
            // 业务处理
            invStockService.reserveStock(event);
            channel.basicAck(message.getMessageProperties().getDeliveryTag(), false);
        } catch (Exception e) {
            // 消费失败，删除幂等Key以允许重试
            redisTemplate.delete(deduplicateKey);
            channel.basicNack(message.getMessageProperties().getDeliveryTag(), false, true);
        }
    }
}
```

### 4.2 幂等规范要点

| 规范项 | 要求 |
|--------|------|
| 去重Key | `erp:mq:consumed:{eventId}`，TTL=24h |
| 去重方式 | Redis SETNX，原子操作 |
| 失败回滚 | 消费失败时删除去重Key，允许重试 |
| ACK时机 | 业务处理成功后ACK，失败时NACK+requeue |
| 顺序消费 | 同一单据的消息路由到同一Queue，保证顺序 |

## 6. 消息发送规范

### 6.1 发送时机

| 规范项 | 要求 |
|--------|------|
| 事务提交后发送 | 使用`TransactionSynchronizationManager.afterCommit()`确保DB事务成功后再发消息 |
| 异步发送 | 使用RabbitTemplate异步发送，不阻塞主业务 |
| 消息确认 | 开启Publisher Confirm，确保消息到达Exchange |
| 失败重试 | 发送失败重试3次，仍失败则记录日志+告警 |

### 6.2 发送示例

```java
@Service
public class SaleOrderServiceImpl {

    @Transactional
    public void auditSaleOrder(Long id, AuditDTO dto) {
        // 1. 业务处理
        SaleOrder order = getById(id);
        order.setAuditStatus(2);
        updateById(order);

        // 2. 事务提交后发送消息
        TransactionSynchronizationManager.registerSynchronization(
            new TransactionSynchronization() {
                @Override
                public void afterCommit() {
                    SaleOrderAuditedEvent event = new SaleOrderAuditedEvent();
                    event.setOrderId(order.getId());
                    event.setTenantId(order.getTenantId());
                    // ... 填充其他字段
                    rabbitTemplate.convertAndSend("erp.sale", "sale.order.audited", event);
                }
            }
        );
    }
}
```
