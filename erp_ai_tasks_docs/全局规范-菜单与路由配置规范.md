# 全局规范-菜单与路由配置规范

> 本文档定义本项目菜单数据结构、动态路由机制、路由守卫逻辑、权限标识规范，所有涉及菜单与路由的开发任务必须严格遵守。

---

## 1. 菜单类型定义

| 类型 | 说明 | 关联页面 | 图标 |
|------|------|---------|------|
| 目录 | 仅作为分组，不关联页面 | 无 | 必须配置 |
| 菜单 | 关联具体页面，点击打开页面 | 必须配置路由路径 | 必须配置 |
| 按钮 | 页面内操作按钮权限 | 无 | 不配置 |

## 2. sys_menu表结构

| 字段名 | 数据类型 | 非空 | 默认值 | 说明 |
|--------|---------|:----:|--------|------|
| id | BIGINT | 是 | 雪花ID | 主键 |
| parent_id | BIGINT | 是 | 0 | 父菜单ID，顶级为0 |
| menu_type | SMALLINT | 是 | — | 类型：0=目录，1=菜单，2=按钮 |
| menu_name | VARCHAR(64) | 是 | — | 菜单名称 |
| menu_name_i18n | VARCHAR(128) | 否 | NULL | 国际化Key（如`menu.sale.order`） |
| path | VARCHAR(200) | 否 | NULL | 路由路径（如`/sale/order`） |
| component | VARCHAR(255) | 否 | NULL | 前端组件路径（如`views/sale/order/index`） |
| permission | VARCHAR(128) | 否 | NULL | 权限标识（如`sale:order:list`） |
| icon | VARCHAR(100) | 否 | NULL | 图标名称（Element Plus图标） |
| sort_order | INT | 是 | 0 | 排序号，升序 |
| visible | SMALLINT | 是 | 1 | 是否可见：0=隐藏，1=显示 |
| open_type | SMALLINT | 是 | 0 | 打开方式：0=标签页，1=弹窗小(400px)，2=弹窗中(600px)，3=弹窗大(800px)，4=抽屉，5=新窗口 |
| keep_alive | SMALLINT | 是 | 1 | 是否缓存组件：0=不缓存，1=缓存 |
| is_external | SMALLINT | 是 | 0 | 是否外链：0=否，1=是 |
| tenant_id | BIGINT | 是 | — | 租户ID |
| creator_id | BIGINT | 否 | NULL | 创建人 |
| create_time | TIMESTAMP | 是 | CURRENT_TIMESTAMP | 创建时间 |
| updater_id | BIGINT | 否 | NULL | 更新人 |
| update_time | TIMESTAMP | 是 | CURRENT_TIMESTAMP | 更新时间 |
| is_deleted | SMALLINT | 是 | 0 | 逻辑删除 |

### 2.1 索引规范

|--------|------|------|

## 3. 页面打开形式

| 形式 | open_type值 | 说明 |
|------|:---------:|------|
| 全局标签页 | 0 | 在主布局区以标签页形式打开（默认方式） |
| 弹窗(小) | 1 | 400px宽度弹窗，适合单表录入 |
| 弹窗(中) | 2 | 600px宽度弹窗，适合主从表录入 |
| 弹窗(大) | 3 | 800px宽度弹窗，适合复杂表单 |
| 抽屉 | 4 | 右侧抽屉形式，适合详情查看 |
| 新窗口 | 5 | 浏览器新窗口打开，适合报表/大屏 |

## 4. 动态路由加载机制

### 4.1 前端路由生成流程

```
用户登录 → 获取菜单树API → 递归生成Vue Router路由 → addRoute动态注册
    │           │                    │                      │
    │    GET /api/sys/menu     递归遍历菜单树        router.addRoute()
    │    返回用户有权限的      将component字符串      动态注册到
    │    菜单JSON数组          转为import()懒加载     Vue Router
```

### 4.2 组件动态导入规则

```typescript
// 组件路径映射规则
// component字段值 → 实际文件路径
// 'views/sale/order/index' → () => import('@/views/sale/order/index.vue')

const modules = import.meta.glob('@/views/**/*.vue')

function loadComponent(component: string) {
  const path = `/src/views/${component}.vue`
  if (modules[path]) {
    return modules[path]
  }
  // 降级：查找index.vue
  const indexPath = `/src/views/${component}/index.vue`
  return modules[indexPath]
}
```

### 4.3 路由元信息（meta）标准字段

| 字段 | 类型 | 说明 |
|------|------|------|
| title | string | 页面标题（显示在标签页/面包屑） |
| titleI18n | string | 国际化Key |
| icon | string | 菜单图标名称 |
| keepAlive | boolean | 是否缓存组件（对应keep_alive字段） |
| hideMenu | boolean | 是否在菜单中隐藏（visible=0时true） |
| hideTab | boolean | 是否在标签页中隐藏 |
| permissions | string[] | 按钮权限列表 |
| openType | number | 打开方式（0-5） |
| affix | boolean | 是否固定标签（如首页） |

## 7. 路由守卫逻辑规范

### 7.1 全局前置守卫流程

```
路由跳转 → 是否已登录？
  ├── 否 → 是否白名单路由？
  │        ├── 是 → 放行
  │        └── 否 → 重定向/login?redirect=目标路径
  └── 是 → Token是否有效？
           ├── 否 → 清除Token → 重定向/login
           └── 是 → 是否已加载权限？
                    ├── 否 → 请求用户信息+菜单API → 生成路由 → addRoute → next(to)
                    └── 是 → 是否有权限访问目标路由？
                             ├── 是 → 设置页面标题 → 放行
                             └── 否 → 跳转403页面
```

### 7.2 白名单路由

| 路径 | 说明 |
|------|------|
| `/login` | 登录页 |
| `/register` | 注册页（如启用） |
| `/forgot-password` | 忘记密码 |
| `/403` | 无权限页 |
| `/404` | 未找到页 |
| `/500` | 服务异常页 |

### 7.3 Token刷新机制

| 规范项 | 要求 |
|--------|------|
| Token有效期 | Sa-Token配置，默认2小时活动超时 |
| 续期策略 | 活动续期（每次请求自动续期） |
| 前端处理 | 响应拦截器检测401状态 → 尝试刷新Token → 失败跳转登录页 |
| 并发控制 | 多请求同时401时，仅发起一次刷新，其他请求排队等待 |

## 8. 菜单排序规则

| 层级 | 排序范围 | 规则 |
|------|---------|------|
| 一级模块 | 0~999 | 按业务重要性排序：系统管理(900)→基础模块(100~200)→业务模块(300~600)→报表(700) |
| 二级菜单 | 0~99 | 按业务逻辑排序：工作台(0)→列表页(10~50)→统计页(80)→设置(90) |
| 按钮权限 | 0~99 | 按操作频率排序：查看(0)→新增(10)→编辑(20)→删除(30)→审核(40)→导出(50) |

### 9.3 初始化规范

| 规范项 | 要求 |
|--------|------|
| ID分配 | 每个模块分配独立ID段，避免冲突（如销售1000~1099，采购1100~1199） |

## 10. 移动端菜单（sys_mobile_menu）

| 规范项 | 要求 |
|--------|------|
| 独立表 | 移动端菜单使用`sys_mobile_menu`表，与PC端`sys_menu`独立管理 |
| 结构对齐 | 字段结构与sys_menu基本一致，增加`mobile_icon`(uni-icons图标名)和`tab_bar`(是否底栏显示)字段 |
| 底栏菜单 | 最多5个底栏菜单项（tab_bar=1），超出部分放入"更多"页面 |
| 权限同步 | 移动端权限标识与PC端一致（如`sale:order:list`），共享角色权限体系 |
