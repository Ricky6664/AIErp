# 全局规范 - 术语表

> **适用范围**：本文档汇总ERP系统全部业务术语与技术术语，为开发、测试、产品团队提供统一的语义参照。
> **数据来源**：本文档为独立规范文档，汇总ERP系统全部业务术语与技术术语，内容自包含，无需参照外部设计文档。

---

## 一、业务术语

> 来源：本文档业务术语部分

| 术语 | 说明 |
|------|------|
| 功能点 | 系统中可独立操作的最小业务单元，对应一个菜单项 |
| 自有展示页 | 功能点自身的列表/查询/看板展示页面 |
| 自有录入页 | 功能点自身的新增/编辑表单页面 |
| 数据视图 | 展示页数据来源的SQL视图定义，支持多表关联 |
| 数据表 | 录入页数据写入的物理表 |
| 关联信息区 | 主从列表页(P03)右侧的标签页区域，展示关联数据 |
| 从表信息区 | 主从表单页(P06)中的标签页区域，录入从表数据 |
| 内嵌展示 | 运行时行为，由关联区配置决定，不属于页面类型属性 |
| 权限部门 | 用于用户数据权限控制的部门体系，与组织架构部门分离 |
| 组织部门 | 用于员工归属管理的部门体系，属于组织架构范畴 |
| 软删除 | 通过is_deleted标记删除状态，物理数据保留 |
| 多租户 | 通过tenant_id字段隔离不同租户的数据 |
| 乐观锁 | 通过version字段实现并发控制 |
| P01~P15 | 15种页面类型编码，详见第四章 |
| 下推 | 将当前单据的关键数据自动带入目标单据，生成上下游关联的业务单据，如报价单下推生成销售订单 |
| 审核 | 单据级操作，由授权人员确认单据有效性，使单据从草稿状态变为已审核状态 |
| 审批 | 工作流级操作，按预定义的审批流程进行多级签核，审批通过后单据生效 |
| 标签(Tag) | 业务分类标记，如客户标签、供应商标签，用于数据分类和筛选 |
| 标签页(Tab) | UI组件，指页面中的选项卡区域，如关联信息区标签页、从表信息区标签页 |

## 二、技术术语

> 来源：本文档技术术语部分

| 术语 | 说明 |
|------|------|
| 主从表 | 主表（单头）+ 从表（明细行），如销售订单(sale_order) + 销售订单明细(sale_order_detail) |
| doc_detail三表 | doc_detail_location + doc_detail_batch + doc_detail_serial，出入库单据的库位/批次/序列号公共从表 |
| 编码引擎 | 根据编码规则自动生成单据编号的服务，支持日期变量/自增序列/手工切换 |
| 数据视图引擎 | 根据视图配置动态构建SQL查询的服务，支持动态JOIN/WHERE/分页/排序 |
| 审核引擎 | 通用单据审核/反审/作废/撤销作废状态流转服务 |
| 流转引擎 | 通用单据引入/下推/复制/追溯服务 |
| 页面类型 | P01~P15共15种标准化页面布局基座 |
| 录入组件 | 20种基础输入组件 + 3种字典组件 + 7大体系业务选择器 |
| 业务增强组件 | 7种ERP特色增强组件（BOM配方/费用分摊/地区/话术/预警/批次有效期/库存可用量） |
| Composable | Vue3组合式函数，封装页面状态/表格配置/字段配置/权限/数据视图/编码规则等可复用逻辑 |

## 三、补充业务术语

| 术语 | 说明 |
|------|------|
| 核销 | 将收款/付款与应收/应付单据进行匹配对冲，标记已结算金额 |
| 对冲 | 用相反方向的单据抵消原始单据的金额（如退款对冲应收） |
| 暂估 | 货物已入库但发票未到时，按预估价格临时入账 |
| 红冲 | 用负数金额的单据冲销原始单据（如红字发票冲销蓝字发票） |
| 凭证过账 | 将会计凭证记入总账/明细账的过程 |
| 试算平衡 | 检查所有账户的借方合计是否等于贷方合计 |
| MRP运算 | 物料需求计划，根据BOM和库存自动计算采购/生产需求 |
| BOM展开 | 将产品的物料清单按层级逐层展开，计算各物料总需求量 |
| 工艺路线 | 产品加工过程中各工序的先后顺序及工时定义 |
| 工单 | 生产任务单，指定生产产品/数量/计划开始完工日期 |
| 排产 | 根据产能/物料/交期安排生产计划 |
| 完工入库 | 生产完工后将成品入库，增加成品库存 |
| 委外发料 | 将原材料发给外协供应商进行加工 |
| 期间结转 | 将本期余额结转至下期作为期初余额 |
| 期初余额 | 系统启用或年度结转时各账户的初始金额 |
| 折旧 | 固定资产按使用年限分摊成本的过程 |
| 摊销 | 无形资产/长期待摊费用按期限分摊 |
| 坏账 | 无法收回的应收账款，经审批后核销 |
| 主从表 | 主表（单头/表头）+从表（明细行/表体），如订单+订单明细 |
| 单据下推 | 将源单据数据自动带入目标单据，生成上下游关联业务单据 |
| 单据流转 | 单据在业务链路中的传递和状态变化（如订单→发货→出库→对账） |
| 对账 | 核对双方数据一致性，如银行对账（银行流水 vs 账面记录）、供应商对账（供应商对账单 vs 应付账款） |
| 反审核 | 将已审核的单据回退到草稿状态，前提是该单据不存在已审核的下游关联单据 |
| 结算 | 根据实际发生数据与约定价格计算最终应付/应收金额，如委外加工完成后按实际产出与加工费进行结算 |
| 调拨 | 将库存从一个仓库/库位转移到另一个仓库/库位，涉及出库和入库两个动作 |
| 合并报表 | Consolidated Financial Statements，将母公司和子公司的财务报表合并为一个整体 |
| 内部交易抵消 | Intercompany Elimination，合并报表时消除集团内部交易的影响 |
| 转移定价 | Transfer Pricing，集团内部关联公司之间交易价格的确定方法 |
| 作业成本法 | Activity-Based Costing (ABC)，以作业为成本归集对象的成本核算方法 |
| 标准成本法 | Standard Costing，以预先制定的标准成本为基础进行成本控制和差异分析 |
| 差异分析 | Variance Analysis，实际成本与标准成本之间差异的分解和归因 |
| 安全库存 | Safety Stock，为应对需求波动和供应不确定性而持有的额外库存 |
| 经济订货量 | EOQ (Economic Order Quantity)，使总库存成本最小的最优订货批量 |
| 主生产计划 | MPS (Master Production Schedule)，确定每一期最终产品的生产数量和时间 |
| 能力需求计划 | CRP (Capacity Requirements Planning)，根据MRP结果计算各工作中心的负荷和能力 |
| 物料需求计划 | MRP (Material Requirements Planning)，根据BOM和主生产计划计算原材料和零部件的需求量和时间 |

## 四、补充技术术语

| 术语 | 说明 |
|------|------|
| DTO | Data Transfer Object，数据传输对象，用于接收前端请求参数 |
| VO | View Object，视图对象，用于返回前端展示数据 |
| Entity | 实体类，与数据库表一一对应的Java类 |
| Mapper XML | MyBatis的SQL映射文件，定义复杂SQL语句 |
| 数据快照 | 下推时将源单商品信息复制到目标单，后续源单修改不影响目标单 |
| 幂等性 | 同一操作执行多次与执行一次的效果相同，防止重复提交/重复消费 |
| 分布式锁 | 跨多个服务实例的互斥访问机制，本项目使用Redis Redisson实现 |
| WebSocket | 全双工通信协议，用于服务端主动推送消息到前端 |
| SSO | Single Sign-On，单点登录，一次登录访问多个系统 |
| SSE | Server-Sent Events，服务端推送事件，用于AI流式响应 |
| Flyway | 数据库版本迁移工具，管理SQL脚本的版本化执行 |
| HikariCP | 高性能JDBC连接池，Spring Boot默认连接池 |
| 逻辑删除 | 通过 `is_deleted` 字段标记删除状态（0=正常，1=已删除），物理数据保留，查询时自动过滤 |
| 乐观锁 | 通过 `version` 字段实现并发控制，更新时检查版本号：`UPDATE ... WHERE id=? AND version=?`，版本号不一致则更新失败 |
| 悲观锁 | 通过数据库行级锁（SELECT ... FOR UPDATE）实现并发控制，锁定期间其他事务无法修改同一行 |
| 防重提交 | 防止用户短时间内重复提交同一请求，通过Redis Token机制实现：前端先获取Token，提交时携带并一次性消费 |
| 数据字典 | 系统中预定义的键值对集合，用于下拉选择、状态翻译等，由 `sys_dict_type` + `sys_dict_data` 表管理 |
| 消息队列 | 异步处理机制，用于解耦业务系统。如：审核通过后异步发送通知、异步生成凭证 |
| 事件驱动 | Event-Driven，系统通过事件的产生和消费来驱动业务流程的架构模式 |
| CQRS | Command Query Responsibility Segregation，命令查询职责分离，将读操作和写操作分离的架构模式 |
| Saga事务 | 分布式事务处理模式，通过一系列本地事务和补偿操作实现最终一致性 |
| 最终一致性 | Eventual Consistency，分布式系统中数据在有限时间内达到一致的保证 |
| 补偿事务 | Compensating Transaction，用于撤销Saga中已完成操作的逆向事务 |
| 熔断器 | Circuit Breaker，防止级联故障的保护机制，当失败率超阈值时快速失败 |
| 限流器 | Rate Limiter，控制请求速率的机制，防止系统过载 |
| 数据湖 | Data Lake，集中存储原始数据的系统，支持结构化和非结构化数据 |
| 低代码 | Low-Code，通过可视化配置而非手写代码来构建应用的开发方式 |
| 数据编织 | Data Fabric，跨异构数据源的统一数据管理架构 |
