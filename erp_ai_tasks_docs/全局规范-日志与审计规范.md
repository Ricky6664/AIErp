# 全局规范-日志与审计规范

> 本文档定义ERP系统操作日志、审计追踪、日志级别策略、敏感信息脱敏及日志查询规范，所有模块的日志记录必须严格遵守。

---

## 1. 操作日志表结构

### 1.1 sys_operation_log 表定义

```sql
CREATE TABLE sys_operation_log (
    id              BIGSERIAL       PRIMARY KEY,
    user_id         BIGINT          NOT NULL,                   -- 操作人ID
    user_name       VARCHAR(64)     NOT NULL DEFAULT '',        -- 操作人姓名
    module          VARCHAR(64)     NOT NULL DEFAULT '',        -- 所属模块（如sale/purchase/inv）
    operation       VARCHAR(128)    NOT NULL DEFAULT '',        -- 操作描述（如"新增销售订单"）
    method          VARCHAR(256)    NOT NULL DEFAULT '',        -- 方法全路径（类名.方法名）
    request_method  VARCHAR(10)     NOT NULL DEFAULT '',        -- HTTP方法（GET/POST/PUT/DELETE）
    request_url     VARCHAR(512)    NOT NULL DEFAULT '',        -- 请求URL
    request_params  TEXT,                                       -- 请求参数（JSON，脱敏后存储）
    response_result TEXT,                                       -- 响应结果（JSON，脱敏后存储，仅异常时存储）
    ip              VARCHAR(64)     NOT NULL DEFAULT '',        -- 操作人IP
    user_agent      VARCHAR(512)    DEFAULT '',                 -- 浏览器User-Agent
    duration        BIGINT          NOT NULL DEFAULT 0,         -- 执行时长（毫秒）
    status          SMALLINT        NOT NULL DEFAULT 1,         -- 操作状态：1=成功 0=失败
    error_msg       TEXT,                                       -- 异常信息（失败时存储完整堆栈）
    tenant_id       BIGINT          NOT NULL,                   -- 租户ID
    create_time     TIMESTAMP       NOT NULL DEFAULT CURRENT_TIMESTAMP, -- 操作时间
    CONSTRAINT chk_status CHECK (status IN (0, 1))
);

-- 索引
CREATE INDEX idx_log_user_id ON sys_operation_log(user_id);
CREATE INDEX idx_log_tenant_id ON sys_operation_log(tenant_id);
CREATE INDEX idx_log_module ON sys_operation_log(module);
CREATE INDEX idx_log_create_time ON sys_operation_log(create_time);
CREATE INDEX idx_log_status ON sys_operation_log(status);

COMMENT ON TABLE sys_operation_log IS '系统操作日志表';
COMMENT ON COLUMN sys_operation_log.id IS '主键ID';
COMMENT ON COLUMN sys_operation_log.user_id IS '操作人ID';
COMMENT ON COLUMN sys_operation_log.user_name IS '操作人姓名';
COMMENT ON COLUMN sys_operation_log.module IS '所属模块';
COMMENT ON COLUMN sys_operation_log.operation IS '操作描述';
COMMENT ON COLUMN sys_operation_log.method IS '方法全路径';
COMMENT ON COLUMN sys_operation_log.request_method IS 'HTTP方法';
COMMENT ON COLUMN sys_operation_log.request_url IS '请求URL';
COMMENT ON COLUMN sys_operation_log.request_params IS '请求参数（脱敏JSON）';
COMMENT ON COLUMN sys_operation_log.response_result IS '响应结果（脱敏JSON，仅异常时）';
COMMENT ON COLUMN sys_operation_log.ip IS '操作IP';
COMMENT ON COLUMN sys_operation_log.user_agent IS '浏览器UA';
COMMENT ON COLUMN sys_operation_log.duration IS '执行时长（ms）';
COMMENT ON COLUMN sys_operation_log.status IS '操作状态：1成功 0失败';
COMMENT ON COLUMN sys_operation_log.error_msg IS '异常堆栈信息';
COMMENT ON COLUMN sys_operation_log.tenant_id IS '租户ID';
COMMENT ON COLUMN sys_operation_log.create_time IS '操作时间';
```

### 1.2 字段填充说明

| 字段 | 填充时机 | 来源 |
|------|---------|------|
| user_id / user_name | 请求开始时 | Sa-Token当前登录用户 |
| module / operation | AOP切面读取注解 | `@OperLog`注解属性 |
| method | AOP切面运行时 | `target.getClass().getName() + "." + methodName` |
| request_url / request_method | 请求上下文 | `HttpServletRequest` |
| request_params | AOP切面序列化 | 方法参数JSON序列化（脱敏后） |
| response_result | 方法异常时 | 异常响应JSON（脱敏后） |
| ip | 请求开始时 | `X-Forwarded-For` -> `X-Real-IP` -> `RemoteAddr` |
| duration | 方法执行完毕 | `System.currentTimeMillis() - startTime` |
| status | 方法执行完毕 | 正常返回=1，抛出异常=0 |
| tenant_id | 请求开始时 | 当前租户上下文 |

## 2. 操作日志AOP切面规范

### 2.1 @OperLog 自定义注解

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface OperLog {

    /** 所属模块 */
    String module() default "";

    /** 操作描述（如"新增销售订单"） */
    String operation() default "";

    /** 是否记录请求参数，默认true */
    boolean saveRequestParams() default true;

    /** 是否记录响应结果，默认false（避免大量数据写入日志表） */
    boolean saveResponseResult() default false;

    /** 是否为审计级别日志（审计日志不可被普通清理策略删除） */
    boolean audit() default false;
}
```

### 2.2 使用示例

```java
@RestController
@RequestMapping("/api/sale/order")
public class SaleOrderController {

    @OperLog(module = "sale", operation = "新增销售订单")
    @PostMapping
    public R<Long> create(@RequestBody @Valid SaleOrderCreateDTO dto) { ... }

    @OperLog(module = "sale", operation = "审核销售订单", audit = true)
    @PostMapping("/{id}/audit")
    public R<Void> audit(@PathVariable Long id, @RequestBody AuditDTO dto) { ... }

    @OperLog(module = "sale", operation = "删除销售订单", audit = true)
    @DeleteMapping("/{id}")
    public R<Void> delete(@PathVariable Long id) { ... }
}
```

### 2.3 OperLogAspect 切面实现要求

```java
@Aspect
@Component
@Slf4j
public class OperLogAspect {

    @Autowired
    private SysOperationLogService operationLogService;

    @Around("@annotation(operLog)")
    public Object around(ProceedingJoinPoint point, OperLog operLog) throws Throwable {
        long startTime = System.currentTimeMillis();
        SysOperationLog logEntity = new SysOperationLog();

        // 1. 填充基础信息（注解属性）
        logEntity.setModule(operLog.module());
        logEntity.setOperation(operLog.operation());
        logEntity.setMethod(point.getTarget().getClass().getName() + "." + point.getSignature().getName());

        // 2. 填充请求上下文
        HttpServletRequest request = WebUtils.getRequest();
        logEntity.setRequestUrl(request.getRequestURI());
        logEntity.setRequestMethod(request.getMethod());
        logEntity.setIp(WebUtils.getClientIp(request));
        logEntity.setUserAgent(request.getHeader("User-Agent"));

        // 3. 填充用户信息
        if (StpUtil.isLogin()) {
            logEntity.setUserId(StpUtil.getLoginIdAsLong());
            logEntity.setUserName(StpUtil.getSession().getString("userName"));
            logEntity.setTenantId(TenantContext.getTenantId());
        }

        // 4. 序列化请求参数（脱敏）
        if (operLog.saveRequestParams()) {
            logEntity.setRequestParams(SensitiveUtils.mask(JsonUtils.toJson(point.getArgs())));
        }

        // 5. 执行目标方法
        Object result;
        try {
            result = point.proceed();
            logEntity.setStatus(1);
        } catch (Throwable e) {
            logEntity.setStatus(0);
            logEntity.setErrorMsg(ExceptionUtils.getStackTrace(e));
            throw e;
        } finally {
            logEntity.setDuration(System.currentTimeMillis() - startTime);
            // 异步写入日志，不阻塞主业务
            operationLogService.saveAsync(logEntity);
        }

        return result;
    }
}
```

**切面关键要求：**

- 日志写入**必须异步**（通过`@Async`或MQ），不得阻塞业务请求
- 日志写入失败**不得影响**业务正常返回（catch并打印warn日志）
- 请求参数序列化时**必须脱敏**（调用`SensitiveUtils.mask`）
- 请求参数超过4KB时**截断存储**，避免大文本撑爆日志表
- `audit = true`的日志需额外写入审计日志表或标记为审计级别

## 3. 日志级别策略

### 3.1 各环境日志级别配置

| 日志级别 | 开发环境(dev) | 测试环境(test) | 生产环境(prod) | 说明 |
|---------|:------------:|:------------:|:-------------:|------|
| TRACE | 开启 | 关闭 | 关闭 | 框架内部追踪 |
| DEBUG | 开启 | 开启 | 关闭 | 业务调试信息 |
| INFO | 开启 | 开启 | 开启 | 关键业务流程节点 |
| WARN | 开启 | 开启 | 开启 | 可恢复的异常/降级 |
| ERROR | 开启 | 开启 | 开启 | 不可恢复异常/系统故障 |

### 3.2 application.yml 日志配置

```yaml
# 开发环境 — application-dev.yml
logging:
  level:
    root: INFO
    com.erp: DEBUG                          # 业务代码DEBUG
    com.erp.modules: DEBUG
    com.baomidou.mybatisplus: DEBUG        # MP SQL日志
    org.springframework.web: DEBUG
  file:
    name: logs/erp-dev.log

# 生产环境 — application-prod.yml
logging:
  level:
    root: WARN
    com.erp: INFO                            # 业务代码INFO
    com.erp.modules: INFO
    com.baomidou.mybatisplus: WARN
    org.springframework.web: WARN
    org.apache.kafka: WARN
    org.springframework.amqp: WARN
  file:
    name: /data/logs/erp-prod.log
  logback:
    rollingpolicy:
      max-file-size: 100MB
      max-history: 30
      total-size-cap: 10GB
```

### 3.3 业务日志 vs 框架日志分离规则

| 日志类型 | 输出路径 | Logger名称 | 说明 |
|---------|---------|-----------|------|
| 业务日志 | `logs/business.log` | `com.erp.modules.*` | 业务流程、关键节点 |
| SQL日志 | `logs/sql.log` | `com.erp.mapper.*` | MyBatis-Plus SQL执行 |
| 接口日志 | `logs/api.log` | `com.erp.*.controller` | HTTP请求/响应 |
| 定时任务日志 | `logs/scheduler.log` | `com.erp.scheduler.*` | 定时任务执行 |
| 错误日志 | `logs/error.log` | 全局ERROR级别 | 所有ERROR级别日志 |
| 框架日志 | `logs/framework.log` | `org.springframework.*` | Spring框架日志 |

## 4. 审计追踪规范

### 4.1 必须记录审计日志的操作

以下操作**必须**标记`@OperLog(audit = true)`，审计日志不可被普通清理策略删除，保留期限>=3年。

| 操作类别 | 具体场景 |
|---------|---------|
| 单据审核 | 销售订单/采购订单/入库单/出库单/调拨单/盘点单/凭证等的审核与反审核 |
| 登录登出 | 用户登录成功/失败、主动登出、Token过期踢出 |
| 权限变更 | 角色分配/权限修改/菜单授权/数据权限变更/字段权限变更 |
| 用户管理 | 账号创建/禁用/启用/密码重置/密码修改 |
| 数据导出 | 任何数据导出/下载操作（需记录导出条件和数据量） |
| 数据删除 | 物理删除或批量软删除操作 |
| 系统配置 | 系统参数修改、租户配置变更、模块启用/停用 |
| 财务操作 | 凭证过账/反过账、期末结账/反结账、汇率变更 |
| 审批流程 | 审批通过/驳回/撤回/转交 |
| 敏感数据访问 | 查看客户手机号/身份证号/银行卡号等敏感字段 |

### 4.2 审计日志附加字段

审计级别日志在`sys_operation_log`基础上，需额外记录：

| 字段 | 说明 |
|------|------|
| before_data | 操作前数据快照（JSON） |
| after_data | 操作后数据快照（JSON） |
| audit_flag | 审计标记，true=审计日志 |

## 5. 日志脱敏规则

### 5.1 脱敏字段清单

| 数据类型 | 脱敏规则 | 示例 |
|---------|---------|------|
| 密码 | 全部替换为`***` | `password: "***"` |
| 手机号 | 中间4位替换为`****` | `138****5678` |
| 身份证号 | 中间10位替换为`*` | `110***********1234` |
| 银行卡号 | 仅保留前4后4 | `6222 **** **** 1234` |
| 邮箱 | 用户名中间3位替换 | `ab***de@gmail.com` |
| 地址 | 门牌号及以后替换 | `北京市朝阳区****` |
| Token | 仅保留前6后4 | `a1b2c3******x9y8` |
| API密钥 | 全部替换 | `***` |

### 5.2 脱敏工具类

```java
public class SensitiveUtils {

    /** 手机号脱敏：138****5678 */
    public static String maskPhone(String phone) {
        if (phone == null || phone.length() < 7) return phone;
        return phone.substring(0, 3) + "****" + phone.substring(phone.length() - 4);
    }

    /** 身份证脱敏：110***********1234 */
    public static String maskIdCard(String idCard) {
        if (idCard == null || idCard.length() < 8) return idCard;
        return idCard.substring(0, 3) + "***********" + idCard.substring(idCard.length() - 4);
    }

    /** 银行卡脱敏：6222 **** **** 1234 */
    public static String maskBankCard(String card) {
        if (card == null || card.length() < 8) return card;
        return card.substring(0, 4) + " **** **** " + card.substring(card.length() - 4);
    }

    /** 自动脱敏JSON字符串中所有匹配敏感模式的字段 */
    public static String mask(String json) {
        if (json == null) return null;
        // 对JSON中key为password/mobile/phone/idCard/bankCard/email的value自动脱敏
        // 实现略：基于正则或Jackson序列化过滤器
        return json;
    }
}
```

### 5.3 Jackson序列化脱敏注解

```java
/** DTO字段标注脱敏策略，JSON序列化时自动脱敏 */
@JsonSerialize(using = SensitiveSerializer.class)
@SensitiveType(type = SensitiveTypeEnum.PHONE)
private String mobile;
```

## 6. 日志查询API

### 6.1 操作日志分页查询

```
GET /api/sys/log/operation
```

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| page | int | 否 | 页码，默认1 |
| pageSize | int | 否 | 每页条数，默认20，最大100 |
| module | string | 否 | 模块名称筛选 |
| operation | string | 否 | 操作描述模糊搜索 |
| userName | string | 否 | 操作人姓名模糊搜索 |
| status | int | 否 | 操作状态：1=成功 0=失败 |
| startTime | string | 否 | 开始时间（yyyy-MM-dd HH:mm:ss） |
| endTime | string | 否 | 结束时间（yyyy-MM-dd HH:mm:ss） |

**响应示例：**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [
      {
        "id": 10001,
        "userId": 1001,
        "userName": "张三",
        "module": "sale",
        "operation": "审核销售订单",
        "method": "com.erp.modules.sale.controller.SaleOrderController.audit",
        "requestMethod": "POST",
        "requestUrl": "/api/sale/order/5001/audit",
        "ip": "192.168.1.100",

```

### 6.2 日志详情查询

```
GET /api/sys/log/operation/{id}
```

返回包含`requestParams`、`responseResult`、`errorMsg`完整内容的日志详情。

### 6.3 日志清理策略

| 日志类型 | 保留期限 | 清理方式 |
|---------|---------|---------|
| 普通操作日志 | 90天 | 定时任务自动清理 |
| 审计日志（audit=true） | 3年 | 不允许自动清理，需管理员手动归档 |
| 错误日志（error.log） | 180天 | 定时任务自动清理 |
| SQL日志 | 30天 | 定时任务自动清理 |
