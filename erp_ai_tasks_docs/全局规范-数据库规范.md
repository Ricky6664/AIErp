# 全局规范-数据库规范

> 本文档定义数据库设计与开发规范，所有数据库表设计及SQL脚本必须严格遵守。

---

## 1. 表命名规则

| 规则 | 说明 | 示例 |
|------|------|------|
| 前缀格式 | `{模块前缀}_{业务名}` | `crm_customer`、`sale_order`、`inv_warehouse` |
| 命名风格 | 全小写+下划线分隔（snake_case） | `purchase_order_detail` |
| 主表 | `{模块}_{业务}` | `sale_order`、`purchase_order` |
| 从表（明细） | `{模块}_{业务}_detail` | `sale_order_detail`、`purchase_order_detail` |
| 关联表 | `{模块}_{业务}_{关联名}` | `crm_customer_contact`、`crm_customer_address` |
| 辅助属性子表 | `doc_detail_{属性名}` | `doc_detail_location`、`doc_detail_batch`、`doc_detail_serial` |

---

## 2. 字段命名规则

| 规则 | 说明 | 示例 |
|------|------|------|
| 命名风格 | 全小写+下划线分隔（snake_case） | `bill_no`、`customer_id` |
| 主键 | `id` | `id bigint` |
| 外键字段 | `{关联表}_id` | `customer_id`、`warehouse_id` |
| 布尔字段 | `is_`前缀 | `is_deleted`、`is_batch_manage` |
| 时间字段 | `{动作}_at` | `created_at`、`updated_at` |
| 操作人字段 | `{动作}_by` | `created_by`、`updated_by` |
| 编码字段 | `{业务}_code` 或 `code` | `product_code`、`customer_code` |
| 名称字段 | `{业务}_name` 或 `name` | `product_name`、`customer_name` |
| 数量字段 | `qty` / `base_qty` | `qty`、`base_qty` |
| 金额字段 | `{业务}_amount` | `total_amount`、`tax_amount` |

## 3. 通用必含字段

所有业务表**必须**包含以下通用字段，文档中不再重复列出：

| 字段名 | 数据类型 | 默认中文标题 | 说明 |
|--------|---------|-------------|------|
| id | bigint | 主键ID | 自增主键，唯一标识 |
| tenant_id | bigint | 租户ID | 多租户隔离字段，所有查询默认带租户条件 |
| created_at | timestamp | 创建时间 | 记录创建时间，自动填充，不可修改 |
| updated_at | timestamp | 更新时间 | 记录最后修改时间，自动更新，不可手动修改 |
| created_by | bigint | 创建人ID | 记录创建人，自动取当前登录用户ID，**不可修改** |
| updated_by | bigint | 修改人ID | 记录最后修改人，自动取当前登录用户ID，**用户不可手动修改，系统每次更新时自动刷新** |
| is_deleted | boolean | 是否删除 | 软删除标记，默认false，删除操作置为true |
| owner_dept_id | bigint | 所属部门ID | 数据权限用，默认取创建人所属部门ID，**可按需变更** |
| owner_id | bigint | 数据负责人ID | 数据权限用，默认取created_by值，**可按需变更**；**注意：数据权限应使用owner_id而非created_by** |
| version | int | 版本号 | 乐观锁版本号，每次更新+1，防止并发修改冲突 |

**设计要点：**

- **created_by与owner_id分离**：created_by记录历史创建人，是审计字段，永不修改；owner_id记录当前数据负责人，用于数据权限判定，可随业务流转而变更。两者职责不同，严禁混用
- **数据权限取值链路**：查询时数据权限过滤条件为 `WHERE owner_dept_id IN (用户可见部门) AND/OR owner_id IN (用户可见人员)`，不使用created_by/created_at等审计字段做权限判定
- **owner_dept_id与owner_id联动**：当owner_id变更时（如数据转办），owner_dept_id应同步更新为新负责人的部门ID

## 4. 单据主表特有字段

所有**单据类主表**（销售订单、采购订单、出入库单等业务交易表）除通用必含字段外，还**必须**包含以下字段：

| 字段名 | 数据类型 | 默认中文标题 | 说明 |
|--------|---------|-------------|------|
| order_no | varchar(50) | 单据编号 | 由编码/单号组件自动生成，格式按配置规则，**默认不可手动修改；是否允许手工修改由编码规则配置的`allow_manual`字段控制** |
| order_date | date | 单据日期 | 默认取当前日期，可手动修改 |
| status | varchar(30) | 单据状态 | 状态机驱动，如：草稿→已审核→已关闭/已作废 |
| remark | varchar(500) | 备注 | 通用备注字段 |

**设计要点：**

- **order_no自动生成**：单据编号由编码/单号组件按配置规则自动生成，新建单据时自动填充，生成后不可修改
- **order_no与code区分**：order_no用于业务单据编号（如SO20250101001），code用于主数据编码（如客户编码C001、商品编码P001），两者语义不同
- **status状态机**：单据状态由后端状态机控制，前端仅做展示和触发，禁止前端直接修改status值

## 5. 明细从表商品冗余字段

所有**含商品的明细从表**（product_id字段），除product_id外，还**必须**冗余存储以下商品快照字段，确保商品信息后续修改不影响历史单据：

| 字段名 | 数据类型 | 默认中文标题 | 说明 |
|--------|---------|-------------|------|
| product_code | varchar(50) | 商品编码 | 下单时商品编码快照 |
| product_name | varchar(100) | 商品名称 | 下单时商品名称快照 |
| model | varchar(100) | 型号 | 下单时型号快照 |
| spec | varchar(100) | 规格 | 下单时规格快照 |
| brand | varchar(50) | 品牌 | 下单时品牌快照 |
| unit_id | bigint | 单位ID | 下单时所选单位 |
| unit | varchar(30) | 单位 | 单位中文名 |
| qty | decimal(18,6) | 数量 | 按所选单位的数量 |
| is_multi_unit | boolean | 是否多单位 | 商品是否启用多单位 |
| conversion_rate | decimal(18,6) | 转换比例 | 所选单位与基础单位的转换比例 |
| base_unit_id | bigint | 基础单位ID | 商品基础单位ID |
| base_qty | decimal(18,6) | 换算数量 | 基础单位数量，库存增减统一使用此值 |

**销售链路额外字段（客户料号）：**

以下场景的明细从表还需冗余 `customer_product_code | varchar(50) | 客户料号`：

- 报价单明细 → 销售订单明细 → 发货通知明细 → 出库明细 → 退货明细 → 对账明细 → 发票明细
- 售后单明细、样品单明细、借用单明细、租赁单明细

**设计要点：**

- **快照原则**：冗余字段在单据保存时从商品主表复制，后续商品信息变更不影响已保存的历史单据数据
- **base_qty核心地位**：换算数量（base_qty）是基础单位的数量，所有库存增减、成本核算、统计汇总**统一使用base_qty**而非qty
- **客户料号传递**：客户料号从报价单开始录入，沿销售链路自动向下传递，减少重复录入

## 6. 软删除规范

- **逻辑删除**：所有业务表删除操作统一使用软删除（`is_deleted = true`），不执行物理DELETE
- **查询默认过滤**：MyBatis-Plus全局逻辑删除插件自动处理，所有查询自动添加 `WHERE is_deleted = false`，无需手动写条件
- **唯一约束**：涉及唯一性校验的字段（如编码code），采用**部分唯一索引**方式，即 `CREATE UNIQUE INDEX uk_xxx_code ON table(code) WHERE is_deleted = false`，仅对未删除数据强制唯一，避免boolean类型is_deleted在联合唯一索引中只能存在一删一活的经典陷阱
- **恢复操作**：软删除数据可通过管理功能恢复（`is_deleted = false`），需记录恢复操作日志

---

## 7. 多租户隔离规范

- **tenant_id必填**：所有业务表必须包含tenant_id字段，不可为空
- **查询隔离**：MyBatis-Plus多租户插件自动注入 `WHERE tenant_id = ?` 条件，无需手动添加
- **索引规范**：tenant_id作为联合索引的首列（如 `INDEX(tenant_id, code)`），确保租户隔离查询性能
- **跨租户禁止**：同一查询禁止返回跨租户数据，MyBatis-Plus多租户插件对联表查询自动注入tenant_id条件
- **唯一约束包含tenant_id**：所有唯一约束必须包含tenant_id字段，如 `UNIQUE(tenant_id, bill_no, is_deleted)`

## 8. 自定义扩展字段

为满足用户个性化字段需求，所有业务表**预留自定义扩展字段机制**：

| 字段名 | 数据类型 | 默认中文标题 | 说明 |
|--------|---------|-------------|------|
| ext_str1 ~ ext_str10 | varchar(200) | 扩展字符串1~10 | 用户自定义字符串字段，可通过字段配置界面设置中文标题、是否必填、校验规则等 |
| ext_num1 ~ ext_num5 | decimal(18,8) | 扩展数值1~5 | 用户自定义数值字段，可通过字段配置界面设置中文标题、精度、是否必填等（DDL统一decimal(18,8)，显示精度由系统参数控制） |
| ext_date1 ~ ext_date3 | date | 扩展日期1~3 | 用户自定义日期字段，可通过字段配置界面设置中文标题、是否必填等 |
| ext_bool1 ~ ext_bool3 | boolean | 扩展布尔1~3 | 用户自定义布尔字段，可通过字段配置界面设置中文标题、默认值等 |
| ext_json | jsonb | 扩展JSON | 预留JSON扩展字段，用于存储动态结构化扩展数据 |

**扩展字段管理机制：**

- （1）**可视化管理**：系统提供"扩展字段配置"功能，管理员可按业务表配置扩展字段的中文标题、字段类型、是否显示、是否必填、校验规则、默认值等
- （2）**前端自动渲染**：录入页和展示页根据扩展字段配置自动渲染对应的表单控件和列表列，无需代码修改
- （3）**列表可搜索**：已启用的扩展字段自动加入查询条件，支持精确/模糊/范围搜索
- （4）**导入导出**：已启用的扩展字段自动纳入导入导出模板
- （5）**权限控制**：扩展字段纳入字段权限管理，支持按角色配置可见/隐藏/只读/可编辑

## 9. 明细表辅助属性存储规范

对于主业务单据明细行中涉及库位、批次、序列号等辅助属性的场景，三者**各自独立建子表**，采用**一行对多行**模式存储，原因如下：

- **库位**：一条明细行可能涉及多个库位出库/入库（如同一商品分批从不同库位发出），因此一行明细对应多条库位记录
- **批次**：一条明细行可能涉及多个批次（如同一商品先进先出时命中不同批次），因此一行明细对应多条批次记录
- **序列号**：一条明细行的数量可能对应多个序列号，因此一行明细对应多条序列号记录
- **独立分表原因**：三者分属不同管理维度，很多时候租户只开启其中一种；分表后各自统计查看互不影响，后续对每一种扩展也不会相互耦合

### 9.1 库位辅助属性子表（doc_detail_location）

> **注意**：以下三张辅助属性子表为从附属质的业务明细子表，仅需包含id主键和下方列出的业务字段，**不需要**包含7.1.1规定的owner_dept_id、owner_id（数据权限跟随主表明细行）、version（乐观锁跟随主表）。但**必须**包含tenant_id（多租户隔离）和created_at/updated_at（审计字段），下表中标注"(继承)"的字段从主表通用字段继承。

| 字段名 | 数据类型 | 默认中文标题 | 说明 |
|--------|---------|-------------|------|
| id | bigint | ID | 主键 |
| tenant_id | bigint | 租户ID | (继承)多租户隔离 |
| detail_id | bigint | 明细行ID | 关联主单据明细行 |
| warehouse_id | bigint | 仓库ID | 仓库（必填） |
| location_id | bigint | 库位ID | 库位（是否必填由商品控制策略is_location_manage控制） |
| qty | decimal(18,6) | 数量 | 本条库位记录对应的数量 |

**存储规则：**

1. **一行对多行**：一条明细行在doc_detail_location中可对应多条记录，每条记录表达一个"仓库+库位"的组合及对应数量
2. **数量校验**：明细行主表的qty字段存储该行总数量，doc_detail_location中同一detail_id的所有qty之和必须等于主表qty，提交时校验一致
3. **库位字段可空**：当商品控制策略`is_location_manage=false`时，location_id可为空；当`is_location_manage=true`时，location_id必填

### 9.2 批次辅助属性子表（doc_detail_batch）

| 字段名 | 数据类型 | 默认中文标题 | 说明 |
|--------|---------|-------------|------|
| id | bigint | ID | 主键 |
| detail_id | bigint | 明细行ID | 关联主单据明细行 |
| warehouse_id | bigint | 仓库ID | 仓库（必填） |
| batch_no | varchar(50) | 批次号 | 批次（是否必填由商品控制策略is_batch_manage控制） |
| qty | decimal(18,6) | 数量 | 本条批次记录对应的数量 |
| production_date | date | 生产日期 | 批次关联的生产日期 |
| shelf_life_date | date | 有效期至 | 批次关联的有效期 |

**存储规则：**

1. **一行对多行**：一条明细行在doc_detail_batch中可对应多条记录，每条记录表达一个"仓库+批次号"的组合及对应数量
2. **数量校验**：doc_detail_batch中同一detail_id的所有qty之和必须等于主表qty，提交时校验一致
3. **批次字段可空**：当商品控制策略`is_batch_manage=false`时，batch_no可为空；当`is_batch_manage=true`时，batch_no必填

### 9.3 序列号辅助属性子表（doc_detail_serial）

| 字段名 | 数据类型 | 默认中文标题 | 说明 |
|--------|---------|-------------|------|
| id | bigint | ID | 主键 |
| detail_id | bigint | 明细行ID | 关联主单据明细行 |
| warehouse_id | bigint | 仓库ID | 仓库（必填） |
| serial_no | varchar(50) | 序列号 | 序列号（是否必填由商品控制策略is_serial_manage控制） |

**存储规则：**

1. **一行对多行**：一条明细行在doc_detail_serial中可对应多条记录，每条记录对应一个序列号
2. **序列号特殊规则**：当开启序列号管理时，每条序列号记录对应一个商品个体，序列号记录数=主表qty
3. **序列号字段可空**：当商品控制策略`is_serial_manage=false`时，本表无需录入数据；当`is_serial_manage=true`时，serial_no必填且唯一

### 9.4 三表独立性说明

- 三张子表各自独立，互不耦合，可单独开启/关闭
- 当只开启库位管理时：仅doc_detail_location有数据，另外两张表无数据
- 当只开启批次管理时：仅doc_detail_batch有数据，另外两张表无数据
- 当只开启序列号管理时：仅doc_detail_serial有数据，另外两张表无数据
- 当同时开启多种管理时：各表独立录入，各自的数量校验规则分别校验主表qty；**当同时启用批次+序列号管理时，序列号与批次的对应关系通过录入顺序隐式关联（按同一detail_id下的录入顺序匹配），不做显式外键关联**
- 三张表均通过detail_id关联主单据明细行，查询时按需LEFT JOIN
- **全局统一规则**：所有业务模块（销售、采购、库存、生产、委外等）的明细行序列号管理，统一使用上述三张通用子表（doc_detail_location/doc_detail_batch/doc_detail_serial），**不再为每个模块单独建立模块级序列号/库位/批次子表**

### 9.5 库位管理与仓库管理的独立性说明

- 仓库管理和库位管理是两个独立的管理维度，不强制绑定
- 租户可能只关心从哪个仓库出入货，不需要精细到库位级别
- 是否启用库位管理由**商品控制策略表**的`is_location_manage`字段控制
- 当`is_location_manage=false`时：出入库单据的库位字段隐藏/禁用，doc_detail_location的location_id可为空
- 当`is_location_manage=true`时：出入库单据必须选择库位，doc_detail_location的location_id必填

### 9.6 商品控制策略表字段补充

| 控制策略字段 | 影响范围 | 开启后行为 | 对应辅助属性子表 |
|-------------|---------|-----------|----------------|
| is_inventory | 库存模块全局 | 该商品参与库存数量计算 | - |
| is_location_manage | 库存模块-库位 | 出入库时必须/可选指定库位 | doc_detail_location |
| is_batch_manage | 库存模块-批次 | 出入库时必须指定批次号 | doc_detail_batch |
| is_serial_manage | 库存模块-序列号 | 出入库时必须逐个录入序列号 | doc_detail_serial |
| is_shelf_life | 库存模块-效期 | 出入库时必须录入生产日期/有效期 | doc_detail_batch |

**优先级规则：** is_inventory是总开关，仅当is_inventory=true时，is_location_manage/is_batch_manage/is_serial_manage/is_shelf_life才生效

## 10. 数据类型约定

| 数据类型 | 说明 | 适用场景 |
|---------|------|---------|
| varchar(N) | 可变字符串 | 名称、编码、备注 |
| int | 整数 | 排序、数量 |
| bigint | 长整数 | ID、外键 |
| decimal(18,P) | 金额精度 | 金额、合计。P=系统参数system.decimal_places_amount，默认2，最高8 |
| decimal(18,P) | 单价精度 | 单价。P=系统参数sale.decimal_places_price或purchase.decimal_places_price，默认4，最高8 |
| decimal(18,P) | 数量精度 | 数量。P=系统参数system.decimal_places_qty，默认6，最高8 |
| decimal(18,P) | 转换率精度 | 单位转换率。P=系统参数system.decimal_places_qty，默认6，最高8 |
| date | 日期 | 业务日期 |
| timestamp | 时间戳 | 创建时间、更新时间 |
| boolean | 布尔 | 状态标记 |
| text | 长文本 | 富文本内容 |
| jsonb | JSON数据 | 扩展字段、配置存储 |

**小数位数可配置说明：**

- 单价、数量、金额、转换率等数值字段的小数位数**不硬编码**，由系统参数统一控制
- 数据库物理字段统一使用`decimal(18,8)`（最大精度8位），实际显示和输入精度由系统参数动态控制。**注：文档中部分表定义写作`decimal(18,8)`或`decimal(18,6)`，仅为标注该字段的业务精度语义（金额/单价/数量），实际建表DDL统一使用`decimal(18,8)`，由前端精度控制和后端校验逻辑按系统参数截断**
- 前端录入组件根据系统参数的精度值控制输入框的`precision`属性，后端校验时按参数值截断/四舍五入

## 11. 索引命名规则

| 类型 | 命名格式 | 示例 |
|------|---------|------|
| 主键索引 | `pk_{表名}` | `pk_sale_order` |
| 唯一索引 | `uk_{表名}_{字段名}` | `uk_sale_order_order_no` |
| 普通索引 | `idx_{表名}_{字段名}` | `idx_sale_order_tenant_id` |
| 联合索引 | `idx_{表名}_{字段1}_{字段2}` | `idx_sale_order_tenant_id_customer_id` |
| 部分唯一索引 | `uk_{表名}_{字段名}_active` | `uk_product_code_active` (WHERE is_deleted = false) |

**索引规范要点：**

- tenant_id作为联合索引的首列，确保租户隔离查询性能
- 业务唯一约束采用部分唯一索引（`WHERE is_deleted = false`），仅对未删除数据强制唯一
- 外键字段建立索引以优化JOIN查询性能
- 高频查询条件字段建立索引

## 12. Flyway迁移脚本规范

### 脚本命名格式

```
V{主版本}.{次版本}.{修订号}__{描述}.sql
```

| 命名元素 | 说明 | 示例 |
|---------|------|------|
| V | 版本化脚本前缀（大写V） | V |
| 主版本.次版本.修订号 | 语义化版本号 | 1.0.0、1.0.1、1.1.0 |
| __ | 双下划线分隔版本号与描述 | __ |
| 描述 | 蛇形命名（snake_case），简洁描述脚本内容 | init_schema、add_sale_order |

**示例：**

```
db/migration/
├── V1.0.0__init_schema.sql          # 初始化全部表结构
├── V1.0.1__init_data.sql            # 初始化预置数据
├── V1.1.0__add_sale_order.sql       # 新增销售订单表
├── V1.1.1__alter_customer_add_ext.sql # 修改客户表增加扩展字段
└── V1.2.0__add_inventory_tables.sql # 新增库存相关表
```

### 脚本格式规范

- 每个脚本文件使用UTF-8编码
- 脚本开头注释说明变更内容和作者
- DDL语句使用标准PostgreSQL语法
- 每个CREATE TABLE必须包含全部通用必含字段
- 索引在CREATE TABLE之后单独创建
- 数据初始化脚本（INSERT）与结构脚本（CREATE TABLE）分开

**脚本模板：**

```sql
-- ============================================================
-- Flyway Migration Script
-- Version: V1.1.0
-- Description: 新增销售订单主表及明细从表
-- Author: AI Generated
-- Date: 2025-01-01
-- ============================================================

-- 销售订单主表
CREATE TABLE sale_order (
    id              BIGSERIAL       PRIMARY KEY,
    tenant_id       BIGINT          NOT NULL,
    order_no        VARCHAR(50)     NOT NULL,
    order_date      DATE            NOT NULL DEFAULT CURRENT_DATE,
    status          VARCHAR(30)     NOT NULL DEFAULT 'draft',
    remark          VARCHAR(500),
    customer_id     BIGINT,
    customer_name   VARCHAR(128),
    -- 扩展字段
    ext_str1        VARCHAR(200),
    ext_str2        VARCHAR(200),
    ext_num1        DECIMAL(18,8),
    ext_json        JSONB,
    -- 通用必含字段
    created_at      TIMESTAMP       NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMP       NOT NULL DEFAULT NOW(),
    created_by      BIGINT,
    updated_by      BIGINT,
    is_deleted      BOOLEAN         NOT NULL DEFAULT FALSE,
    owner_dept_id   BIGINT,
    owner_id        BIGINT,
    version         INT             NOT NULL DEFAULT 0
);

-- 索引
CREATE INDEX idx_sale_order_tenant_id ON sale_order(tenant_id);
CREATE UNIQUE INDEX uk_sale_order_order_no_active ON sale_order(tenant_id, order_no) WHERE is_deleted = FALSE;

-- 注释
COMMENT ON TABLE sale_order IS '销售订单主表';
COMMENT ON COLUMN sale_order.order_no IS '单据编号';
COMMENT ON COLUMN sale_order.status IS '单据状态：draft=草稿/audited=已审核/closed=已关闭/voided=已作废';
```
