### 8.4.5 编码/单号自动生成组件（全局统一，所有单据/档案编码通用）

> **定位**：ERP系统中所有业务单据编号（如销售订单号SO20250217-0001）、档案编码（如客户编码CUST-2025-0001）均由本组件统一管理。组件提供**可视化配置规则 + 运行时自动生成 + 手工补录兜底**的全链路能力。

#### 一、编码结构设计（段式组合模型）

编码由若干**段（Segment）**顺序组合而成，每段有独立的类型和配置：

```
完整编码 = 段1 + 段2 + 段3 + ... + 段N + 分隔符(可选)
示例：SO-2025-02-0001
      └─前缀 └─年  └─月  └─序号
```

#### 二、段类型定义

| 段类型 | 说明 | 可配置项 | 示例 |
|--------|------|---------|------|
| 固定前缀 | 业务含义标识，手动填写 | 前缀字符串、大小写转换规则 | SO、PO、CUST、WH |
| 日期段 | 取当前日期的年/月/日组合 | 日期格式 | 2025、0217、202502 |
| 序号段 | 自增流水号 | 起始值、位数、步长、溢出策略 | 0001、00001 |
| 组织段 | 取当前用户所属公司/部门编码 | 来源字段、截取规则 | BJ、SH |
| 分类段 | 取当前业务分类编码 | 来源字段、截取规则 | A01、RAW |
| 自定义段 | 自由输入或公式计算 | 默认值、允许手工修改 | 任意 |

**日期格式可选项**：

| 格式代码 | 含义 | 示例值(2025-02-17) |
|---------|------|-------------------|
| YYYY | 四位年 | 2025 |
| YY | 两位年 | 25 |
| YYYYMM | 年月 | 202502 |
| YYMM | 两位年月 | 2502 |
| YYYYMMDD | 年月日 | 20250217 |
| YYMMDD | 两位年月日 | 250217 |
| MM | 月份 | 02 |
| DD | 日期 | 17 |

#### 三、序号段配置规则（核心）

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 位数 | 序号位数（不足补零） | 4 |
| 起始值 | 序号起始值 | 1 |
| 步长 | 每次递增值 | 1 |
| 重置周期 | 序号归零重新计数的周期 | 不重置 |
| 溢出策略 | 序号超出位数时的处理方式 | 自动扩位 |

**重置周期选项**：

| 重置周期 | 说明 | 示例 |
|---------|------|------|
| 不重置 | 全局递增，永不归零 | SO-0001, SO-0002, ... SO-10000 |
| 按年重置 | 每年1月1日归零 | SO-2024-9999, SO-2025-0001 |
| 按月重置 | 每月1日归零 | SO-202501-9999, SO-202502-0001 |
| 按日重置 | 每日归零 | SO-20250217-0001, SO-20250218-0001 |

> **序号归零判断依据**：以日期段实际值为分组键。例如重置周期=按月，则YYYYMM值变化时序号归零。无日期段时，重置周期只能选"不重置"。

#### 四、分隔符配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 段间分隔符 | 各段之间的连接字符 | - |
| 前缀后分隔符 | 前缀段与后续段之间 | 跟随段间分隔符 |
| 日期段后分隔符 | 日期段与序号段之间 | 跟随段间分隔符 |

#### 五、编码规则配置表（sys_code_rule）

| 字段名 | 数据类型 | 默认中文标题 | 说明 |
|--------|---------|-------------|------|
| tenant_id | bigint | 租户ID | 多租户隔离，不同租户可配置独立编码规则 |
| rule_code | varchar(50) | 规则编码 | 唯一标识，如SALE_ORDER、CRM_CUSTOMER |
| rule_name | varchar(100) | 规则名称 | 如"销售订单编号规则" |
| target_table | varchar(100) | 目标表名 | 如sale_order |
| target_field | varchar(50) | 目标字段名 | 如order_no |
| is_enabled | boolean | 是否启用 | - |
| allow_manual | boolean | 允许手工修改 | 默认false |
| manual_prefix_lock | boolean | 手工时前缀锁定 | 默认true |
| reset_period | varchar(20) | 重置周期 | 不重置/按年/按月/按日 |
| separator | varchar(5) | 段间分隔符 | 默认"-" |
| preview_sample | varchar(100) | 预览示例 | 配置后自动生成示例 |

#### 六、编码规则段配置表（sys_code_rule_segment）

| 字段名 | 数据类型 | 默认中文标题 | 说明 |
|--------|---------|-------------|------|
| id | bigint | 主键ID | 自增主键 |
| rule_id | bigint | 规则ID | 关联sys_code_rule |
| segment_type | varchar(20) | 段类型 | 固定前缀/日期段/序号段/组织段/分类段/自定义段 |
| segment_order | int | 段顺序 | 从1开始 |
| fixed_value | varchar(50) | 固定值 | 段类型=固定前缀时填写 |
| date_format | varchar(20) | 日期格式 | 段类型=日期段时选择 |
| seq_digits | int | 序号位数 | 段类型=序号段时配置，默认4 |
| seq_start | int | 序号起始值 | 默认1 |
| seq_step | int | 序号步长 | 默认1 |
| source_field | varchar(50) | 来源字段 | 段类型=组织段/分类段时指定 |
| source_truncate | int | 来源截取长度 | 截取来源字段前N位，0=不截取 |
| default_value | varchar(50) | 默认值 | 段类型=自定义段时填写 |

#### 七、编码流水号记录表（sys_code_sequence）

| 字段名 | 数据类型 | 默认中文标题 | 说明 |
|--------|---------|-------------|------|
| id | bigint | 主键ID | 自增主键 |
| tenant_id | bigint | 租户ID | 多租户隔离 |
| rule_id | bigint | 规则ID | 关联sys_code_rule |
| group_key | varchar(50) | 分组键 | 日期段实际值拼接，如202502；无日期段=GLOBAL |
| current_value | int | 当前序号值 | 已使用的最大序号 |
| last_generated_at | timestamp | 最后生成时间 | - |

> **并发安全**：序号生成采用数据库行级锁（SELECT ... FOR UPDATE），确保高并发下序号不重复不跳号。
> **唯一约束**：UNIQUE(tenant_id, rule_id, group_key)，确保同一规则同一分组只有一条序号记录。首次生成时采用INSERT ON CONFLICT DO UPDATE处理。

#### 八、运行时生成流程

```
1. 用户点击"新增" → 前端请求编码
2. 后端根据 rule_code 查找规则配置
3. 按段顺序拼接各段值：
   - 固定前缀段 → 直接取 fixed_value
   - 日期段 → 取当前日期按 date_format 格式化
   - 组织段 → 取当前用户所属组织的 source_field 截取
   - 分类段 → 取当前表单分类字段的 source_field 截取
   - 序号段 → 从 sys_code_sequence 获取并递增（行级锁保护）
4. 各段用 separator 拼接
5. 返回完整编码 → 前端填充到编码字段（只读或可编辑，取决于allow_manual）
```

|---------|---------|---------|--------|

| 客户编码 | CRM_CUSTOMER | CUST-0001 | 前缀(CUST) + 序号(4位,不重置) |
| 供应商编码 | SRM_SUPPLIER | SRM-0001 | 前缀(SRM) + 序号(4位,不重置) |

#### 十、前端交互规范

- **新增态**：编码字段默认只读，自动填充生成的编码；若配置`allow_manual=true`，则显示"手工输入"切换按钮
- **编辑态**：编码字段始终只读，不可修改（已生成的编码具有历史唯一性）
- **复制单据**：新单据重新生成编码，不沿用原单编码
- **编码预览**：规则配置页提供实时预览，段配置变更后自动刷新预览示例
- **序号跳号告警**：当检测到序号不连续时，系统消息中心发提醒，但不会自动补号
- **编码唯一性**：后端强制唯一索引约束，与前端校验双重保障

#### 十一、编码控制优先级链路

编码自动生成受三级开关控制，优先级从高到低：

| 优先级 | 控制项 | 位置 | 说明 |
|--------|--------|------|------|
| 1（最高） | 全局总开关 | 系统参数 system.auto_code_enabled | false时所有编码均手工输入，忽略下级配置 |
| 2 | 规则级开关 | sys_code_rule.is_enabled | 每条编码规则独立控制是否启用自动生成 |
| 3 | 规则级手工权限 | sys_code_rule.allow_manual | 规则启用时，控制用户是否可手工修改自动生成的编码 |

**判定流程**：auto_code_enabled=false → 全部手工 → 否则检查 is_enabled → false则手工 → true则自动生成 → 再看allow_manual决定是否可修改
