# 全局规范-文件上传与存储规范

> 本文档定义ERP系统文件上传、存储、访问、处理的完整规范，涵盖MinIO对象存储集成、文件上传API、存储路径策略、访问控制、图片处理及临时文件生命周期管理，所有涉及文件操作的模块必须严格遵守。

## 1. MinIO Bucket命名策略

### 1.1 Bucket命名格式

统一格式：`erp-{module}-{env}`

- 全部小写，各层级使用连字符`-`分隔
- `{module}`为业务模块缩写
- `{env}`为环境标识（dev/test/staging/prod）

### 1.2 Bucket分配表

| Bucket名称模式 | 用途 | 访问级别 | 示例（prod环境） |
|---------------|------|---------|-----------------|
| `erp-sys-{env}` | 系统文件（用户头像、Logo、配置附件） | 内部 | `erp-sys-prod` |
| `erp-sale-{env}` | 销售模块（合同附件、报价单PDF） | 内部 | `erp-sale-prod` |
| `erp-pur-{env}` | 采购模块（采购合同、供应商资质） | 内部 | `erp-pur-prod` |
| `erp-inv-{env}` | 库存模块（出入库单扫描件） | 内部 | `erp-inv-prod` |
| `erp-fin-{env}` | 财务模块（发票扫描件、凭证附件） | 内部 | `erp-fin-prod` |
| `erp-hrm-{env}` | 人力模块（员工证件、合同文件） | 内部 | `erp-hrm-prod` |
| `erp-tmp-{env}` | 临时文件（上传中转、导入导出临时） | 内部 | `erp-tmp-prod` |
| `erp-pub-{env}` | 公开文件（产品图册、帮助文档） | 公开只读 | `erp-pub-prod` |

### 1.3 Bucket策略配置

| 配置项 | 内部Bucket | 公开Bucket |
|--------|-----------|-----------|
| 访问策略 | private | public-read |
| 版本控制 | 关闭 | 关闭 |
| 生命周期 | 无自动清理 | 无自动清理 |
| 跨域CORS | 允许前端域名 | 允许前端域名 |
| 服务端加密 | SSE-S3（AES-256） | SSE-S3（AES-256） |

```yaml
# application.yml — MinIO配置
minio:
  endpoint: http://minio:9000
  access-key: ${MINIO_ACCESS_KEY}
  secret-key: ${MINIO_SECRET_KEY}
  region: cn-east-1
  secure: false
```

## 2. 文件上传API规范

### 2.1 上传方式分类

| 上传方式 | 适用场景 | 文件大小 | API路径 |
|---------|---------|---------|--------|
| 普通上传（multipart） | 常规文件 | ≤ 50MB | POST `/api/system/file/upload` |
| 分片上传（chunked） | 大文件 | > 50MB | POST `/api/system/file/upload/init` → `/chunk` → `/complete` |
| 流式上传（streaming） | 服务器端生成文件 | 不限 | 内部调用FileService |

### 2.2 普通上传接口

```
POST /api/system/file/upload
Content-Type: multipart/form-data
```

**请求参数：**

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| file | MultipartFile | 是 | 上传的文件 |
| module | String | 是 | 业务模块标识（sys/sale/pur/inv/fin/hrm） |
| bizType | String | 否 | 业务类型（如avatar/contract/invoice） |
| bizId | Long | 否 | 关联业务ID（可上传后绑定） |

**响应结构：**

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 10001,
    "originalName": "销售合同-2025.pdf",
    "storagePath": "2025/05/26/1900000000000001.pdf",
    "mimeType": "application/pdf",
    "sizeBytes": 1048576,
    "bucket": "erp-sale-prod",
    "md5": "a1b2c3d4e5f6...",
    "url": "/api/system/file/10001/download",
    "status": "CONFIRMED"
  },
  "timestamp": 1748246400000
}
```

### 2.3 分片上传接口

| 阶段 | HTTP方法 | URL | 说明 |
|------|---------|-----|------|
| 初始化 | POST | `/api/system/file/upload/init` | 获取uploadId，预分配存储路径 |
| 上传分片 | POST | `/api/system/file/upload/chunk` | 逐片上传，每片5MB |
| 合并完成 | POST | `/api/system/file/upload/complete` | 合并分片，生成最终文件 |
| 取消上传 | POST | `/api/system/file/upload/cancel` | 清理已上传的分片 |

**初始化请求：**

```json
{
  "originalName": "产品演示视频.mp4",
  "totalSize": 524288000,
  "md5": "f1e2d3c4b5a6...",
  "module": "sale",
  "bizType": "video"

```

**初始化响应：**

```json
{

  "data": {
    "uploadId": "upl_1900000000000001",

    "storagePath": "2025/05/26/1900000000000001.mp4",

```

**分片上传请求（multipart/form-data）：**

| 参数名 | 类型 | 说明 |
|--------|------|------|
| uploadId | String | 上传ID |
| chunkIndex | int | 分片序号（从0开始） |
| chunkFile | MultipartFile | 分片数据 |

### 2.4 文件下载接口

| 操作 | HTTP方法 | URL | 权限 |
|------|---------|-----|------|
| 获取文件信息 | GET | `/api/system/file/{id}` | `system:file:detail` |
| 下载文件 | GET | `/api/system/file/{id}/download` | `system:file:download` |
| 预览文件 | GET | `/api/system/file/{id}/preview` | `system:file:preview` |
| 删除文件 | DELETE | `/api/system/file/{id}` | `system:file:delete` |
| 批量删除 | POST | `/api/system/file/batch-delete` | `system:file:delete` |

**下载接口行为：**

- 设置响应头`Content-Disposition: attachment; filename="{originalName}"`
- 设置`Content-Type`为文件对应的MIME类型
- 大文件（> 10MB）使用流式传输，不预加载到内存
- 支持`Range`请求头实现断点续传

## 3. 文件大小限制

| 文件类型 | 允许扩展名 | 单文件大小上限 | 配置Key |
|---------|-----------|-------------|--------|
| 图片 | jpg, jpeg, png, gif, bmp, webp, svg | 10MB | `file.max_size.image` |
| 文档 | pdf, doc, docx, xls, xlsx, ppt, pptx, txt, csv | 50MB | `file.max_size.document` |
| 视频 | mp4, avi, mov, wmv, flv, mkv | 500MB | `file.max_size.video` |
| 音频 | mp3, wav, aac, flac, ogg | 100MB | `file.max_size.audio` |
| 压缩包 | zip, rar, 7z, tar, gz | 200MB | `file.max_size.archive` |
| 其他 | 未在上述列表中的类型 | 50MB | `file.max_size.default` |

**校验规则：**

- 文件大小校验在**上传前**执行，超限立即拒绝，返回错误码`100101`
- 分片上传时校验totalSize参数，超限返回错误码`100101`
- 文件大小上限通过系统参数（sys_param）配置，管理员可调整
- 前端上传组件在文件选择时预校验，后端二次校验兜底

### 4.2 Magic Number验证

仅依赖扩展名和Content-Type不够安全，必须通过文件头Magic Number进行二次验证：

```java
@Component
public class FileTypeValidator {

    /** 文件头Magic Number映射表 */
    private static final Map<String, byte[][]> MAGIC_NUMBERS = Map.ofEntries(
        Map.entry("jpg",  new byte[][] { {(byte)0xFF, (byte)0xD8, (byte)0xFF} }),
        Map.entry("jpeg", new byte[][] { {(byte)0xFF, (byte)0xD8, (byte)0xFF} }),
        Map.entry("png",  new byte[][] { {(byte)0x89, 0x50, 0x4E, 0x47} }),
        Map.entry("gif",  new byte[][] { {0x47, 0x49, 0x46, 0x38} }),
        Map.entry("pdf",  new byte[][] { {0x25, 0x50, 0x44, 0x46} }),
        Map.entry("zip",  new byte[][] { {0x50, 0x4B, 0x03, 0x04} }),
        Map.entry("docx", new byte[][] { {0x50, 0x4B, 0x03, 0x04} }), // ZIP格式
        Map.entry("xlsx", new byte[][] { {0x50, 0x4B, 0x03, 0x04} }), // ZIP格式
        Map.entry("mp4",  new byte[][] { {0x00, 0x00, 0x00, 0x18, 0x66, 0x74, 0x79, 0x70},
                                          {0x00, 0x00, 0x00, 0x20, 0x66, 0x74, 0x79, 0x70} })
    );

    /**
     * 验证文件类型是否与声明的扩展名一致
     * @param file 上传的文件
     * @param declaredExt 声明的扩展名（从文件名提取）
     * @return 验证结果
     */
    public FileTypeValidationResult validate(MultipartFile file, String declaredExt) {
        // 1. 扩展名白名单检查
        if (!ALLOWED_EXTENSIONS.contains(declaredExt.toLowerCase())) {
            return FileTypeValidationResult.fail("不支持的文件类型：" + declaredExt);
        }

        // 2. MIME类型检查
        String mimeType = file.getContentType();
        if (!isAllowedMimeType(declaredExt, mimeType)) {
            return FileTypeValidationResult.fail("MIME类型不匹配：" + mimeType);
        }

        // 3. Magic Number验证
        try (InputStream is = file.getInputStream()) {
            byte[] header = is.readNBytes(16);
            if (!matchesMagicNumber(declaredExt, header)) {
                return FileTypeValidationResult.fail("文件内容与扩展名不符");
            }
        }

        return FileTypeValidationResult.ok();
    }
}
```

**禁止上传的文件类型：**

| 扩展名 | 原因 |
|--------|------|
| exe, bat, cmd, sh, ps1 | 可执行文件，安全风险 |
| jar, war, class | Java可执行文件 |
| php, jsp, asp, aspx | Web脚本文件 |
| html, htm, js | 可能包含XSS攻击代码 |
| sql | 数据库脚本，注入风险 |

## 5. 存储路径规范

### 5.1 路径格式

统一格式：`{bucket}/{yyyy}/{MM}/{dd}/{snowflake-id}.{ext}`

| 路径层级 | 说明 | 示例 |
|---------|------|------|
| bucket | 按模块分配 | `erp-sale-prod` |
| yyyy | 年份目录 | `2025` |
| MM | 月份目录 | `05` |
| dd | 日期目录 | `26` |
| snowflake-id | 雪花算法生成的唯一ID | `1900000000000001` |
| ext | 原始文件扩展名（小写） | `pdf` |

**完整路径示例：**

```
erp-sale-prod/2025/05/26/1900000000000001.pdf
erp-sys-prod/2025/05/26/1900000000000002.jpg
erp-tmp-prod/2025/05/26/1900000000000003.xlsx
```

### 5.2 路径生成工具

```java
@Component
public class StoragePathGenerator {

    @Autowired
    private SnowflakeIdGenerator idGenerator;

    /**
     * 生成存储路径
     * @param module 业务模块
     * @param originalName 原始文件名（用于提取扩展名）
     * @param env 环境标识
     * @return 完整存储路径
     */
    public StoragePath generate(String module, String originalName, String env) {
        String ext = extractExtension(originalName).toLowerCase();
        String bucket = "erp-" + module + "-" + env;
        LocalDate now = LocalDate.now();
        long fileId = idGenerator.nextId();

        String path = String.format("%d/%02d/%02d/%d.%s",
            now.getYear(), now.getMonthValue(), now.getDayOfMonth(), fileId, ext);

        return new StoragePath(bucket, path, fileId, ext);
    }

    private String extractExtension(String fileName) {
        if (fileName == null || !fileName.contains(".")) {
            return "bin";
        }
        return fileName.substring(fileName.lastIndexOf('.') + 1);
    }
}
```

## 6. 文件访问控制

### 6.1 权限校验流程

所有文件下载/预览操作**必须**经过Sa-Token权限校验：

```java
@RestController
@RequestMapping("/api/system/file")
public class FileController {

    @SaCheckPermission("system:file:download")
    @GetMapping("/{id}/download")
    public void download(@PathVariable Long id, HttpServletResponse response) {
        // 1. 查询文件记录
        SysFile file = fileService.getById(id);
        if (file == null || file.getIsDeleted()) {
            throw new BusinessException(100104, "文件不存在");
        }

        // 2. 租户隔离校验
        Long currentTenantId = TenantContext.getTenantId();
        if (!file.getTenantId().equals(currentTenantId)) {
            throw new BusinessException(900003, "无权访问该文件");
        }

        // 3. 业务权限校验（根据文件关联的业务模块判定）
        fileAccessService.checkBizPermission(file);

        // 4. 记录下载日志
        auditLogService.log("FILE_DOWNLOAD", file.getId(), file.getOriginalName());

        // 5. 流式输出文件
        fileService.streamToResponse(file, response);
    }
}
```

## 8. 图片处理

### 8.1 缩略图生成

图片上传后自动生成以下规格的缩略图：

| 缩略图类型 | 尺寸 | 用途 | 存储后缀 |
|-----------|------|------|---------|
| 小图 | 100×100 | 列表头像、选择器 | `_thumb_s.{ext}` |
| 中图 | 400×400 | 详情页展示 | `_thumb_m.{ext}` |
| 大图 | 1200×1200 | 全屏预览 | `_thumb_l.{ext}` |

### 8.2 图片压缩

```java
@Component
public class ImageProcessor {

    /**
     * 图片上传后处理：生成缩略图 + 压缩原图
     */
    public ImageProcessResult process(InputStream source, String ext, StoragePath path) {
        BufferedImage original = ImageIO.read(source);

        // 1. 压缩原图（质量压缩，保持尺寸）
        byte[] compressed = compress(original, ext, 0.85f);
        minioService.upload(path.getBucket(), path.getPath(), compressed);

        // 2. 生成缩略图
        Map<String, byte[]> thumbnails = new LinkedHashMap<>();
        thumbnails.put("_thumb_s", resize(original, 100, 100, ext));
        thumbnails.put("_thumb_m", resize(original, 400, 400, ext));
        thumbnails.put("_thumb_l", resize(original, 1200, 1200, ext));

        for (Map.Entry<String, byte[]> entry : thumbnails.entrySet()) {
            String thumbPath = appendSuffix(path.getPath(), entry.getKey());
            minioService.upload(path.getBucket(), thumbPath, entry.getValue());
        }

        return ImageProcessResult.builder()
            .originalWidth(original.getWidth())
            .originalHeight(original.getHeight())
            .compressedSize(compressed.length)
            .thumbnailPaths(thumbnails.keySet().stream()
                .map(s -> appendSuffix(path.getPath(), s))
                .collect(Collectors.toList()))
            .build();
    }

    private byte[] resize(BufferedImage original, int maxWidth, int maxHeight, String ext) {
        // 等比缩放，不超过指定尺寸
        int w = original.getWidth();
        int h = original.getHeight();
        double ratio = Math.min((double) maxWidth / w, (double) maxHeight / h);
        if (ratio >= 1.0) ratio = 1.0;
        int newW = (int) (w * ratio);
        int newH = (int) (h * ratio);

        BufferedImage resized = new BufferedImage(newW, newH, BufferedImage.TYPE_INT_RGB);
        Graphics2D g2d = resized.createGraphics();
        g2d.setRenderingHint(RenderingHints.KEY_INTERPOLATION,
                             RenderingHints.VALUE_INTERPOLATION_BILINEAR);
        g2d.drawImage(original, 0, 0, newW, newH, null);
        g2d.dispose();

        return toBytes(resized, ext, 0.85f);
    }
}
```

### 8.3 EXIF信息处理

- 上传时读取EXIF信息（拍摄时间、GPS坐标、设备信息），存入`sys_file.ext_json`
- 缩略图生成时**剥离**EXIF信息，防止隐私泄露
- GPS坐标信息按敏感数据处理，接口返回时脱敏

## 9. 临时文件生命周期

### 9.1 临时文件状态流转

```
上传到临时Bucket(erp-tmp-{env})
    │
    ├──[业务确认]──→ 移动到永久Bucket(erp-{module}-{env})，状态变为CONFIRMED
    │
    └──[超时未确认]──→ 自动清理（XXL-JOB定时任务扫描删除）
```

### 9.2 生命周期规则

| 状态 | 存储位置 | 保留时长 | 清理方式 |
|------|---------|---------|---------|
| PENDING（上传未确认） | `erp-tmp-{env}` | 24小时 | XXL-JOB定时扫描+MinIO删除 |
| CONFIRMED（已确认） | `erp-{module}-{env}` | 永久 | 跟随业务数据软删除 |
| DELETED（已删除） | 原Bucket | 30天 | 软删除后30天物理清理 |
| IMPORT_TEMP（导入临时） | `erp-tmp-{env}` | 7天 | 导入完成后7天自动清理 |

### 9.3 临时文件清理Job

```java
@Component
@XxlJob("tempFileCleanupJobHandler")
public class TempFileCleanupJobHandler extends BaseJobHandler {

    @Override
    protected void processChunk(List<SysFile> chunk, JobContext context) {
        for (SysFile file : chunk) {
            try {
                // 从MinIO删除
                minioService.removeObject(file.getBucket(), file.getStoragePath());
                // 删除数据库记录
                sysFileMapper.deleteById(file.getId());
                context.incrementSuccess();
            } catch (Exception e) {
                log.error("清理临时文件失败: fileId={}", file.getId(), e);
                context.incrementFail();
            }
        }
    }

    @Override
    protected LambdaQueryWrapper<SysFile> buildQueryWrapper(JobContext context) {
        return new LambdaQueryWrapper<SysFile>()
            .eq(SysFile::getStatus, FileStatus.PENDING)
            .lt(SysFile::getCreatedAt, LocalDateTime.now().minusHours(24));
    }
}
```

## 10. 病毒扫描

### 10.1 扫描钩子点

文件上传流程中集成病毒扫描，在文件**移动到永久存储前**执行：

```
上传文件 → 类型校验 → MD5校验 → 病毒扫描 → 移动到永久Bucket → 返回结果
                                    │
                                    └── 扫描异常 → 文件隔离 → 通知管理员
```

### 10.2 ClamAV集成

```java
@Component
public class VirusScanService {

    @Value("${virus-scan.enabled:true}")
    private boolean enabled;

    @Value("${virus-scan.clamav-host:clamav}")
    private String clamavHost;

    @Value("${virus-scan.clamav-port:3310}")
    private int clamavPort;

    /**
     * 扫描文件是否包含病毒
     * @return ScanResult：CLEAN=安全, INFECTED=感染, ERROR=扫描异常
     */
    public ScanResult scan(InputStream fileStream) {
        if (!enabled) {
            return ScanResult.CLEAN; // 未启用扫描，直接放行
        }

        try (ClamavClient client = new ClamavClient(clamavHost, clamavPort)) {
            ClamavScanResult result = client.scan(fileStream);
            if (result.isClean()) {
                return ScanResult.CLEAN;
            } else {
                log.warn("病毒扫描命中: virus={}", result.getVirusName());
                return ScanResult.INFECTED;
            }
        } catch (Exception e) {
            log.error("病毒扫描服务异常", e);
            return ScanResult.ERROR;
        }
    }
}
```

**扫描策略：**

| 场景 | 扫描行为 | 异常处理 |
|------|---------|---------|
| 生产环境 | 必须扫描，扫描不通过拒绝上传 | 扫描服务异常时拒绝上传（安全优先） |
| 开发/测试环境 | 可选关闭 | 通过配置`virus-scan.enabled=false`关闭 |
| 超大文件（>100MB） | 异步扫描，先存储到隔离区 | 扫描完成前不允许业务访问 |

### 11.2 秒传机制

上传前计算文件MD5，与数据库已有记录比对，若存在相同MD5文件则直接复用存储路径：

```java
public FileUploadResult uploadOrReuse(MultipartFile file, String module, String bizType) {
    String md5 = DigestUtils.md5Hex(file.getInputStream());

    // 1. 检查是否存在相同MD5的文件（秒传）
    SysFile existing = sysFileMapper.selectOne(
        new LambdaQueryWrapper<SysFile>()
            .eq(SysFile::getTenantId, TenantContext.getTenantId())
            .eq(SysFile::getMd5, md5)
            .eq(SysFile::getStatus, FileStatus.CONFIRMED)
            .last("LIMIT 1")
    );

    if (existing != null) {
        // 秒传：仅创建新记录，指向同一存储路径
        SysFile newRecord = cloneFileRecord(existing, module, bizType);
        sysFileMapper.insert(newRecord);
        return FileUploadResult.from(newRecord, true); // isReused=true
    }

    // 2. 无匹配，正常上传流程
    return doUpload(file, module, bizType, md5);
}
```

## 14. 检查清单

新功能涉及文件操作时，必须逐项确认：

| 检查项 | 通过标准 |
|--------|---------|
| 文件类型校验 | 扩展名白名单 + MIME类型 + Magic Number三重校验 |
| 文件大小校验 | 前端预校验 + 后端二次校验 |
| 存储路径 | 使用StoragePathGenerator生成，禁止手动拼接 |
| Bucket选择 | 按模块使用对应Bucket，临时文件使用erp-tmp |
| 权限校验 | 下载/预览/删除接口均有Sa-Token权限注解 + 租户隔离校验 |
| 数据库记录 | 上传成功后写入sys_file表，包含完整元数据 |
| 病毒扫描 | 生产环境上传必须经过ClamAV扫描 |
| 临时文件清理 | 未确认文件24小时后自动清理 |
| 图片缩略图 | 图片上传自动生成三种尺寸缩略图 |
| 日志记录 | 文件上传/下载/删除操作记录审计日志 |
| 前端组件 | 使用FileUpload标准组件，传递正确Props |
| 错误码 | 使用规范中定义的错误码，不自定义错误信息 |
