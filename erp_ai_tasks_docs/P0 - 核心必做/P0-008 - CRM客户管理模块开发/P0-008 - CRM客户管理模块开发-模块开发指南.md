# P0-008 CRM客户管理模块开发 - 模块开发指南

## 一、模块概述

- **模块定位**：客户档案管理 + 客户分类 + 标签 + 联系人/地址/附件/评价/财务配置 + 客户画像 + 客户机会 + 客户项目，为销售模块提供客户基础数据支撑
- **前置依赖**：P0-001（后端框架）、P0-002（前端框架）、P0-003（数据库）、P0-004（认证与权限）、P0-005（公共组件）、P0-006（组织架构提供公司/部门/员工数据）、P0-007（商品管理提供商品数据）
- **被依赖方**：P1-005（销售管理）、P1-010（应收管理）
- **开发阶段**：阶段五（基础数据）

**业务校验规则**：

| 校验项 | 校验时机 | 规则 | 错误提示 |
|--------|---------|------|---------|
| 客户名称唯一 | 新增/修改 | 同tenant_id+company_id下is_deleted=false不能有同名 | "同一公司主体下客户名称已存在" |
| 客户编码唯一 | 新增 | 编码引擎保证唯一 | "客户编码已存在" |

| 删除前关联检查 | 删除 | 检查合同/订单/机会/项目/销价是否引用 | "该客户已被其他业务数据引用，无法删除" |

### 4.2 crm_customer_class（客户分类表）— 主表

**业务字段**：

| 字段名 | 数据类型 | 约束 | 默认值 | 中文标题 | 说明 |

| parent_id | bigint | - | 0 | 上级分类ID | 0或null表示顶级，树形结构 |
| sort_no | int | NOT NULL | 0 | 排序号 | 数值越小越靠前 |
| enable_flag | boolean | NOT NULL | true | 是否启用 | 启用/禁用状态 |

**索引设计**：

| 索引名 | 类型 | 字段 | 说明 |
|--------|------|------|------|
| pk_crm_customer_class | 主键 | id | 主键索引 |

| idx_crm_customer_class_parent | 普通 | parent_id | 按上级查下级(树形查询) |

**业务校验规则**：

| 校验项 | 校验时机 | 规则 | 错误提示 |
|--------|---------|------|---------|

## 六、Service层业务逻辑规格

### 6.1 CrmCustomerClassService

| 方法 | 事务 | 业务逻辑要点 |
|------|------|------------|
| tree() | 无(只读) | 查询全部客户分类，构建树形结构返回 |
| getById(Long) | 无(只读) | 返回CustomerClassDetailVO |
| create(CustomerClassCreateDTO) | @Transactional | 名称唯一性校验 → 循环引用检查 → DTO转Entity → save → 操作日志 |
| update(id, CustomerClassUpdateDTO) | @Transactional | 存在性校验 → 名称唯一性校验(排除自身) → 循环引用检查 → 乐观锁更新 |
| delete(Long) | @Transactional | 子分类检查 → 客户引用检查 → 逻辑删除 |

### 6.2 CrmTagDefinitionService

| 方法 | 事务 | 业务逻辑要点 |
|------|------|------------|
| list() | 无(只读) | 查询全部启用标签(下拉选择用) |
| page(TagQueryDTO) | 无(只读) | 支持tagName模糊搜索 + tagGroup筛选 |
| create(TagDefinitionCreateDTO) | @Transactional | 名称唯一性校验 → save |
| update(id, TagDefinitionUpdateDTO) | @Transactional | 存在性校验 → 名称唯一性校验(排除自身) → 乐观锁更新 |
| delete(Long) | @Transactional | 客户标签关联检查 → 逻辑删除 |

### 6.3 CrmCustomerService

| 方法 | 事务 | 业务逻辑要点 |
|------|------|------------|

## 八、模块级专属约束

1. **功能点优先级**：设计文档11.3节定义的14个功能点（工作台/客户中心/客户分类/标签定义/客户基本信息/客户联系人/客户地址/客户标签/客户画像/客户附件/客户评价/客户财务配置/客户机会/客户项目）按顺序开发，客户中心主从页面（含9个标签页）为核心功能点。
2. **客户名称唯一性**：客户名称在同一公司主体下必须唯一，新增/修改时需进行唯一性校验，校验失败时返回明确的业务异常提示。
3. **联系人联系方式唯一性**：同一客户下联系方式值（手机号/邮箱）需进行唯一性参数控制，防止重复录入。
4. **客户机会阶段流转**：客户机会的阶段字段需按"初步接触→需求确认→方案报价→商务谈判→赢单/输单"顺序流转，禁止跳跃式推进，赢单/输单后不可回退。
5. **客户画像聚合性能**：客户画像聚合接口涉及多表JOIN与统计计算，需使用异步查询或缓存策略，单次查询响应时间≤500ms。
6. **标签批量操作事务**：客户标签的批量绑定/解绑操作需在同一事务内完成，部分失败需全量回滚。
