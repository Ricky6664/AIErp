## 1. 模块架构约束

### 1.1 模块定位
P0-008负责开发ERP系统的CRM客户管理功能，包括客户档案管理、客户分类（树形）、标签管理、联系人/地址/附件/评价/财务配置管理、客户画像、客户机会管理、客户项目管理。本模块为销售模块（P1-005）提供客户基础数据支撑，为应收管理（P1-010）提供客户财务配置数据。

### 1.2 依赖关系
- 前置依赖：
  - P0-001（后端框架）
  - P0-002（前端框架）
  - P0-003（数据库提供crm_*系列表）
  - P0-004（认证与权限）
  - P0-005（公共组件提供页面基座/选择器）
  - P0-006（组织架构提供公司/部门/员工数据）
  - P0-007（商品管理提供商品数据——客户机会可能关联商品）
- 后续依赖：
  - P1-005（销售管理）——引用客户数据（报价单/销售订单/发货/出库等）
  - P1-010（应收管理）——引用客户财务配置（收款/发票/核销等）

### 1.3 技术约束
- **技术栈约束**：Spring Boot 3.4.x + MyBatis-Plus 3.5.5 + Redis（缓存）+ Vue3 + Element Plus + Vxe Table
- **性能约束**：客户列表查询 < 200ms（10万客户）；客户画像聚合接口 ≤ 500ms（需使用异步查询或缓存策略）
- **安全约束**：客户数据按数据权限过滤（owner_id/owner_dept_id）；客户名称同一公司主体下唯一

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| crm_customer | 客户主表 | customer_code, customer_name, short_name, class_id, business_rep_id, business_dept_id, company_id, source, status |
| crm_customer_class | 客户分类表 | class_name, parent_id, sort_order, is_enabled |
| crm_tag_definition | 标签定义表 | tag_name, tag_group, tag_color, sort_order |
| crm_customer_contact | 客户联系人表 | customer_id, contact_name, nickname, gender, is_default, position, role |
| crm_contact_comm | 联系人联系方式表 | customer_id, contact_id, comm_type, comm_value, comm_label, is_default |
| crm_customer_address | 客户地址表 | customer_id, address_type, country, province, city, district, detail_address, is_default |
| crm_customer_tag_rel | 客户标签关联表 | customer_id, tag_id |
| crm_customer_attachment | 客户附件表 | customer_id, file_name, file_path, file_size |
| crm_customer_evaluation | 客户评价表 | customer_id, satisfaction_score, credit_level, evaluator_id, evaluation_content |
| crm_customer_finance | 客户财务配置表 | customer_id, currency, invoice_type, settlement_method, credit_limit, tax_no, bank_account |
| crm_opportunity | 客户机会表 | customer_id, opportunity_name, sales_person_id, estimated_amount, estimated_close_date, stage, probability |
| crm_project | 客户项目表 | customer_id, opportunity_id, project_name, project_manager_id, start_date, end_date, total_amount, stage |

### 2.2 表关系图
- `crm_customer_class`（树形自引用）1:N `crm_customer`：分类与客户一对多
- `crm_customer` 1:N `crm_customer_contact` → `crm_customer_contact` 1:N `crm_contact_comm`：客户-联系人-联系方式三级
- `crm_customer` 1:N `crm_customer_address`：客户与地址一对多（收货/开票/其他）
- `crm_customer` N:N `crm_tag_definition`（通过crm_customer_tag_rel）：客户与标签多对多
- `crm_customer` 1:N `crm_customer_attachment`：客户与附件一对多
- `crm_customer` 1:N `crm_customer_evaluation`：客户与评价一对多
- `crm_customer` 1:1 `crm_customer_finance`：客户与财务配置一对一
- `crm_customer` 1:N `crm_opportunity`：客户与机会一对多
- `crm_customer` 1:N `crm_project`：客户与项目一对多
- `crm_opportunity` 1:N `crm_project`：机会可关联多个项目

### 2.3 数据流转
1. **客户新增流程**：选择分类 → 填写基本信息 → 编码引擎生成客户编码 → 名称唯一性校验 → 选择公司主体 → 保存客户主表 → 可继续维护联系人/地址/标签/附件/评价/财务配置
2. **客户机会管理流程**：选择客户 → 新增机会 → 设置阶段（初步接触）→ 阶段推进（需求确认→方案报价→商务谈判→赢单/输单）→ 赢单后可创建关联项目
3. **客户画像聚合流程**：选择客户 → 聚合查询基本信息+交易统计+跟进记录+标签画像 → 异步计算或缓存命中 → 返回画像数据

## 3. 业务流程

### 3.1 核心业务流程
1. **CRM后端开发**（P0-008-001）：
   - 客户分类CRUD（树形结构）
   - 标签定义CRUD
   - 客户主表CRUD（含名称唯一性校验+公司主体范围校验）
   - 客户联系人CRUD（主从保存+联系方式唯一性校验）
   - 客户地址/附件/评价/财务配置CRUD
   - 客户标签批量绑定/解绑（事务保证）
   - 客户机会CRUD（含阶段流转校验）
   - 客户项目CRUD
   - 客户画像聚合接口（异步查询/缓存策略）
   - CRM工作台聚合接口
2. **CRM前端页面**（P0-008-002）：
   - CRM工作台（P02）
   - 客户中心（P03主从列表+P06主从表单，关联信息区含9个标签页）
   - 客户分类（P05树形列表）
   - 各子功能列表页（P04）+ 表单页（P07）
   - 客户画像（P12画像页）

### 3.2 业务规则
- **功能点优先级**：14个功能点按顺序开发，客户中心主从页面（含9个标签页）为核心功能点
- **客户名称唯一性**：客户名称在同一公司主体下必须唯一，校验失败返回明确业务异常
- **联系人联系方式唯一性**：同一客户下联系方式值（手机号/邮箱）需唯一性参数控制
- **客户机会阶段流转**：按"初步接触→需求确认→方案报价→商务谈判→赢单/输单"顺序流转，禁止跳跃式推进，赢单/输单后不可回退
- **客户画像聚合性能**：聚合接口需使用异步查询或缓存策略，单次查询响应时间≤500ms
- **标签批量操作事务**：批量绑定/解绑需在同一事务内完成，部分失败全量回滚

### 3.3 状态流转
- **客户审核状态**：草稿(draft) → 待审核(pending) → 已审核(approved) → 已禁用(disabled)
- **客户机会阶段**：初步接触 → 需求确认 → 方案报价 → 商务谈判 → 赢单(won) / 输单(lost)
- **客户项目阶段**：立项 → 执行 → 验收 → 结项
- **客户启用状态**：启用(enabled) ↔ 禁用(disabled)

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **P0-008-001 CRM后端开发**（前端依赖后端接口）
2. **P0-008-001** → **P0-008-002 CRM前端页面**

后端内部开发顺序：
1. 客户分类CRUD（客户主表依赖分类树）
2. 标签定义CRUD（客户标签关联依赖标签定义）
3. 客户主表CRUD（联系人/地址/标签等依赖客户主表）
4. 联系人/地址/标签/附件/评价/财务配置CRUD（可并行）
5. 客户机会CRUD → 客户项目CRUD（项目可关联机会）
6. 客户画像聚合接口 + 工作台聚合接口

### 5.2 可并行执行的任务
- 客户联系人、客户地址、客户附件、客户评价、客户财务配置CRUD可并行（均仅依赖客户主表）
- 前端页面中各子功能列表页/表单页可并行开发
- 客户画像页面与客户机会/项目页面可并行开发
