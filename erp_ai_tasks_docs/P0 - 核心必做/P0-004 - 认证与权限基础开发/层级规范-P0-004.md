## 1. 模块架构约束

### 1.1 模块定位
P0-004负责构建ERP系统的完整认证与权限体系，包括Sa-Token登录认证、用户管理、五层权限体系（菜单权限/按钮权限/数据权限/字段权限/权限方案）、SSO/OAuth2配置管理、登录安全增强。本模块为全系统提供统一的身份认证和细粒度权限控制能力，是所有业务模块的权限基础设施。

### 1.2 依赖关系
- 前置依赖：P0-001（后端框架提供Sa-Token集成基础）、P0-003（数据库提供sys_user/sys_role/sys_menu等表）
- 后续依赖：P0-006~P0-012全部基础数据模块、P1全部模块（所有业务模块均依赖认证与权限控制）

### 1.3 技术约束
- **技术栈约束**：Sa-Token 1.39.0（认证授权框架）；BCrypt（密码加密）；Redis（Token存储+验证码缓存+登录失败计数器）
- **性能约束**：登录接口响应 < 500ms；Token校验 < 50ms；权限数据加载 < 200ms；验证码生成 < 100ms
- **安全约束**：密码必须BCrypt加密存储，禁止明文或可逆加密；Token有效期30天+临时有效期30分钟；登录失败连续5次锁定15分钟；验证码Redis缓存5分钟+一次性消费；登录日志异步写入不阻塞主流程

### 2.2 表关系图
- **用户-角色多对多**：sys_user N:N sys_role（通过sys_user_role）
- **角色-菜单多对多**：sys_role N:N sys_menu（通过sys_role_menu，含permission_type区分查看/新增/编辑/删除/审核）
- **角色-数据权限**：sys_role 1:N sys_role_data（一个角色可配置多个业务类型的数据权限）
- **角色-字段权限**：sys_role 1:N sys_role_field（一个角色可配置多个业务类型的字段权限）
- **角色继承**：sys_role N:N sys_role（通过sys_role_inheritance自引用，子角色自动继承父角色全部权限）
- **角色互斥**：sys_role N:N sys_role（通过sys_role_exclusion自引用，同一用户不可同时拥有互斥角色）
- **权限方案体系**：sys_data_permission_scheme 1:N sys_data_permission_scheme_detail + N:N sys_role（通过sys_data_permission_scheme_role）
- **用户-部门多对多**：sys_user N:N sys_dept（通过sys_user_dept，支持多部门归属）
- **用户组体系**：sys_user_group 1:N sys_user_group_member + 1:N sys_user_group_role

### 2.3 数据流转
1. **登录流程**：用户提交凭证+验证码 → 验证码Redis校验（一次性消费）→ 密码BCrypt比对 → 密码策略校验 → 登录失败计数（Redis）→ Sa-Token签发Token → 记录在线设备 → 异步写入登录日志
2. **权限加载流程**：用户登录成功 → StpInterfaceImpl.getPermissionList查询sys_role_menu → 合并角色继承权限 → 过滤互斥角色 → 缓存到Sa-Token Session → 前端获取权限标识列表
3. **数据权限过滤流程**：业务查询 → MyBatis-Plus数据权限拦截器 → 查询当前用户角色的sys_role_data配置 → 注入WHERE owner_dept_id IN (...) AND/OR owner_id IN (...)

## 3. 业务流程

### 3.1 核心业务流程
1. **登录认证后端开发**（P0-004-001）：实现登录/登出/Token刷新/Token校验接口 → 实现验证码生成 → 实现用户信息获取（含菜单权限树+按钮权限+字段权限）
2. **用户管理后端开发**（P0-004-002）：实现用户CRUD → 用户角色批量分配 → 用户部门关联 → 密码重置/修改
3. **权限配置后端开发**（P0-004-003）：实现角色CRUD → 角色菜单权限绑定 → 角色数据权限配置 → 角色字段权限配置 → 角色继承/互斥管理 → 数据权限方案/字段权限方案CRUD
4. **菜单管理后端开发**（P0-004-004）：实现菜单树CRUD → 移动端菜单管理 → 按角色权限过滤加载菜单树
5. **认证配置后端开发**（P0-004-005）：实现认证方式CRUD → 密码策略管理 → 在线设备管理 → SSO/OAuth2配置管理
6. **前端登录页面开发**（P0-004-006）：登录页UI → 验证码集成 → 表单校验 → 登录逻辑
7. **前端权限体系集成**（P0-004-007）：动态路由权限过滤 → 按钮权限指令v-permission → 字段权限控制
8. **前端管理页面**（P0-004-008~010）：用户管理/权限配置/认证配置前端页面
9. **登录安全增强**（P0-004-011）：图形验证码增强 → 密码强度校验 → 登录失败锁定 → 短信验证码预留
10. **SSO/OAuth2配置管理**（P0-004-012）：SSO/OAuth2配置CRUD前端页面（协议对接在P2阶段扩展）

### 3.2 业务规则
- Sa-Token集成：所有登录认证必须通过Sa-Token框架API实现，不允许自行实现Token机制
- 密码安全：BCrypt加密存储，密码策略由auth_password_policy表驱动（最小8位、大小写+数字+特殊字符四选三）
- 登录安全增强：图形验证码Redis缓存5分钟+一次性消费；登录失败连续5次锁定15分钟（Redis计数器）
- 五层权限体系：菜单权限（sys_role_menu控制页面访问）→ 按钮权限（permission_code控制操作按钮）→ 数据权限（sys_role_data控制数据范围）→ 字段权限（sys_role_field控制字段可见/可编辑/隐藏）→ 权限方案（可复用的数据权限方案+字段权限方案）
- 角色继承与互斥：子角色自动继承父角色全部权限；互斥角色在用户角色分配时强制校验
- 权限部门与组织架构部门分离：sys_dept为权限部门（管用户数据权限），org_department为组织架构部门（管员工归属）
- SSO/OAuth2：P0阶段仅完成配置表CRUD和管理页面，协议对接在P2阶段扩展
- 登录日志异步写入：不阻塞登录主流程

### 3.3 状态流转
- **用户账户状态**：正常 → 锁定（连续5次登录失败）→ 正常（管理员手动解锁或锁定时长到期）→ 禁用（管理员操作）
- **在线设备状态**：在线 → 已下线（用户主动登出）/ 已踢出（管理员强制下线）
- **供应商准入状态（SRM引用）**：待提交 → 待审核 → 已通过/已驳回 → 已归档

## 5. 开发顺序约束
