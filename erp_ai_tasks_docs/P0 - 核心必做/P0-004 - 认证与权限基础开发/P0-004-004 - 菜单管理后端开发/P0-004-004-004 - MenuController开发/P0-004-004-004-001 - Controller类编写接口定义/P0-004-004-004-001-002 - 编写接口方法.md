### 5.1 核心功能
1. 创建MenuController类，添加@RestController + @RequestMapping("/api/system/menu")注解
2. 编写GET /api/system/menu查询完整菜单树（管理后台用），递归构建目录/菜单/按钮三级树形结构
3. 编写GET /api/system/menu/tree按当前用户角色权限过滤加载菜单树（前端路由用），仅返回该用户有权访问的菜单
4. 编写GET /{id}查询菜单详情、POST新增菜单、PUT /{id}修改菜单、DELETE /{id}删除菜单
5. 编写移动端菜单管理接口：GET /api/system/mobile-menu查询移动端菜单树、POST/PUT/DELETE操作
6. 菜单树构建算法：一次性查询所有菜单，在内存中递归构建树（避免N+1查询），按sort_order排序

### 5.2 数据交互
**菜单树查询响应**：`GET /api/system/menu/tree`
```json
{
  "code": 200,
  "data": [{
    "id": "Long", "parentId": "Long", "name": "系统管理", "type": "directory",
    "icon": "setting", "path": "/system", "component": "", "permissionCode": "",
    "sortOrder": 1, "visible": true, "enabled": true,
    "children": [{ "id": "Long", "name": "用户管理", "type": "menu", "path": "/system/user", "component": "system/user/index", "children": [
      { "id": "Long", "name": "新增用户", "type": "button", "permissionCode": "system:user:add" }
    ]}]
  }]
}
```
**涉及数据表**：sys_menu, sys_mobile_menu, sys_role_menu

### 5.3 关键逻辑
- **菜单树构建**：一次查询SELECT * FROM sys_menu WHERE is_deleted=0 ORDER BY sort_order，内存中按parentId分组递归构建树，时间复杂度O(n)
- **权限过滤菜单树**：查询当前用户角色关联的sys_role_menu获取有权限的menuId集合，构建树时过滤掉无权限节点；按钮类型节点不显示在菜单中但permissionCode需返回给前端
- **菜单类型**：directory(目录)→menu(菜单页面)→button(按钮权限)，目录和菜单影响路由，button仅影响按钮显隐
- **删除菜单级联校验**：删除前检查是否有子菜单（parent_id引用），有则禁止删除；同时检查是否有角色关联该菜单(sys_role_menu)
- **permissionCode规范**：按钮类型菜单的permission_code格式为`模块:资源:操作`，如system:user:add、system:role:delete，前端通过v-permission指令校验

### 5.4 验证
1. 完整菜单树返回正确的三级目录/菜单/按钮树形结构，排序按sort_order
2. 按角色权限过滤的菜单树仅返回当前用户有权限的菜单节点
3. 新增菜单时parent_id校验存在性，级次(level)自动计算为父级次+1
4. 删除有子菜单的菜单节点返回"存在子菜单，无法删除"错误
5. 按钮类型菜单的permissionCode正确返回，前端可据此控制按钮显隐

## 八、易错警示

> ⚠️ Sa-Token的StpUtil.login(userId)中userId必须是唯一标识，建议使用Long类型用户ID

> ⚠️ 多租户隔离(tenant_id)由MyBatis-Plus TenantLineInnerInterceptor自动注入，不要手动拼接
