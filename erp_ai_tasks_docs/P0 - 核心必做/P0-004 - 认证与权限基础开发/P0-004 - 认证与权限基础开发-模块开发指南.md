# P0-004 认证与权限基础开发 - 模块开发指南

## 一、模块概述

- **模块定位**：Sa-Token登录认证 + 用户管理 + 五层权限体系（菜单权限/按钮权限/数据权限/字段权限/权限方案） + SSO/OAuth2 + 登录安全
- **前置依赖**：P0-001（后端框架）、P0-003（数据库）
- **被依赖方**：P0-006~P0-012 全部基础数据模块、P1全部模块
- **开发阶段**：阶段三（认证权限）

## 四、模块级专属约束

1. **Sa-Token集成**：所有登录认证必须通过Sa-Token框架实现，Token签发/注销/校验/续期均使用Sa-Token API，不允许自行实现Token机制。
2. **密码安全**：用户密码必须使用BCrypt加密存储，不允许明文存储或可逆加密。密码策略配置（最小8位、大小写+数字+特殊字符四选三）由auth_password_policy表驱动。
3. **登录安全增强（P0-004-011）属于P0认证基础设施**：必须在系统上线前完成，包括图形验证码（Redis缓存5分钟+一次性消费）、密码强度校验、登录失败锁定（Redis计数器+连续5次锁定15分钟）、短信验证码（预留）。
4. **五层权限体系**：菜单权限（sys_role_menu控制页面访问）、按钮权限（permission_code控制操作按钮）、数据权限（sys_role_data控制数据范围）、字段权限（sys_role_field控制字段可见/可编辑/隐藏）、权限方案（可复用的数据权限方案+字段权限方案）。
5. **角色继承与互斥**：子角色自动继承父角色全部权限；互斥角色约束（如采购员与审批人、出纳与会计）在用户角色分配时强制校验，同一用户不可同时拥有互斥角色。
6. **权限部门与组织架构部门分离**：sys_dept为权限部门（管用户数据权限），org_department为组织架构部门（管员工归属），两者独立维护但可通过映射关联。
7. **SSO/OAuth2初期实现配置管理**：P0阶段完成配置表的CRUD管理和前端配置页面，具体协议对接（SAML/OAuth2/CAS授权流程）在P2阶段按需扩展。
8. **登录日志异步写入**：登录成功/失败的日志记录必须异步写入sys_login_log，不阻塞登录主流程。
