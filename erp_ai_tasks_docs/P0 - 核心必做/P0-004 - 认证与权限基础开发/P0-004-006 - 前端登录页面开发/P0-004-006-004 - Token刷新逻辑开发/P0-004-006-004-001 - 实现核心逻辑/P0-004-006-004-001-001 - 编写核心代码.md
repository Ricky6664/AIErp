### 5.1 核心功能
1. 在Axios响应拦截器中检测401状态码，区分accessToken过期(TOKEN_EXPIRED=401001)和refreshToken过期
2. accessToken过期时调用POST /api/auth/token/refresh，传递refreshToken获取新Token对
3. 刷新成功：更新localStorage中的satoken和refresh_token，重放失败的原始请求
4. 刷新失败(refreshToken也过期)：清除所有Token，跳转到登录页
5. 实现刷新锁机制：并发多个请求同时401时，仅第一个触发刷新，其余请求进入等待队列
6. 刷新完成后依次重放队列中的请求

### 5.2 数据交互
**Token刷新请求**：`POST /api/auth/token/refresh`
```json
{ "refreshToken": "string" }
```
**刷新成功响应**：
```json
{ "code": 200, "data": { "token": "new-access-token", "refreshToken": "new-refresh-token", "expiresIn": 3600 } }
```
**Axios拦截器伪代码**：
```javascript
axios.interceptors.response.use(response => response, async error => {
  if (error.response?.data?.code === 401001) {
    // Token过期处理刷新逻辑
  }
});
```

### 5.3 关键逻辑
- **刷新锁(Refresh Lock)**：使用isRefreshing标志位+requestQueue数组实现；第一个401请求设置isRefreshing=true并发起刷新，后续401请求将resolve回调推入requestQueue；刷新完成后遍历requestQueue执行resolve
- **请求重放**：将失败请求的config保存，刷新成功后用新Token更新config.headers.satoken，再用axios(config)重新发送
- **refreshToken过期处理**：刷新接口返回REFRESH_TOKEN_EXPIRED时，清除所有Token和store状态，router.push('/login?redirect='+当前路径)
- **防止无限循环**：刷新请求本身(/api/auth/token/refresh)的401不触发再次刷新，直接跳转登录页
- **Token更新传播**：刷新成功后更新Pinia userStore中的token和localStorage中的satoken+refresh_token

### 5.4 验证
1. accessToken过期时自动刷新，用户无感知，原始请求正常返回
2. 并发5个请求同时触发401时，仅发送1次刷新请求，5个请求均被正确重放
3. refreshToken过期时跳转到登录页，携带redirect参数
4. 刷新请求本身失败时不触发无限循环
5. 刷新后新Token正确存入localStorage和Pinia store
