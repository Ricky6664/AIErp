## 五、详细开发规格


> **📦 本任务模块上下文**（来源：P0-004模块开发指南）

> - 本模块涉及API：/api/auth/login, /api/auth/logout, /api/auth/token/refresh, /api/auth/token/verify, /api/auth/user-info
> - 本模块业务规则：Sa-Token集成：所有登录认证必须通过Sa-Token框架实现，Token签发/注销/校验/续期均使用Sa-Token API，不允许自行实现Token机制。; 密码安全：用户密码必须使用BCrypt加密存储，不允许明文存储或可逆加密。密码策略配置（最小8位、大小写+数字+特殊字符四选三）由auth_password_policy表驱动。
>
> 💡 开发本任务时，请结合上述模块上下文理解业务场景和数据关系。
### 5.1 核心功能
1. 在Layout组件头部用户菜单中创建"退出登录"选项，绑定handleLogout事件
2. 点击退出时弹出ElMessageBox确认框("确定要退出登录吗？")，用户确认后执行退出逻辑
3. 调用POST /api/auth/logout接口通知后端注销Token
4. 清除Pinia userStore中的所有状态(token/userInfo/permissions/menuTree)
5. 清除localStorage中的satoken和refresh_token
6. 使用router.push('/login')跳转到登录页，携带redirect参数记录当前页面路径

### 5.2 数据交互
**退出请求**：`POST /api/auth/logout`（Header中携带satoken）
```json
// 响应
{ "code": 200, "message": "退出成功" }
```
**前端状态清理**：
- localStorage.removeItem('satoken')
- localStorage.removeItem('refresh_token')
- userStore.$reset() (Pinia store重置)
- permissionStore.$reset() (权限store重置)

### 5.3 关键逻辑
- **退出确认防误操作**：使用ElMessageBox.confirm()二次确认，取消操作不执行退出
- **接口调用容错**：logout接口调用失败(如Token已过期)时仍执行前端清理和跳转（不阻塞退出流程）
- **路由重定向参数**：退出跳转登录页时携带redirect=/当前页面路径，方便重新登录后跳回
- **WebSocket断开**：若项目有WebSocket连接，退出时主动关闭连接(ws.close())
- **动态路由清理**：退出时调用permissionStore.resetRoutes()清除动态添加的路由，防止下一用户看到上一用户的路由

### 5.4 验证
1. 点击退出弹出确认框，取消后不执行退出
2. 确认后成功退出并跳转到登录页，URL包含redirect参数
3. 退出后Pinia store和localStorage中的Token均已清除
4. 退出后浏览器直接访问系统页面被路由守卫拦截跳转到登录页
5. 退出接口调用失败时(如网络断开)仍能正常清理前端状态并跳转
