## 五、详细开发规格


> **📦 本任务模块上下文**（来源：P0-004模块开发指南）
> - 本模块涉及数据表：sys_user, sys_dept, sys_user_dept, sys_user_role, sys_user_group, sys_user_group_member, sys_user_group_role, sys_user_password_history, sys_role, sys_role_menu
> - 本模块涉及API：/api/auth/login, /api/auth/logout, /api/auth/token/refresh, /api/auth/token/verify, /api/auth/user-info
> - 本模块业务规则：Sa-Token集成：所有登录认证必须通过Sa-Token框架实现，Token签发/注销/校验/续期均使用Sa-Token API，不允许自行实现Token机制。; 密码安全：用户密码必须使用BCrypt加密存储，不允许明文存储或可逆加密。密码策略配置（最小8位、大小写+数字+特殊字符四选三）由auth_password_policy表驱动。
>
> 💡 开发本任务时，请结合上述模块上下文理解业务场景和数据关系。
### 5.1 核心功能
1. 创建useLogin组合式函数，封装登录API调用逻辑和状态管理(loading/error)
2. 调用POST /api/auth/login发送登录请求，传递username/password/captchaCode/captchaKey
3. 登录成功后将返回的token存入Pinia userStore(调用store.setToken)，同时存入localStorage持久化
4. 调用GET /api/auth/user-info获取用户信息和权限列表，存入Pinia userStore(avatar/nickname/permissions/menuTree)
5. 根据用户权限菜单树动态生成路由(addRoute)，跳转至目标页面(redirect参数或默认/dashboard)
6. 登录失败时处理不同错误类型：验证码过期/账户锁定/密码错误/账户禁用，显示对应ElMessage提示

### 5.2 数据交互
**登录请求**：`POST /api/auth/login`
```json
{ "username": "string", "password": "string", "captchaCode": "string", "captchaKey": "string" }
```
**登录响应**：
```json
{ "code": 200, "data": { "token": "string", "userId": "Long", "username": "string" } }
```
**用户信息请求**：`GET /api/auth/user-info`
```json
{ "code": 200, "data": { "userId": "Long", "nickname": "string", "avatar": "string", "menuTree": [], "permissions": ["system:user:add"] } }
```

### 5.3 关键逻辑
- **Token存储策略**：accessToken存入Pinia store + localStorage('satoken')，refreshToken存入localStorage('refresh_token')；Axios请求拦截器自动从localStorage读取token注入Header
- **错误码映射**：CAPTCHA_EXPIRED→"验证码已过期"、ACCOUNT_LOCKED→"账户已锁定，请{N}分钟后再试"、PASSWORD_ERROR→"用户名或密码错误"、ACCOUNT_DISABLED→"账户已禁用"、CAPTCHA_ERROR→"验证码错误"
- **动态路由生成**：登录成功后根据menuTree中type=menu的节点生成路由配置，使用router.addRoute()动态添加，按钮权限(permissionCode)存入permissions数组供v-permission指令使用
- **登录失败自动刷新验证码**：登录失败后自动调用refreshCaptcha()刷新验证码，清空验证码输入框
- **重定向处理**：登录成功后检查路由query.redirect参数，有则跳转到指定页面，无则跳转/dashboard

### 5.4 验证
1. 正确凭据登录后成功跳转至目标页面，Pinia store中token/userInfo/permissions均已填充
2. 密码错误时显示"用户名或密码错误"，验证码自动刷新
3. 账户锁定时显示"账户已锁定，请15分钟后再试"，不发送登录请求
4. Token正确存入localStorage，刷新页面后登录状态保持
5. 动态路由正确生成，无权限的菜单路由不可访问
