## 五、详细开发规格

> - 本模块涉及数据表：sys_user, sys_dept, sys_user_dept, sys_user_role, sys_user_group, sys_user_group_member, sys_user_group_role, sys_user_password_history, sys_role, sys_role_menu

> - 本模块业务规则：Sa-Token集成：所有登录认证必须通过Sa-Token框架实现，Token签发/注销/校验/续期均使用Sa-Token API，不允许自行实现Token机制。; 密码安全：用户密码必须使用BCrypt加密存储，不允许明文存储或可逆加密。密码策略配置（最小8位、大小写+数字+特殊字符四选三）由auth_password_policy表驱动。
>
> 💡 开发本任务时，请结合上述模块上下文理解业务场景和数据关系。
### 5.1 核心功能
1. 创建RoleController类，添加@RestController + @RequestMapping("/api/system/role")注解
2. 编写角色CRUD接口：GET分页查询角色列表、GET /{id}查询角色详情、POST新增角色、PUT /{id}修改角色、DELETE /{id}删除角色
3. 编写POST /menu角色菜单权限批量绑定，接收roleId+menuIdList+permissionType列表，事务内先删后插sys_role_menu
4. 编写GET /menu/{roleId}按角色查询菜单权限树，返回sys_menu树形结构+每个节点上该角色拥有的权限类型
5. 编写POST /data-scope角色数据权限配置，写入sys_role_data表（数据范围:全部/本部门/本部门及下级/仅本人/自定义）
6. 编写POST /field-permission角色字段权限配置，写入sys_role_field表（字段可见/可编辑/隐藏+页面状态add/edit/detail/all）
7. 编写POST /inheritance角色继承关系配置，写入sys_role_inheritance；POST /exclusion角色互斥关系配置，写入sys_role_exclusion
8. 编写数据权限方案CRUD（/api/system/data-permission-scheme）和字段权限方案CRUD（/api/system/field-permission-scheme）

### 5.2 数据交互
**角色菜单权限绑定请求**：`POST /api/system/role/menu`
```json
{ "roleId": "Long", "menuPermissions": [{ "menuId": "Long", "permissionTypes": ["view","add","edit","delete","audit"] }] }
```
**数据权限配置请求**：`POST /api/system/role/data-scope`
```json
{ "roleId": "Long", "dataScope": "custom", "customDeptIds": [1,2,3], "customUserIds": [10,20] }
```
**涉及数据表**：sys_role, sys_role_menu, sys_role_data, sys_role_field, sys_role_inheritance, sys_role_exclusion, sys_data_permission_scheme, sys_data_permission_scheme_detail, sys_field_permission_scheme, sys_field_permission_scheme_detail

### 5.3 关键逻辑
- **菜单权限批量绑定**：事务内先DELETE FROM sys_role_menu WHERE role_id=#{roleId}，再批量INSERT新权限记录；UNIQUE约束(role_id+menu_id+permission_type)防止重复
- **角色继承权限传递**：查询角色权限时递归查询sys_role_inheritance获取所有父角色ID，合并父角色权限（子角色自动拥有父角色全部权限）
- **角色互斥校验**：用户分配角色时查询sys_role_exclusion表，若角色A与角色B互斥，则同一用户不可同时拥有；分配时实时校验并拒绝
- **数据权限JSON存储**：自定义数据范围的部门ID列表和人员ID列表使用PostgreSQL jsonb类型存储(sys_role_data.custom_dept_ids/custom_user_ids)
- **权限方案复用**：数据权限方案和字段权限方案可绑定多个角色(sys_data_permission_scheme_role/sys_field_permission_scheme_role)，修改方案自动影响所有绑定角色

### 5.4 验证
1. 角色菜单权限绑定后sys_role_menu表记录正确，权限树接口返回完整的菜单树+权限标记
2. 角色继承关系中子角色查询权限时包含父角色的所有权限
3. 互斥角色(如采购员与审批人)无法分配给同一用户，返回互斥错误
4. 数据权限配置custom范围时，jsonb字段正确存储部门ID和人员ID数组
5. 权限方案修改后所有绑定角色的权限同步更新

## 八、易错警示

> ⚠️ Sa-Token的StpUtil.login(userId)中userId必须是唯一标识，建议使用Long类型用户ID

> ⚠️ 密码比对使用BCrypt.checkpw()，不要使用MD5/SHA等可逆或弱哈希算法

> ⚠️ 多租户隔离(tenant_id)由MyBatis-Plus TenantLineInnerInterceptor自动注入，不要手动拼接
