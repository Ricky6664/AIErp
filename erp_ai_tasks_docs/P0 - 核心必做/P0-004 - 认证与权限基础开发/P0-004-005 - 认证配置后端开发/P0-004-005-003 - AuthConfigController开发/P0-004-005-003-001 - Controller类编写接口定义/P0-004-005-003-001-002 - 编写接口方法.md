## 五、详细开发规格


> **📦 本任务模块上下文**（来源：P0-004模块开发指南）
> - 本模块涉及数据表：sys_user, sys_dept, sys_user_dept, sys_user_role, sys_user_group, sys_user_group_member, sys_user_group_role, sys_user_password_history, sys_role, sys_role_menu
> - 本模块涉及API：/api/auth/login, /api/auth/logout, /api/auth/token/refresh, /api/auth/token/verify, /api/auth/user-info
> - 本模块业务规则：Sa-Token集成：所有登录认证必须通过Sa-Token框架实现，Token签发/注销/校验/续期均使用Sa-Token API，不允许自行实现Token机制。; 密码安全：用户密码必须使用BCrypt加密存储，不允许明文存储或可逆加密。密码策略配置（最小8位、大小写+数字+特殊字符四选三）由auth_password_policy表驱动。
>
> 💡 开发本任务时，请结合上述模块上下文理解业务场景和数据关系。
### 5.1 核心功能
1. 创建AuthConfigController类，添加@RestController注解，管理认证方式/密码策略/在线设备三类接口
2. 编写认证方式CRUD：GET /api/system/auth-config分页查询、POST新增(方式名称/编码/类型[密码/短信/邮箱/LDAP/OAuth2/SAML]/配置JSON/优先级/启用状态)、PUT修改、DELETE删除
3. 编写密码策略管理：GET /api/system/password-policy查询策略列表、POST新增策略(最小长度/需含大写/小写/数字/特殊字符/过期天数/历史校验数/最大登录尝试次数/锁定时长)、PUT修改、DELETE删除
4. 编写在线设备管理：GET /api/system/online-device查询在线设备列表(用户ID/设备类型/设备名/OS/浏览器/IP/登录时间/最后活跃/状态)、POST /{tokenId}/kick强制下线设备
5. 编写认证配置工作台聚合接口：GET /api/system/auth-config/workbench，返回在线设备数/今日登录次数/失败次数/SSO配置数

### 5.2 数据交互
**密码策略请求**：`POST /api/system/password-policy`
```json
{ "name": "默认策略", "minLength": 8, "maxLength": 32, "requireUppercase": true, "requireLowercase": true, "requireDigit": true, "requireSpecialChar": true, "expireDays": 90, "historyCheckCount": 3, "maxLoginAttempts": 5, "lockDuration": 15, "enabled": true }
```
**强制下线请求**：`POST /api/system/online-device/{tokenId}/kick`
**涉及数据表**：auth_method, auth_password_policy, auth_online_device, auth_sso_config, auth_oauth2_config

### 5.3 关键逻辑
- **认证方式配置JSON**：auth_method.config字段使用PostgreSQL jsonb类型存储不同认证方式的专属配置（如LDAP的server/port/baseDN、OAuth2的scope等）
- **密码策略驱动校验**：登录密码校验和修改密码校验均从auth_password_policy表读取当前启用的策略，动态校验密码复杂度(四选三规则：大写+小写+数字+特殊字符至少满足三项)
- **强制下线实现**：调用StpUtil.kickoutByTokenValue(tokenId)使目标Token失效，同时更新auth_online_device状态为"已踢出"
- **在线设备状态管理**：设备状态包括online(在线)/offline(已下线)/kicked(已踢出)，通过定时任务(每5分钟)检查last_active_time超过30分钟的设备自动标记为offline
- **认证方式优先级**：auth_method.priority字段控制登录页面认证方式的显示顺序，优先级高的排在前面

### 5.4 验证
1. 认证方式CRUD操作正常，jsonb配置字段正确存储和读取
2. 密码策略修改后，用户修改密码时按新策略校验复杂度
3. 强制下线后目标设备Token失效，被踢出用户下次请求返回401并被引导到登录页
4. 在线设备列表正确显示当前在线/已下线/已踢出状态
5. 工作台聚合接口正确返回在线设备数/今日登录统计

## 八、易错警示

> ⚠️ Sa-Token的StpUtil.login(userId)中userId必须是唯一标识，建议使用Long类型用户ID

> ⚠️ 密码比对使用BCrypt.checkpw()，不要使用MD5/SHA等可逆或弱哈希算法

> ⚠️ 多租户隔离(tenant_id)由MyBatis-Plus TenantLineInnerInterceptor自动注入，不要手动拼接
