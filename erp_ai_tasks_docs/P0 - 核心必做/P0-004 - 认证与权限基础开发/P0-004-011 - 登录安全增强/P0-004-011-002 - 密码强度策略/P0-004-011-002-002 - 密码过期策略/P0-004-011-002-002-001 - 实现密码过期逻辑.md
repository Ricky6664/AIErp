>
> 💡 开发本任务时，请结合上述模块上下文理解业务场景和数据关系。
### 5.1 核心功能
1. 后端：在UserService中实现checkPasswordExpired(userId)方法，查询sys_user.password_expire_date判断是否过期
2. 后端：登录成功后调用checkPasswordExpired，过期则在LoginResponse中添加passwordExpired=true标记
3. 后端：创建PasswordExpireTask定时任务(每日凌晨)，扫描password_expire_date < 当前日期的用户，批量更新状态
4. 后端：密码修改时根据auth_password_policy.expire_days计算新的password_expire_date = 当前日期 + expire_days天
5. 前端：登录成功后检查passwordExpired标记，为true则强制跳转修改密码页面(/change-password)
6. 前端：修改密码页面不可跳过，修改成功后跳转至正常页面

### 5.2 数据交互
**登录响应增加字段**：
```json
{ "code": 200, "data": { "token": "xxx", "passwordExpired": true, "passwordExpireDate": "2026-05-20" } }
```
**密码修改请求**：`PUT /api/system/user/password`
```json
{ "oldPassword": "string", "newPassword": "string" }
```
**涉及数据表**：sys_user(password_expire_date字段), sys_user_password_history, auth_password_policy(expire_days字段)

### 5.3 关键逻辑
- **过期日期计算**：密码修改时password_expire_date = NOW() + auth_password_policy.expire_days天；expire_days=0表示永不过期
- **过期状态判断**：password_expire_date IS NOT NULL AND password_expire_date < CURRENT_DATE视为过期；expire_days=0时password_expire_date设为null(永不过期)
- **强制修改密码路由**：前端路由守卫检测到passwordExpired=true时，仅允许访问/change-password路由，其他路由重定向到修改密码页
- **新密码不可与旧密码相同**：修改密码时查询sys_user_password_history最近N条记录，BCrypt逐一比对，重复则拒绝
- **密码历史记录**：修改密码成功后将旧密码哈希写入sys_user_password_history表(user_id + password_hash + create_time)

### 5.4 验证
1. 密码过期用户登录后自动跳转到修改密码页面，无法访问其他页面
2. 修改密码成功后password_expire_date更新为当前日期+expire_days天
3. 新密码与最近3条历史密码重复时返回"不可使用近期使用过的密码"
4. expire_days=0(永不过期)时登录不跳转修改密码页
5. 定时任务正确扫描并标记密码过期用户

## 八、易错警示

> ⚠️ Sa-Token的StpUtil.login(userId)中userId必须是唯一标识，建议使用Long类型用户ID

> ⚠️ 密码比对使用BCrypt.checkpw()，不要使用MD5/SHA等可逆或弱哈希算法

> ⚠️ 多租户隔离(tenant_id)由MyBatis-Plus TenantLineInnerInterceptor自动注入，不要手动拼接
