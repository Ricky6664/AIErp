### 5.1 核心功能
1. 实现GET /api/auth/lock-status?username={username}接口：查询用户锁定状态和剩余锁定时间
2. 在LoginAttemptService中实现getLockStatus(username)：检查`login:lock:{username}`是否存在，存在则获取TTL计算剩余分钟数
3. 实现POST /api/auth/unlock/{username}管理员手动解锁接口：删除Redis中`login:fail:{username}`和`login:lock:{username}`两个Key
4. 前端登录页：输入用户名后(失焦或停止输入500ms)调用lock-status接口，锁定状态时在密码框上方显示锁定提示
5. 管理员在用户管理列表页可点击"解锁"按钮手动解锁被锁用户

### 5.2 数据交互
**锁定状态查询**：`GET /api/auth/lock-status?username=admin`
```json
// 锁定中
{ "code": 200, "data": { "locked": true, "remainingSeconds": 845, "remainingMinutes": 14 } }
// 未锁定
{ "code": 200, "data": { "locked": false, "remainingSeconds": 0, "remainingMinutes": 0 } }
```
**管理员解锁**：`POST /api/auth/unlock/{username}`
```json
{ "code": 200, "message": "用户admin已解锁" }
```

### 5.3 关键逻辑
- **剩余时间计算**：使用Redis TTL命令获取Key剩余秒数，除以60取整为分钟数；TTL=-2表示Key不存在(未锁定)
- **前端锁定提示**：el-alert type="warning"显示"该账户已被锁定，请{N}分钟后重试"，每分钟自动更新剩余时间(setInterval 60秒)
- **管理员解锁权限**：POST /api/auth/unlock接口需@SaCheckPermission("system:user:unlock")权限，仅管理员可操作
- **解锁操作审计**：管理员解锁操作写入操作日志(sys_operation_log)，记录操作人/被解锁用户/操作时间
- **批量解锁**：用户管理列表页提供"批量解锁"按钮，勾选多个被锁用户后批量调用解锁接口

### 5.4 验证
1. 锁定状态查询正确返回locked=true和剩余时间
2. 未锁定用户查询返回locked=false
3. 管理员解锁后用户可立即正常登录
4. 前端锁定提示每分钟自动更新剩余时间
5. 无解锁权限的管理员调用解锁接口返回权限不足错误
