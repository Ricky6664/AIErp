### 5.1 核心功能
1. 创建LoginAttemptService，使用Redis实现登录失败计数器
2. 实现incrementFailCount(username)：递增Redis Key `login:fail:{username}`，首次设置TTL=auth_password_policy.lock_duration分钟(默认15分钟)
3. 实现getFailCount(username)：获取当前失败次数
4. 实现isLocked(username)：检查失败次数是否≥auth_password_policy.max_login_attempts(默认5次)
5. 登录成功时调用resetFailCount(username)：删除Redis Key `login:fail:{username}`
6. 达到锁定阈值时设置Redis Key `login:lock:{username}` = "locked"，TTL=lock_duration分钟

### 5.2 数据交互
**Redis Key设计**：
| Key | Value | TTL | 用途 |
|-----|-------|-----|------|
| login:fail:{username} | Integer(失败次数) | lock_duration分钟 | 失败计数器 |
| login:lock:{username} | "locked" | lock_duration分钟 | 锁定标记 |

**登录流程调用**：
```java
// 登录前检查锁定
if (loginAttemptService.isLocked(username)) { throw new AccountLockedException(remainingLockTime); }
// 密码错误时递增
loginAttemptService.incrementFailCount(username);
// 登录成功时重置
loginAttemptService.resetFailCount(username);
```

### 5.3 关键逻辑
- **原子计数**：使用Redis INCR命令原子递增，避免并发登录导致计数不准确；INCR返回递增后的值，首次INCR自动创建Key并设为1
- **TTL设置策略**：每次失败时检查Key是否已有TTL，无TTL(首次失败)时设置EXPIRE；已有TTL时不重置(避免每次失败延长锁定时间)
- **锁定时间计算**：isLocked()返回锁定时，通过Redis TTL命令获取剩余锁定秒数，返回给前端显示"账户已锁定，请{N}分钟后再试"
- **锁定阈值动态读取**：max_login_attempts和lock_duration从auth_password_policy表读取当前启用的策略，管理员可动态调整
- **区分用户名/IP锁定**：当前仅按用户名锁定；可扩展为同时按IP锁定(同一IP连续失败N次锁定IP)，预留IP参数

### 5.4 验证
1. 连续输入错误密码5次后账户被锁定
2. 锁定期间即使输入正确密码也返回"账户已锁定"
3. 15分钟后锁定自动解除，可正常登录
4. 登录成功后失败计数器清零
5. 第4次失败后输入正确密码仍可登录(未达阈值)
