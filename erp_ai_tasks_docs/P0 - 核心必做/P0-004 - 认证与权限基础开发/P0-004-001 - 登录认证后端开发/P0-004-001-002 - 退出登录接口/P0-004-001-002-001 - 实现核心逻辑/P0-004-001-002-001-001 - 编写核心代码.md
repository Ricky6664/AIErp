### 5.1 核心功能
1. 在AuthController中编写logout方法，通过Sa-Token拦截器确认用户已登录状态
2. 调用StpUtil.getLoginIdAsLong()获取当前登录用户ID
3. 查询auth_online_device表找到当前会话对应的设备记录，更新状态为"已下线"
4. 调用StpUtil.logout()注销当前Token，清除Sa-Token Session中存储的权限标识列表
5. 清除Redis中该用户相关的缓存数据(如用户权限缓存user:permission:{userId}、菜单树缓存user:menu:{userId})
6. 异步写入sys_login_log登出时间，更新logout_time字段

### 5.2 数据交互
**请求**：`POST /api/auth/logout`（Header中携带satoken）
```json
// 无请求体，Token从Header中获取
```
**响应**：
```json
{ "code": 200, "message": "退出成功" }
```
**Token传递规范**：Header Key为`satoken`，前端Axios拦截器统一注入

### 5.3 关键逻辑
- **Token注销原子性**：先更新auth_online_device状态，再调用StpUtil.logout()，确保设备状态与Token状态一致
- **未登录容错处理**：若Token已过期或不存在，StpUtil.getLoginIdAsLong()抛出NotLoginException，捕获后仍返回成功（幂等退出）
- **多设备场景**：仅注销当前设备Token，不影响用户在其他设备的登录会话（使用StpUtil.logout(tokenValue)而非StpUtil.kickout）
- **缓存清理**：删除Redis Key `user:permission:{userId}` 和 `user:menu:{userId}`，确保下次登录重新加载权限

### 5.4 验证
1. 正常登录后调用退出接口，Token失效，后续请求返回401未登录
2. 重复调用退出接口不报错，返回200（幂等性）
3. 退出后auth_online_device表中对应设备状态更新为"已下线"
4. 退出后Redis中该用户权限缓存已清除
5. 用户A退出不影响用户B的登录状态

## 八、易错警示

> ⚠️ Sa-Token的StpUtil.login(userId)中userId必须是唯一标识，建议使用Long类型用户ID

> ⚠️ 密码比对使用BCrypt.checkpw()，不要使用MD5/SHA等可逆或弱哈希算法

> ⚠️ 多租户隔离(tenant_id)由MyBatis-Plus TenantLineInnerInterceptor自动注入，不要手动拼接
