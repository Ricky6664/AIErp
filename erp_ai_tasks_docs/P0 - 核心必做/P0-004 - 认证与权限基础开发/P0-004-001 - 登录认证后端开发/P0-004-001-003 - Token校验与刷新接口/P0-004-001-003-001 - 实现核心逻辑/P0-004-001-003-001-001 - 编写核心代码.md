### 5.1 核心功能
1. 实现token/verify接口，调用StpUtil.checkLogin()校验当前Token有效性，有效则自动续期（Sa-Token activity-timeout机制）
2. 实现token/refresh接口，接收refreshToken参数，校验refreshToken合法性后签发新的accessToken+refreshToken对
3. 刷新Token时调用StpUtil.replaced(oldToken, newToken)实现平滑替换，旧Token在5秒宽限期内仍可使用
4. 更新auth_online_device表的last_active_time字段为当前时间
5. Token过期时返回特定错误码TOKEN_EXPIRED=401001，前端根据错误码触发自动刷新逻辑

### 5.2 数据交互
**Token校验**：`GET /api/auth/token/verify`（Header中携带satoken）
```json
{ "code": 200, "data": { "valid": true, "userId": "Long", "expireInSeconds": 1800 } }
```
**Token刷新**：`POST /api/auth/token/refresh`
```json
// 请求
{ "refreshToken": "string" }
// 响应
{ "code": 200, "data": { "token": "string", "refreshToken": "string", "expiresIn": 3600 } }
```
**双Token机制**：accessToken有效期30min，refreshToken有效期7天，refreshToken使用独立Redis Key `refresh:token:{value}` 存储

### 5.3 关键逻辑
- **Sa-Token自动续期**：通过sa-token配置`activity-timeout=1800`实现最后活跃超时自动过期，每次有效请求自动续期
- **双Token刷新策略**：accessToken过期时用refreshToken换取新Token对，refreshToken一次性使用后失效（防止Token泄露重放）
- **Token替换宽限期**：使用Sa-Token的replaced机制，旧Token在5秒宽限期内仍有效，避免并发请求因Token刷新全部失败
- **设备活跃时间更新**：每次Token校验/刷新时更新auth_online_device.last_active_time，用于在线设备管理

### 5.4 验证
1. 有效Token调用verify返回valid=true及剩余有效秒数
2. 过期Token调用verify返回TOKEN_EXPIRED错误码
3. 使用有效refreshToken刷新后获得新Token对，旧refreshToken立即失效
4. 使用已失效的refreshToken刷新返回REFRESH_TOKEN_EXPIRED错误码
5. Token刷新后auth_online_device.last_active_time更新为当前时间

## 八、易错警示

> ⚠️ Sa-Token的StpUtil.login(userId)中userId必须是唯一标识，建议使用Long类型用户ID

> ⚠️ 密码比对使用BCrypt.checkpw()，不要使用MD5/SHA等可逆或弱哈希算法

> ⚠️ 多租户隔离(tenant_id)由MyBatis-Plus TenantLineInnerInterceptor自动注入，不要手动拼接
