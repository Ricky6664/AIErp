### 5.1 核心功能
1. 在src/router/permission.js中创建全局前置守卫router.beforeEach((to, from, next) => {...})
2. 白名单路由(/login, /404, /403)直接放行，无需登录校验
3. 检查localStorage中是否存在satoken：无token则重定向到/login?redirect=to.fullPath
4. 有token但userStore中无用户信息时，调用GET /api/auth/user-info获取用户信息+权限列表+菜单树
5. 根据菜单树动态生成路由(permissionStore.generateRoutes(menuTree))，使用router.addRoute()添加动态路由
6. 动态路由添加后使用next({ ...to, replace: true })重新导航，确保新路由生效
7. 已有用户信息时校验当前路由是否在权限路由列表中，无权限则跳转/403页面

### 5.2 数据交互
**路由守卫流程**：
```
请求路由 → 白名单? → 有Token? → 有用户信息? → 有路由权限? → 放行
                ↓        ↓          ↓              ↓
              放行    →登录页   →获取用户信息   →/403页面
                              →生成动态路由
```
**Pinia Store交互**：
- userStore: token / userInfo / permissions
- permissionStore: routes(动态路由列表) / addRoutes(已添加的路由)

### 5.3 关键逻辑
- **NProgress进度条**：路由守卫开始时NProgress.start()，afterEach中NProgress.done()，提供页面切换加载进度条
- **动态路由只添加一次**：使用permissionStore.addRoutes标志位判断是否已添加，避免重复addRoute
- **Token有效性校验**：获取用户信息接口返回401时，说明Token已失效，清除本地Token跳转登录页
- **页面标题设置**：路由守卫afterEach中根据to.meta.title设置document.title，格式为"页面标题 - ERP管理系统"
- **路由元信息(meta)**：动态路由生成时设置meta: { title, icon, permission, keepAlive }，keepAlive控制页面缓存

### 5.4 验证
1. 未登录访问系统页面自动跳转到/login?redirect=原路径
2. 登录后根据权限动态生成路由，无权限的页面跳转/403
3. 白名单页面(登录页)未登录也可正常访问
4. 刷新页面后动态路由重新生成，用户信息和权限保持
5. Token过期后访问任何页面跳转登录页
