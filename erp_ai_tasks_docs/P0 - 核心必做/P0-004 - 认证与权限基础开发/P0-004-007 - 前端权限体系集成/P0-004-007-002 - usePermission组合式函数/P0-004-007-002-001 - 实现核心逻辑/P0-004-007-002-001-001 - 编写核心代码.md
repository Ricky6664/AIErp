### 5.1 核心功能
1. 创建src/composables/usePermission.js组合式函数，导出hasPermission、hasRole、hasAnyPermission方法
2. hasPermission(permissionCode)：从Pinia userStore.permissions数组中查找是否包含指定permissionCode，返回boolean
3. hasAnyPermission(permissionCodes[])：传入权限标识数组，任意一个匹配即返回true
4. hasRole(roleCode)：从userStore.roles中查找是否包含指定角色编码
5. 创建v-permission自定义指令：在元素mounted时调用hasPermission，无权限则el.parentNode.removeChild(el)移除DOM元素
6. 创建v-role自定义指令：同理基于角色编码控制元素显隐

### 5.2 数据交互
**组合式函数使用方式**：
```javascript
import { usePermission } from '@/composables/usePermission'
const { hasPermission, hasAnyPermission } = usePermission()
// 模板中使用
// <el-button v-if="hasPermission('system:user:add')">新增用户</el-button>
```
**自定义指令使用方式**：
```html
<el-button v-permission="'system:user:edit'">编辑</el-button>
<el-button v-permission="['system:user:add','system:user:edit']">操作</el-button>
```
**数据来源**：userStore.permissions → 登录时从GET /api/auth/user-info返回的permissionCode列表

### 5.3 关键逻辑
- **权限标识格式**：`模块:资源:操作`，如system:user:add、system:role:delete、wms:warehouse:edit
- **v-permission vs v-if区别**：v-permission在mounted阶段直接移除DOM元素(比v-if更彻底，防止通过DevTools修改显示)；但对于需要动态切换权限的场景推荐使用v-if+hasPermission
- **superadmin绕过**：角色编码为superadmin的用户拥有所有权限，hasPermission直接返回true，无需逐一匹配
- **权限数据缓存**：permissions数组存储在Pinia store中，hasPermission仅做数组includes查找，时间复杂度O(n)，权限标识数量通常<200，性能可接受
- **指令更新处理**：v-permission指令的updated钩子中重新校验权限，支持权限动态变更后更新DOM显隐

### 5.4 验证
1. hasPermission('system:user:add')在有权限时返回true，无权限时返回false
2. v-permission指令正确移除无权限的按钮DOM元素
3. superadmin角色用户所有按钮均可见
4. hasAnyPermission(['system:user:add','system:user:edit'])任一匹配返回true
5. 权限变更后(管理员修改角色权限)重新登录，按钮显隐正确更新
