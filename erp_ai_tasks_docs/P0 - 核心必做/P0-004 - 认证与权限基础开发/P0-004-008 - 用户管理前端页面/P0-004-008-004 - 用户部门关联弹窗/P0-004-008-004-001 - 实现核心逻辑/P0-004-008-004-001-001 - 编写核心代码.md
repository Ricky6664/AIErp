## 五、详细开发规格

> - 本模块业务规则：Sa-Token集成：所有登录认证必须通过Sa-Token框架实现，Token签发/注销/校验/续期均使用Sa-Token API，不允许自行实现Token机制。; 密码安全：用户密码必须使用BCrypt加密存储，不允许明文存储或可逆加密。密码策略配置（最小8位、大小写+数字+特殊字符四选三）由auth_password_policy表驱动。
>

### 5.1 核心功能
1. 创建UserDeptDialog.vue弹窗组件，使用el-dialog(中尺寸width:600px)展示部门关联界面
2. 弹窗打开时加载用户当前关联部门(GET /api/system/user/{userId}获取deptIds+primaryDeptId)
3. 左侧展示权限部门树(sys_dept)使用el-tree组件，支持checkbox多选，加载GET /api/system/dept/tree
4. 右侧展示已选部门列表，支持通过radio标记主部门
5. 保存时调用POST /api/system/user/dept批量关联部门，传递userId+deptIds+primaryDeptId
6. 主部门必须在已选部门列表中，切换已选部门时自动更新主部门选项

### 5.2 数据交互
**部门关联请求**：`POST /api/system/user/dept`
```json
{ "userId": "Long", "deptIds": [1, 2, 3], "primaryDeptId": 1 }
```
**组件Props/Events**：
- Props: visible(boolean), userId(number), username(string)
- Emits: update:visible, success(关联成功后刷新)
**部门树数据**：`GET /api/system/dept/tree`返回树形结构(id/name/children)

### 5.3 关键逻辑
- **el-tree半选处理**：使用el-tree的check-strictly=false模式，勾选父节点自动勾选子节点；获取选中节点时同时获取半选节点(getCheckedKeys+getHalfCheckedKeys)
- **主部门约束**：主部门必须在已选部门列表中；取消勾选包含主部门的节点时弹出提示"请先更换主部门"
- **部门与组织架构分离**：此处使用的是sys_dept(权限部门)，非org_department(组织架构部门)；权限部门用于控制用户的数据权限范围
- **保存确认**：变更部门关联时弹出确认框("确定修改用户{username}的部门关联？")
- **清除关联**：提供"清除全部"按钮，调用DELETE /api/system/user/dept/{userId}清除所有部门关联

### 5.4 验证
1. 弹窗正确显示用户当前关联的部门(树节点已勾选)
2. 主部门标记正确，切换已选部门时主部门radio同步更新
3. 保存后sys_user_dept表更新正确，主部门标记正确
4. 取消勾选主部门所在节点时提示先更换主部门
5. 清除全部关联后用户无任何部门关联记录
