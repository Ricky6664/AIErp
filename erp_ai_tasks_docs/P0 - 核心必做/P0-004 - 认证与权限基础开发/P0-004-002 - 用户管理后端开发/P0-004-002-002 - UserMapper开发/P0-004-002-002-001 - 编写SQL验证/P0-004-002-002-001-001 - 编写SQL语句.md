### 5.1 核心功能
1. 创建UserMapper接口继承BaseMapper<SysUser>，标注@Mapper注解
2. 编写自定义SQL：用户列表分页查询（LEFT JOIN hrm_employee ON employee_id获取员工姓名）
3. 编写用户名唯一性校验SQL：SELECT COUNT(*) FROM sys_user WHERE username=#{username} AND is_deleted=0 AND id!=#{excludeId}
4. 编写用户密码历史查询SQL：SELECT password_hash FROM sys_user_password_history WHERE user_id=#{userId} ORDER BY create_time DESC LIMIT #{historyCount}
5. 编写按部门查询用户列表SQL：通过sys_user_dept关联表查询指定部门下的用户
6. 编写用户角色关联查询SQL：LEFT JOIN sys_user_role + sys_role获取用户角色名称列表
7. 在UserMapper.xml中编写所有自定义SQL，确保使用#{param}参数化防SQL注入

### 5.2 数据交互
**用户列表分页查询SQL**：
```sql
SELECT u.*, e.employee_name FROM sys_user u
LEFT JOIN hrm_employee e ON u.employee_id = e.id
WHERE u.is_deleted = 0 AND u.tenant_id = #{tenantId}
<if test="keyword != null">AND (u.username LIKE CONCAT('%',#{keyword},'%') OR u.nickname LIKE CONCAT('%',#{keyword},'%'))</if>
<if test="status != null">AND u.status = #{status}</if>
ORDER BY u.create_time DESC
```
**涉及数据表**：sys_user, sys_user_dept, sys_user_role, sys_role, sys_user_password_history, hrm_employee

### 5.3 关键逻辑
- **MyBatis-Plus BaseMapper复用**：基础CRUD直接使用BaseMapper方法(insert/updateById/selectById/deleteById)，仅复杂查询编写自定义SQL
- **多租户隔离**：所有SQL通过MyBatis-Plus TenantLineInnerInterceptor自动追加tenant_id条件，无需手动编写
- **逻辑删除**：使用is_deleted字段(0=正常,1=已删除)，所有查询自动过滤已删除记录（MyBatis-Plus @TableLogic注解）
- **密码历史校验**：修改密码时查询最近N条(由auth_password_policy.history_check_count配置)历史密码，使用BCrypt.checkpw逐一比对，禁止重复使用
- **UNIQUE约束**：sys_user表的username字段设置UNIQUE索引，数据库层面防止用户名重复

### 5.4 验证
1. 分页查询返回正确的用户列表数据，包含关联的员工姓名
2. 用户名唯一性校验SQL在新增和修改场景均正确返回重复/不重复结果
3. 密码历史查询返回最近N条密码哈希记录，按时间倒序
4. 按部门查询正确返回该部门下所有用户（通过sys_user_dept关联）
5. 所有SQL均使用#{param}参数化，无SQL注入风险
