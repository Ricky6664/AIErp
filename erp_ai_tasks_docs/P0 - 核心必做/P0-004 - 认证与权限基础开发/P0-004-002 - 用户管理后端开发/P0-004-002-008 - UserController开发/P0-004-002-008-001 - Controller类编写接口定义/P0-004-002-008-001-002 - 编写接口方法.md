## 五、详细开发规格


> **📦 本任务模块上下文**（来源：P0-004模块开发指南）
> - 本模块涉及数据表：sys_user, sys_dept, sys_user_dept, sys_user_role, sys_user_group, sys_user_group_member, sys_user_group_role, sys_user_password_history, sys_role, sys_role_menu
> - 本模块涉及API：/api/auth/login, /api/auth/logout, /api/auth/token/refresh, /api/auth/token/verify, /api/auth/user-info
> - 本模块业务规则：Sa-Token集成：所有登录认证必须通过Sa-Token框架实现，Token签发/注销/校验/续期均使用Sa-Token API，不允许自行实现Token机制。; 密码安全：用户密码必须使用BCrypt加密存储，不允许明文存储或可逆加密。密码策略配置（最小8位、大小写+数字+特殊字符四选三）由auth_password_policy表驱动。
>
> 💡 开发本任务时，请结合上述模块上下文理解业务场景和数据关系。
### 5.1 核心功能
1. 创建UserController类，添加@RestController + @RequestMapping("/api/system/user")注解
2. 编写GET /api/system/user分页查询接口，接收UserQueryDTO(pageNum/pageSize/keyword/status/deptId)，调用UserService.pageQuery
3. 编写GET /api/system/user/{id}查询用户详情，返回用户信息+角色列表+部门列表
4. 编写POST /api/system/user新增用户，接收UserCreateDTO，校验用户名唯一性，BCrypt加密密码，写入sys_user
5. 编写PUT /api/system/user/{id}修改用户，校验角色互斥关系(sys_role_exclusion)，更新用户信息
6. 编写DELETE /api/system/user/{id}软删除用户（逻辑删除is_deleted=1），同时清除用户角色和部门关联
7. 编写POST /api/system/user/{id}/reset-password管理员重置密码（生成随机密码+BCrypt加密+返回新密码）
8. 编写PUT /api/system/user/password用户自行修改密码（旧密码校验+密码策略校验+密码历史校验）
9. 编写POST /api/system/user/role批量分配角色、DELETE /api/system/user/role/{userId}清除角色

### 5.2 数据交互
**新增用户请求**：`POST /api/system/user`
```json
{ "username": "string", "password": "string", "nickname": "string", "email": "string", "phone": "string", "deptIds": [1,2], "roleIds": [1,2], "status": "normal" }
```
**分页查询响应**：
```json
{ "code": 200, "data": { "records": [{ "id": "Long", "username": "string", "nickname": "string", "status": "string", "deptNames": [], "roleNames": [] }], "total": 100, "pageNum": 1, "pageSize": 20 } }
```
**涉及API**：/api/system/user (GET/POST), /api/system/user/{id} (GET/PUT/DELETE), /api/system/user/{id}/reset-password, /api/system/user/password, /api/system/user/role

### 5.3 关键逻辑
- **用户名唯一性**：新增时校验username不重复，修改时校验排除自身后不重复（数据库UNIQUE约束+代码双重校验）
- **密码BCrypt加密**：新增/重置/修改密码均使用BCrypt.hashpw(password, BCrypt.gensalt(12))生成哈希，strength=12
- **角色互斥校验**：分配角色时查询sys_role_exclusion表，校验新分配的角色列表是否存在互斥对(如采购员与审批人、出纳与会计)，存在则拒绝并返回互斥角色名称
- **管理员重置密码**：生成8位随机密码(大小写+数字+特殊字符)，BCrypt加密后存入sys_user，同时将旧密码写入sys_user_password_history
- **权限控制**：所有接口添加@SaCheckPermission注解，如@SaCheckPermission("system:user:add")，由Sa-Token校验当前用户是否有对应权限标识

### 5.4 验证
1. 新增用户后sys_user表有记录，密码为BCrypt哈希格式（$2a$12$开头）
2. 用户名重复时返回"用户名已存在"错误，不写入数据库
3. 分配互斥角色时返回"角色互斥：采购员与审批人不可同时分配"错误
4. 管理员重置密码后返回新密码明文，用户可用新密码登录
5. 修改密码时旧密码错误返回"原密码不正确"，新密码与最近3条历史密码重复时返回"不可使用近期使用过的密码"

## 八、易错警示

> ⚠️ Sa-Token的StpUtil.login(userId)中userId必须是唯一标识，建议使用Long类型用户ID

> ⚠️ 密码比对使用BCrypt.checkpw()，不要使用MD5/SHA等可逆或弱哈希算法

> ⚠️ 多租户隔离(tenant_id)由MyBatis-Plus TenantLineInnerInterceptor自动注入，不要手动拼接
