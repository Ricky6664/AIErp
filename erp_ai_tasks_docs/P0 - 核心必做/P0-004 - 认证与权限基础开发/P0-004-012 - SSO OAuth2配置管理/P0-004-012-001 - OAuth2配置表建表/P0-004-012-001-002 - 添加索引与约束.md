### 5.1 核心功能
1. 为auth_oauth2_config表添加索引：supplier_name唯一索引(同一供应商不可重复配置)、type+enabled复合索引(按类型查询启用的OAuth2配置)
2. 为auth_sso_config表添加索引：sso_name唯一索引、type+enabled复合索引
3. 为auth_online_device表添加索引：user_id+status复合索引(查询用户在线设备)、session_token_id唯一索引(通过Token定位设备)、last_active_time索引(定时清理过期设备)
4. 为sys_login_log表添加索引：user_id+login_time复合索引(按用户查询登录历史)、login_time索引(按时间范围查询)、ip_address索引(按IP查询)
5. 编写Flyway迁移脚本V{version}__add_auth_indexes.sql，确保幂等执行

### 5.2 数据交互
**auth_oauth2_config索引**：
```sql
CREATE UNIQUE INDEX uk_oauth2_supplier ON auth_oauth2_config(supplier_name) WHERE is_deleted = 0;
CREATE INDEX idx_oauth2_type_enabled ON auth_oauth2_config(type, enabled) WHERE is_deleted = 0;
```
**auth_sso_config索引**：
```sql
CREATE UNIQUE INDEX uk_sso_name ON auth_sso_config(sso_name) WHERE is_deleted = 0;
CREATE INDEX idx_sso_type_enabled ON auth_sso_config(type, enabled) WHERE is_deleted = 0;
```
**auth_online_device索引**：
```sql
CREATE INDEX idx_device_user_status ON auth_online_device(user_id, status) WHERE is_deleted = 0;
CREATE UNIQUE INDEX uk_device_token ON auth_online_device(session_token_id) WHERE is_deleted = 0;
CREATE INDEX idx_device_active_time ON auth_online_device(last_active_time);
```

### 5.3 关键逻辑
- **部分索引(WHERE is_deleted=0)**：PostgreSQL支持部分索引，仅对未删除记录建索引，减少索引体积，同时确保逻辑删除的记录不参与唯一约束
- **UNIQUE索引与软删除兼容**：使用WHERE is_deleted=0的部分唯一索引，已删除记录不影响唯一性校验
- **索引命名规范**：唯一索引uk_{表名缩写}_{字段名}、普通索引idx_{表名缩写}_{字段名}
- **Flyway幂等迁移**：使用CREATE INDEX IF NOT EXISTS / DROP INDEX IF EXISTS确保迁移脚本可重复执行
- **索引性能分析**：使用EXPLAIN ANALYZE验证索引生效，确保关键查询使用索引扫描(Index Scan)而非全表扫描(Seq Scan)

### 5.4 验证
1. 所有索引正确创建，\di命令可查看索引列表
2. 部分唯一索引：已删除记录的同名供应商可重新创建，未删除的不可重复
3. EXPLAIN ANALYZE查询auth_online_device按user_id+status查询时使用索引扫描
4. Flyway迁移脚本重复执行不报错(IF NOT EXISTS)
5. sys_login_log按login_time范围查询使用索引，查询性能<100ms(10万条数据)

## 八、易错警示

> ⚠️ Sa-Token的StpUtil.login(userId)中userId必须是唯一标识，建议使用Long类型用户ID

> ⚠️ 密码比对使用BCrypt.checkpw()，不要使用MD5/SHA等可逆或弱哈希算法

> ⚠️ 多租户隔离(tenant_id)由MyBatis-Plus TenantLineInnerInterceptor自动注入，不要手动拼接
