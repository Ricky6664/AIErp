## 1. 模块架构约束

### 1.1 模块定位
P0-010负责开发ERP系统的仓库与库位管理功能，包括仓库定义（实体/虚拟/委外仓库）和库位管理（存储/拣货/暂存/不良品库位）。本模块为库存管理（P1-007）及所有出入库业务（销售出库、采购入库、生产入库/领料、委外收发）提供基础数据支撑。

### 1.2 依赖关系
- 前置依赖：
  - P0-001（后端框架）
  - P0-002（前端框架）
  - P0-003（数据库提供inv_warehouse/inv_location表）
  - P0-004（认证与权限）
  - P0-005（公共组件提供页面基座/选择器）
  - P0-006（组织架构提供部门/员工数据——仓管员引用）
  - P0-007（商品管理提供商品数据——库存关联）
- 后续依赖：
  - P1-007（库存管理）——引用仓库/库位数据
  - P1-005（销售管理-出库）——引用仓库/库位
  - P1-006（采购管理-入库）——引用仓库/库位
  - P1-008（生产入库/领料）——引用仓库/库位
  - P1-009（委外收发）——引用仓库/库位

### 1.3 技术约束
- **技术栈约束**：Spring Boot 3.4.x + MyBatis-Plus 3.5.5 + Redis（工作台缓存）+ Vue3 + Element Plus + Vxe Table
- **性能约束**：仓库/库位列表查询 < 100ms；工作台聚合查询使用@Cacheable缓存（TTL=5min，命中率≥90%）
- **安全约束**：仓库编码全局唯一；库位编码在同一仓库内唯一；删除操作需校验关联数据

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| inv_warehouse | 仓库表 | warehouse_code, warehouse_name, warehouse_type(实体/虚拟/委外), address, manager_id, is_enabled |
| inv_location | 库位表 | warehouse_id, location_code, location_name, location_type(存储/拣货/暂存/不良品), sort_order, is_enabled |

### 2.2 表关系图
- `inv_warehouse` 1:N `inv_location`：一个仓库下包含多个库位
- `inv_warehouse` N:1 `hrm_employee`（manager_id）：仓库负责人引用员工表
- `inv_warehouse`被引用关系：inv_stock（库存实时表）引用warehouse_id，所有出入库单据引用warehouse_id
- `inv_location`被引用关系：inv_stock_location（库位库存表）引用location_id，doc_detail_location引用location_id

### 2.3 数据流转
1. **仓库新增流程**：填写仓库信息 → 编码引擎生成仓库编码 → 全局唯一性校验 → 选择仓管员 → 保存仓库 → 可继续维护库位
2. **库位新增流程**：选择仓库 → 填写库位信息 → 编码引擎生成库位编码 → 仓库范围内唯一性校验 → 保存库位
3. **工作台聚合流程**：查询仓库总数/库位总数/库存预警数/本月出入库汇总 → Redis缓存命中返回 → 未命中则查库并缓存（TTL=5min）

## 3. 业务流程

### 3.1 核心业务流程
1. **仓库库位后端开发**（P0-010-001）：
   - 仓库CRUD（含仓库编码全局唯一性校验）
   - 库位CRUD（含所属仓库关联+库位编码仓库范围内唯一性校验）
   - 仓库删除关联校验（校验库位/库存/在途单据，存在时禁止删除并返回关联清单）
   - 库位删除关联校验（校验库位库存记录，存在时禁止删除）
   - 全部启用仓库查询接口（供下拉选择器使用）
   - 按仓库ID查询库位列表接口（供下拉选择器使用）
   - 仓库管理工作台聚合接口（含@Cacheable缓存策略）
2. **仓库库位前端页面**（P0-010-002）：
   - 仓库管理工作台（P02：KPI卡片+仓库利用率图表+出入库趋势+预警分布）
   - 仓库定义列表页（P04）+ 新增/编辑表单（P07弹窗中）
   - 库位管理列表页（P04）+ 新增/编辑表单（P07弹窗中）

### 3.2 业务规则
- **仓库编码唯一性**：仓库编码在系统内全局唯一，编码生成需在事务内完成，禁止并发重复
- **库位编码唯一性**：库位编码在同一仓库内唯一，新增/修改时需进行仓库范围内唯一性校验
- **仓库删除关联校验**：删除仓库前需校验该仓库下是否存在库位、库存、在途单据，存在时禁止删除并返回关联数据清单
- **库位删除关联校验**：删除库位前需校验该库位是否存在库存记录，存在时禁止删除
- **工作台聚合性能**：聚合查询使用@Cacheable缓存策略，缓存TTL=5min，缓存命中率≥90%
- **仓库利用率计算**：仓库利用率 = 已用库位数 / 总库位数 × 100%，保留2位小数，总库位数为0时返回0%

### 3.3 状态流转
- **仓库启用状态**：启用(enabled) ↔ 禁用(disabled)，禁用后不可被新单据引用，已有库存不受影响
- **库位启用状态**：启用(enabled) ↔ 禁用(disabled)，禁用后不可被新出入库操作引用

## 4. 接口契约

### 4.1 对外接口
| 接口路径 | 方法 | 说明 |
|---------|------|------|
| /api/warehouse/warehouse | GET | 分页查询仓库列表 |
| /api/warehouse/warehouse/{id} | GET | 查询仓库详情 |
| /api/warehouse/warehouse | POST | 新增仓库（含编码唯一性校验） |
| /api/warehouse/warehouse/{id} | PUT | 修改仓库 |
| /api/warehouse/warehouse/{id} | DELETE | 删除仓库（含关联校验） |
| /api/warehouse/warehouse/all | GET | 查询全部启用仓库（下拉选择器用） |
| /api/warehouse/location | GET | 分页查询库位列表 |
| /api/warehouse/location/{id} | GET | 查询库位详情 |
| /api/warehouse/location | POST | 新增库位（含仓库关联+编码唯一性校验） |
| /api/warehouse/location/{id} | PUT | 修改库位 |
| /api/warehouse/location/{id} | DELETE | 删除库位（含库存关联校验） |
| /api/warehouse/location/by-warehouse/{warehouseId} | GET | 按仓库ID查询库位列表（下拉选择器用） |
| /api/warehouse/workbench | GET | 仓库管理工作台聚合数据 |

### 4.2 依赖接口
- `/api/code/generate`（P0-001编码引擎）——生成仓库/库位编码
- `/api/hrm/employee/all`（P0-012 HRM）——员工数据（仓管员选择）
- `/api/system/dict/data/by-code/{dictTypeCode}`（P0-005字典组件）——仓库类型/库位类型下拉
- P0-005提供的仓库选择器/库位选择器/职员选择器
- P0-005提供的P02/P04/P07页面类型基座组件

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **P0-010-001 仓库库位后端开发**（前端依赖后端接口）
2. **P0-010-001** → **P0-010-002 仓库库位前端页面**

后端内部开发顺序：
1. 仓库CRUD（库位依赖仓库表）
2. 库位CRUD（依赖仓库表外键）
3. 工作台聚合接口（依赖仓库+库位+库存数据）

### 5.2 可并行执行的任务
- 仓库CRUD和库位CRUD的后端开发可在仓库表创建后快速衔接（库位仅依赖仓库表外键）
- 前端页面中仓库定义页面和库位管理页面可并行开发
- 工作台页面可在仓库和库位管理页面完成后快速集成
