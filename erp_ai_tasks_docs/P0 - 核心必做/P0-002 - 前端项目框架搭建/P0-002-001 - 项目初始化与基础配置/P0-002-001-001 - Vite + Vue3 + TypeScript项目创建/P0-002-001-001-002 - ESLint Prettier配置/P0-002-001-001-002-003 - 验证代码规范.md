## 五、详细开发规格

> **📦 验证任务说明**
> 本任务为验证任务，需逐项验证前置任务（安装ESLint+Prettier依赖+编写配置、配置VSCode设置）的交付物是否符合规格。

### 5.1 验证清单
| 序号 | 验证项 | 预期结果 | 验证方法 |
|:---:|--------|---------|---------|
| 1 | `pnpm lint` 执行 | 无配置加载报错，可正常扫描 `.vue/.ts` 文件 | 执行 `pnpm lint` 检查退出码 |
| 2 | `pnpm format` 执行 | 所有文件被 Prettier 格式化 | 执行 `pnpm format` 后 `git diff` 查看格式化变更 |
| 3 | ESLint 检测规范问题 | 故意写一个 `var` 声明，ESLint 报 `no-var` 错误 | 创建测试文件后执行 `pnpm lint` |
| 4 | Prettier 格式化一致性 | 保存文件后自动移除分号、转换双引号为单引号 | VSCode 中保存 `.ts` 文件观察格式变化 |
| 5 | VSCode 保存自动修复 | 保存时自动修复 ESLint 可修复项 | 故意留尾逗号后保存，确认自动删除 |
| 6 | .eslintignore 生效 | dist/ 和 node_modules/ 下文件不被扫描 | 执行 `pnpm lint --debug` 确认忽略路径 |
| 7 | .prettierignore 生效 | pnpm-lock.yaml 不被格式化 | 执行 `pnpm format` 后检查 lock 文件未变更 |

### 5.2 测试方法
1. **命令行验证**：
   - 执行 `pnpm lint`，确认退出码为 0 或仅有可修复 warning
   - 执行 `pnpm format`，确认格式化覆盖 src/ 下所有 `.vue/.ts/.tsx/.css/.scss/.json` 文件
2. **编辑器验证**：
   - VSCode 打开项目，确认 ESLint 扩展状态栏图标为绿色（激活状态）
   - 新建 `test.ts` 输入 `var x = 1;`，保存后自动变为 `const x = 1`（ESLint auto-fix + Prettier）
   - 检查 Problems 面板是否有实时 ESLint 提示
3. **忽略规则验证**：
   - 在 dist/ 目录放一个不规范的 `.js` 文件，执行 `pnpm lint` 确认不被扫描

### 5.3 问题处理
- **pnpm lint 报配置加载错误**：检查 `.eslintrc.cjs` 文件是否存在、`extends` 中引用的包是否已安装
- **编辑器中 ESLint 不生效**：确认 VSCode 已安装 ESLint 扩展、`eslint.validate` 包含 `vue` 和 `typescript`
- **格式化后代码仍有分号**：检查 `.prettierrc` 中 `semi: false` 是否正确、`.vscode/settings.json` 中 `defaultFormatter` 是否指向 Prettier
- **忽略规则不生效**：检查 `.eslintignore`/`.prettierignore` 文件路径格式（不要加 `./` 前缀）

## 七、验收标准

| 序号 | 检查项 | 验证方法 |
|:---:|--------|---------|
