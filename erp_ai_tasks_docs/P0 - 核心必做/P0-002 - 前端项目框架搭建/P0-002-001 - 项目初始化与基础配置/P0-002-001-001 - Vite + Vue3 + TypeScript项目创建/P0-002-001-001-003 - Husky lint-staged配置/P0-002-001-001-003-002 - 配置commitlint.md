### 5.1 安装依赖
```bash
pnpm add -D @commitlint/cli @commitlint/config-conventional
```

### 5.2 创建 commitlint.config.js
```js
module.exports = {
  extends: ['@commitlint/config-conventional'],
  rules: {
    'type-enum': [2, 'always', [
      'feat',     // 新功能
      'fix',      // 修复 bug
      'docs',     // 文档变更
      'style',    // 代码格式（不影响功能）
      'refactor', // 重构
      'perf',     // 性能优化
      'test',     // 测试
      'build',    // 构建系统/外部依赖
      'ci',       // CI 配置
      'chore'     // 其他杂项
    ]],
    'type-case': [2, 'always', 'lower-case'],
    'subject-empty': [2, 'never'],
    'subject-full-stop': [2, 'never', '.'],
    'header-max-length': [2, 'always', 100]
  }
}
```
- `type-enum`：限定 10 种允许的提交类型
- `header-max-length`：提交信息首行不超过 100 字符
- `subject-empty`：提交描述不能为空

### 5.3 配置 Husky commit-msg 钩子
```bash
pnpm exec husky add .husky/commit-msg 'pnpm exec commitlint --edit "$1"'
```
- `commit-msg` 钩子在 `git commit` 编辑提交信息后触发
- `--edit "$1"` 读取临时提交信息文件进行校验
- 不符合规范的提交信息将被拒绝，commit 中止

### 5.4 关键配置项
| 配置项 | 作用 | 注意事项 |
|--------|------|----------|
| `@commitlint/config-conventional` | 约定式提交规范预设 | 包含 Angular 风格的 commit 规范 |
| `type-enum` | 限定允许的提交类型 | 10 种类型覆盖常见场景 |
| `commit-msg` 钩子 | 校验提交信息格式 | 与 `pre-commit` 钩子独立运行 |
| `--edit "$1"` | 从 Git 临时文件读取提交信息 | 不要遗漏 `"$1"` 参数 |

### 5.5 环境适配
- commitlint.config.js 使用 CJS 格式（因 package.json 设置了 `"type": "module"`）
- `commit-msg` 钩子与 `pre-commit` 钩子是独立的两个文件，都需要配置
- 提交信息格式示例：`feat: 添加用户登录页面`、`fix(auth): 修复Token过期未刷新`
- 如果已有 `.husky/` 目录，使用 `husky add` 而非 `husky init`

## 七、验收标准

| 序号 | 检查项 | 验证方法 |
|:---:|--------|---------|
| 1 | `commitlint.config.js` 含 10 种 type（feat/fix/docs/style/refactor/perf/test/build/ci/chore） | 查看文件内容确认 `type-enum` 列表 |
| 2 | `.husky/commit-msg` 钩子执行 `commitlint --edit "$1"` | `cat .husky/commit-msg` 确认内容 |
| 3 | 不规范 commit message 被拒绝 | 执行 `git commit -m "bad message"` 确认被拦截 |
| 4 | 规范 commit message 通过 | 执行 `git commit -m "feat: 新功能"` 确认放行 |

## 八、易错警示

> ⚠️ `commitlint.config.js` 必须使用 CJS 导出（`module.exports = {}`），不能用 ESM

> ⚠️ `husky add .husky/commit-msg` 命令中的 `"$1"` 参数不可遗漏，否则无法读取提交信息

> ⚠️ `commit-msg` 钩子与 `pre-commit` 钩子是独立文件，两者都需要配置

> ⚠️ type 必须小写（`feat` 而非 `Feat`），由 `type-case` 规则约束
