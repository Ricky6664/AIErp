## 五、详细开发规格

> **📦 验证任务说明**
> 本任务为验证任务，需逐项验证前置任务（安装Husky+lint-staged、配置commitlint）的交付物是否符合规格。

### 5.1 验证清单
| 序号 | 验证项 | 预期结果 | 验证方法 |
|:---:|--------|---------|---------|
| 1 | husky + lint-staged 已安装 | `pnpm ls husky lint-staged` 显示版本号 | 终端执行查看 |
| 2 | `.husky/pre-commit` 钩子文件存在 | 文件内容包含 `pnpm exec lint-staged` | `cat .husky/pre-commit` |
| 3 | `.husky/commit-msg` 钩子文件存在 | 文件内容包含 `commitlint --edit "$1"` | `cat .husky/commit-msg` |
| 4 | pre-commit 拦截不规范代码 | 暂存含 `var` 的代码后 `git commit` 被阻止 | 故意写入不规范代码测试 |
| 5 | commit-msg 拦截不规范提交 | `git commit -m "bad"` 被拒绝 | 执行不规范提交测试 |
| 6 | commit-msg 放行规范提交 | `git commit -m "feat: test"` 通过（pre-commit 通过后） | 执行规范提交测试 |
| 7 | lint-staged 仅检查暂存文件 | 未暂存的不规范文件不触发 ESLint | 仅暂存部分文件后 commit |
| 8 | 整个钩子流程执行时间 | pre-commit + commit-msg 总耗时 < 5 秒 | 终端计时观察 |

### 5.2 测试方法
1. **pre-commit 钩子测试**：
   - 创建测试文件 `src/test-lint.ts`，写入 `var x = 1`（违反 no-var）
   - 执行 `git add src/test-lint.ts && git commit -m "feat: test lint"`
   - 预期：commit 被阻止，终端显示 ESLint 错误
2. **commit-msg 钩子测试**：
   - 先确保暂存区代码规范（或 `git add` 已格式化的文件）
   - 执行 `git commit -m "update something"`（缺少 type 前缀）
   - 预期：commit 被 commitlint 拒绝，显示 type-enum 错误
3. **规范提交流程测试**：
   - 暂存规范代码 → `git commit -m "feat: 添加测试功能"`
   - 预期：pre-commit 通过 → commit-msg 通过 → commit 成功

### 5.3 问题处理
- **钩子不触发**：检查 `.husky/` 目录是否在 git 仓库根目录、`pnpm install` 是否执行了 `prepare` 脚本
- **lint-staged 超时**：检查文件匹配规则是否过于宽泛，确认 ESLint 未扫描全量文件
- **commitlint 不报错**：检查 `commit-msg` 钩子文件中 `"$1"` 参数是否完整、`@commitlint/cli` 是否已安装
- **测试后清理**：删除测试文件，执行 `git reset HEAD` 清理暂存区
