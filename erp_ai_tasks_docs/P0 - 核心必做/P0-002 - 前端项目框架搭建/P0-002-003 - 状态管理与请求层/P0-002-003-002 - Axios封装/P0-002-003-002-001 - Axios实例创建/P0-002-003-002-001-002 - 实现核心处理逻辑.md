### 5.1 请求拦截器核心逻辑

```typescript
apiClient.interceptors.request.use(
  (config: InternalAxiosRequestConfig) => {
    // 1. 注入Authorization token
    const userStore = useUserStore()
    if (userStore.token) {
      config.headers.Authorization = `Bearer ${userStore.token}`
    }
    // 2. 注入Accept-Language头（国际化）
    const appStore = useAppStore()
    config.headers['Accept-Language'] = appStore.language || 'zh-CN'
    // 3. 请求去重key生成（用于请求取消机制）
    const requestKey = `${config.method?.toUpperCase()}:${config.url}:${JSON.stringify(config.params)}:${JSON.stringify(config.data)}`
    config.metadata = { requestKey, startTime: Date.now() }
    return config
  },
  (error) => {
    return Promise.reject(error)
  }
)
```

### 5.2 请求类型扩展

扩展Axios请求配置类型以支持metadata：
```typescript
declare module 'axios' {
  interface InternalAxiosRequestConfig {
    metadata?: {
      requestKey: string
      startTime: number
      skipCancel?: boolean  // 标记不参与自动取消
    }
  }
}
```

### 5.3 TypeScript类型安全

- 所有拦截器回调函数必须有明确的参数和返回类型
- 请求拦截器fulfilled回调返回`InternalAxiosRequestConfig`
- 请求拦截器rejected回调返回`Promise.reject(error)`

## 八、易错警示

> ⚠️ 请求拦截器中`useUserStore()`必须在回调函数内部调用，不能在模块顶层调用（Pinia可能未初始化）

> ⚠️ `config.headers`赋值要用`config.headers.Authorization`或`config.headers.set()`，不要直接替换整个headers对象

> ⚠️ requestKey的JSON.stringify对undefined会返回undefined字符串，需要做空值兜底

> ⚠️ 请求拦截器的rejected回调必须返回`Promise.reject(error)`，不能return error
