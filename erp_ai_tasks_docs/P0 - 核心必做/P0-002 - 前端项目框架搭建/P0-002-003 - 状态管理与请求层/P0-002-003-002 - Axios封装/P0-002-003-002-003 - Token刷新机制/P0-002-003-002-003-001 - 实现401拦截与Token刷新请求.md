实现401拦截与Token刷新请求：在响应拦截器中检测response.data.code===20001或HTTP 401时触发刷新流程；调用POST /auth/refresh-token接口（传递refreshToken）获取新的accessToken和refreshToken；刷新期间设置isRefreshing=true防止并发触发多次刷新；刷新成功后更新userStore.token并持久化到localStorage(key: erp_user)

### 5.1 401检测逻辑

在响应拦截器中（`erp-web/src/utils/request.ts`）：
```typescript
// fulfilled回调中
if (code === 20001) {
  return handleTokenRefresh(response.config)
}

// rejected回调中
if (error.response?.status === 401) {
  return handleTokenRefresh(error.config!)
}
```

### 5.2 handleTokenRefresh核心函数

在`erp-web/src/utils/request/tokenRefresh.ts`中实现：
```typescript
let isRefreshing = false

export async function handleTokenRefresh(config: InternalAxiosRequestConfig) {
  if (isRefreshing) {
    // 已在刷新中，将请求加入等待队列
    return addToQueue(config)
  }
  isRefreshing = true

  try {
    const userStore = useUserStore()
    // 调用刷新token接口（独立Axios实例，不经过拦截器避免死循环）
    const res = await refreshAxios.post<ApiResponse<TokenVO>>('/auth/refresh-token', {
      refreshToken: localStorage.getItem('erp_refresh_token')
    })
    // 更新token
    userStore.token = res.data.data.accessToken
    localStorage.setItem('erp_refresh_token', res.data.data.refreshToken)
    // 重发原请求 + 处理队列
    config.headers.Authorization = `Bearer ${userStore.token}`
    replayRequests()
    return apiClient(config)
  } catch (error) {
    handleRefreshFailure()
    return Promise.reject(error)
  }
}
```

### 5.3 refreshAxios独立实例

刷新token请求使用独立的Axios实例，避免触发拦截器造成死循环：
```typescript
const refreshAxios = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 10000,
})
```

## 八、易错警示

> ⚠️ Axios拦截器中401刷新token时需加锁（isRefreshing标记），防止并发请求触发多次刷新

> ⚠️ 刷新token的请求必须使用独立Axios实例（refreshAxios），不经过主拦截器，否则可能死循环

> ⚠️ refreshToken也失败时直接调用handleRefreshFailure跳转登录页，不要无限重试

> ⚠️ `useUserStore()`必须在handleTokenRefresh函数内部调用，不能在模块顶层调用
