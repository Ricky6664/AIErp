## 二、任务目标

在tokenRefresh.ts中定义pendingQueue数组存储刷新期间的待重发请求：当isRefreshing为true时，新请求通过new Promise将其resolve/reject回调存入队列，暂不发送；刷新完成后遍历队列，逐个替换新token并重发请求；队列元素类型为{resolve: Function, reject: Function, config: InternalAxiosRequestConfig}

### 5.1 排队数据结构

在`erp-web/src/utils/request/tokenRefresh.ts`中定义：
```typescript
interface PendingRequest {
  resolve: (value: any) => void
  reject: (reason?: any) => void
  config: InternalAxiosRequestConfig
}

const pendingQueue: PendingRequest[] = []
```

### 5.2 addToQueue函数

```typescript
function addToQueue(config: InternalAxiosRequestConfig): Promise<any> {
  return new Promise((resolve, reject) => {
    pendingQueue.push({ resolve, reject, config })
  })
}
```

- 当`isRefreshing === true`时，新请求调用`addToQueue`返回一个挂起的Promise
- 请求方不感知排队，正常使用`await apiClient.get(...)`等待结果
- 队列中每个元素保存原始config，刷新完成后用于重发

### 5.3 超时保护

排队请求设置30秒超时，避免token刷新卡死导致请求永久挂起：
```typescript
function addToQueue(config: InternalAxiosRequestConfig): Promise<any> {
  return new Promise((resolve, reject) => {
    const timer = setTimeout(() => {
      reject(new Error('请求排队超时'))
    }, 30000)
    pendingQueue.push({
      resolve: (v) => { clearTimeout(timer); resolve(v) },
      reject: (r) => { clearTimeout(timer); reject(r) },
      config
    })
  })
}
```

## 八、易错警示

> ⚠️ 队列使用数组存Promise的resolve/reject回调，不要用回调函数（不便管理超时）

> ⚠️ 超时的排队请求要主动从pendingQueue中移除，避免内存泄漏

> ⚠️ config对象是引用类型，重发时修改headers.Authorization不影响队列中其他请求的config
