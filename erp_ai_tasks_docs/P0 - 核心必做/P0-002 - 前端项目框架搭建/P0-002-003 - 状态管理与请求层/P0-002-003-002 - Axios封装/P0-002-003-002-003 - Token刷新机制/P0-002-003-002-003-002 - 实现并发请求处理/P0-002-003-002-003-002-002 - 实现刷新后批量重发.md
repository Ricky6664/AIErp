## 五、详细开发规格

> **📦 模块上下文**
> - 任务类型：前端请求层开发 — Token刷新后批量重发排队请求
> - 技术栈：Vue 3.5.x + Pinia 2.x + Axios 1.x + TypeScript 5.x
> - 重发架构：遍历pendingQueue → 替换新token → apiClient(config)重发 → 清空队列

### 5.1 replayRequests函数

在`erp-web/src/utils/request/tokenRefresh.ts`中实现：
```typescript
function replayRequests(newToken: string) {
  const queue = [...pendingQueue]  // 复制队列
  pendingQueue.length = 0           // 清空原队列

  queue.forEach(({ resolve, reject, config }) => {
    // 替换新token
    config.headers.Authorization = `Bearer ${newToken}`
    // 重发请求
    apiClient(config)
      .then(resolve)
      .catch(reject)
  })
}
```

### 5.2 重发流程说明

1. 先复制队列再清空，避免重发过程中新请求误入已清空的队列
2. 每个请求替换Authorization header为新token后重发
3. 重发成功调用对应Promise的resolve，请求方正常获得数据
4. 重发失败调用reject，请求方感知到错误

### 5.3 与handleTokenRefresh集成

在handleTokenRefresh的try块中，刷新成功后调用：
```typescript
replayRequests(userStore.token)
isRefreshing = false
```

| 序号 | 检查项 | 验证方法 |

| 5 | isRefreshing在重发完成后重置为false | 控制台检查 |

## 八、易错警示

> ⚠️ 重发时要先复制队列再清空（`const queue = [...pendingQueue]; pendingQueue.length = 0`），避免重发中再次触发刷新导致队列混乱

> ⚠️ 重发使用原始config但更新Authorization header，不要创建新的config对象（丢失原始参数）

> ⚠️ 重发请求的then/catch要分别调用队列中的resolve/reject，不要遗漏任何一个

> ⚠️ isRefreshing必须在replayRequests之后才重置为false，否则重发请求可能再次触发刷新
