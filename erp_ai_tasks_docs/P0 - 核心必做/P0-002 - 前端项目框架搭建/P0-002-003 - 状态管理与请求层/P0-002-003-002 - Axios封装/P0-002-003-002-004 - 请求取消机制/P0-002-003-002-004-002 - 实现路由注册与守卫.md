### 5.1 请求拦截器集成

在请求拦截器中为每个请求注入AbortController的signal：
```typescript
// erp-web/src/utils/request.ts 请求拦截器中
apiClient.interceptors.request.use((config) => {
  // 跳过取消的请求不处理
  if (config.metadata?.skipCancel) return config

  // 生成请求key
  const requestKey = generateCancelKey(config)

  // 如果相同key的请求已存在，取消旧请求
  if (pendingMap.has(requestKey)) {
    const controller = pendingMap.get(requestKey)!
    controller.abort()
    pendingMap.delete(requestKey)
  }

  // 创建新的AbortController
  const controller = new AbortController()
  config.signal = controller.signal
  pendingMap.set(requestKey, controller)

  return config
})
```

### 5.2 响应拦截器清理

请求完成后从pendingMap中移除：
```typescript
// 响应拦截器中（fulfilled和rejected都要处理）
const requestKey = generateCancelKey(response.config)
pendingMap.delete(requestKey)
```

### 5.3 路由守卫集成

在`erp-web/src/router/index.ts`的beforeEach中调用取消：
```typescript
router.beforeEach((to, from) => {
  // 路由切换时取消前一页面的pending请求
  if (from.path !== to.path) {
    cancelPendingRequests()
  }
  // ... 其他守卫逻辑
})
```

### 5.4 取消错误识别

在响应拦截器的rejected回调中识别取消错误：
```typescript
if (axios.isCancel(error) || error.name === 'CanceledError' || error.name === 'AbortError') {
  console.log('请求已取消:', error.message)
  return Promise.reject(error)  // 不弹错误提示
}
```

## 八、易错警示

> ⚠️ Axios v1.x使用AbortController的signal替代废弃的cancelToken

> ⚠️ 取消请求时catch中要判断`axios.isCancel(error)`或`error.name === 'CanceledError'`，避免误报错误

> ⚠️ POST请求不要随意取消，可能导致后端已执行但前端无感知（如创建订单），仅用于GET查询

> ⚠️ pendingMap在路由守卫和拦截器中共享，必须使用模块级变量确保同一引用
