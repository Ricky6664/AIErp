### 5.1 取消配置类型定义

在`erp-web/src/utils/request/cancelRequest.ts`中定义：
```typescript
interface CancelConfig {
  /** 请求唯一标识生成函数 */
  generateKey: (config: InternalAxiosRequestConfig) => string
  /** 是否跳过自动取消 */
  skipCancel: (config: InternalAxiosRequestConfig) => boolean
  /** 取消时的错误信息 */
  cancelMessage: string
}

const defaultConfig: CancelConfig = {
  generateKey: (config) => {
    const { method, url, params, data } = config
    return `${method?.toUpperCase()}:${url}:${JSON.stringify(params || {})}:${JSON.stringify(data || {})}`
  },
  skipCancel: (config) => {
    return config.metadata?.skipCancel === true
  },
  cancelMessage: '请求已取消（页面切换）',
}
```

### 5.2 pendingMap管理

```typescript
const pendingMap = new Map<string, AbortController>()

/** 添加请求到pendingMap */
function addPending(config: InternalAxiosRequestConfig): void

/** 从pendingMap移除并完成取消 */
function removePending(config: InternalAxiosRequestConfig): void

/** 取消指定页面的所有pending请求 */
function cancelPendingRequests(pageKey?: string): void
```

### 5.3 白名单配置

以下请求不参与自动取消（通过`config.metadata.skipCancel = true`标记）：
- 登录接口 `/auth/login`
- Token刷新接口 `/auth/refresh-token`
- 文件上传接口（responseType判断）
- 文件导出接口（responseType === 'blob'）

## 八、易错警示

> ⚠️ Axios的cancelToken已废弃（v1.x），优先使用signal + AbortController

> ⚠️ cancelKey的生成必须包含method+url+params+data，相同URL不同参数的请求不应互相取消

> ⚠️ JSON.stringify对undefined/null/circular对象的特殊处理：使用`|| {}`兜底

> ⚠️ pendingMap的key如果过长（大数据量的POST请求），考虑做hash摘要
