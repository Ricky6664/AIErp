### 5.1 fulfilled回调核心逻辑

```typescript
(response: AxiosResponse<ApiResponse<any>>) => {
  const { code, data, message } = response.data

  // 1. 业务成功：code === 0，返回解包后的数据
  if (code === 0) {
    return data
  }

  // 2. Token过期：code === 20001，触发刷新流程
  if (code === 20001) {
    return handleTokenRefresh(response.config)
  }

  // 3. 权限不足：code === 40001 或 40003
  if (code === 40001 || code === 40003) {
    ElMessage.error('权限不足，请联系管理员')
    return Promise.reject(new Error(message))
  }

  // 4. 其他业务错误：显示后端返回的message
  ElMessage.error(message || '请求失败')
  return Promise.reject(new Error(message))
}
```

### 5.2 rejected回调核心逻辑

```typescript
(error: AxiosError) => {
  if (error.response) {
    const status = error.response.status
    switch (status) {
      case 401:
        // 未授权，触发token刷新
        return handleTokenRefresh(error.config!)
      case 403:
        ElMessage.error('没有权限访问该资源')
        break
      case 404:
        ElMessage.error('请求的资源不存在')
        break
      case 500:
        ElMessage.error('服务器内部错误')
        break
      default:
        ElMessage.error(`请求失败(${status})`)
    }
  } else if (error.code === 'ECONNABORTED') {
    ElMessage.error('请求超时，请稍后重试')
  } else if (!error.response) {
    ElMessage.error('网络连接异常，请检查网络')
  }
  return Promise.reject(error)
}
```

## 七、验收标准

| 序号 | 检查项 | 验证方法 |
|:---:|--------|---------|
| 1 | code===0时API调用返回response.data.data（已解包） | 调用API后直接获得业务数据，无需手动取.data |
| 2 | code===20001时触发handleTokenRefresh | 后端返回20001，Network面板出现refreshToken请求 |
| 3 | code===40001/40003时显示"权限不足"ElMessage | 模拟权限不足响应，观察页面提示 |
| 4 | 其他非0 code显示后端返回的message | 模拟业务错误，ElMessage内容与后端message一致 |
| 5 | HTTP 401触发token刷新 | Network面板观察refreshToken请求 |
| 6 | 请求超时显示"请求超时"提示 | 设置timeout: 1模拟超时 |

## 八、易错警示

> ⚠️ fulfilled回调中`return data`使API调用方直接获得业务数据，整个项目必须统一此约定

> ⚠️ `handleTokenRefresh`中要检查`isRefreshing`标记防止并发刷新，详见Token刷新机制任务

> ⚠️ ElMessage.error要做防抖或限制（如3秒内同类型错误只弹一次），避免并发错误时满屏提示

> ⚠️ rejected回调中对`error.config`可能为undefined，使用前要做空值检查
