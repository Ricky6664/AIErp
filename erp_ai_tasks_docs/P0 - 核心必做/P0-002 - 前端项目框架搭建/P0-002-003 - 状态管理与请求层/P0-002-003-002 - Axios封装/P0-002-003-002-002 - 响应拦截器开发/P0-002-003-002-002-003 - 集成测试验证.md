## 五、详细开发规格

> **📦 验证任务说明**
> 本任务为验证任务，需逐项验证响应拦截器注册（P0-002-003-002-002-001）和核心处理逻辑（P0-002-003-002-002-002）的交付物是否符合规格。

### 5.1 验证清单

| 序号 | 验证项 | 预期结果 | 验证方法 |
|:---:|--------|---------|---------|
| 1 | code===0时API返回解包数据 | API调用结果为data字段值 | 调用任意正常API，检查返回值 |
| 2 | code非0时显示ElMessage | 页面弹出错误提示 | 触发参数错误，观察ElMessage |
| 3 | code===20001触发token刷新 | Network出现refreshToken请求 | 后端模拟token过期 |
| 4 | code===40001/40003显示"权限不足" | ElMessage内容正确 | 访问无权限接口 |
| 5 | HTTP 401触发token刷新 | refreshToken请求发出 | 清除token后发请求 |
| 6 | HTTP 500显示"服务器内部错误" | ElMessage内容正确 | 后端模拟500 |
| 7 | 请求超时显示"请求超时" | ElMessage内容正确 | 设置极短timeout测试 |
| 8 | 网络断开显示"网络连接异常" | ElMessage内容正确 | DevTools Offline模式 |

### 5.2 测试方法

1. 执行`pnpm dev`启动前端开发服务器
2. 打开浏览器DevTools → Network面板 + Console面板
3. 逐项执行验证清单中的测试场景
4. 使用DevTools的Offline模式测试网络异常
5. 修改Axios timeout为1ms测试超时场景

### 5.3 问题处理

- 如果code===0未解包：检查fulfilled回调中是否return `data`而非`response`
- 如果错误提示未显示：检查ElMessage是否已全局引入
- 如果401未触发刷新：检查handleTokenRefresh函数是否已实现
- 如果并发错误满屏提示：检查是否添加了ElMessage防抖
