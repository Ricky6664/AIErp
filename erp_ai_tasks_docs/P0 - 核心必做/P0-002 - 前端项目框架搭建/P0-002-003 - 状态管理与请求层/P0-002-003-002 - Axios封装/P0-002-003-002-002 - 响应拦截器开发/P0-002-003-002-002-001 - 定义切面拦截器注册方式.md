### 5.1 响应拦截器注册

在`erp-web/src/utils/request.ts`中注册响应拦截器：
```typescript
apiClient.interceptors.response.use(
  (response: AxiosResponse<ApiResponse<any>>) => {
    const { code, data, message } = response.data
    // 具体处理逻辑由P0-002-003-002-002-002任务实现
    return response
  },
  (error: AxiosError) => {
    // HTTP错误处理逻辑
    return Promise.reject(error)
  }
)
```

### 5.2 响应数据类型定义

```typescript
// erp-web/src/types/api.d.ts
export interface ApiResponse<T = any> {
  code: number     // 业务状态码：0=成功，20001=token过期，40001/40003=权限不足
  data: T          // 业务数据
  message: string  // 提示信息
}

export interface PageResult<T> {
  records: T[]     // 数据列表
  total: number    // 总记录数
  pageNum: number  // 当前页码
  pageSize: number // 每页条数
}
```

### 5.3 拦截器执行顺序

1. HTTP状态码2xx → 进入fulfilled回调 → 判断`response.data.code`
2. HTTP状态码非2xx → 进入rejected回调 → 按HTTP状态码处理
3. 所有拦截器按注册顺序依次执行（FIFO）

## 八、易错警示

> ⚠️ 响应拦截要判断`response.data.code`（业务状态码），不是HTTP状态码

> ⚠️ fulfilled回调中如果return `response.data.data`，则API调用方直接得到解包后的数据；如果return `response`，调用方需要自己解包

> ⚠️ rejected回调必须返回`Promise.reject(error)`，不能直接return error

> ⚠️ 响应拦截器的fulfilled/rejected回调是成对注册的，两者都必须提供
