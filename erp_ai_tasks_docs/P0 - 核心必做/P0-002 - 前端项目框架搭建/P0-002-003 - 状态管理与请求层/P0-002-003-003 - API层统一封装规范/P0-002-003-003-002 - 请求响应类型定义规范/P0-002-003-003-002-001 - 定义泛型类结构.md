## 五、详细开发规格

### 5.1 ApiResponse\<T\>接口

```typescript
// erp-web/src/types/api.d.ts
export interface ApiResponse<T = unknown> {
  code: number      // 业务状态码：0=成功，非0=失败（如20001=token过期，40001=权限不足）
  data: T           // 业务数据（泛型T）
  message: string   // 提示信息（成功时为"操作成功"，失败时为错误描述）
}
```

### 5.2 PageResult\<T\>接口

```typescript
export interface PageResult<T = unknown> {
  records: T[]      // 当前页数据列表
  total: number     // 总记录数
  pageNum: number   // 当前页码
  pageSize: number  // 每页条数
}
```

### 5.3 PageQuery接口

```typescript
export interface PageQuery {
  pageNum: number   // 当前页码，默认1
  pageSize: number  // 每页条数，默认10
}
```

各业务模块的查询DTO继承此类型：
```typescript
export interface UserQueryDTO extends PageQuery {
  username?: string
  status?: string
  deptId?: number
}
```

### 5.4 类型使用示例

```typescript
// API方法中的使用
import type { ApiResponse, PageResult, PageQuery } from '@/types/api'

function getUserPage(params: UserQueryDTO) {
  return apiClient.get<ApiResponse<PageResult<UserListVO>>>('/api/system/user/page', { params })
}
```

## 八、易错警示

> ⚠️ 泛型默认值推荐使用`unknown`而非`any`，强制类型安全；简单场景可用`T = unknown`

> ⚠️ 不要把所有API类型放在一个文件，按模块拆分（api.d.ts放通用类型，各业务类型放对应模块的types文件）

> ⚠️ PageQuery的pageNum/pageSize字段名要与后端接口参数名一致（驼峰命名，非下划线）

> ⚠️ ApiResponse的code是业务状态码（number），不要与HTTP状态码混淆
