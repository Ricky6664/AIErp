## 五、详细开发规格

> **📦 验证任务说明**
> 本任务为类型测试任务，使用Vitest的expectTypeOf对API类型定义进行编译时类型检查。

### 5.1 验证清单

| 序号 | 验证项 | 预期结果 | 验证方法 |
|:---:|--------|---------|---------|
| 1 | ApiResponse\<UserVO\>的data类型为UserVO | expectTypeOf推断正确 | vitest typecheck |
| 2 | ApiResponse默认泛型data为unknown | 不指定泛型时data为unknown | vitest typecheck |
| 3 | PageResult\<UserVO\>的records为UserVO[] | 数组元素类型为UserVO | vitest typecheck |
| 4 | PageResult包含total(number)字段 | total类型为number | vitest typecheck |
| 5 | PageQuery的pageNum/pageSize为number | 字段类型正确 | vitest typecheck |
| 6 | isSuccess函数返回boolean | 返回值类型推断 | vitest typecheck |
| 7 | assertSuccess后data类型收窄 | 类型守卫生效 | vitest typecheck |

### 5.2 测试方法

1. 在`erp-web/src/types/__tests__/api.test-d.ts`中编写类型测试
2. 使用`expectTypeOf<T>().toEqualTypeOf<U>()`进行类型等值断言
3. 使用`expectTypeOf<T>().toHaveProperty('fieldName')`检查字段存在
4. 执行`pnpm run test:type`（或`vitest typecheck`）运行类型测试

### 5.3 测试代码示例

```typescript
import { expectTypeOf, test } from 'vitest'
import type { ApiResponse, PageResult, PageQuery } from '../api'

interface UserVO { id: number; name: string }

test('ApiResponse泛型类型', () => {
  expectTypeOf<ApiResponse<UserVO>>().toHaveProperty('code')
  expectTypeOf<ApiResponse<UserVO>>().toHaveProperty('data')
  expectTypeOf<ApiResponse<UserVO>>().toHaveProperty('message')
  expectTypeOf<ApiResponse<UserVO>['data']>().toEqualTypeOf<UserVO>()
})

test('PageResult泛型类型', () => {
  expectTypeOf<PageResult<UserVO>['records']>().toEqualTypeOf<UserVO[]>()
  expectTypeOf<PageResult<UserVO>['total']>().toEqualTypeOf<number>()
})
```

### 5.4 问题处理

- 如果typecheck失败：检查类型定义文件中的泛型参数和字段声明
- 如果import路径错误：确认使用相对路径`../api`而非`@/types/api`
- 如果vitest未安装：执行`pnpm add -D vitest`

## 八、易错警示

> ⚠️ 类型测试用vitest的`expectTypeOf`，不要用运行时断言（expect/toBe），类型测试在编译时执行

> ⚠️ 测试文件放`__tests__`目录，文件名以`.test-d.ts`结尾（-d表示type definition测试）

> ⚠️ vitest typecheck需要安装`@vitest/coverage-v8`或配置`vitest.config.ts`中的`test.typecheck`选项
