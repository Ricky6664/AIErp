## 五、详细开发规格



> **本任务模块上下文**
> - 涉及数据表：无独立业务表(前端框架层)
> - 涉及API：路由配置、Pinia状态管理、Axios请求封装、i18n国际化、权限指令、布局组件

### 5.1 核心功能
1. 在src/api/modules/{module}.ts中实现各API方法的完整请求逻辑
2. GET请求：参数通过{ params }传递，URL路径拼接id参数使用模板字符串
3. POST请求：参数通过data传递，Content-Type为application/json
4. 文件上传：使用FormData封装，Content-Type为multipart/form-data
5. 批量操作：支持ids数组参数，用于批量删除/批量状态变更等场景

### 5.2 数据交互
```typescript
// 批量删除示例
export function batchDeleteCompany(ids: number[]) {
  return request.put<Result<void>>('/api/org/company/batch-delete', { ids })
}

// 文件上传示例
export function importCompany(file: File) {
  const formData = new FormData()
  formData.append('file', file)
  return request.post<Result<ImportResultVO>>('/api/org/company/import', formData, {
    headers: { 'Content-Type': 'multipart/form-data' },
    timeout: 60000
  })
}

// 导出示例（返回Blob）
export function exportCompany(params: CompanyQueryDTO) {
  return request.get('/api/org/company/export', {
    params,
    responseType: 'blob'
  })
}
```

### 5.3 关键逻辑
1. 所有API方法统一使用封装的request实例（自动携带Authorization header、处理token刷新、统一错误提示）
2. 导出接口需设置responseType: 'blob'，由调用方处理文件下载
3. 上传接口需设置合理的timeout（大文件建议60s+）
4. 批量操作接口统一使用POST/PUT + ids数组，不使用DELETE + query参数
5. API方法保持纯粹的请求转发，不包含业务逻辑处理

### 5.4 验证
1. TypeScript编译无报错（npx tsc --noEmit）
2. GET请求参数正确出现在URL query string中
3. POST请求参数正确出现在request body中（Network面板检查）
4. 文件上传Content-Type正确为multipart/form-data
5. 导出接口返回Blob对象，可正常触发浏览器下载

## 八、易错警示

> ⚠️ POST请求的Content-Type要与后端约定一致（默认application/json，表单用multipart/form-data）

> ⚠️ 大文件上传要设timeout: 0或合理超时时间（默认30s对大文件不够）

> ⚠️ 不要在API层做业务逻辑处理，保持纯粹的请求转发

> ⚠️ 导出接口设置responseType: 'blob'后，响应拦截器中需判断跳过code校验（Blob响应无code字段）
