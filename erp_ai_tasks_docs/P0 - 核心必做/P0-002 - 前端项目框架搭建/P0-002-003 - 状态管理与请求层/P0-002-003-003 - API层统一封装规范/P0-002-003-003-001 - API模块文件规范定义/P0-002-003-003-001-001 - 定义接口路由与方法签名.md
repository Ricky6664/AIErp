## 五、详细开发规格



> **本任务模块上下文**
> - 涉及数据表：无独立业务表(前端框架层)
> - 涉及API：路由配置、Pinia状态管理、Axios请求封装、i18n国际化、权限指令、布局组件

### 5.1 核心功能
1. 在src/api/modules/下为每个业务模块创建独立的API文件（如org.ts、product.ts、sale.ts）
2. 定义TypeScript接口类型：请求参数类型(XxxQueryDTO/XxxCreateDTO)和响应数据类型(Result<XxxVO>/Result<PageResult<XxxVO>>)
3. 使用named export导出API方法，每个方法使用泛型约束请求参数和响应类型
4. URL路径统一RESTful风格：GET列表/query、GET详情/{id}、POST新增、PUT修改/{id}、DELETE删除/{id}
5. 请求方法统一使用封装的request实例（src/utils/request/index.ts），自动携带token和处理错误

### 5.2 数据交互
```typescript
// 示例：erp-web/src/api/modules/org.ts
import request from '@/utils/request'
import type { Result, PageResult } from '@/types/api'
import type { CompanyQueryDTO, CompanyCreateDTO, CompanyListVO, CompanyDetailVO } from '@/types/org'

/** 分页查询公司列表 */
export function getCompanyPage(params: CompanyQueryDTO) {
  return request.get<Result<PageResult<CompanyListVO>>>('/api/org/company', { params })
}

/** 查询公司详情 */
export function getCompanyDetail(id: number) {
  return request.get<Result<CompanyDetailVO>>(`/api/org/company/${id}`)
}

/** 新增公司 */
export function createCompany(data: CompanyCreateDTO) {
  return request.post<Result<number>>('/api/org/company', data)
}
```

### 5.3 关键逻辑
1. 每个API文件仅导出函数，不使用default export（便于tree-shaking）
2. 请求参数和响应数据全部使用TypeScript interface定义类型
3. GET请求参数通过{ params }传递，POST/PUT请求通过data传递
4. 分页接口统一返回PageResult<T>类型，包含records/total/pageNum/pageSize
5. 文件命名与后端模块对应（org.ts对应/api/org/*接口）

### 5.4 验证
1. TypeScript编译无报错（npx tsc --noEmit）
2. ESLint检查无告警（npx eslint src/api/）
3. API方法可在Vue组件中正确导入和调用
4. 请求/响应类型与后端接口文档一致

> ⚠️ 方法参数用interface定义，不要用any
