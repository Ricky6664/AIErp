### 5.1 State/接口设计

定义TypeScript接口`IUserState`：
```typescript
// erp-web/src/types/user.d.ts
export interface UserInfoVO {
  id: number
  username: string
  nickname: string
  avatar: string
  email: string
  phone: string
  deptId: number
  deptName: string
}

export interface IUserState {
  token: string
  userInfo: UserInfoVO | null
  permissions: string[]
  roles: string[]
}
```

### 5.2 State初始值

使用Pinia defineStore创建userStore，state函数返回`IUserState`初始值：
- `token`：从localStorage读取（key: `erp_user_token`），未登录为空字符串`''`
- `userInfo`：`null`（登录后通过getInfo接口填充）
- `permissions`：`[] as string[]`（登录后由后端返回）
- `roles`：`[] as string[]`（登录后由后端返回）

### 5.3 持久化策略

配置`pinia-plugin-persistedstate`持久化插件：
- `persist.key`：`'erp_user'`
- `persist.pick`：`['token']`（仅持久化token，不持久化userInfo/permissions/roles）
- 应用启动时自动从localStorage恢复token，保持登录态

## 七、验收标准

| 序号 | 检查项 | 验证方法 |
|:---:|--------|---------|
| 1 | IUserState接口包含token(string)/userInfo(UserInfoVO\|null)/permissions(string[])/roles(string[])字段 | `npx tsc --noEmit`编译无报错 |
| 2 | token初始值从localStorage(`erp_user_token`)读取，为空串时未登录 | 清除localStorage后刷新，Pinia DevTools检查state.token为`''` |
| 3 | defineStore的id为`'user'`，DevTools可见 | Vue DevTools → Pinia面板看到`user` store |
| 4 | persist配置pick仅包含`['token']` | 修改permissions后刷新页面，permissions恢复为`[]` |

## 八、易错警示

> ⚠️ Pinia store必须使用`persist: { pick: ['token'] }`配置持久化，不要手动监听state写localStorage

> ⚠️ State类型不要用any，UserInfoVO的每个字段都要明确类型

> ⚠️ defineStore的id`'user'`全局唯一，不要与其他store冲突

> ⚠️ token初始值要从localStorage读，否则刷新页面后登录态丢失
