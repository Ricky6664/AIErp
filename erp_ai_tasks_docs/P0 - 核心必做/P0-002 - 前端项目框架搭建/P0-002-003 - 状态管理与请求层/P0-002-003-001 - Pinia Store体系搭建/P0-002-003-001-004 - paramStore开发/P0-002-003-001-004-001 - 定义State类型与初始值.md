### 5.1 State/接口设计

定义TypeScript接口和类型：
```typescript
// erp-web/src/types/dict.d.ts
export interface DictItem {
  dictLabel: string   // 字典标签（显示文本）
  dictValue: string   // 字典值（实际数据）
  dictType: string    // 字典类型
  cssClass?: string   // 样式类名（用于标签颜色区分）
  listClass?: string  // 列表样式（primary/success/danger等）
  isDefault?: string  // 是否默认（Y/N）
  dictSort: number    // 排序
}

export interface IParamState {
  dictMap: Record<string, DictItem[]>
  systemConfig: Record<string, string>
  loading: boolean
}
```

### 5.2 State初始值

使用Pinia defineStore创建paramStore，state函数返回`IParamState`初始值：
- `dictMap`：`{} as Record<string, DictItem[]>`（按需加载，首次使用时才请求）
- `systemConfig`：`{} as Record<string, string>`（应用初始化时统一加载）
- `loading`：`false`

### 5.3 持久化策略

**paramStore不配置持久化**（无persist字段）：
- 字典数据和系统参数每次应用启动从后端API获取最新值
- 不需要跨会话保持，避免缓存过期数据

### 5.4 与组件集成

组件中通过`const paramStore = useParamStore()`获取store实例，在`onMounted`中调用`paramStore.loadDict('sys_user_status')`按需加载字典。

## 八、易错警示

> ⚠️ paramStore不配置持久化，字典数据是后端动态维护的，缓存到localStorage会导致数据过期

> ⚠️ State初始值dictMap和systemConfig用空对象`{}`而非null，避免模板中`dictMap[type]`报TypeError

> ⚠️ DictItem的dictValue是string类型（即使值是数字），前端展示时需要做类型转换
