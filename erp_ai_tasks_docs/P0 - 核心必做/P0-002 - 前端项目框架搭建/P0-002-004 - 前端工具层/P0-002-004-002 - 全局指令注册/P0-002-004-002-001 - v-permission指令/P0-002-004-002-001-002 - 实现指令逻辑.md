### 5.1 函数签名与类型定义

```typescript
// erp-web/src/directives/permission.ts (逻辑实现)

import { useUserStore } from '@/stores/modules/user';

/**
 * 核心权限检查逻辑
 * 从userStore获取当前用户权限列表，判断是否包含目标权限码
 * @param value - 权限码(string)或权限码数组(string[])
 * @returns 是否有权限
 */
function checkPermission(value: string | string[]): boolean;

/**
 * 权限不足时的DOM处理
 * 从DOM中移除无权限元素
 * @param el - 目标DOM元素
 */
function removeElement(el: HTMLElement): void;
```

### 5.2 实现逻辑

1. **权限数据来源**：通过`useUserStore().permissions`获取当前用户的权限码列表(string[])
2. **权限判断逻辑**：
   - value为string时：`permissions.includes(value)`
   - value为string[]时：`value.some(p => permissions.includes(p))`（满足任一即可）
   - 超级管理员角色(admin)跳过权限检查，直接返回true
3. **DOM移除**：无权限时执行`el.parentNode?.removeChild(el)`从DOM树移除元素
4. **空值保护**：binding.value为空或空数组时不做任何操作（不移除元素）

**关键实现细节**：
- 使用some而非includes进行数组权限判断，支持角色数组匹配
- 移除前先检查el.parentNode存在性，避免报错
- v-permission只控制UI显示，不替代路由级权限守卫(beforeEach)

### 5.3 使用场景

1. **菜单按钮权限**：`<el-button v-permission="'order:export'">导出订单</el-button>` 无权限时按钮不渲染
2. **操作列权限**：表格操作列中的编辑/删除按钮按权限显隐
3. **动态权限切换**：管理员修改用户权限后，updated钩子自动重新判断

## 八、易错警示

> ⚠️ v-permission使用removeChild移除DOM后无法恢复，如需动态显隐应改用hasPermission函数配合v-if

> ⚠️ 权限判断用some而非includes，支持权限码数组（满足任一即可）

> ⚠️ v-permission只控制UI显示，不替代路由级权限守卫，二者必须同时使用

> ⚠️ v-permission指令使用v-if方式(移除DOM)而非v-show，确保DOM中不存在无权限元素
