### 5.1 配置结构

**文件：`erp-web/src/router/constants.ts` — 守卫配置常量**

```typescript
/** 白名单路径 - 无需登录即可访问 */
export const WHITE_LIST: string[] = [
  '/login',
  '/404',
  '/403',
  '/no-permission'
]

/** 登录页路径 */
export const LOGIN_PATH = '/login'

/** 首页路径 */
export const HOME_PATH = '/home'

/** 404页面路径(用于catch-all路由) */
export const NOT_FOUND_PATH = '/404'

/** Token存储Key */
export const TOKEN_KEY = 'erp_token'

/** 动态路由加载标记Key */
export const ROUTES_LOADED_KEY = 'routes_loaded'
```

**文件：`erp-web/src/stores/modules/permission.ts` — 权限Store接口**

```typescript
import { defineStore } from 'pinia'
import type { RouteRecordRaw } from 'vue-router'

interface PermissionState {
  routes: RouteRecordRaw[]     // 动态路由列表
  isRoutesLoaded: boolean      // 动态路由是否已加载
  permissions: string[]        // 用户权限标识列表
}

export const usePermissionStore = defineStore('permission', {
  state: (): PermissionState => ({
    routes: [],
    isRoutesLoaded: false,
    permissions: []
  }),
  actions: {
    /** 生成并注册动态路由 */
    async generateRoutes(menus: any[]) { /* ... */ },
    /** 检查用户是否有权限访问路由 */
    hasPermission(routePermissions: string[]): boolean {
      if (!routePermissions?.length) return true
      return routePermissions.some(p => this.permissions.includes(p))
    },
    /** 重置权限状态(退出登录时调用) */
    resetPermission() {
      this.routes = []
      this.isRoutesLoaded = false
      this.permissions = []
    }
  }
})
```

### 5.2 关键配置项

| 配置项 | 值/类型 | 用途 |
|-------|--------|------|
| WHITE_LIST | string[] | 守卫中判断路径是否在白名单，白名单路由直接放行 |
| LOGIN_PATH | '/login' | 未登录重定向目标，已登录访问时跳首页 |
| TOKEN_KEY | 'erp_token' | localStorage中Token的存储Key |
| isRoutesLoaded | boolean | 标记动态路由是否已加载，防止重复加载 |
| permissions | string[] | 用户权限列表，用于hasPermission判断 |

### 5.3 与路由守卫的集成

1. guards.ts中导入WHITE_LIST判断是否放行
2. 通过TOKEN_KEY从localStorage读取token判断登录状态
3. 通过permissionStore.isRoutesLoaded判断是否需要加载动态路由
4. 通过permissionStore.hasPermission(meta.permissions)判断路由访问权限

## 七、验收标准

| 序号 | 检查项 | 验证方法 |
|:---:|--------|---------|
| 1 | WHITE_LIST包含/login/404/403/no-permission | Console检查数组内容 |
| 2 | TOKEN_KEY与登录模块使用的Key一致 | 搜索项目中TOKEN_KEY引用确认统一 |
| 3 | permissionStore.isRoutesLoaded初始值为false | 刷新页面后DevTools Pinia检查状态 |
| 4 | hasPermission(['sale:order:list'])在用户有该权限时返回true | Console调用store方法验证 |
| 5 | resetPermission()后isRoutesLoaded变为false | 退出登录后检查store状态 |

## 八、易错警示

> ⚠️ WHITE_LIST必须包含所有静态路由中的非业务页面路径，遗漏会导致未登录时被拦截

> ⚠️ permissionStore的isRoutesLoaded不要持久化到localStorage，刷新后需重新加载动态路由

> ⚠️ hasPermission使用some()而非every()，用户只要拥有其中一个权限即可访问
