### 5.1 文件结构与组件设计

文件路径：`erp-web/src/layouts/components/Sidebar/SidebarItem.vue`

```vue
<template>
  <!-- 隐藏菜单项不渲染 -->
  <template v-if="!item.hideMenu">
    <!-- 有子菜单：渲染el-sub-menu + 递归 -->
    <el-sub-menu
      v-if="hasVisibleChildren"
      :index="item.path"
    >
      <template #title>
        <MenuItemIcon :icon="item.icon" />
        <span>{{ item.title }}</span>
      </template>
      <!-- 递归调用自身 -->
      <SidebarItem
        v-for="child in visibleChildren"
        :key="child.path"
        :item="child"
      />
    </el-sub-menu>

    <!-- 无子菜单：渲染el-menu-item -->
    <el-menu-item
      v-else
      :index="item.path"
    >
      <MenuItemIcon :icon="item.icon" />
      <template #title>
        <span>{{ item.title }}</span>
      </template>
    </el-menu-item>
  </template>
</template>

<script setup lang="ts">
import { computed } from 'vue'
import type { MenuItemData } from './types'
import MenuItemIcon from './MenuItemIcon.vue'

// 递归组件必须设置name
defineOptions({ name: 'SidebarItem' })

interface Props {
  item: MenuItemData
}
const props = defineProps<Props>()

// 过滤出可见子菜单
const visibleChildren = computed(() =>
  (props.item.children || []).filter(child => !child.hideMenu)
)

// 是否有可见子菜单
const hasVisibleChildren = computed(() =>
  visibleChildren.value.length > 0
)
</script>
```

### 5.2 核心实现逻辑

1. **递归组件name**：`defineOptions({ name: 'SidebarItem' })`使组件可以递归引用自身
2. **hasVisibleChildren判断**：过滤hideMenu后的children数量>0才渲染el-sub-menu
3. **单个可见子项优化**：如果只有1个可见子项且为叶子节点，可提升为直接菜单项(可选优化)
4. **v-for key=path**：使用菜单path作为唯一标识，不用index
5. **hideMenu过滤**：v-if="!item.hideMenu"在渲染层过滤，不修改原始数据

### 5.3 交互逻辑

1. el-sub-menu展开 → 显示子菜单项 → 子项递归渲染(可能有更深层级)
2. el-menu-item点击 → el-menu的select事件 → 触发router.push(item.path)
3. 折叠模式下 → el-sub-menu变为popup弹出子菜单 → el-menu-item只显示图标

## 八、易错警示

> ⚠️ 递归组件必须设置defineOptions({ name })，否则模板中无法引用自身

> ⚠️ v-for的key必须使用path唯一标识，不要用index，否则菜单顺序变化时DOM复用异常

> ⚠️ el-sub-menu的index属性必须与el-menu-item的index属性值域不冲突，否则el-menu高亮异常

> ⚠️ visibleChildren使用computed缓存过滤结果，避免每次渲染都重新过滤
