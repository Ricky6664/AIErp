### 5.1 文件结构与组件设计

**文件1：`erp-web/src/directives/permission.ts` — v-permission指令**

```typescript
import type { Directive, DirectiveBinding } from 'vue'
import { usePermissionStore } from '@/stores/modules/permission'

/**
 * v-permission 按钮级权限控制指令
 * 用法：v-permission="['sale:order:add']"
 * 无权限时移除DOM元素
 */
export const permission: Directive = {
  mounted(el: HTMLElement, binding: DirectiveBinding<string[]>) {
    const requiredPermissions = binding.value
    if (!requiredPermissions?.length) return

    const permissionStore = usePermissionStore()
    const hasAuth = requiredPermissions.some(
      p => permissionStore.permissions.includes(p)
    )

    if (!hasAuth) {
      el.parentNode?.removeChild(el)
    }
  }
}
```

**文件2：`erp-web/src/directives/index.ts` — 指令注册**

```typescript
import type { App } from 'vue'
import { permission } from './permission'

export function setupDirectives(app: App) {
  app.directive('permission', permission)
}
```

**Sidebar组件中权限过滤已在index.vue的filteredMenus computed中实现(见004-002-002)**

### 5.2 核心实现逻辑

1. **v-permission指令**：mounted钩子中检查权限，无权限则removeChild移除DOM
2. **指令注册**：在main.ts中调用setupDirectives(app)全局注册
3. **菜单级过滤**：Sidebar组件的filteredMenus computed过滤无权限菜单
4. **按钮级过滤**：v-permission指令在业务页面中控制按钮显示/隐藏
5. **实时更新**：permissionStore.permissions响应式变化 → computed重新计算 → 菜单更新

### 5.3 交互逻辑

1. 用户登录 → getInfo返回permissions → permissionStore赋值 → 菜单过滤
2. 渲染侧边栏 → filteredMenus computed → 仅渲染有权限的菜单
3. 业务页面 → v-permission="['sale:order:add']" → 无权限时按钮DOM移除
4. 权限变更 → 管理员修改角色 → 用户重新登录 → permissions更新 → 菜单和按钮更新

## 八、易错警示

> ⚠️ v-permission使用removeChild直接移除DOM，而非v-if隐藏，确保无权限按钮不在DOM中

> ⚠️ 权限过滤只影响前端UI，安全校验必须由后端接口保障，前端过滤仅为用户体验

> ⚠️ v-permission指令在mounted中执行，如果permissions异步获取可能需要updated钩子补充检查

> ⚠️ 角色匹配使用some()而非every()，用户拥有任一所需权限即可操作
