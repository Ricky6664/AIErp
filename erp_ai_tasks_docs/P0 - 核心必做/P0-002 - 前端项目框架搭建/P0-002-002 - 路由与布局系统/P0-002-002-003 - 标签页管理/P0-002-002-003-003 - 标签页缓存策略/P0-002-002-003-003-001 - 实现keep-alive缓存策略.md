### 5.1 文件结构与组件设计

文件路径：`erp-web/src/layouts/AppLayout.vue`（keep-alive部分）

```vue
<template>
  <!-- 内容区域 -->
  <el-main class="app-layout__content">
    <router-view v-slot="{ Component, route }">
      <transition name="fade-transform" mode="out-in">
        <keep-alive
          :include="cachedViews"
          :max="MAX_CACHED_VIEWS"
        >
          <component :is="Component" :key="route.fullPath" />
        </keep-alive>
      </transition>
    </router-view>
  </el-main>
</template>

<script setup lang="ts">
import { computed } from 'vue'
import { useTagsViewStore } from '@/stores/modules/tagsView'

defineOptions({ name: 'AppLayout' })

const MAX_CACHED_VIEWS = 10  // 最大缓存数
const tagsViewStore = useTagsViewStore()

// 从store获取需要缓存的组件名列表
const cachedViews = computed(() => tagsViewStore.cachedViews)
</script>
```

tagsView store中LRU淘汰逻辑：
```typescript
function addCachedView(route: RouteLocationNormalized) {
  const name = route.name as string
  if (!name || !route.meta?.keepAlive) return
  if (cachedViews.value.includes(name)) return

  cachedViews.value.push(name)

  // LRU淘汰：超过最大缓存数时移除最早的
  if (cachedViews.value.length > MAX_CACHED_VIEWS) {
    const removed = cachedViews.value.shift()
    console.log(`[KeepAlive] LRU淘汰: ${removed}`)
  }
}
```

### 5.2 核心实现逻辑

1. **include动态绑定**：绑定cachedViews(组件name字符串数组)，仅缓存列表中的组件
2. **max属性**：Vue内置的keep-alive max限制最大缓存实例数
3. **LRU淘汰**：cachedViews数组push新项、shift移除最早项
4. **key=route.fullPath**：同一组件不同参数视为不同实例
5. **transition mode="out-in"**：旧组件先离开，新组件再进入，避免重叠闪烁

### 5.3 交互逻辑

1. 访问新页面 → addView → addCachedView → cachedViews更新 → keep-alive include变化
2. 关闭标签 → delView → delCachedView → 从include移除 → 组件被销毁
3. 缓存已满(10个) → 访问新页面 → LRU淘汰最早的缓存 → 最早标签的组件被销毁
4. 返回已缓存页面 → keep-alive命中缓存 → 组件不重新创建，触发activated钩子

## 八、易错警示

> ⚠️ keep-alive的include必须匹配组件defineOptions({name})属性，否则缓存不生效

> ⚠️ 组件name必须与路由name一致(或手动在addCachedView中映射)，否则include找不到组件

> ⚠️ max属性设为合理值(建议10)，过大导致内存占用过高，过小导致频繁淘汰

> ⚠️ key使用route.fullPath而非route.name，确保同路由不同参数各自独立缓存
