## 1. 模块架构约束

### 1.1 模块定位
P0-002是整个ERP系统的前端基石，负责搭建Vue3 + Vite + TypeScript + Element Plus + Vxe Table前端项目骨架。本模块配置路由与布局系统、Pinia状态管理、Axios请求层、工具函数库、国际化基础设施、全局样式体系与性能优化基础设施，为后续所有前端业务模块提供统一的开发基座和组件渲染环境。

### 1.2 依赖关系
- 前置依赖：无（可与P0-001并行开发）
- 后续依赖：
  - P0-005（公共组件基础开发）——依赖前端框架提供组件渲染基座
  - P0-004-006及后续所有前端业务模块——依赖路由、状态管理、请求层、样式体系

### 1.3 技术约束
- **技术栈约束**：Vue 3.x（Composition API）+ Vite 5.x + TypeScript 5.x + Element Plus 2.x + Vxe Table 4.x + Pinia 2.x + Vue Router 4.x + Vue I18n 9.x + Axios 1.x + Tailwind CSS 3.x
- **性能约束**：首屏加载时间 < 2秒（Gzip后）；路由切换响应时间 < 200ms；组件渲染帧率 ≥ 30fps；打包产物单chunk < 500KB
- **安全约束**：XSS防护（Vue模板自动转义+富文本内容过滤）；CSRF防护（Axios请求头Token注入）；CSP安全头配置；敏感数据不存储在localStorage

### 2.2 表关系图
前端框架不涉及数据库表，但维护以下前端状态模型：
- **permissionStore**：维护用户菜单权限树、按钮权限标识列表、动态路由表
- **appStore**：维护应用全局状态（语言、主题、侧边栏折叠、标签页配置）
- **userStore**：维护用户Token、用户信息、登录状态
- **tagViewStore**：维护visitedViews（已打开标签页）和cachedViews（需缓存标签页）

### 2.3 数据流转
1. **登录流程**：用户输入凭证 → 调用/api/auth/login → userStore存储Token → permissionStore请求菜单权限 → 动态注册路由 → 跳转首页
2. **页面渲染流程**：路由切换 → beforeEach守卫校验Token → 加载动态路由（首次） → 根据路由meta加载对应组件 → keep-alive缓存控制
3. **请求流程**：组件发起请求 → Axios拦截器注入Token → 后端响应 → 响应拦截器处理401（Token刷新）/403（权限不足）/500（错误提示）

## 3. 业务流程

### 3.1 核心业务流程
1. **项目初始化**：Vite创建Vue3+TS项目 → 配置ESLint+Prettier → 配置环境变量（.env.dev/.env.prod）→ 配置Vite构建优化
2. **路由与布局系统**：实现AdminLayout主布局（顶部导航+侧边栏+标签页栏+内容区+底部状态栏）→ 实现静态路由（登录/404/403）→ 实现动态路由机制 → 实现路由守卫
3. **状态管理与请求层**：实现Pinia stores（user/app/permission/tagView）→ 封装Axios实例（拦截器+Token刷新+请求取消+并发控制）→ 实现请求取消与路由切换联动
4. **前端工具层**：封装日期处理/数值格式化/树形数据转换/文件下载/深拷贝等工具函数
5. **国际化基础**：配置Vue I18n → 实现语言包加载（zh-CN/en-US）→ 实现Element Plus locale联动 → 实现语言切换
6. **样式体系**：定义CSS变量Design Token → 配置Tailwind CSS扩展 → 覆盖Element Plus主题变量 → 实现暗色模式

### 3.2 业务规则
- 动态路由权限约束：静态路由（登录/404/403/首页）直接注册；动态路由由permissionStore根据后端菜单权限数据过滤后动态注册
- Token刷新并发队列：401触发Token刷新，刷新期间并发请求暂存待重发队列，刷新成功后逐一重发，仅触发一次refreshToken请求
- 标签页缓存与keep-alive联动：cachedViews列表控制keep-alive include，组件name必须与路由meta缓存标识一致，最大缓存数超出时按LRU策略淘汰
- 请求取消与路由切换联动：路由切换前取消所有未完成pending请求，同一接口+参数的重复请求自动拦截
- 样式Design Token约束：所有颜色/间距/圆角等通过CSS变量定义，禁止硬编码颜色值
- 国际化联动约束：切换语言时同步更新Element Plus ConfigProvider locale，禁止硬编码中文字符串
- 外部资源国内CDN兜底：通过VITE_EXTERNAL_CDN_BASE环境变量控制CDN来源，国内环境优先使用镜像

### 3.3 状态流转
- **应用主题状态**：light ↔ dark（通过data-theme属性切换，CSS变量覆盖）
- **侧边栏状态**：expanded ↔ collapsed（appStore控制，持久化到localStorage）
- **用户登录状态**：unauthenticated → authenticating → authenticated → unauthenticated（Token过期/手动登出）
- **标签页状态**：opened → cached → activated/deactivated → closed

### 4.2 依赖接口
前端框架Axios封装层将调用以下后端接口：
- `/api/auth/login` —— 用户登录
- `/api/auth/logout` —— 退出登录
- `/api/auth/token/refresh` —— Token刷新
- `/api/auth/user-info` —— 获取当前用户信息（含菜单权限树+按钮权限标识）
- `/api/auth/captcha` —— 图形验证码

## 5. 开发顺序约束

1. **P0-002-001 项目初始化与基础配置**（所有子模块的前置依赖）

以下子模块均仅依赖P0-002-001，可并行开发：
- P0-002-002 路由与布局系统
- P0-002-003 状态管理与请求层
- P0-002-004 前端工具层
- P0-002-006 样式体系

P0-002-005国际化基础需等待P0-002-003完成后开发。
