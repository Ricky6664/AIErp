### 5.1 词条结构设计
zh-CN/index.ts 作为中文语言包的聚合入口，负责汇总所有子模块词条：
```typescript
import common from './common'
import status from './status'
import validation from './validation'

const zhCN = {
  common: { ...common },
  status: { ...status },
  validation: { ...validation }
}

export default zhCN
```

### 5.2 导出与聚合
- 使用扩展运算符`{ ...common }`展开各模块，保持代码可读性和结构清晰
- 新增模块时只需：①创建新.ts文件 ②在index.ts添加import ③在zhCN对象中添加扩展运算符
- 聚合后的zhCN对象在i18n/index.ts中作为`messages['zh-CN']`的值传入
- en-US/index.ts也须保持相同的模块结构（common/status/validation），确保Key一一对应

### 5.3 特殊处理
- 索引文件中不要直接定义词条，所有词条必须放在对应模块文件中
- 模块名（common/status/validation）作为顶层命名空间，与组件中$t()调用的第一段Key对应
- 若某模块词条需要覆盖默认值，可在展开后追加：`{ ...common, confirm: '确定' }`
- 动态新增模块时须同步更新en-US/index.ts，避免切换语言时Key缺失

## 八、易错警示

> ⚠️ 索引文件必须export default整个聚合对象，不要分别export各模块（i18n的messages需要单一对象）

> ⚠️ 语言包结构是：语言代码(zh-CN) → 模块(common) → Key(confirm)，共三层，不要多嵌套或少嵌套

> ⚠️ 新增模块时en-US/index.ts必须同步添加对应模块，否则切换英文后该模块所有词条会fallback到中文

> ⚠️ 不要在索引文件中直接定义词条Key-Value，保持索引文件只负责聚合

> ⚠️ Key命名规范：{module}.{function}.{field}（如 common.confirm），使用点号分隔
