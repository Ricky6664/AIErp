### 5.1 配置结构
1. 创建`erp-web/src/stores/modules/locale.ts`，使用`defineStore('locale', () => {...})`
2. 定义State接口`LocaleState`：
```typescript
interface LocaleState {
  language: string           // 当前语言代码，如'zh-CN'或'en-US'
  loadedLocales: string[]    // 已动态加载的语言包列表，避免重复加载
  availableLanguages: Array<{ // 可选语言列表，供切换组件使用
    code: string             // 语言代码
    label: string            // 显示名称，如'中文'/'English'
  }>
}
```

### 5.2 关键配置项
1. 初始语言优先级链：用户设置 > localStorage('app-language') > navigator.language > 'zh-CN'
2. 初始化逻辑封装为`getInitialLocale()`工具函数：
```typescript
function getInitialLocale(): string {
  const saved = localStorage.getItem('app-language')
  if (saved && ['zh-CN', 'en-US'].includes(saved)) return saved
  const browserLang = navigator.language
  if (browserLang.startsWith('zh')) return 'zh-CN'
  if (browserLang.startsWith('en')) return 'en-US'
  return 'zh-CN'
}
```
3. loadedLocales初始值包含`['zh-CN']`（默认语言包已静态加载）

### 5.3 与Element Plus/dayjs集成
- State变化时通过watch触发Element Plus locale更新
- loadedLocales记录可避免重复import.meta.glob加载同一语言包
- availableLanguages与i18n实例的messages keys保持同步

## 八、易错警示

> ⚠️ 语言代码统一使用zh-CN/en-US格式（RFC 5646），不要混用zh_CN/zh/en等变体

> ⚠️ Pinia store的State初始值必须是完整对象，不要遗漏loadedLocales和availableLanguages

> ⚠️ localStorage key统一为'app-language'，不要与其他模块的持久化key冲突

> ⚠️ 初始语言优先级：用户设置 > localStorage > 浏览器语言 > 默认zh-CN

> ⚠️ createI18n必须设置legacy: false，否则无法使用Composition API模式
