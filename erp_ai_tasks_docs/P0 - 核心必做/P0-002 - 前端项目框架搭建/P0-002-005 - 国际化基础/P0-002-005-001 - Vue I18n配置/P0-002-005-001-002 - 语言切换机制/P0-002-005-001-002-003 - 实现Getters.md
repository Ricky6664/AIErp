### 5.1 配置结构
1. 实现`currentLanguage` getter：使用`computed`返回当前语言代码
```typescript
const currentLanguage = computed(() => language.value)
```
2. 实现`currentLanguageLabel` getter：返回当前语言的显示名称（如'中文'/'English'）
```typescript
const currentLanguageLabel = computed(() => {
  const found = availableLanguages.value.find(l => l.code === language.value)
  return found?.label ?? ''
})
```

### 5.2 关键配置项
1. 实现`availableLanguages` getter：返回可选语言列表供下拉组件使用
```typescript
const availableLanguages = computed(() => [
  { code: 'zh-CN', label: '中文' },
  { code: 'en-US', label: 'English' }
])
```
2. 实现`isLocaleLoaded` getter：判断指定语言包是否已加载
```typescript
function isLocaleLoaded(locale: string): boolean {
  return loadedLocales.value.includes(locale)
}
```
3. 所有getter保持纯计算，不做IO操作或异步调用

### 5.3 与Element Plus/dayjs集成
- currentLanguage可直接绑定到语言切换下拉组件的v-model
- availableLanguages列表需与实际已加载/可加载的语言包保持一致
- isLocaleLoaded用于判断是否需要触发loadLocaleMessages

## 八、易错警示

> ⚠️ getter不要做IO操作或异步调用，保持纯计算（Pinia的computed getter必须同步返回）

> ⚠️ availableLanguages的列表要与实际加载的语言包对应，不要出现列表中有但语言包不存在的情况

> ⚠️ isLocaleLoaded是函数式getter（返回函数），不是computed，调用时需要传参

> ⚠️ getter返回类型要与组件模板使用场景匹配（如下拉组件需要label而非code）

> ⚠️ createI18n必须设置legacy: false，否则无法使用Composition API模式
