### 5.1 配置结构
1. 在`erp-web/src/main.ts`中引入i18n实例：`import { i18n } from './i18n'`
2. 在createApp后、mount前注册：`app.use(i18n)`
3. 注册顺序：Pinia → i18n → Router → app.mount（i18n须在Pinia之后注册，因为locale store依赖Pinia）
4. 确保app.use(i18n)只调用一次，避免重复注册

### 5.2 关键配置项
1. TypeScript类型扩展：在`env.d.ts`中声明`module 'vue-i18n'`扩展`DefineLocaleMessage`接口，使$t()具有类型推导
2. 初始语言检测逻辑：`const initialLocale = localStorage.getItem('app-language') || navigator.language.startsWith('zh') ? 'zh-CN' : 'en-US'`
3. 全局属性挂载（可选）：`app.config.globalProperties.$i18n = i18n` 方便非setup组件使用

### 5.3 与Element Plus/dayjs集成
- main.ts中Element Plus配置需传入动态locale：`app.use(ElementPlus, { locale: computedLocale })`
- computedLocale从i18n.global.locale响应式获取，确保Element Plus组件（如DatePicker）跟随语言切换
- dayjs locale初始化：在main.ts中调用`dayjs.locale(initialLocale.toLowerCase())`

## 八、易错警示

> ⚠️ app.use(i18n)必须在app.use(router)之前注册，否则路由守卫中的$t()调用会报错

> ⚠️ 初始语言检测逻辑须在createI18n之前执行，因为locale参数在实例创建时即固定

> ⚠️ TypeScript类型声明文件须放在env.d.ts或global.d.ts中，确保被tsconfig.json的include覆盖

> ⚠️ createI18n必须设置legacy: false，否则无法使用Composition API模式

> ⚠️ 切换语言时必须同步更新：i18n.locale + Element Plus locale + dayjs.locale + document.documentElement.lang
