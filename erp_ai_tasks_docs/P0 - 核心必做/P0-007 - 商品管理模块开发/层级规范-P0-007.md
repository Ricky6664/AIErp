## 1. 模块架构约束

### 1.1 模块定位
P0-007负责开发ERP系统的商品管理功能，包括商品档案、商品分类（树形）、BOM物料清单、工序管理、多单位管理、安全库存、定价体系（标准价/购价/销价/竞品），以及V8扩展项（商品价格/属性/规格/条码/图片/关联/标签/序列号模板）。本模块为销售、采购、库存、生产、委外等所有业务模块提供商品基础数据支撑。

### 1.2 依赖关系
- 前置依赖：
  - P0-001（后端框架）
  - P0-002（前端框架）
  - P0-003（数据库提供prod_*系列表）
  - P0-004（认证与权限）
  - P0-005（公共组件提供页面基座/录入组件/选择器）
  - P0-006（组织架构提供公司/部门数据）
- 后续依赖：P1-005~P1-009（销售/采购/库存/生产/委外）——引用商品数据

### 1.3 技术约束
- **技术栈约束**：Spring Boot 3.4.x + MyBatis-Plus 3.5.5 + Redis（编码缓存）+ Vue3 + Element Plus + Vxe Table
- **性能约束**：商品列表查询 < 200ms（10万商品）；商品分类树加载 < 300ms；BOM展开 < 500ms（10层深度）
- **安全约束**：商品编码唯一性通过数据库行级锁保证；BOM层级展开深度限制10层+循环引用检测

### 2.2 表关系图
- `prod_product_class`（树形自引用）1:N `prod_product`：分类与商品一对多
- `prod_product` 1:N `prod_product_unit`：商品与多单位一对多
- `prod_product` 1:1 `prod_product_control`：商品与控制策略一对一
- `prod_product` 1:N `prod_product_safety_stock`：商品按仓库设置安全库存
- `prod_product` 1:1 `prod_product_standard_price`：商品与标准价一对一
- `prod_product` 1:N `prod_product_purchase_price`：商品按供应商核定购价
- `prod_product` 1:N `prod_product_sale_price`：商品按客户核定销价
- `prod_product` 1:N `prod_bom` → `prod_bom` 1:N `prod_bom_detail`：商品可有多个BOM版本，每个BOM包含多个子件
- `prod_product` 1:N `prod_product_process` → `prod_product_process` 1:N `prod_process_param` + `prod_process_price`
- `prod_standard_process`被`prod_process_param`和`prod_process_price`引用

### 2.3 数据流转
1. **商品新增流程**：选择分类 → 填写基本信息 → 编码引擎生成商品编码 → 设置基础单位 → 保存商品主表 → 可继续维护多单位/控制策略/安全库存/价格等
2. **BOM管理流程**：选择成品商品 → 新增BOM版本 → 添加子件（引用商品选择器）→ 设置用量/损耗率 → BOM审核 → 标记默认版本
3. **商品查询流程**：工作台/商品中心 → 数据视图引擎加载视图字段 → 查询区筛选 → 列表展示 → 点击行进入详情（关联信息区展示各维度数据）

## 3. 业务流程

### 3.1 核心业务流程
1. **商品管理后端开发**（P0-007-001）：
   - 商品分类CRUD（树形结构+编码唯一性）
   - 商品主表CRUD（编码唯一性+行级锁+主从保存）
   - 商品多单位/控制策略/安全库存/附件/其他信息CRUD
   - 商品标准价/购价核定/销价核定/竞品CRUD
   - BOM管理（主从保存+版本管理+循环引用检测+深度限制10层）
   - 标准工序/商品工序/工序参数/工序加工价格CRUD
   - V8扩展：商品价格/属性/规格/条码/图片/关联/标签/序列号模板CRUD
   - 商品管理工作台聚合接口
2. **商品管理前端页面**（P0-007-002）：
   - 商品管理工作台（P02）
   - 商品中心（P03主从列表+P06主从表单，关联信息区含多维度标签页）
   - 商品分类（P05树形列表）
   - 各子功能列表页（P04）+ 表单页（P07）
   - BOM成本报表（P10报表页）

### 3.2 业务规则
- **基线与扩展优先级**：19个基线功能点优先开发，8个V8扩展项在基线完成后开发
- **商品编码唯一性**：通过数据库行级锁保证唯一性，编码生成需在事务内完成
- **BOM层级校验**：BOM展开深度限制10层，需进行循环引用检测（A引用B、B引用C、C引用A）
- **多单位转换率**：所有非基础单位的转换率必须以基础单位为基准换算（base_qty = qty × conversion_rate）
- **商品图片管理**：为用户明确要求保留项，须确保开发完成
- **快照字段不可修改**：商品快照字段（product_code/product_name/model/spec/brand/unit）在单据保存后不可修改

### 3.3 状态流转
- **商品审核状态**：草稿(draft) → 已审核(approved)，审核通过后才可被业务单据引用
- **商品启用状态**：启用(enabled) ↔ 禁用(disabled)
- **BOM版本状态**：草稿 → 已审核 → 默认版本（同一商品仅一个默认BOM版本）
- **商品工序版本状态**：草稿 → 已审核 → 默认版本

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **P0-007-001 商品管理后端开发**（前端依赖后端接口）
2. **P0-007-001** → **P0-007-002 商品管理前端页面**

后端内部开发顺序：
1. 商品分类CRUD（其他商品功能依赖分类树）
2. 商品主表CRUD（多单位/控制策略/价格等依赖商品主表）
3. 商品多单位/控制策略/安全库存/附件/其他信息CRUD
4. 商品标准价/购价核定/销价核定/竞品CRUD
5. 标准工序CRUD → 商品工序CRUD → 工序参数/加工价格CRUD
6. BOM管理（依赖商品主表+标准工序）
7. V8扩展功能
8. 工作台聚合接口

### 5.2 可并行执行的任务
- 商品多单位、控制策略、安全库存、附件、其他信息CRUD可并行（均仅依赖商品主表）
- 商品标准价、购价核定、销价核定、竞品CRUD可并行
- 前端页面中各子功能列表页/表单页可并行开发（各自独立页面）
- V8扩展项之间可并行开发
