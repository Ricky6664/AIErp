## 1. 模块架构约束

### 1.1 模块定位
P0-012负责开发ERP系统的HRM人力资源管理功能，包括员工档案管理（员工基本信息+详细档案）、招聘管理、考勤管理、薪资管理（主从表结构）。本模块为全系统提供人员基础数据支撑，被CRM客户评价、SRM供应商评价、销售/采购/库存/生产/委外等业务模块引用（评价人/业务员/仓管员等角色引用员工数据）。

### 1.2 依赖关系
- 前置依赖：
  - P0-001（后端框架）
  - P0-002（前端框架）
  - P0-003（数据库提供hrm_*系列表）
  - P0-004（认证与权限）
  - P0-005（公共组件提供页面基座/选择器）
  - P0-006（组织架构提供部门/岗位数据——员工关联部门和岗位）
- 后续依赖：
  - P0-008（CRM客户评价/机会引用评价人）
  - P0-009（SRM供应商评价引用评价人）
  - P1-005~P1-009（销售/采购/库存/生产/委外引用业务员）

### 1.3 技术约束
- **技术栈约束**：Spring Boot 3.4.x + MyBatis-Plus 3.5.5 + Vue3 + Element Plus + Vxe Table
- **性能约束**：员工列表查询 < 200ms（1万员工）；考勤月度汇总查询 < 300ms；薪资计算 < 500ms
- **安全约束**：身份证号在列表展示时脱敏（保留前6后4），仅详情查看且有权限时展示完整号码；工号全局唯一

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| hrm_employee | 员工表 | employee_no, employee_name, gender, id_card, phone, email, department_id, position_id, hire_date, employee_status |
| hrm_employee_archive | 员工档案表 | employee_id, education, major, university, emergency_contact, emergency_phone, address, bank_card, bank_name, social_security_no |
| hrm_recruitment | 招聘表 | position_id, department_id, recruit_count, salary_range, requirements, recruitment_status, deadline |
| hrm_attendance | 考勤表 | employee_id, attendance_date, clock_in, clock_out, work_hours, attendance_type, overtime_hours |
| hrm_salary | 薪资主表 | employee_id, fiscal_year, fiscal_month, base_salary, overtime_pay, bonus, deduction, gross_pay, net_pay, payment_status |
| hrm_salary_detail | 薪资明细表 | salary_id, line_no, item_name, item_type(加项/减项), amount |

### 2.2 表关系图
- `hrm_employee` N:1 `org_department`（department_id）：员工属于一个部门
- `hrm_employee` N:1 `org_position`（position_id）：员工担任一个岗位
- `hrm_employee` 1:1 `hrm_employee_archive`（employee_id）：员工与详细档案一对一
- `hrm_employee` 1:N `hrm_attendance`（employee_id）：员工与考勤记录一对多
- `hrm_employee` 1:N `hrm_salary`（employee_id）：员工与薪资记录一对多
- `hrm_salary` 1:N `hrm_salary_detail`（salary_id）：薪资主表与明细一对多
- `hrm_recruitment` N:1 `org_position` + N:1 `org_department`：招聘关联岗位和部门
- `hrm_employee`被引用关系：sys_user.employee_id（系统用户关联员工）、crm_customer_evaluation.evaluator_id、srm_supplier_evaluation.evaluator_id

### 2.3 数据流转
1. **员工新增流程**：选择部门/岗位 → 填写基本信息 → 编码引擎生成工号 → 工号唯一性校验 → 部门岗位关联校验 → 保存员工 → 可继续维护详细档案
2. **考勤管理流程**：选择员工+日期 → 录入打卡时间 → 自动计算工作时长 → 判断考勤类型（正常/迟到/早退/缺勤/加班）→ 员工+日期唯一性校验 → 保存
3. **薪资计算流程**：选择员工+月份 → 自动汇总该月考勤数据 → 计算加班费 → 录入奖金/扣款 → 添加薪资明细（加项/减项）→ 计算应发工资和实发工资 → 保存

## 3. 业务流程

### 3.1 核心业务流程
1. **HRM后端开发**（P0-012-001）：
   - 员工CRUD（含工号唯一性+部门岗位关联校验）
   - 员工档案CRUD（一对一关联员工）
   - 全部启用员工查询接口（供下拉选择器使用）
   - 招聘CRUD
   - 考勤CRUD（含员工+日期唯一性校验+月度汇总查询）
   - 薪资CRUD（主从保存+薪资计算接口）
   - HRM工作台聚合接口
2. **HRM前端页面**（P0-012-002）：
   - HRM工作台（P02：员工总数/本月入职/考勤异常/待审薪资统计）
   - 员工中心（P03主从列表+P06主从表单，关联信息区含员工档案标签页）
   - 员工档案列表页（P04）+ 表单页（P07弹窗大）
   - 招聘管理列表页（P04）+ 表单页（P07弹窗大）
   - 考勤管理列表页（P04）+ 表单页（P07弹窗中）
   - 薪资管理（P03主从列表+P06主从表单，关联信息区含薪资明细标签页）

### 3.2 业务规则
- **开发优先级**：员工档案（hrm_employee + hrm_employee_archive）为核心基础数据，必须优先开发并为其他模块提供人员选择器；招聘/考勤/薪资建议P1核心业务完成后再深度开发
- **工号唯一性**：工号在系统内全局唯一，编码生成需在事务内完成
- **部门岗位关联校验**：新增/修改员工时需校验部门ID与岗位ID有效且启用，岗位需属于所选部门
- **薪资计算精度**：金额字段保留4位小数；应发工资 = 基本工资 + 加班费 + 奖金 + 加项明细 - 减项明细；实发工资 = 应发工资 - 扣款；误差不得超过0.01
- **薪资发放状态流转**：待发放→已发放单向流转，已发放后不可修改，需通过红冲+重发处理
- **考勤日期唯一性**：同一员工同一考勤日期只能有一条记录
- **身份证号脱敏**：列表展示时脱敏（保留前6后4），仅详情+有权限时展示完整号码

### 3.3 状态流转
- **员工状态**：试用期(probation) → 在职(active) → 离职(resigned)
- **招聘状态**：招聘中(recruiting) → 已完成(completed) / 已取消(cancelled)
- **考勤类型**：正常(normal) / 迟到(late) / 早退(early) / 缺勤(absent) / 加班(overtime)
- **薪资发放状态**：待发放(pending) → 已发放(paid)，已发放后不可修改

### 4.2 依赖接口

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **P0-012-001 HRM后端开发**（前端依赖后端接口）
2. **P0-012-001** → **P0-012-002 HRM前端页面**

后端内部开发顺序：
1. 员工CRUD + 员工档案CRUD（核心基础数据，必须最先完成，为其他模块提供人员选择器）
2. 招聘CRUD（独立模块）
3. 考勤CRUD（独立模块，可被薪资计算引用）
4. 薪资CRUD + 薪资计算接口（依赖考勤数据）

### 5.2 可并行执行的任务
- 招聘CRUD和考勤CRUD可并行开发（互不依赖）
- 前端页面中员工中心、招聘管理、考勤管理三个页面可并行开发
- 薪资管理页面可在考勤管理完成后开发
- 员工档案CRUD可与招聘/考勤CRUD并行（仅依赖员工主表）
