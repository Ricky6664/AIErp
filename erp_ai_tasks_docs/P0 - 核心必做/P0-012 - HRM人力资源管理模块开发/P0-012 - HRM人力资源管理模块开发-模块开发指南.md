# P0-012 HRM人力资源管理模块开发 - 模块开发指南

## 一、模块概述

- **模块定位**：员工档案基础数据 + 招聘管理 + 考勤管理 + 薪资管理，为全系统提供人员基础数据支撑
- **前置依赖**：P0-001（后端框架）、P0-002（前端框架）、P0-003（数据库）、P0-004（认证与权限）、P0-005（公共组件）、P0-006（组织架构提供部门/岗位数据）
- **被依赖方**：P0-008（CRM客户评价/机会引用评价人）、P0-009（SRM供应商评价引用评价人）、P1-005~P1-009（销售/采购/库存/生产/委外引用业务员）
- **开发阶段**：阶段五（基础数据）

### 模块级专属约束

1. **开发优先级**：员工档案（hrm_employee + hrm_employee_archive）为核心基础数据，必须优先开发并为其他模块提供人员选择器；招聘管理、考勤管理、薪资管理属HR运营功能，建议在P1核心业务完成后再进行深度开发，不影响其他模块的依赖关系。
2. **工号唯一性**：工号在系统内全局唯一，编码生成需在事务内完成，禁止并发重复。
3. **部门岗位关联校验**：新增/修改员工时，需校验部门ID与岗位ID是否有效且启用，岗位需属于所选部门。
4. **薪资计算精度**：薪资相关金额字段保留4位小数，应发工资 = 基本工资 + 加班费 + 奖金 + 加项明细 - 减项明细；实发工资 = 应发工资 - 扣款，计算误差不得超过0.01。
5. **薪资发放状态流转**：薪资发放状态按"待发放→已发放"单向流转，已发放后不可修改薪资数据，需通过红冲+重发流程处理。
6. **考勤日期唯一性**：同一员工同一考勤日期只能有一条考勤记录，新增时需进行员工+日期唯一性校验。
7. **身份证号脱敏**：员工身份证号在列表展示时需进行脱敏处理（保留前6后4），仅在详情查看且有权限时展示完整号码。

| monthly(Long employeeId, int year, int month) | 无(只读) | 按员工+月份查询考勤汇总统计（正常/迟到/早退/缺勤/加班天数、总工时、总加班时长） |
| getById(Long) | 无(只读) | 返回AttendanceDetailVO |
| create(AttendanceCreateDTO) | @Transactional | 员工存在性校验 → 员工+日期唯一性校验 → 打卡时间合理性校验 → 工时自动计算 → save |
| update(id, AttendanceUpdateDTO) | @Transactional | 存在性校验 → 员工+日期唯一性(排除自身) → 工时重新计算 → 乐观锁更新 |
| delete(Long) | @Transactional | 存在性校验 → 逻辑删除 |

### 6.5 HrmSalaryService

| 方法 | 事务 | 业务逻辑要点 |
|------|------|------------|
| page(SalaryQueryDTO) | 无(只读) | 按employeeId/periodYear/periodMonth/payStatus筛选，联查工号/姓名 |
| getById(Long) | 无(只读) | 返回SalaryDetailVO，含薪资明细列表(details) |
| create(SalaryCreateDTO) | @Transactional | 员工存在性校验 → 员工+月份唯一性校验 → 自动计算应发工资/实发工资 → 主从表保存(薪资主表+明细) → 操作日志 |
| update(id, SalaryUpdateDTO) | @Transactional | 存在性校验 → 已发放状态校验(paid不可修改) → 唯一性校验(排除自身) → 重新计算应发/实发 → 主从表保存(先删旧明细再插新明细) → 乐观锁更新 |
| delete(Long) | @Transactional | 存在性校验 → 已发放状态校验(paid不可删除) → 删除明细 → 删除主表 → 操作日志 |
| calculate(Long employeeId, int year, int month) | @Transactional | 查询员工基本工资 → 汇总该月考勤数据(加班费) → 汇总明细项目 → 计算gross/net → 返回SalaryCalculateVO |

### 6.6 HrmSalaryDetailService

| 方法 | 事务 | 业务逻辑要点 |
|------|------|------------|
| listBySalaryId(Long salaryId) | 无(只读) | 按salaryId查询全部明细行，按lineNo排序 |
| create(SalaryDetailCreateDTO) | @Transactional | 薪资主表存在性校验 → 主表状态校验(paid不可追加) → 行号唯一性校验 → save |
| update(id, SalaryDetailUpdateDTO) | @Transactional | 存在性校验 → 主表状态校验 → 乐观锁更新 |
| delete(Long) | @Transactional | 存在性校验 → 主表状态校验 → 逻辑删除 |

> 注：薪资明细通常通过薪资主表的主从保存（create/update）统一操作，独立CRUD接口供特殊场景使用。

### 6.7 HrmWorkbenchService

| 方法 | 事务 | 业务逻辑要点 |
|------|------|------------|
| getWorkbenchData() | 无(只读) | 聚合查询：员工总数(在职/试用期/离职分布) + 本月入职人数 + 本月考勤异常数(迟到+早退+缺勤) + 待审薪资数 + 进行中的招聘数 |
