## 1. 模块架构约束

### 1.1 模块定位
P0-014负责搭建ERP系统的测试基础设施，包括后端测试框架搭建（JUnit 5 + Mockito + Testcontainers）、前端测试框架搭建（Vitest + Vue Test Utils）、测试规范与基础设施（测试基类/数据工厂/覆盖率门禁/测试报告/测试规范文档）。本模块确保测试覆盖率达到项目质量标准，为所有业务模块的单元测试和集成测试提供统一框架和模板。

### 1.2 依赖关系
- 前置依赖：
  - P0-001（后端框架提供Spring Boot测试集成点+MyBatis-Plus Mapper）
  - P0-002（前端框架提供Vue组件测试集成点+Composable函数）
- 后续依赖：
  - P0-006~P0-012（所有基础数据模块的单元测试/集成测试）
  - P1级所有模块
  - P2级所有模块

### 1.3 技术约束
- **技术栈约束（后端）**：JUnit 5.10.x + Mockito 5.x + AssertJ 3.x + H2 Database 2.x + Testcontainers PostgreSQL 1.19.x + Spring Boot Starter Test + JaCoCo 0.8.x
- **技术栈约束（前端）**：Vitest 1.x + Vue Test Utils 2.x + Happy-DOM + @vitest/coverage-v8 + MSW 2.x
- **性能约束**：单元测试套件执行时间 < 5分钟；集成测试套件执行时间 < 15分钟；覆盖率报告生成 < 1分钟
- **安全约束**：测试数据统一使用TEST_前缀标记，防止测试数据泄漏到生产环境；集成测试使用独立Docker容器，测试后销毁

### 2.2 表关系图
本模块不涉及业务数据库表，但维护以下测试基础设施文件：
- **测试基类**：BaseServiceTest（@SpringBootTest + Testcontainers PostgreSQL + 通用Mock方法 + @Transactional事务回滚）
- **测试数据工厂**：TestDataFactory（buildEntity/buildDTO/buildPage/buildUser等通用方法，各业务模块继承扩展）
- **测试配置**：application-test.yml（测试环境配置，H2内存数据库/Testcontainers PostgreSQL）
- **覆盖率配置**：JaCoCo pom.xml配置 + Vitest vitest.config.ts配置
- **测试规范文档**：docs/TESTING_GUIDE.md

### 2.3 数据流转
1. **后端测试执行流**：mvn test → 加载测试配置 → 单元测试（Mockito Mock依赖）→ 集成测试（Testcontainers启动PostgreSQL容器）→ JaCoCo收集覆盖率 → 生成HTML/XML报告
2. **前端测试执行流**：npm run test:coverage → Vitest加载配置 → 组件单元测试（Vue Test Utils mount）→ Composable测试（renderComposable）→ MSW拦截API → V8收集覆盖率 → 生成lcov报告
3. **CI门禁流**：CI流水线执行测试 → 收集覆盖率报告 → 比对阈值 → 低于阈值则流水线失败 → 上传报告为artifact → PR评论展示覆盖率变化

## 3. 业务流程

### 3.1 核心业务流程
1. **后端测试框架搭建**（P0-014-001）：
   - 配置pom.xml测试依赖（junit-jupiter/mockito/assertj/h2/testcontainers/jacoco）
   - 开发BaseServiceTest测试基类（@SpringBootTest + Testcontainers PostgreSQL + @Transactional事务回滚 + AssertJ断言工具）
   - 开发TestDataFactory通用数据工厂（buildEntity/buildDTO/buildPage/buildUser）
   - 配置application-test.yml（H2内存数据库/Testcontainers连接）
   - 配置JaCoCo覆盖率插件（行覆盖率+分支覆盖率+HTML/XML报告输出）
   - 编写各层测试模板：
     - Service层：@ExtendWith(MockitoExtension.class) + @Mock + @InjectMocks + given/when/then + 覆盖率≥80%
     - Controller层：@WebMvcTest + MockMvc + @MockBean + JSON断言 + 覆盖率≥70%
     - Mapper层：@MybatisPlusTest + @Sql + H2 + 覆盖率≥60%
     - 集成测试：@SpringBootTest + Testcontainers + @Transactional自动回滚
2. **前端测试框架搭建**（P0-014-002）：
   - 配置package.json测试依赖（vitest/@vue/test-utils/happy-dom/@vitest/coverage-v8/msw）
   - 配置vitest.config.ts（测试文件匹配/DOM环境/覆盖率配置）
   - 配置MSW API Mock服务（拦截HTTP请求+响应模拟+错误场景覆盖）
   - 编写各层测试模板：
     - 组件单元测试：mount + props传参 + 事件触发 + DOM断言 + 快照测试 + 覆盖率≥70%
     - Composable测试：renderComposable + 响应式状态验证 + 异步操作测试
     - API Mock策略：MSW拦截 + 401/403/500错误场景 + Loading状态测试
3. **测试规范与基础设施**（P0-014-003）：
   - 配置CI覆盖率门禁（后端Service≥80%/Controller≥70%/Mapper≥60%/前端组件≥70%）
   - 配置测试报告集成（JaCoCo HTML/XML + Vitest lcov + CI artifact上传 + PR评论覆盖率变化）
   - 配置覆盖率徽章（README.md展示Service/Controller/前端组件三项徽章）
   - 编写docs/TESTING_GUIDE.md测试规范文档（框架配置/模板示例/命名规范/数据准备/报告查看/问题排查）

### 3.2 业务规则
- **测试覆盖率阈值（CI门禁强制校验）**：
  - 后端Service层：行覆盖率≥80%，分支覆盖率≥70%
  - 后端Controller层：行覆盖率≥70%
  - 后端Mapper层：行覆盖率≥60%
  - 前端组件：行覆盖率≥70%，分支覆盖率≥60%
  - 覆盖率低于阈值时流水线强制失败，禁止合并
- **测试命名规范**：
  - 测试类：`<被测类名>Test`（如UserServiceTest）
  - 测试方法：`should_<预期行为>_when_<条件>`（如should_createUserSuccessfully_when_validInput）
  - 测试结构：所有测试方法使用given/when/then三段式注释
- **测试数据隔离策略**：
  - 单元测试：MockitoExtension，不依赖真实数据库
  - 集成测试：Testcontainers独立PostgreSQL容器，测试后销毁
  - 数据前缀标记：测试数据统一使用TEST_前缀
  - 并行测试安全：@TestInstance(PER_CLASS) + 数据库事务回滚
- **测试报告集成**：JaCoCo HTML报告（target/site/jacoco/index.html）+ Vitest Coverage（coverage/lcov-report/index.html）+ CI artifact上传 + PR评论 + 覆盖率徽章

### 3.3 状态流转
- **测试执行状态**：pending → running → passed / failed → coverage_collected → gate_checked（通过/未通过门禁）
- **覆盖率门禁状态**：passed（全部指标达标）/ failed（任一指标未达标）→ failed时CI流水线终止

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **P0-014-001 后端测试框架搭建**（测试规范依赖测试框架）
2. **P0-014-002 前端测试框架搭建**（测试规范依赖测试框架）
3. **P0-014-001 + P0-014-002** → **P0-014-003 测试规范与基础设施**（规范文档和CI门禁依赖前后端测试框架均已就绪）

### 5.2 可并行执行的任务
- P0-014-001（后端测试框架）和P0-014-002（前端测试框架）完全独立，可并行开发
- 后端测试框架内部：BaseServiceTest基类、TestDataFactory数据工厂、各层测试模板可并行编写
- 前端测试框架内部：vitest配置、MSW配置、各层测试模板可并行编写
- P0-014-003中的测试规范文档（TESTING_GUIDE.md）可在框架搭建过程中同步编写
