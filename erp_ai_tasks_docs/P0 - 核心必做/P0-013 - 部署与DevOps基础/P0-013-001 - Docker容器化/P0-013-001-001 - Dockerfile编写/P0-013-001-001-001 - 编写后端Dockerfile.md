### 5.1 多阶段构建结构

后端Dockerfile采用两阶段构建，严格分离构建环境与运行环境，减小最终镜像体积并提高安全性：

1. **阶段1 - 构建镜像（builder）**：基于 `maven:3.9-eclipse-temurin-17`
   - 工作目录：`/build`
   - 先COPY `pom.xml` 执行 `mvn dependency:go-offline -B`，利用Docker层缓存加速后续构建
   - 再COPY `src/` 目录，执行 `mvn clean package -DskipTests -B` 生成可执行jar
2. **阶段2 - 运行镜像（runtime）**：基于 `eclipse-temurin:17-jre`（或 `eclipse-temurin:17-jre-alpine`）
   - 工作目录：`/app`
   - 仅从builder阶段COPY构建产物 `*.jar`，不携带源码与Maven依赖
   - 运行镜像体积目标：< 300MB

### 5.2 JAR分层优化

1. 在 `pom.xml` 中启用 Spring Boot 分层jar（`<layers><enabled>true</enabled></layers>`）
2. Dockerfile中使用 `java -Djarmode=layertools -jar app.jar extract` 解压分层
3. 按 `dependencies` / `spring-boot-loader` / `snapshot-dependencies` / `application` 顺序逐层COPY
4. 不常变动的依赖层靠前，频繁变动的应用层靠后，最大化利用Docker层缓存

### 5.3 非root用户与安全配置

1. 在运行镜像中创建非root用户：`addgroup -S appgroup && adduser -S appuser -G appgroup`（UID/GID=1001）
2. 使用 `USER appuser` 切换运行身份，禁止以root身份运行Java进程
3. 设置文件权限：`chown -R appuser:appgroup /app`
4. 禁止在镜像中 bake 任何密钥、密码或凭证

### 5.4 环境变量与JVM参数

通过 `ENV` 指令注入运行时参数，支持在docker-compose或K8s中覆盖：

1. `JAVA_OPTS="-Xms512m -Xmx1024m -XX:+UseG1GC -XX:MaxGCPauseMillis=200 -XX:+HeapDumpOnOutOfMemoryError"`
2. `SPRING_PROFILES_ACTIVE=prod`（默认prod，可在运行时覆盖）
3. `TZ=Asia/Shanghai`（时区设置，同时软链接 `/etc/localtime`）
4. `LANG=C.UTF-8`（字符集设置）

### 5.5 端口与健康检查

1. `EXPOSE 8080`：暴露Spring Boot应用端口
2. HEALTHCHECK配置：
   ```
   HEALTHCHECK --interval=30s --timeout=10s --start-period=60s --retries=3 \
     CMD wget -q --spider http://localhost:8080/actuator/health || exit 1
   ```
3. 启动周期（start-period）设为60s，给Spring Boot足够的启动时间
4. 健康检查端点依赖后端 `/actuator/health`（由P0-001后端框架提供）

### 5.6 ENTRYPOINT与启动命令

```dockerfile
ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar app.jar --spring.profiles.active=$SPRING_PROFILES_ACTIVE"]
```

1. 使用 `sh -c` 形式以便环境变量 `$JAVA_OPTS` 能被正确展开
2. 支持通过 `docker run -e JAVA_OPTS="..."` 覆盖JVM参数
3. 支持通过 `docker run -e SPRING_PROFILES_ACTIVE=dev` 切换环境

### 5.7 镜像元数据

1. `LABEL maintainer="erp-team"`：标注维护者
2. `LABEL version="${BUILD_VERSION}"`：可选，构建时通过 `--build-arg` 注入版本号
3. `LABEL description="ERP Backend Service"`：镜像描述

### 5.8 验证

1. `docker build -t erp-backend:latest .` 构建成功无错误
2. `docker images` 查看镜像体积 < 300MB
3. `docker run --rm erp-backend:latest whoami` 确认运行用户为 appuser
4. `docker inspect` 确认HEALTHCHECK配置正确
5. `docker compose up backend` 容器启动并通过健康检查

## 八、易错警示

> ⚠️ 禁止在Dockerfile中硬编码数据库密码、JWT密钥等敏感信息，必须通过环境变量或Secret注入

> ⚠️ 必须使用非root用户运行容器，避免容器逃逸风险

> ⚠️ 必须使用具体版本标签（如 `eclipse-temurin:21-jre-slim`），禁止使用 `latest` 标签避免不可复现构建

> ⚠️ 构建阶段先COPY `pom.xml` 再COPY源码，利用Docker层缓存加速依赖下载

> ⚠️ 运行镜像仅包含JRE，不要包含完整JDK或Maven，避免镜像过大与攻击面扩大

> ⚠️ HEALTHCHECK的 `start-period` 必须足够长（≥60s），否则Spring Boot启动期间会被误判为不健康

> ⚠️ 使用 `sh -c` 形式ENTRYPOINT以便环境变量展开，直接使用 `java -jar` 形式会导致 `$JAVA_OPTS` 不生效
