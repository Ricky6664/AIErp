### 5.1 多阶段构建结构

前端Dockerfile采用两阶段构建，将Node构建环境与Nginx运行环境分离：

1. **阶段1 - 构建镜像（builder）**：基于 `node:20-alpine`
   - 工作目录：`/build`
   - 先COPY `package.json` 和 `package-lock.json`，执行 `npm ci` 安装依赖（利用Docker层缓存）
   - 再COPY前端源码（`src/`、`public/`、`vite.config.*` 等），执行 `npm run build` 生成 `dist/` 产物
   - 构建过程中启用 `NODE_OPTIONS="--max-old-space-size=2048"` 避免OOM
2. **阶段2 - 运行镜像（runtime）**：基于 `nginx:1.27-alpine`
   - 仅从builder阶段COPY `dist/` 目录到 `/usr/share/nginx/html`
   - COPY自定义 `nginx.conf` 到 `/etc/nginx/conf.d/default.conf`
   - 运行镜像体积目标：< 50MB

### 5.2 静态资源与gzip压缩

1. Vite构建时启用gzip压缩插件（`vite-plugin-compression`），预生成 `.gz` 文件
2. Nginx配置 `gzip_static on` 优先返回预压缩文件
3. 对未预压缩文件启用动态gzip：`gzip on; gzip_min_length 1024; gzip_types text/css application/javascript application/json image/svg+xml`
4. 静态资源文件名带content-hash（如 `app.[hash].js`），便于长期缓存

### 5.3 缓存策略

1. `js`/`css`/图片等带hash的静态资源：`Cache-Control: public, max-age=31536000, immutable`
2. `index.html` 与其他无hash文件：`Cache-Control: no-cache, no-store, must-revalidate`
3. 字体文件（woff2/ttf）：`Cache-Control: public, max-age=31536000`

### 5.4 安全头（CSP与其他）

在Nginx配置中添加以下安全头：

1. `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self' data:; connect-src 'self' https://api.erp.example.com`
2. `X-Frame-Options: SAMEORIGIN`（防止点击劫持）
3. `X-Content-Type-Options: nosniff`（防止MIME嗅探）
4. `X-XSS-Protection: 1; mode=block`（XSS过滤）
5. `Strict-Transport-Security: max-age=31536000; includeSubDomains`（HSTS）
6. `Referrer-Policy: strict-origin-when-cross-origin`

### 5.5 非root用户与安全配置

1. Nginx官方alpine镜像默认以root启动master进程，worker进程以nginx用户运行（可接受）
2. 若需更高安全等级，使用 `nginx:1.27-alpine-slim` 配合自定义UID
3. 移除Nginx默认站点配置与示例文件：`rm /etc/nginx/conf.d/default.conf` 后替换为自定义配置
4. 删除版本头：`server_tokens off;` 与 `more_clear_headers Server;`

### 5.6 端口与健康检查

1. `EXPOSE 80`：暴露HTTP端口（HTTPS由外层反向代理或K8s Ingress处理）
2. HEALTHCHECK配置：
   ```
   HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
     CMD wget -q --spider http://localhost:80/ || exit 1
   ```
3. 在 `/usr/share/nginx/html/healthz` 放置一个静态健康检查文件，避免SPA路由返回404

### 5.7 SPA路由支持

1. Nginx配置 `try_files $uri $uri/ /index.html;` 支持Vue Router的History模式
2. 避免刷新页面时出现404

### 5.8 验证

1. `docker build -t erp-frontend:latest .` 构建成功无错误
2. `docker images` 查看镜像体积 < 50MB
3. `docker run -p 8080:80 erp-frontend:latest` 启动容器
4. 浏览器访问 `http://localhost:8080` 正常显示前端页面
5. 刷新页面时SPA路由正常工作（不返回404）
6. 响应头中包含CSP、X-Frame-Options等安全头
7. 静态资源带 `Cache-Control: public, max-age=31536000`

## 八、易错警示

> ⚠️ 必须使用 `npm ci` 而非 `npm install`，确保依赖版本与lock文件一致，构建可复现

> ⚠️ 构建阶段先COPY `package*.json` 再COPY源码，利用Docker层缓存加速依赖安装

> ⚠️ 必须配置 `try_files $uri $uri/ /index.html;` 否则SPA路由刷新会返回404

> ⚠️ CSP策略要兼顾项目实际需求，过严会导致第三方资源（如字体、图标、CDN）加载失败

> ⚠️ 不要在运行镜像中包含Node.js与源码，只保留Nginx与构建产物，减小镜像体积与攻击面

> ⚠️ 静态资源文件名必须带content-hash，否则长期缓存会导致用户访问旧版本

> ⚠️ 禁止在镜像中 bake `.env.production` 中的敏感信息（如API Key），应通过运行时环境变量或Nginx模板注入

> ⚠️ Nginx版本头要通过 `server_tokens off;` 关闭，避免暴露版本号给攻击者
