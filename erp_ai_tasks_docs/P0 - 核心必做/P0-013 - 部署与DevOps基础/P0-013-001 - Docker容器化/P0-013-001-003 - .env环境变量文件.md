### 5.1 环境文件结构

按环境隔离配置3套独立的.env文件：

1. `.env.dev`：开发环境（本地开发、调试用）
2. `.env.staging`：预发布环境（接近生产配置，用于验收测试）
3. `.env.prod`：生产环境（高可用、安全加固、SSL启用）
4. `.env.example`：变量模板（提交到Git，供开发者复制为本地.env文件）

**关键原则**：`.env.dev`/`.env.staging`/`.env.prod` 必须加入 `.gitignore`，仅 `.env.example` 提交到代码仓库。

### 5.2 变量分类与命名规范

变量按功能模块分组，统一使用大写蛇形命名：

```bash
# ==================== 通用配置 ====================
COMPOSE_PROJECT_NAME=erp
ENV=dev                          # dev / staging / prod
TZ=Asia/Shanghai
TAG=latest                       # 镜像标签

# ==================== PostgreSQL ====================
DB_HOST=postgres
DB_PORT=5432
DB_NAME=erp
DB_USER=erp_user
DB_PASSWORD=<strong-password>    # 必填，禁止使用默认值
DB_POOL_SIZE=20

# ==================== Redis ====================
REDIS_HOST=redis
REDIS_PORT=6379
REDIS_PASSWORD=<strong-password>

# ==================== MinIO ====================
MINIO_ENDPOINT=http://minio:9000
MINIO_ACCESS_KEY=erp_minio
MINIO_SECRET_KEY=<strong-password>
MINIO_BUCKET=erp-files

# ==================== Elasticsearch ====================
ES_HOST=elasticsearch
ES_PORT=9200
ES_USERNAME=elastic              # prod环境启用xpack后生效
ES_PASSWORD=<strong-password>

# ==================== 后端应用 ====================
SPRING_PROFILES_ACTIVE=dev
JAVA_OPTS=-Xms512m -Xmx1024m -XX:+UseG1GC
JWT_SECRET=<random-256-bit-key>
JWT_EXPIRATION=86400

# ==================== 前端应用 ====================
VITE_API_BASE_URL=/api
VITE_APP_TITLE=ERP管理系统

# ==================== 外部服务（可选）====================
SMTP_HOST=
SMTP_PORT=587
SMTP_USER=
SMTP_PASSWORD=
SMS_API_KEY=
```

### 5.3 环境差异

| 配置项 | dev | staging | prod |
|--------|-----|---------|------|
| `ENV` | dev | staging | prod |
| `SPRING_PROFILES_ACTIVE` | dev | staging | prod |
| `JAVA_OPTS` | `-Xms256m -Xmx512m -agentlib:jdwp=...` | `-Xms512m -Xmx1024m` | `-Xms1024m -Xmx2048m -XX:+UseG1GC` |
| `DB_PASSWORD` | 弱密码可接受 | 强密码 | 强密码+定期轮换 |
| `VITE_API_BASE_URL` | `http://localhost:8080` | `/api` | `/api` |
| 日志级别 | DEBUG | INFO | WARN |
| SSL | 关闭 | 可选 | 强制启用 |

### 5.4 密钥生成与存储

1. 所有密码/密钥禁止人工臆造弱密码，使用以下命令生成：
   - `openssl rand -base64 32`（数据库密码、Redis密码）
   - `openssl rand -hex 32`（JWT_SECRET 256位）
2. 生产环境密钥推荐通过K8s Secret、AWS Secrets Manager、HashiCorp Vault等专用工具管理，.env文件仅作为开发/staging的简化方案
3. 仓库中仅保留 `.env.example`，使用占位符 `<replace-me>` 标注需要填充的变量

### 5.5 与docker-compose.yml集成

1. docker-compose.yml通过 `env_file: .env` 或 `${VAR}` 引用变量
2. 启动命令：
   - 开发环境：`docker compose --env-file .env.dev up -d`
   - 预发布：`docker compose --env-file .env.staging up -d`
   - 生产：`docker compose --env-file .env.prod up -d`
3. 也可通过 `COMPOSE_ENV_FILES` 环境变量或 `docker-compose.override.yml` 指定

### 5.6 .gitignore配置

确保以下条目在 `.gitignore` 中：

```
.env
.env.dev
.env.staging
.env.prod
.env.local
!.env.example
```

### 5.7 验证

1. 使用 `docker compose --env-file .env.dev config` 校验变量正确注入
2. 使用 `docker compose --env-file .env.dev up -d` 启动，所有服务健康
3. 使用脚本扫描 `.env.*` 文件中是否存在弱密码（如 `password`、`123456`）
4. 确认 `.env.dev` 等未被提交到Git（`git ls-files | grep .env` 应只返回 `.env.example`）

## 八、易错警示

> ⚠️ 绝对禁止将 `.env.dev`/`.env.staging`/`.env.prod` 提交到Git，仓库中只允许 `.env.example`

> ⚠️ 生产环境密码禁止使用弱密码（如 `password`、`admin123`、`erp2024`），必须使用 `openssl rand` 生成强密码

> ⚠️ 生产环境JWT_SECRET必须为高强度随机字符串，被泄露会导致所有token可伪造

> ⚠️ 不同环境的数据库必须物理隔离，禁止dev/staging连接到prod数据库

> ⚠️ `.env.example` 中要包含所有变量及注释说明，新人拿到后能快速复制为本地.env

> ⚠️ docker-compose.yml中使用 `${VAR:-default}` 语法设置默认值，避免变量缺失时容器启动失败

> ⚠️ 敏感文件权限：`.env.prod` 文件在服务器上应设置 `chmod 600`，仅属主可读

> ⚠️ 环境变量变更后必须重启对应服务（`docker compose up -d --force-recreate`），仅重启容器不一定生效
