### 5.1 .dockerignore作用

`.dockerignore` 决定哪些文件不会发送到Docker daemon的构建上下文，影响：

1. **构建速度**：减小上下文体积，加快 `docker build` 传输与缓存
2. **镜像体积**：避免无关文件被COPY进镜像
3. **安全性**：防止密钥、日志、IDE配置等敏感文件进入镜像
4. **缓存命中率**：避免频繁变动的本地文件（如.git）导致Docker层缓存失效

### 5.2 必须排除的目录与文件

按分类组织 `.dockerignore` 条目：

### 5.3 特殊处理

1. **白名单语法**：使用 `!` 前缀可以反向包含之前被排除的文件，如 `!**/README.md` 保留所有子目录README
2. **通配符**：支持 `*`、`**`、`?` 等glob语法
3. **注释**：使用 `#` 开头注释，方便维护
4. **后端Dockerfile场景**：后端Dockerfile位于 `deploy/backend/Dockerfile` 时，构建上下文通常是项目根目录，因此根目录 `.dockerignore` 生效
5. **前端Dockerfile场景**：同上，前端Dockerfile共享根目录 `.dockerignore`

### 5.4 多Dockerfile场景

Docker支持 `<Dockerfile>.dockerignore` 机制（Docker 1.x+）：

1. 如果后端Dockerfile路径为 `deploy/backend/Dockerfile`，可以创建 `deploy/backend/Dockerfile.dockerignore` 独立控制
2. 本任务统一使用项目根目录 `.dockerignore`，简化维护
3. 如果未来有复杂的构建场景，可以拆分为多个独立 `.dockerignore`

### 5.5 验证

1. 使用 `docker build` 观察构建上下文大小：`Sending build context to Docker daemon  XX.XXMB`，应该< 50MB
2. 使用 `docker history <image>` 检查镜像层，确认无.git/node_modules等
3. 使用工具 `docker run --rm -it -v $(pwd):/workdir -w /workdir alpine sh -c "du -sh . --exclude=node_modules --exclude=target"` 估算有效上下文
4. 进入构建后的镜像验证：`docker run --rm <image> ls -la /app` 确认仅含所需文件

### 5.6 与团队同步

1. `.dockerignore` 条目变更要在PR中说明原因
2. 与 `.gitignore` 保持一定一致性（但也有区别：.gitignore管版本控制，.dockerignore管构建上下文）
3. 新增大型目录时要评估是否需要加入 `.dockerignore`

## 八、易错警示

> ⚠️ `.dockerignore` 与 `.gitignore` 是两个不同文件，作用范围不同，不要混淆

> ⚠️ 不要排除 `pom.xml`、`package.json`、`src/` 等构建必需文件，否则镜像构建会失败

> ⚠️ 必须排除 `.git` 目录，否则镜像会包含完整git历史，体积暴增且可能泄露历史密钥

> ⚠️ 必须排除 `.env`（除 `.env.example`），否则敏感信息会被COPY进镜像

> ⚠️ 排除规则要注意顺序和通配符，`**/*.md` 会排除所有md包括子目录，使用 `!` 白名单保留需要的

> ⚠️ 修改 `.dockerignore` 后第一次 `docker build` 缓存可能失效，属于正常现象

> ⚠️ Windows与Linux的换行符差异可能导致 `.dockerignore` 解析异常，使用 `LF` 换行符

> ⚠️ 前端Dockerfile构建时需要 `package-lock.json`，不要把它加入 `.dockerignore`
