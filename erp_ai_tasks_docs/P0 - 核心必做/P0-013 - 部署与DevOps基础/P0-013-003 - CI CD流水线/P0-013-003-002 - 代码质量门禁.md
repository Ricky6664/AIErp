> **本任务模块上下文**
> - 配置范围：CI流水线中的代码质量门禁Job

> - 门禁目标：任一检查失败则流水线中断，禁止合并与部署

### 5.1 后端质量门禁

#### 5.1.1 Checkstyle（代码风格）

1. 在 `erp-server/pom.xml` 中引入 maven-checkstyle-plugin：
   ```xml
   <plugin>
     <groupId>org.apache.maven.plugins</groupId>
     <artifactId>maven-checkstyle-plugin</artifactId>
     <version>3.3.1</version>
     <configuration>
       <configLocation>checkstyle.xml</configLocation>
       <consoleOutput>true</consoleOutput>
       <failsOnError>true</failsOnError>
       <violationSeverity>warning</violationSeverity>
     </configuration>
   </plugin>
   ```
2. 配置规则文件 `erp-server/checkstyle.xml`：基于Google Java Style + 项目自定义规则
3. 关键规则：缩进4空格、方法长度≤80行、类长度≤500行、参数数量≤7、避免魔法数字
4. 执行命令：`mvn checkstyle:check`，违规时构建失败

#### 5.1.2 SpotBugs（缺陷检测）

1. 在 `erp-server/pom.xml` 中引入 spotbugs-maven-plugin：
   ```xml
   <plugin>
     <groupId>com.github.spotbugs</groupId>
     <artifactId>spotbugs-maven-plugin</artifactId>
     <version>4.8.3.1</version>
     <configuration>
       <effort>Max</effort>
       <threshold>Medium</threshold>
       <failOnError>true</failOnError>
       <excludeFilterFile>spotbugs-exclude.xml</excludeFilterFile>
     </configuration>
   </plugin>
   ```
2. 配置排除文件 `erp-server/spotbugs-exclude.xml`：过滤误报规则
3. 检测重点：空指针、资源泄漏、SQL注入、并发问题
4. 执行命令：`mvn spotbugs:check`，发现缺陷时构建失败

#### 5.1.3 JaCoCo覆盖率

1. 在 `erp-server/pom.xml` 中引入 jacoco-maven-plugin：
   ```xml
   <plugin>
     <groupId>org.jacoco</groupId>
     <artifactId>jacoco-maven-plugin</artifactId>
     <version>0.8.11</version>
     <executions>
       <execution>
         <goals><goal>prepare-agent</goal></goals>
       </execution>
       <execution>
         <id>report</id>
         <phase>test</phase>
         <goals><goal>report</goal></goals>
       </execution>
       <execution>
         <id>check</id>
         <goals><goal>check</goal></goals>
         <configuration>
           <rules>
             <rule>
               <element>BUNDLE</element>
               <limits>
                 <limit>
                   <counter>LINE</counter>
                   <value>COVEREDRATIO</value>
                   <minimum>0.80</minimum>
                 </limit>
               </limits>
             </rule>
           </rules>
         </configuration>
       </execution>
     </executions>
   </plugin>
   ```
2. 行覆盖率最低要求：80%
3. 执行命令：`mvn jacoco:check`，覆盖率不达标时构建失败

### 5.2 前端质量门禁

#### 5.2.1 ESLint（代码质量）

1. 在 `erp-ui/package.json` 中配置脚本：`"lint": "eslint . --ext .vue,.js,.ts --max-warnings 0"`
2. 配置 `.eslintrc.cjs`：继承 `plugin:vue/vue3-recommended`、`@vue/eslint-config-typescript`
3. `--max-warnings 0`：任何warning都视为失败，强制代码清洁
4. 执行命令：`npm run lint`

#### 5.2.2 Prettier（代码格式）

1. 配置 `.prettierrc`：统一代码风格（单引号、无分号、tabWidth=2）
2. 配置脚本：`"format:check": "prettier --check 'src/**/*.{vue,ts,js,scss}'"`
3. 执行命令：`npm run format:check`，格式不一致时失败

#### 5.2.3 Vitest覆盖率

1. 配置 `vitest.config.ts` 覆盖率阈值：
   ```ts
   test: {
     coverage: {
       provider: 'v8',
       reporter: ['text', 'html', 'lcov'],
       thresholds: {
         lines: 70,
         functions: 70,
         branches: 60,
         statements: 70
       }
     }
   }
   ```
2. 执行命令：`npm run test:coverage`，覆盖率不达标时失败

3. 质量门禁规则：覆盖率 ≥80%、无Blocker/Critical问题、重复率 ≤3%

### 5.4 流水线集成

在CI配置文件中新增lint Job，作为docker Job的前置依赖：

```yaml
lint-backend:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - uses: actions/setup-java@v4
      with: { distribution: temurin, java-version: '21', cache: maven }
    - run: cd erp-server && mvn -B checkstyle:check spotbugs:check jacoco:check

lint-frontend:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - uses: actions/setup-node@v4
      with: { node-version: '20', cache: npm, cache-dependency-path: erp-ui/package-lock.json }
    - run: cd erp-ui && npm ci && npm run lint && npm run format:check && npm run test:coverage

docker:
  needs: [ backend, frontend, lint-backend, lint-frontend ]   # 新增lint依赖
  ...
```

### 5.5 验证

1. 故意引入违规代码（如未使用的变量、魔法数字），验证checkstyle/spotbugs/lint拦截
2. 故意降低覆盖率（删除部分测试），验证jacoco/vitest门禁拦截
3. 流水线中任一lint Job失败，docker Job不执行
4. 修复违规代码后流水线恢复正常

| 序号 | 检查项 | 验证方法 |
|:---:|--------|---------|
| 1 | `mvn checkstyle:check` 能检测到违规代码并失败 | 故意引入违规测试 |
| 2 | `mvn spotbugs:check` 能检测到缺陷并失败 | 故意引入缺陷测试 |
| 3 | `mvn jacoco:check` 覆盖率 <80% 时失败 | 临时调高阈值验证 |

| 7 | CI流水线中lint Job失败会阻止docker Job | 故障注入测试 |

## 八、易错警示

> ⚠️ 质量门禁阈值不要设置过高（如100%覆盖率），否则团队会为了达标而写无意义测试，初期80%是合理起点

> ⚠️ SpotBugs/ESLint首次运行会报大量历史问题，建议先用baseline机制忽略历史问题，新代码严格执行

> ⚠️ `--max-warnings 0` 很严格，团队必须先清理所有warning才能启用，否则CI会长期红灯

> ⚠️ 覆盖率门禁要区分"新代码"与"存量代码"，SonarQube的Quality Gate可以做到这点，纯JaCoCo只能看整体覆盖率

> ⚠️ 不要为了覆盖率写"测试断言自己"这种无意义测试，Review时要关注测试质量而非单纯数字

> ⚠️ SpotBugs的误报率较高，必须维护 `spotbugs-exclude.xml` 排除已知安全的问题，否则开发者会麻木

> ⚠️ SonarQube Server未部署前占位Job要保持注释状态，不要启用假数据，避免CI浪费时间

> ⚠️ lint Job要与build Job并行运行（不互相依赖），否则流水线总时间会增加

> ⚠️ 质量门禁规则变更要在团队内公示，避免突然引入大量失败导致CI不可用
