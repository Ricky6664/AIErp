## 五、详细开发规格

> **本任务模块上下文**
> - 验证范围：CI配置文件定义的完整流水线（8个阶段）
> - 验证目标：push触发 → 构建成功 → 测试通过 → 镜像推送 → 部署成功

### 5.1 验证清单（按任务目标逐项验证）

1. **触发机制验证**
   - push到develop分支：触发backend + frontend + docker三个Job
   - push到main分支：触发所有4个Job（含deploy）
   - 创建PR到main：仅触发backend + frontend（不触发docker和deploy）
   - 修改 `docs/*.md`：不触发流水线（paths-ignore生效）

2. **后端Job验证（backend）**
   - JDK 21环境安装成功
   - Maven缓存命中（第二次构建时间显著减少）
   - `mvn clean package -DskipTests` 成功，生成jar包
   - `mvn test jacoco:report` 成功，测试全部通过
   - JaCoCo覆盖率报告生成（`target/site/jacoco/index.html`）
   - Checkstyle检查通过，无违规代码
   - 测试报告Artifact上传成功

3. **前端Job验证（frontend）**
   - Node 20环境安装成功
   - npm缓存命中（第二次构建时间显著减少）
   - `npm ci` 安装依赖成功
   - `npm run lint` ESLint检查通过
   - `npm run build` 构建成功，生成 `dist/`
   - `npm run test:coverage` 测试通过，覆盖率报告生成
   - 覆盖率Artifact上传成功

4. **Docker Job验证（docker）**
   - 仅当backend和frontend都通过时触发（needs依赖）
   - Docker Buildx配置成功
   - Docker Hub登录成功
   - 后端镜像构建成功（`erp-backend:{sha}` + `erp-backend:latest`）
   - 前端镜像构建成功（`erp-frontend:{sha}` + `erp-frontend:latest`）
   - 镜像成功推送到Docker Hub
   - Docker层缓存生效（第二次构建时间显著减少）

5. **Deploy Job验证（deploy）**
   - 仅main分支触发
   - SSH连接到部署服务器成功
   - `deploy.sh {sha}` 执行成功
   - 部署后健康检查通过
   - `/var/log/erp-deploy.log` 记录部署信息

6. **失败场景验证**
   - 故意引入编译错误，验证流水线中断
   - 故意让一个单元测试失败，验证test Job失败
   - 故意让ESLint报错，验证lint门禁生效
   - 验证失败时后续Job不执行（needs依赖）

### 5.2 测试方法

1. **自动化验证**：通过实际push与PR触发流水线，观察Job运行结果
2. **日志分析**：查看每个Job的详细日志，确认关键步骤执行
3. **产物检查**：验证Artifact、镜像标签、部署日志正确生成
4. **故障注入**：故意引入错误验证门禁机制

## 八、易错警示

> ⚠️ 验证时使用独立的feature分支，避免影响main分支的稳定性

> ⚠️ 故意引入错误的故障注入测试，验证完成后务必回滚或关闭PR，避免污染代码库

> ⚠️ 缓存命中与否要看日志中 `Cache restored` 字样，不能仅凭构建时间判断

> ⚠️ Docker层缓存第一次构建没有效果，从第二次开始才明显

> ⚠️ deploy Job需要真实的部署服务器与SSH密钥，无法在空仓库中完整验证，可使用staging环境替代

> ⚠️ 验证报告要包含失败项与修复方案，仅记录PASS项会掩盖潜在问题

> ⚠️ 流水线运行时间受GitHub Actions/GitLab CI并发数与排队影响，时间数据仅供参考

> ⚠️ 截图要包含时间戳与commit SHA，证明是本次验证的运行结果而非历史记录
