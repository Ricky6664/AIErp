### 5.1 GitHub Actions配置（.github/workflows/ci.yml）

```yaml
name: ERP CI/CD Pipeline

on:
  push:
    branches: [ main, develop, 'release/**' ]
    paths-ignore:
      - 'docs/**'
      - '**.md'
  pull_request:
    branches: [ main, develop ]

env:
  REGISTRY: docker.io
  IMAGE_BACKEND: ${{ secrets.DOCKERHUB_USERNAME }}/erp-backend
  IMAGE_FRONTEND: ${{ secrets.DOCKERHUB_USERNAME }}/erp-frontend

jobs:
  # ==================== 后端构建与测试 ====================
  backend:
    name: Backend Build & Test
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up JDK 21
        uses: actions/setup-java@v4
        with:
          distribution: 'temurin'
          java-version: '21'
          cache: 'maven'

      - name: Build Backend
        working-directory: ./erp-server
        run: mvn -B clean package -DskipTests

      - name: Run Tests with Coverage
        working-directory: ./erp-server
        run: mvn -B test jacoco:report

      - name: Upload Test Reports
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: backend-test-reports
          path: erp-server/target/surefire-reports/

      - name: Upload Coverage Report
        uses: actions/upload-artifact@v4
        with:
          name: backend-coverage
          path: erp-server/target/site/jacoco/

      - name: Checkstyle
        working-directory: ./erp-server
        run: mvn -B checkstyle:check

  # ==================== 前端构建与测试 ====================
  frontend:
    name: Frontend Build & Test
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up Node 20
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: erp-ui/package-lock.json

      - name: Install Dependencies
        working-directory: ./erp-ui
        run: npm ci

      - name: Lint
        working-directory: ./erp-ui
        run: npm run lint

      - name: Build
        working-directory: ./erp-ui
        run: npm run build

      - name: Test with Coverage
        working-directory: ./erp-ui
        run: npm run test:coverage

      - name: Upload Coverage Report
        uses: actions/upload-artifact@v4
        with:
          name: frontend-coverage
          path: erp-ui/coverage/

  # ==================== Docker镜像构建与推送 ====================
  docker:
    name: Docker Build & Push
    runs-on: ubuntu-latest
    needs: [ backend, frontend ]
    if: github.event_name == 'push' && (github.ref == 'refs/heads/main' || startsWith(github.ref, 'refs/heads/release/'))
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Login to Docker Hub
        uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}

      - name: Build & Push Backend
        uses: docker/build-push-action@v5
        with:
          context: .
          file: ./deploy/backend/Dockerfile
          push: true
          tags: |
            ${{ env.IMAGE_BACKEND }}:${{ github.sha }}
            ${{ env.IMAGE_BACKEND }}:latest
          cache-from: type=gha
          cache-to: type=gha,mode=max

      - name: Build & Push Frontend
        uses: docker/build-push-action@v5
        with:
          context: .
          file: ./deploy/frontend/Dockerfile
          push: true
          tags: |
            ${{ env.IMAGE_FRONTEND }}:${{ github.sha }}
            ${{ env.IMAGE_FRONTEND }}:latest
          cache-from: type=gha
          cache-to: type=gha,mode=max

  # ==================== 部署 ====================
  deploy:
    name: Deploy to Server
    runs-on: ubuntu-latest
    needs: [ docker ]
    if: github.ref == 'refs/heads/main'
    environment: production
    steps:
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.DEPLOY_HOST }}
          username: ${{ secrets.DEPLOY_USER }}
          key: ${{ secrets.DEPLOY_SSH_KEY }}
          script: |
            cd /opt/erp
            bash deploy.sh ${{ github.sha }}
```

### 5.2 GitLab CI配置（.gitlab-ci.yml，备选）

```yaml
stages:
  - build
  - test
  - docker
  - deploy

variables:
  MAVEN_OPTS: "-Dmaven.repo.local=$CI_PROJECT_DIR/.m2/repository"
  DOCKER_DRIVER: overlay2

cache:
  key: "$CI_COMMIT_REF_SLUG"
  paths:
    - .m2/repository/
    - erp-ui/node_modules/

backend-build:
  stage: build
  image: maven:3.9-eclipse-temurin-17
  script:
    - cd erp-server
    - mvn -B clean package -DskipTests
  artifacts:
    paths:
      - erp-server/target/*.jar
    expire_in: 1 hour

frontend-build:
  stage: build
  image: node:20-alpine
  script:
    - cd erp-ui
    - npm ci
    - npm run build
  artifacts:
    paths:
      - erp-ui/dist/
    expire_in: 1 hour

backend-test:
  stage: test
  image: maven:3.9-eclipse-temurin-17
  script:
    - cd erp-server
    - mvn -B test jacoco:report
  artifacts:
    reports:
      junit: erp-server/target/surefire-reports/*.xml

docker-build:
  stage: docker
  image: docker:24
  services:
    - docker:24-dind
  script:
    - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY
    - docker build -t $CI_REGISTRY_IMAGE/backend:$CI_COMMIT_SHA -f deploy/backend/Dockerfile .
    - docker push $CI_REGISTRY_IMAGE/backend:$CI_COMMIT_SHA

deploy-prod:
  stage: deploy
  only:
    - main
  script:
    - ssh $DEPLOY_USER@$DEPLOY_HOST "cd /opt/erp && bash deploy.sh $CI_COMMIT_SHA"
```

### 5.3 缓存策略

1. **Maven本地仓库**：使用 `actions/setup-java` 的内置缓存（按 `pom.xml` hash作为key）
2. **npm依赖**：使用 `actions/setup-node` 的内置缓存（按 `package-lock.json` hash作为key）
3. **Docker层缓存**：使用GitHub Container Registry缓存（`cache-from: type=gha`）
4. **缓存Key策略**：依赖文件变更时缓存失效，否则复用缓存节省构建时间

### 5.4 触发条件

| 场景 | 触发 | 运行Job |
|------|------|---------|
| push到main | `on.push.branches: main` | backend + frontend + docker + deploy |
| push到develop | `on.push.branches: develop` | backend + frontend + docker |
| push到release/* | `on.push.branches: release/**` | backend + frontend + docker |
| PR到main/develop | `on.pull_request` | backend + frontend（不docker、不deploy） |
| 修改docs/*.md | paths-ignore | 不触发 |

### 5.5 密钥管理（Repository Secrets）

在GitHub仓库Settings → Secrets中配置：

1. `DOCKERHUB_USERNAME`：Docker Hub用户名
2. `DOCKERHUB_TOKEN`：Docker Hub访问令牌（不要用密码）
3. `DEPLOY_HOST`：部署服务器IP/域名
4. `DEPLOY_USER`：部署用户名
5. `DEPLOY_SSH_KEY`：部署服务器SSH私钥

GitLab在Settings → CI/CD → Variables中配置，勾选 "Masked" 与 "Protected"。

### 5.6 验证

1. 推送到develop分支，验证backend/frontend构建与测试Job成功运行
2. 查看Maven/npm缓存命中情况，首次构建后后续构建时间应显著减少
3. 合并PR到main分支，验证docker + deploy Job触发
4. 在Docker Hub上查看镜像标签是否正确推送（`{sha}` + `latest`）
5. 部署服务器查看 `/var/log/erp-deploy.log` 确认deploy.sh执行成功

## 八、易错警示

> ⚠️ 绝对禁止在CI配置文件中硬编码密钥、密码或Token，必须使用 `${{ secrets.XXX }}` 或 `$CI_VARIABLE` 引用

> ⚠️ Docker Hub Token不要使用账户密码，应在Docker Hub设置中生成专用的Access Token，便于撤销

> ⚠️ Maven/npm缓存Key要基于依赖文件（pom.xml/package-lock.json）hash，依赖文件变更时自动失效，否则可能使用过期依赖

> ⚠️ PR流水线不要触发docker build + deploy，避免PR提交者意外部署到生产环境

> ⚠️ 部署Job要配置 `environment: production` 与manual approval，避免误部署

> ⚠️ GitHub Actions的 `on.push.paths-ignore` 可以过滤docs/*.md等无关变更，避免不必要的构建浪费配额

> ⚠️ 多分支场景下镜像标签要区分，避免develop分支覆盖main分支的 `latest` 标签，建议main才打 `latest`

> ⚠️ `actions/checkout@v4` 默认只拉取最新commit，如需git history（如计算版本号）要配置 `fetch-depth: 0`

> ⚠️ 测试失败时流水线应该中断（默认行为），不要把 `|| true` 加到测试命令后忽略失败

> ⚠️ 缓存与Artifacts不同：缓存用于依赖加速（可丢失），Artifacts用于构建产物（必须保留）
