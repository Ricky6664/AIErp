## 1. 模块架构约束

### 1.1 模块定位
P0-013负责搭建ERP系统的部署与DevOps基础设施，包括Docker容器化配置（Docker Compose多服务编排）、Nginx反向代理与静态资源配置、CI/CD流水线搭建（GitHub Actions/GitLab CI）。本模块确保开发/测试/生产环境一致性与自动化部署能力，为所有后续业务模块提供可靠的运行环境和持续集成/持续部署能力。

### 1.2 依赖关系
- 前置依赖：
  - P0-001（后端框架提供Spring Boot应用产物）
  - P0-002（前端框架提供Vue应用构建产物）
- 后续依赖：
  - P0-014（测试基础模块依赖CI/CD集成）
  - P1-001~P1-010（所有后续业务模块的部署运行环境）
  - P2级所有模块

### 1.3 技术约束
- **技术栈约束**：Docker 24+ + Docker Compose V2 + Nginx 1.27+ + PostgreSQL 16 + Redis 7-alpine + MinIO latest + Elasticsearch 8.x（单节点）
- **性能约束**：Docker镜像构建时间 < 5分钟；容器启动时间 < 30秒；健康检查通过时间 < 60秒；部署回滚时间 < 2分钟
- **安全约束**：所有密钥（数据库密码/JWT密钥/API Key/MinIO凭证）禁止硬编码，必须通过.env文件或K8s Secret注入；Dockerfile使用非root用户（erpuser:1001）；Nginx配置安全头（X-Frame-Options/X-Content-Type-Options/X-XSS-Protection/HSTS/CSP）；生产环境必须配置SSL证书

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |

| 无 | 部署与DevOps模块无数据库表 | - |

### 2.2 表关系图
本模块不涉及数据库表，但维护以下基础设施配置文件：
- **Docker编排**：docker-compose.yml（7个服务定义）+ .env.dev/.env.staging/.env.prod（多环境变量）
- **Dockerfile**：后端Dockerfile（多阶段构建：maven构建→JRE运行）+ 前端Dockerfile（多阶段构建：node构建→nginx运行）
- **Nginx配置**：nginx.dev.conf/nginx.staging.conf/nginx.prod.conf（多环境配置）
- **CI/CD配置**：.github/workflows/ci-cd.yml 或 .gitlab-ci.yml
- **部署脚本**：deploy.sh（自动化部署+备份+回滚）

### 2.3 数据流转
1. **容器编排数据流**：docker-compose.yml定义服务 → .env文件注入环境变量 → Docker Compose启动所有服务 → 健康检查确认服务就绪 → Nginx反向代理统一入口
2. **CI/CD数据流**：代码提交 → 触发CI/CD流水线 → 代码检出 → 依赖缓存 → 编译构建 → 单元测试+覆盖率 → 代码质量门禁 → Docker镜像构建 → 镜像推送 → 远程部署
3. **部署数据流**：deploy.sh执行 → 数据库备份 → 拉取新镜像 → 滚动更新 → 健康检查（30次×2s）→ 成功则完成 / 失败则回滚

## 3. 业务流程

### 3.1 核心业务流程
1. **Docker容器化**（P0-013-001）：
   - 编写docker-compose.yml（postgres/redis/minio/elasticsearch/backend/frontend/nginx共7个服务）
   - 配置erp_network桥接网络和数据卷（erp_pgdata/erp_redis/erp_minio/erp_es）
   - 编写后端Dockerfile（多阶段构建：maven:3.9-eclipse-temurin-17构建→eclipse-temurin:17-jre运行，Spring Boot分层jar，非root用户）
   - 编写前端Dockerfile（多阶段构建：node:20-alpine构建→nginx:1.27-alpine运行，gzip+CSP+content-hash）
   - 配置.dockerignore（排除node_modules/target/.git/logs等）
   - 配置多环境.env文件（.env.dev/.env.staging/.env.prod）
2. **Nginx反向代理与静态资源**（P0-013-002）：
   - 配置upstream（后端服务backend:8080，支持扩展多节点）
   - 配置API反向代理（/api/*→backend，/ws/*→WebSocket Upgrade）
   - 配置静态资源缓存（js/css/图片Cache-Control: public, max-age=31536000, immutable；HTML: no-cache）
   - 配置gzip压缩（min_length 1024，压缩text/css/js/json）
   - 配置安全头（X-Frame-Options/X-Content-Type-Options/X-XSS-Protection/HSTS/CSP）
   - 配置多环境nginx.conf + 生产环境SSL
3. **CI/CD流水线**（P0-013-003）：
   - 配置代码检出（actions/checkout@v4）
   - 配置依赖缓存（Maven本地仓库+npm缓存）
   - 配置编译构建（后端mvn clean package，前端npm ci && npm run build）
   - 配置单元测试+JaCoCo/Vitest覆盖率报告
   - 配置代码质量门禁（后端Checkstyle+SpotBugs，前端ESLint+Prettier）
   - 预留SonarQube扫描stage
   - 配置Docker镜像构建+推送（标签规则：{仓库}:{git-sha-short}+{仓库}:latest）
   - 配置部署stage（远程deploy.sh执行）
   - 编写deploy.sh（备份→滚动更新→健康检查→回滚机制→日志记录）

### 3.2 业务规则
- **Docker Compose编排结构**：必须包含postgres/redis/minio/elasticsearch/backend/frontend/nginx共7个服务，所有服务配置健康检查
- **多环境变量管理**：开发/预发布/生产三套.env文件，密钥禁止硬编码
- **Dockerfile多阶段构建**：后端使用maven构建+JRE运行，前端使用node构建+nginx运行；运行镜像使用非root用户
- **.dockerignore规范**：必须排除node_modules/target/.git/logs/.env.local/*.log/.idea/.vscode/dist
- **Nginx安全头**：必须配置X-Frame-Options/X-Content-Type-Options/X-XSS-Protection/HSTS/CSP
- **CI/CD流水线阶段**：必须包含检出→缓存→构建→测试→门禁→镜像→推送→部署共8个阶段
- **自动化部署规范**：部署前备份数据库（保留7天）→ 滚动更新 → 健康检查（30次×2s）→ 失败回滚（保留最近3个版本）→ 日志记录

### 3.3 状态流转
- **容器服务状态**：starting → healthy（健康检查通过）/ unhealthy（健康检查失败）→ running → stopped
- **CI/CD流水线状态**：queued → running → success / failed → deploying → deployed / rolled_back
- **部署状态**：backing_up → updating → health_checking → success / rolling_back → rolled_back

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **P0-013-001 Docker容器化**（Nginx和CI/CD依赖Docker配置）
2. **P0-013-001** → **P0-013-002 Nginx反向代理与静态资源**（Nginx配置依赖Docker服务定义）
3. **P0-013-001 + P0-013-002** → **P0-013-003 CI/CD流水线**（CI/CD依赖Docker镜像构建+Nginx配置）

### 5.2 可并行执行的任务
- P0-013-001中的后端Dockerfile和前端Dockerfile可并行编写
- P0-013-001中的docker-compose.yml和多环境.env文件可并行配置
- P0-013-002中不同环境的nginx.conf可并行编写（nginx.dev.conf/nginx.staging.conf/nginx.prod.conf）
- P0-013-003中CI/CD流水线配置文件和deploy.sh部署脚本可并行编写（但deploy.sh需在流水线deploy stage中引用）
