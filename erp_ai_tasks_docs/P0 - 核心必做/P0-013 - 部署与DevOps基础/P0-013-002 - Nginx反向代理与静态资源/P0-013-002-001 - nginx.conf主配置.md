### 5.1 主配置结构（nginx.conf）

```nginx
user  nginx;
worker_processes  auto;
error_log  /var/log/nginx/error.log warn;
pid        /var/run/nginx.pid;

events {
    worker_connections  1024;
    multi_accept on;
}

http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;

    # 日志格式
    log_format  main  '$remote_addr - $remote_user [$time_local] "$request" '
                      '$status $body_bytes_sent "$http_referer" '
                      '"$http_user_agent" "$http_x_forwarded_for"';
    access_log  /var/log/nginx/access.log  main;

    sendfile        on;
    tcp_nopush      on;
    tcp_nodelay     on;
    keepalive_timeout  65;
    types_hash_max_size 2048;
    client_max_body_size 50m;       # 上传文件限制
    server_tokens off;              # 隐藏Nginx版本号

    # gzip压缩
    include /etc/nginx/conf.d/gzip.conf;
    # 安全头
    include /etc/nginx/conf.d/security-headers.conf;
    # upstream定义
    include /etc/nginx/conf.d/upstream.conf;
    # server块
    include /etc/nginx/conf.d/*.conf;
}
```

### 5.2 Upstream定义（upstream.conf）

```nginx
upstream backend {
    # 当前单节点，未来可扩展为多节点负载均衡
    server backend:8080 max_fails=3 fail_timeout=30s;
    # server backend-2:8080 max_fails=3 fail_timeout=30s;
    keepalive 32;
}

upstream frontend {
    server frontend:80;
    keepalive 16;
}
```

1. `backend` 指向docker-compose中定义的backend服务名（Docker DNS自动解析）
2. `max_fails=3 fail_timeout=30s`：3次失败后标记为不可用，30秒后重试
3. `keepalive 32`：保持长连接，减少TCP握手开销

### 5.3 Server块主配置（erp.conf）

```nginx
server {
    listen 80;
    server_name erp.example.com;

    # 健康检查端点
    location /health {
        access_log off;
        return 200 "OK\n";
        add_header Content-Type text/plain;
    }

    # 后端健康检查代理
    location /actuator/health {
        proxy_pass http://backend;
    }

    # API反向代理
    location /api/ {
        proxy_pass http://backend/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 30s;
        proxy_read_timeout 120s;
    }

    # WebSocket代理
    location /ws/ {
        proxy_pass http://backend/ws/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;
    }

    # 前端静态资源
    location / {
        proxy_pass http://frontend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 静态资源缓存（由frontend Nginx处理，这里也可加层缓存头）
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        proxy_pass http://frontend;
        expires 1y;
        add_header Cache-Control "public, immutable";
        access_log off;
    }
}
```

### 5.4 Gzip压缩配置（gzip.conf）

```nginx
gzip on;
gzip_vary on;
gzip_proxied any;
gzip_comp_level 6;
gzip_min_length 1024;
gzip_types
    text/plain
    text/css
    text/xml
    text/javascript
    application/json
    application/javascript
    application/xml
    application/xml+rss
    application/x-javascript
    image/svg+xml;
```

1. `gzip_min_length 1024`：小于1KB不压缩（压缩后可能更大）
2. `gzip_comp_level 6`：压缩级别1-9，6为性能与压缩率平衡点
3. `gzip_vary on`：添加 `Vary: Accept-Encoding` 头，告知CDN/代理

### 5.5 安全头配置（security-headers.conf）

```nginx
add_header X-Frame-Options "SAMEORIGIN" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-XSS-Protection "1; mode=block" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self' data:; connect-src 'self' https:;" always;
add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;
```

### 5.6 缓存策略

1. **HTML文件**：`Cache-Control: no-cache, no-store, must-revalidate`（强制每次验证）
2. **带hash的JS/CSS**：`Cache-Control: public, max-age=31536000, immutable`（长期缓存）
3. **图片/字体**：`Cache-Control: public, max-age=31536000`（长期缓存）
4. **API响应**：默认不缓存，由后端控制 `Cache-Control`

### 5.7 验证

1. `nginx -t` 测试配置语法正确
2. `nginx -T` 输出完整配置，确认include正确
3. `docker compose restart nginx` 重载配置
4. `curl -I http://localhost/api/xxx` 验证API代理返回200
5. `curl -I http://localhost/` 验证前端资源返回200 + 正确Cache-Control
6. `curl -H "Accept-Encoding: gzip" -I http://localhost/assets/app.*.js` 验证gzip生效
7. `curl -I http://localhost/` 检查安全头全部存在
8. 浏览器开发者工具Network面板验证WebSocket连接成功

## 八、易错警示

> ⚠️ Nginx配置修改后必须 `nginx -t` 验证语法，错误配置会导致Nginx启动失败，整个系统不可访问

> ⚠️ upstream的server名必须与docker-compose.yml中的服务名完全一致（backend/frontend），Docker DNS才能解析

> ⚠️ WebSocket代理必须配置 `proxy_http_version 1.1;` + `Upgrade` + `Connection "upgrade"` 三个指令，缺少任一都会导致WebSocket握手失败

> ⚠️ `client_max_body_size` 默认只有1MB，文件上传接口会返回 `413 Request Entity Too Large`，根据业务需要调整为50m或更大

> ⚠️ CSP策略要兼顾项目实际需求，过严会导致第三方资源（字体、CDN、外部API）加载失败，配置前与前端团队确认白名单

> ⚠️ `proxy_pass http://backend/api/` 结尾带 `/` 与不带 `/` 行为不同，带 `/` 会去掉location匹配的 `/api/` 前缀，按需求选择

> ⚠️ `add_header` 在location块中使用时会覆盖外层（server/http）的同名header，要在location内重复声明或使用 `include` 引入

> ⚠️ gzip对已压缩的格式（jpg/png/mp4）无效且浪费CPU，不要在 `gzip_types` 中包含这些类型

> ⚠️ Nginx日志文件会持续增长，生产环境要配合logrotate做日志轮转，避免磁盘占满
