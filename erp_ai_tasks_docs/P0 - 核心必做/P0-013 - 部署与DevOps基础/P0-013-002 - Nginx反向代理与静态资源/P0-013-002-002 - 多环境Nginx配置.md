### 5.1 多环境配置结构

采用文件命名隔离的方式组织多环境配置：

```
deploy/nginx/
├── nginx.conf                    # 公共主配置（所有环境共享）
├── nginx.dev.conf                # 开发环境server块
├── nginx.staging.conf            # 预发布环境server块
├── nginx.prod.conf               # 生产环境server块（含SSL）
└── ssl/                          # SSL证书目录（prod使用，不入库）
    ├── erp.example.com.crt
    └── erp.example.com.key
```

通过docker-compose的卷挂载选择不同环境配置：

```yaml
nginx:
  volumes:
    - ./deploy/nginx/nginx.conf:/etc/nginx/nginx.conf:ro
    - ./deploy/nginx/nginx.${ENV}.conf:/etc/nginx/conf.d/default.conf:ro
    - ./deploy/nginx/ssl:/etc/nginx/ssl:ro   # prod环境挂载
```

### 5.2 开发环境（nginx.dev.conf）

```nginx
server {
    listen 80;
    server_name localhost;

    # 开发环境允许所有来源CORS
    add_header Access-Control-Allow-Origin * always;
    add_header Access-Control-Allow-Methods "GET, POST, PUT, DELETE, OPTIONS" always;
    add_header Access-Control-Allow-Headers "DNT,User-Agent,X-Requested-With,Authorization,Content-Type" always;

    # 处理OPTIONS预检请求
    if ($request_method = 'OPTIONS') {
        return 204;
    }

    # 关闭访问日志（减少开发时噪音）
    access_log off;

    # 其他location与主配置相同（include /api/, /ws/, /）
    location /api/ { proxy_pass http://backend/api/; ... }
    location /ws/  { proxy_pass http://backend/ws/; ... }
    location /     { proxy_pass http://frontend; ... }
}
```

特点：
- 仅HTTP（无SSL）
- CORS允许所有来源（开发方便）
- 关闭访问日志
- 域名 `localhost`

### 5.3 预发布环境（nginx.staging.conf）

```nginx
server {
    listen 80;
    server_name staging.erp.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name staging.erp.example.com;

    ssl_certificate     /etc/nginx/ssl/staging.erp.example.com.crt;
    ssl_certificate_key /etc/nginx/ssl/staging.erp.example.com.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    # 限制CORS为允许的域名列表
    set $cors_origin "";
    if ($http_origin ~* "^https?://(staging\.erp\.example\.com|staging-admin\.erp\.example\.com)$") {
        set $cors_origin $http_origin;
    }
    add_header Access-Control-Allow-Origin $cors_origin always;
    add_header Access-Control-Allow-Credentials true always;
    ...
}
```

特点：
- HTTP强制跳转HTTPS
- SSL证书（Let's Encrypt或自签名）
- CORS限制为staging域名列表
- 开启访问日志

### 5.4 生产环境（nginx.prod.conf）

```nginx
# HTTP → HTTPS强制跳转
server {
    listen 80;
    server_name erp.example.com www.erp.example.com;
    return 301 https://$host$request_uri;
}

# HTTPS主配置
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name erp.example.com;

    # SSL证书（Let's Encrypt）
    ssl_certificate     /etc/nginx/ssl/erp.example.com.crt;
    ssl_certificate_key /etc/nginx/ssl/erp.example.com.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers on;
    ssl_session_cache   shared:SSL:10m;
    ssl_session_timeout 10m;
    ssl_session_tickets off;

    # OCSP Stapling
    ssl_stapling on;
    ssl_stapling_verify on;
    resolver 8.8.8.8 8.8.4.4 valid=300s;

    # 严格CORS
    set $cors_origin "";
    if ($http_origin ~* "^https?://(erp\.example\.com|admin\.erp\.example\.com)$") {
        set $cors_origin $http_origin;
    }
    add_header Access-Control-Allow-Origin $cors_origin always;
    add_header Access-Control-Allow-Credentials true always;
    add_header Access-Control-Allow-Methods "GET, POST, PUT, DELETE, OPTIONS" always;
    add_header Access-Control-Allow-Headers "DNT,User-Agent,X-Requested-With,Authorization,Content-Type,Accept" always;
    add_header Access-Control-Max-Age 86400;

    # 访问日志（生产必须记录）
    access_log /var/log/nginx/erp-access.log main;
    error_log  /var/log/nginx/erp-error.log warn;

    # 限流（基于IP）
    limit_req_zone $binary_remote_addr zone=api_limit:10m rate=100r/s;
    location /api/ {
        limit_req zone=api_limit burst=20 nodelay;
        proxy_pass http://backend/api/;
        ...
    }

    # 其他location同主配置
    location /ws/  { proxy_pass http://backend/ws/; ... }
    location /     { proxy_pass http://frontend; ... }
}
```

特点：
- HTTP强制跳转HTTPS
- 完整SSL配置（TLS1.2/1.3、OCSP Stapling、会话缓存）
- 严格CORS白名单
- 限流（防止API滥用）
- 完整访问日志与错误日志
- CSP、HSTS、X-Frame-Options等安全头全部启用

### 5.5 SSL证书管理

1. **Let's Encrypt（推荐）**：使用certbot自动申请与续期
   ```bash
   certbot certonly --nginx -d erp.example.com
   ```
2. **自签名证书（仅开发/测试）**：
   ```bash
   openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
     -keyout erp.example.com.key -out erp.example.com.crt
   ```
3. 证书文件放入 `deploy/nginx/ssl/`，**加入.gitignore**
4. 生产环境证书由运维通过Secret或证书管理服务注入

### 5.6 环境切换

通过docker-compose环境变量 `ENV` 选择配置：

```bash
# 开发
ENV=dev docker compose --env-file .env.dev up -d

# 预发布
ENV=staging docker compose --env-file .env.staging up -d

# 生产
ENV=prod docker compose --env-file .env.prod up -d
```

### 5.7 验证

1. 每个环境分别启动，验证配置加载正确
2. dev环境：`curl http://localhost` 返回200，CORS头包含 `*`
3. staging环境：`curl -I http://staging.erp.example.com` 返回301跳转到HTTPS
4. prod环境：`curl -I https://erp.example.com` 返回200，SSL证书有效，安全头完整
5. 使用 [SSL Labs](https://www.ssllabs.com/ssltest/) 测试SSL评分（prod目标 A+）

## 八、易错警示

> ⚠️ 生产环境SSL证书禁止提交到Git，必须加入.gitignore，通过Secret或证书管理服务注入

> ⚠️ 生产环境必须禁用TLS 1.0/1.1，仅启用TLS 1.2/1.3，否则SSL Labs评分会很低且存在安全风险

> ⚠️ CORS白名单配置要严格，`Access-Control-Allow-Origin: *` 与 `Access-Control-Allow-Credentials: true` 不能同时使用

> ⚠️ Nginx的 `if` 指令有很多陷阱（"If is Evil"），尽量用 `map` 指令替代复杂的if判断

> ⚠️ HTTP→HTTPS跳转要用301（永久）而非302（临时），有利于SEO与浏览器缓存

> ⚠️ HSTS头 `Strict-Transport-Security` 一旦设置，浏览器会强制HTTPS访问，撤销困难，初次部署时max-age不要设置过长

> ⚠️ Let's Encrypt证书有效期90天，必须配置自动续期（certbot renew + cron/systemd timer）

> ⚠️ dev/staging/prod三个环境的配置文件变更要保持一致（如upstream修改），建议提取公共部分到include文件

> ⚠️ 限流配置 `limit_req_zone` 要在http块中定义，`limit_req` 在location块中引用，顺序不能颠倒
