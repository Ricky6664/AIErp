### 5.3 测试数据准备

1. 插入3个公司（2个启用，1个禁用，验证enable_flag过滤）
2. 在公司下分别插入business/functional/project类型部门共10个

4. 清空Redis缓存确保首次查询走数据库

### 5.4 缓存验证方法

```java
@Test
void test_cache_hit() {
    // 清空缓存
    redisTemplate.delete("org:workbench:" + TenantContext.getTenantId());
    // 第一次请求(走DB)
    long start = System.currentTimeMillis();
    workbenchService.getWorkbenchData();
    long firstTime = System.currentTimeMillis() - start;
    // 第二次请求(走缓存)
    start = System.currentTimeMillis();
    workbenchService.getWorkbenchData();
    long secondTime = System.currentTimeMillis() - start;
    // 缓存命中应显著快于DB查询
    assertThat(secondTime).isLessThan(firstTime);
    // 验证Redis key存在
    assertThat(redisTemplate.hasKey("org:workbench:" + TenantContext.getTenantId())).isTrue();
}
```

## 八、易错警示

> ⚠️ 缓存测试前务必清空Redis中对应key，避免残留数据干扰测试结果

> ⚠️ 多租户测试需要切换TenantContext验证数据隔离，确保租户A不读到租户B的缓存

> ⚠️ HRM模块降级测试：若hrm_employee表不存在，employeeCount应返回0而非抛异常，测试需验证降级逻辑

> ⚠️ 聚合查询测试数据量不宜过大(测试环境建议<100条)，避免测试执行时间过长

> ⚠️ 缓存TTL测试不适合真实等待600秒，建议测试时将TTL设为5秒或使用Mock验证set方法的参数
