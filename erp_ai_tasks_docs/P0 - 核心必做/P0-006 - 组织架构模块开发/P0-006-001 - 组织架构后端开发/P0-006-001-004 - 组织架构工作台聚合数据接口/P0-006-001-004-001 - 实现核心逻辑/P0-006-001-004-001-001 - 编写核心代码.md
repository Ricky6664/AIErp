## 五、详细开发规格

### 5.1 OrgWorkbenchService接口

```java
public interface OrgWorkbenchService {
    WorkbenchVO getWorkbenchData();
}
```

### 5.2 WorkbenchVO定义

```java
public class WorkbenchVO {
    private Long companyCount;       // 公司总数
    private Long departmentCount;    // 部门总数
    private Long positionCount;      // 岗位总数
    private Long employeeCount;      // 在职员工总数
    private List<TypeDistribution> deptTypeDistribution;  // 部门类型分布
    private List<CompanyDeptCount> companyDeptCount;      // 各公司部门数量
    private List<DeptStaffCount> deptStaffDistribution;   // 各部门人员分布
}
```

### 5.3 ServiceImpl实现逻辑

```java
@Service
public class OrgWorkbenchServiceImpl implements OrgWorkbenchService {
    @Autowired private OrgCompanyMapper companyMapper;
    @Autowired private OrgDepartmentMapper departmentMapper;
    @Autowired private OrgPositionMapper positionMapper;
    @Autowired private RedisTemplate<String, Object> redisTemplate;

    @Override
    @Transactional(readOnly = true)
    public WorkbenchVO getWorkbenchData() {
        String cacheKey = "org:workbench:" + TenantContext.getTenantId();
        // 1. 查Redis缓存
        WorkbenchVO cached = (WorkbenchVO) redisTemplate.opsForValue().get(cacheKey);
        if (cached != null) return cached;

        // 2. 聚合查询
        WorkbenchVO vo = new WorkbenchVO();
        vo.setCompanyCount(companyMapper.selectCount(enabledWrapper()));
        vo.setDepartmentCount(departmentMapper.selectCount(enabledWrapper()));
        vo.setPositionCount(positionMapper.selectCount(enabledWrapper()));
        vo.setEmployeeCount(employeeMapper.countActiveEmployees());

        // 3. 部门类型分布：GROUP BY dept_type
        vo.setDeptTypeDistribution(departmentMapper.countByDeptType());

        // 4. 各公司部门数量：GROUP BY company_id
        vo.setCompanyDeptCount(departmentMapper.countByCompany());

        // 5. 各部门人员分布：GROUP BY dept_id (查hrm_employee)
        vo.setDeptStaffDistribution(employeeMapper.countByDept());

        // 6. 写入缓存，TTL=600秒
        redisTemplate.opsForValue().set(cacheKey, vo, 600, TimeUnit.SECONDS);
        return vo;
    }
}
```

### 5.4 SQL聚合逻辑

- **公司/部门/岗位总数**：SELECT COUNT(*) FROM org_xxx WHERE is_deleted=false AND enable_flag=true
- **部门类型分布**：SELECT dept_type, COUNT(*) as count FROM org_department WHERE is_deleted=false GROUP BY dept_type
- **各公司部门数量**：SELECT c.company_name, COUNT(d.id) as dept_count FROM org_company c LEFT JOIN org_department d ON c.id=d.company_id AND d.is_deleted=false WHERE c.is_deleted=false GROUP BY c.id, c.company_name
- **在职员工总数**：SELECT COUNT(*) FROM hrm_employee WHERE is_deleted=false AND status='active'

### 5.5 Controller定义

```java
@RestController
@RequestMapping("/api/org/workbench")
@RequiredArgsConstructor
public class OrgWorkbenchController {
    @Autowired private OrgWorkbenchService workbenchService;

    @GetMapping
    @PreAuthorize("@permission.has('org:workbench:query')")
    public Result<WorkbenchVO> getWorkbenchData() {
        return Result.ok(workbenchService.getWorkbenchData());
    }
}
```

### 5.6 缓存策略

- Redis Key格式：`org:workbench:{tenantId}`
- TTL：600秒(10分钟)
- 缓存穿透防护：空结果也缓存，TTL=60秒
- 缓存更新：公司/部门/岗位的增删改操作后主动删除缓存key

## 八、易错警示

> ⚠️ @Transactional(readOnly=true)加在getWorkbenchData方法上，聚合查询都是只读操作

> ⚠️ Redis缓存Key必须包含tenantId，否则多租户环境下不同租户会读到相同缓存数据

> ⚠️ 聚合查询涉及4张表(org_company/org_department/org_position/hrm_employee)，注意SQL性能，数据量大时考虑分批查询或物化视图

> ⚠️ 缓存更新策略：在公司/部门/岗位的增删改操作成功后，主动删除Redis缓存key，避免数据不一致

> ⚠️ hrm_employee表可能尚未开发(P0-006不依赖HRM模块)，employeeCount和deptStaffDistribution需要做降级处理(返回0或空列表)
