### 5.2 测试用例清单

| 测试方法名 | 测试场景 | 预期结果 |
|-----------|---------|---------|
| test_create_success | 正常新增部门，companyId和参数合法 | 返回非null ID，deptCode由编码引擎生成 |
| test_create_companyNotFound | companyId不存在 | 抛出BusinessException，message包含"所属公司不存在" |
| test_create_duplicateName | 同公司同上级下新增同名部门 | 抛出BusinessException，message包含"部门名称已存在" |
| test_create_differentParent_sameName | 同公司不同上级下同名部门 | 创建成功（不同上级允许同名） |
| test_create_topLevel | parentId为0或null创建顶级部门 | 创建成功，parentId存储为0 |
| test_update_success | 正常修改部门名称 | 数据库中名称已更新 |
| test_update_circularRef_self | parentId设为自身ID | 抛出BusinessException，message包含"不能将部门设为自身" |
| test_update_circularRef_descendant | parentId设为子孙部门ID(A→B→C，C的parent改为A) | 抛出BusinessException |
| test_delete_success | 删除无关联数据的部门 | 删除成功 |
| test_delete_hasChildDept | 删除有子部门的部门 | 抛出BusinessException，message包含"存在子部门" |
| test_delete_hasPosition | 删除有关联岗位的部门 | 抛出BusinessException，message包含"存在岗位" |
| test_delete_hasEmployee | 删除有关联员工的部门 | 抛出BusinessException，message包含"存在员工" |
| test_tree_multiLevel | 3级部门树(顶级→二级→三级) | 返回正确的树形结构，children嵌套正确 |
| test_tree_emptyCompany | 无部门的公司查询树 | 返回空列表 |
| test_page_companyFilter | 按companyId筛选 | 返回结果全部属于指定公司 |

### 5.3 测试数据准备

1. 插入2个公司记录（测试跨公司隔离）
2. 在公司A下插入3级部门结构：技术部→研发中心→前端组
3. 在前端组下插入1个岗位记录（用于删除关联检查）
4. Mock编码引擎返回固定编码

### 5.4 循环引用测试场景

```
场景1: A(parent=0) → 修改A.parent=A → 拒绝(自身引用)
场景2: A→B→C → 修改A.parent=C → 拒绝(子孙引用)
场景3: A→B, C(parent=0) → 修改C.parent=B → 允许(正常引用)
```

## 八、易错警示

> ⚠️ 循环引用测试需要构造多层级部门数据(A→B→C)，确保测试数据的parent_id链路正确

> ⚠️ Mock编码引擎时使用@MockBean，when(codeEngineService.generateCode(any(), any())).thenReturn("DEPT_TEST_001")

> ⚠️ 删除关联检查测试需要准备hrm_employee数据，若HRM模块未开发可Mock员工Mapper

> ⚠️ tree方法测试要验证多级嵌套(至少3级)和空树两种场景，断言children的size和内容

> ⚠️ 部门名称唯一性校验范围是同公司同上级下，不同上级或不同公司允许同名，测试用例需覆盖这两种情况
