### 5.2 测试用例清单

| 测试方法名 | 测试场景 | 预期结果 |
|-----------|---------|---------|
| test_create_success | 正常新增岗位，departmentId存在且参数合法 | 返回非null ID，positionCode由编码引擎生成 |
| test_create_deptNotFound | departmentId不存在 | 抛出BusinessException，message包含"所属部门不存在" |
| test_create_duplicateName | 同部门下新增同名岗位 | 抛出BusinessException，message包含"岗位名称已存在" |
| test_create_differentDept_sameName | 不同部门下同名岗位 | 创建成功（不同部门允许同名） |
| test_create_blankName | positionName为空字符串 | 抛出MethodArgumentNotValidException |
| test_update_success | 正常修改岗位名称和级别 | 数据库中数据已更新 |
| test_update_duplicateNameExcludeSelf | 修改为同部门下其他岗位的名称 | 抛出BusinessException |
| test_update_changeDept | 修改岗位所属部门 | 在新部门下做名称唯一性校验 |
| test_update_notFound | 修改不存在的岗位ID | 抛出BusinessException |
| test_delete_success | 删除无关联员工的岗位 | 删除成功 |
| test_delete_hasEmployee | 删除有关联员工的岗位 | 抛出BusinessException，message包含"该岗位下存在员工" |
| test_delete_notFound | 删除不存在的岗位 | 抛出BusinessException |
| test_page_deptFilter | 按departmentId筛选 | 返回结果全部属于指定部门 |
| test_page_keywordSearch | keyword模糊搜索positionName/positionCode | 返回结果匹配keyword |
| test_page_combinedFilter | departmentId+keyword+enableFlag组合筛选 | 返回结果同时满足所有条件 |
| test_getById_withDeptName | 查询岗位详情 | 返回PositionDetailVO含departmentName关联字段 |

### 5.3 测试数据准备

1. 插入1个公司记录
2. 在公司下插入2个部门：研发部(ID=101)、产品部(ID=102)
3. 在研发部插入2个岗位：前端开发、后端开发
4. 在产品部插入1个岗位：产品经理（测试跨部门同名场景）
5. 为"前端开发"岗位关联1个员工记录（用于删除检查）
6. Mock编码引擎返回固定编码

### 5.4 边界测试

- positionName长度为100(最大值)：创建成功
- positionName长度为101：校验失败
- sortNo为负数：@Min(0)校验失败
- positionType为非法值(如"admin")：@Pattern校验失败

## 八、易错警示

> ⚠️ 岗位名称唯一性范围是同departmentId下，测试必须覆盖"同部门拒绝同名"和"不同部门允许同名"两种场景

> ⚠️ Mock编码引擎时使用@MockBean，确保不影响其他模块的编码生成

> ⚠️ 员工关联测试需要构造hrm_employee数据，若HRM模块未开发可通过直接SQL插入测试数据

> ⚠️ update方法变更departmentId时，需在新部门下重新做名称唯一性校验，测试用例需覆盖此场景

> ⚠️ 边界测试(字段长度、负数、非法枚举值)由DTO层校验注解处理，测试时断言MethodArgumentNotValidException而非BusinessException
