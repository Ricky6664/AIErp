## 五、详细开发规格

### 5.1 OrgCompanyServiceImpl实现

继承ServiceImplX\<OrgCompanyMapper, OrgCompany\>，实现OrgCompanyService接口：

```java
@Service
public class OrgCompanyServiceImpl extends ServiceImplX<OrgCompanyMapper, OrgCompany>
    implements OrgCompanyService {

    @Override
    @Transactional(readOnly = true)
    public PageResult<CompanyListVO> page(CompanyQueryDTO query) { ... }

    @Override
    @Transactional(readOnly = true)
    public CompanyDetailVO getById(Long id) { ... }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public Long create(CompanyCreateDTO dto) { ... }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void update(Long id, CompanyUpdateDTO dto) { ... }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void delete(Long id) { ... }
}
```

### 5.2 page方法实现逻辑

1. 构建LambdaQueryWrapper，条件：is_deleted=false
2. 若keyword非空：嵌套条件 WHERE (company_name LIKE '%keyword%' OR company_short_name LIKE '%keyword%')
3. 若enabled非空：AND enable_flag = enabled
4. 按created_at DESC排序
5. 调用page(pageParam, wrapper)获取分页结果
6. Entity列表 → CompanyListVO列表（使用BeanUtils.copyProperties或MapStruct）
7. 返回PageResult\<CompanyListVO\>

### 5.3 create方法实现逻辑

1. **名称唯一性校验**：查询is_deleted=false AND tenant_id=当前租户 AND company_name=dto.companyName，存在则抛BusinessException(ErrorCode.DUPLICATE, "公司名称已存在")
2. **信用代码校验**（若creditCode非空）：
   - 格式校验：正则`^[0-9A-HJ-NP-RTUW-Y]{2}\d{6}[0-9A-HJ-NP-RTUW-Y]{10}$`，不匹配抛BusinessException(ErrorCode.INVALID_FORMAT, "统一社会信用代码格式不正确")
   - 唯一性校验：查询is_deleted=false AND credit_code=dto.creditCode，存在则抛BusinessException(ErrorCode.DUPLICATE, "统一社会信用代码已存在")
3. **注册资本校验**：registeredCapital >= 0（DTO层@DecimalMin已校验，此处双重保险）
4. **DTO → Entity转换**：BeanUtils.copyProperties(dto, entity)
5. **系统字段自动填充**：enableFlag默认true，version默认1（由BaseEntity处理）
6. 调用save(entity)
7. 记录操作日志：operLogService.saveLog("新增公司", entity.getId())
8. 返回entity.getId()

### 5.4 update方法实现逻辑

1. **存在性校验**：getById(id)，不存在抛BusinessException(ErrorCode.NOT_FOUND, "公司不存在")
2. **名称唯一性校验(排除自身)**：查询is_deleted=false AND tenant_id=当前租户 AND company_name=dto.companyName AND id != 当前id
3. **信用代码校验(排除自身)**：若creditCode非空，格式校验+唯一性校验(排除自身)
4. **DTO → Entity转换 + 乐观锁更新**：使用updateById(entity)，MyBatis-Plus乐观锁插件自动处理version字段
5. 记录操作日志

### 5.5 delete方法实现逻辑

1. **存在性校验**：getById(id)，不存在抛BusinessException
2. **关联部门检查**：查询org_department表WHERE company_id=id AND is_deleted=false，count>0则抛BusinessException(ErrorCode.REFERENCE_EXISTS, "该公司下存在部门，无法删除")
3. **逻辑删除**：removeById(id)（MyBatis-Plus逻辑删除插件自动设置is_deleted=true）
4. 记录操作日志

### 5.6 集成点

- **操作日志**：通过OperLogService记录增删改操作，日志内容含操作类型、操作对象ID、操作前后数据快照
- **多租户隔离**：tenant_id由TenantContext自动注入到SQL条件中，无需手动处理
- **乐观锁**：通过@Version注解的version字段实现，updateById时自动version+1并检查原version

## 八、易错警示

> ⚠️ @Transactional加在实现方法上，不要加在接口上；写方法必须指定rollbackFor=Exception.class

> ⚠️ 避免大事务：只读方法(page/getById)加readOnly=true，减少数据库锁开销

> ⚠️ 业务异常使用BusinessException(ErrorCode.XXX, "消息")，不要使用RuntimeException或原生throw

> ⚠️ 信用代码格式校验和唯一性校验都要做，格式校验在前、唯一性校验在后（减少数据库查询）

> ⚠️ 名称唯一性校验的条件必须包含tenant_id(多租户隔离)和is_deleted=false(软删除)，UPDATE时还要排除自身ID
