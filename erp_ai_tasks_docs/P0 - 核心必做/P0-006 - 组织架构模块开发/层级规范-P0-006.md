## 1. 模块架构约束

### 1.1 模块定位
P0-006负责开发ERP系统的组织架构管理功能，包括公司管理、部门管理（树形结构）、岗位管理。本模块为所有业务模块提供公司、部门、岗位基础数据支撑，是员工管理、数据权限、业务单据归属等功能的底层数据来源。

### 1.2 依赖关系
- 前置依赖：
  - P0-001（后端框架提供基础DAO层/统一响应/异常处理）
  - P0-002（前端框架提供路由/布局/状态管理）
  - P0-003（数据库提供org_company/org_department/org_position表）
  - P0-004（认证与权限提供权限控制/数据权限过滤）
  - P0-005（公共组件提供页面类型基座/录入组件/选择器）
- 后续依赖：
  - P0-007~P0-012（商品/CRM/SRM/WMS/财务基础/HRM）——引用公司/部门/岗位数据
  - P1-005~P1-010（销售/采购/库存/生产/委外/质检）——引用组织架构数据

### 1.3 技术约束
- **技术栈约束**：Spring Boot 3.4.x + MyBatis-Plus 3.5.5 + Sa-Token权限控制 + Vue3 + Element Plus + Vxe Table
- **性能约束**：部门树加载 < 300ms（1000个节点）；公司/岗位列表查询 < 100ms
- **安全约束**：部门数据按数据权限过滤（用户仅可见本部门及下级部门）；删除操作需校验关联数据

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| org_company | 公司表 | company_name, short_name, credit_code, legal_person, registered_capital, address, phone, is_enabled |
| org_department | 部门表 | dept_name, dept_code, parent_id, company_id, manager_id, dept_type, sort_order, is_enabled |
| org_position | 岗位表 | position_name, position_code, department_id, position_level, position_type, sort_order, is_enabled |

### 2.2 表关系图
- `org_company` 1:N `org_department`：一个公司下包含多个部门
- `org_department` 自引用（parent_id）：部门为树形结构，支持无限层级
- `org_department` 1:N `org_position`：一个部门下包含多个岗位
- `org_department` N:1 `hrm_employee`（manager_id）：部门负责人引用员工表
- 被引用关系：sys_user_dept引用org_department，crm_customer引用org_company，所有业务单据的owner_dept_id引用org_department

### 2.3 数据流转
1. **公司管理**：新增公司 → 编码引擎生成公司编码 → 保存到org_company → 前端列表刷新
2. **部门管理**：选择公司 → 加载部门树 → 新增/编辑部门节点 → 校验部门编码唯一性 → 保存 → 更新部门树
3. **岗位管理**：选择部门 → 加载该部门岗位列表 → 新增/编辑岗位 → 校验岗位编码唯一性 → 保存

## 3. 业务流程

### 3.1 核心业务流程
1. **组织架构后端开发**（P0-006-001）：
   - 实现公司CRUD接口（含编码自动生成+名称唯一性校验+信用代码唯一性校验）
   - 实现部门树CRUD接口（含树形结构查询+部门编码唯一性校验+删除关联校验）
   - 实现岗位CRUD接口（含岗位编码唯一性校验+所属部门关联校验+删除关联校验）
   - 实现组织架构工作台聚合接口（公司数量/部门数量/岗位数量/在职人数统计）
2. **组织架构前端页面**（P0-006-002）：
   - 组织架构工作台（P02工作台页面：KPI卡片+统计图表）
   - 组织中心首页（P02工作台：组织架构图展示）
   - 公司管理列表页（P04）+ 新增/编辑表单（P07弹窗大）
   - 部门管理树形列表页（P05）+ 新增/编辑表单（P07弹窗中）
   - 岗位管理列表页（P04）+ 新增/编辑表单（P07弹窗中）

### 3.2 业务规则
- **公司编码唯一性**：公司编码通过编码引擎自动生成，在事务内保证唯一
- **统一社会信用代码唯一性**：公司信用代码全局唯一
- **部门树形结构**：部门支持无限层级嵌套，parent_id为null或0表示顶级部门
- **部门删除关联校验**：删除部门前需校验是否存在下级部门、是否存在关联岗位、是否存在关联员工，存在时禁止删除
- **岗位归属校验**：岗位的所属部门必须有效且启用
- **数据权限过滤**：部门列表查询时根据当前用户角色的数据权限范围过滤可见部门
- **编码自动生成**：公司编码、部门编码、岗位编码均通过P0-001编码引擎自动生成

### 3.3 状态流转
- **公司启用状态**：启用(enabled) ↔ 禁用(disabled)，禁用后关联部门/岗位不受影响但不可被新单据引用
- **部门启用状态**：启用(enabled) ↔ 禁用(disabled)，禁用后下级部门自动禁用
- **岗位启用状态**：启用(enabled) ↔ 禁用(disabled)

| /api/org/department | POST | 新增部门 |
| /api/org/department/{id} | PUT | 修改部门 |

### 4.2 依赖接口
- `/api/code/generate`（P0-001编码引擎）——生成公司/部门/岗位编码
- `/api/system/dict/data/by-code/{dictTypeCode}`（P0-005字典组件）——部门类型/岗位类型下拉
- P0-004提供的数据权限过滤能力（owner_dept_id过滤）
- P0-005提供的P02/P04/P05/P07页面类型基座组件

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **P0-006-001 组织架构后端开发**（前端页面依赖后端接口）
2. **P0-006-001** → **P0-006-002 组织架构前端页面**

### 5.2 可并行执行的任务
后端开发内部可按以下顺序并行：
- 公司管理CRUD、部门管理CRUD、岗位管理CRUD三者可并行开发（互不依赖，但部门删除校验依赖岗位/员工查询接口）
- 工作台聚合接口可在三个CRUD完成后开发

前端开发内部可按以下顺序并行：
- 公司管理页面、部门管理页面、岗位管理页面可并行开发（各自独立页面类型）
- 工作台页面可在三个管理页面完成后开发
