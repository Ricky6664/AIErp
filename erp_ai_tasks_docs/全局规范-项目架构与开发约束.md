# 全局规范 - 项目架构与开发约束

> 本文档是项目开发任务的最高层级架构参考文档。所有开发任务执行前必须理解本文档所述架构约束与开发原则。
>
> **文档定位**：本规范汇总项目核心架构信息，使末端任务文档无需加载任何外部总文档即可独立执行开发。

---

## 1. 项目概述

本项目为全栈企业ERP系统，覆盖以下业务域：

- **基础管理**：组织架构、商品管理、CRM客户管理、SRM供应商管理
- **供应链**：采购管理、销售管理、库存管理、仓库管理
- **生产制造**：生产管理、委外管理
- **财务核算**：应收管理、应付管理、凭证管理、账簿查询、财务报表、成本核算
- **扩展业务**：费用管理、固定资产、期末处理、OA办公、AI助手
- **系统支撑**：认证权限、消息管理、审批流程、通用单据引擎、模板中心、报表中心

共计46个一级模块，按P0（核心必做）、P1（重要）、P2（常规）三级优先级分批交付。

## 3. 开发执行核心原则

| 原则 | 说明 |
|------|------|
| 依赖前置 | 被依赖的模块必须先开发，依赖方必须后开发 |
| 先基础后业务 | 先完成框架、数据库、认证、公共组件，再做业务模块 |
| 先底层后上层 | 先完成后端接口/服务层，再完成前端页面/展示层 |
| 先公共后业务 | 先完成通用引擎（编码引擎/审核引擎/流转引擎），再做业务单据 |
| 后端先行 | 每个模块内部，后端（建表→Entity→Mapper→Service→Controller）先于前端（页面→组件→交互） |
| 单任务原子性 | 每个最末级任务为一个最小不可拆分的开发执行单元，AI单次可独立完成 |

### 单模块开发内部顺序

每个业务模块严格按以下顺序执行：

```
1. 数据库建表（CREATE TABLE + 索引 + 约束）
2. 后端 Entity/DTO/VO 定义
3. 后端 Mapper 层（MyBatis-Plus Mapper + XML映射）
4. 后端 Service 层（业务逻辑 + 校验 + 联动 + 计算）
5. 后端 Controller 层（RESTful API接口）
6. 后端单元可运行验证（接口可调通）
7. 前端页面路由注册 + 菜单数据配置
8. 前端页面开发（基于页面类型基座组件 + 字段配置渲染）
9. 前后端联调验证
```

### 任务颗粒度标准

最末级任务（叶子节点）必须同时满足：
1. **单次可完成**：AI在单次执行上下文中可独立完成，无需跨上下文
2. **边界明确**：有清晰的输入（依赖项）和输出（交付物）
3. **可验证**：有明确的验证标准（接口可调通/页面可渲染/功能可操作）
4. **无交叉**：与其他叶子任务无功能重叠或逻辑耦合
5. **原子性**：不可进一步拆分为更小的有意义的开发单元

### 代码规范通用要求

- 标点符号**全部半角**，禁止中文全角标点（字符串内中文文本除外）
- 所有函数参数（含回调、事件处理器）**必须标注类型**，禁止隐式 any
- 所有组件/函数/类型**使用前必须 import**，禁止假设全局可用
- 括号 `(){}[]` 和模板字符串必须**成对闭合**

## 5. 开发约束（强制性规则）

以下约束适用于所有开发任务，违反任何一条均为不合格交付：

| 编号 | 约束内容 | 详细规范 |
|------|---------|---------|
| C-01 | 技术栈版本必须与《全局规范-技术栈版本锁定》严格对齐，禁止升级/降级/替换 | 全局规范-技术栈版本锁定.md |
| C-02 | 所有业务表必须包含 `tenant_id` 字段，多租户隔离由 MyBatis-Plus TenantLineInnerInterceptor 自动注入 | 全局规范-通用业务规则.md |
| C-03 | 所有删除操作使用软删除（`is_deleted`），禁止物理 DELETE | 全局规范-通用业务规则.md |
| C-04 | 所有业务表必须包含 `version` 乐观锁字段，防止并发修改冲突 | 全局规范-通用业务规则.md |
| C-05 | 主键统一使用雪花算法（`IdType.ASSIGN_ID`），禁止自增ID和UUID | 全局规范-通用业务规则.md |
| C-06 | API响应统一使用 `R<T>` 包装，分页使用 `PageResult<T>` | 全局规范-后端代码规范.md |
| C-07 | 敏感信息（密码、密钥、Token）禁止硬编码，必须使用环境变量注入 | 全局规范-安全开发规范.md |
| C-08 | 所有API接口必须添加 Knife4j/SpringDoc 注解，保证接口文档可自动生成 | 全局规范-API接口规范.md |
| C-09 | 事务操作必须添加 `@Transactional` 注解，明确事务传播行为和回滚规则 | 全局规范-后端代码规范.md |
| C-10 | 前端页面严格遵循 Element Plus + Tailwind CSS 主题划分约定，深色模式统一通过 Element Plus 的 dark class 切换 | 全局规范-前端代码规范.md |
| C-11 | 前端代码禁止隐式 any，所有函数参数必须标注类型，使用前必须 import | 全局规范-前端代码规范.md |
| C-12 | 数据库唯一约束必须包含 `is_deleted` 条件（部分唯一索引），避免软删除后冲突 | 全局规范-数据库规范.md |

## 7. 数据库通用字段规范

所有业务表必须包含以下通用系统字段（不重复列入各模块字段清单）：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `id` | bigint | 主键，雪花算法（IdType.ASSIGN_ID） |
| `tenant_id` | bigint | 租户ID，多租户隔离，NOT NULL |
| `is_deleted` | boolean | 软删除标记，默认 false |
| `version` | int | 乐观锁版本号，默认 0 |
| `created_by` | bigint | 创建人ID，自动填充 |
| `created_at` | timestamp | 创建时间，自动填充 |
| `updated_by` | bigint | 最后更新人ID，自动填充 |
| `updated_at` | timestamp | 最后更新时间，自动填充 |

> 详细字段规范（含单据主表特有字段、明细从表快照原则等）详见《全局规范-数据库规范.md》和《全局规范-通用业务规则.md》。

## 8. 后端项目结构约定

```
erp-server/
└── src/main/java/com/erp/
    ├── ErpApplication.java           # Spring Boot 启动类
    ├── config/                       # 全局配置类
    │   ├── MybatisPlusConfig.java    # MyBatis-Plus（多租户/软删除/乐观锁/分页）
    │   ├── SaTokenConfig.java        # Sa-Token 权限配置
    │   ├── RedisConfig.java          # Redis 配置
    │   └── CorsConfig.java           # 跨域配置
    ├── common/                       # 公共基础
    │   ├── entity/BaseEntity.java    # 实体基类（通用字段）
    │   ├── result/R.java             # 统一响应包装类
    │   ├── result/PageResult.java    # 分页响应包装类
    │   ├── exception/                # 全局异常处理
    │   ├── utils/                    # 工具类
    │   └── enums/                    # 公共枚举
    ├── modules/                      # 业务模块（按模块分子包）
    │   └── {module}/                 # 每个模块含 controller/service/mapper/entity/dto/vo
    └── engine/                       # 通用引擎（编码/审核/流转/消息）
```

> 完整项目结构（含前端项目结构、配置文件目录）详见《全局规范-后端代码规范.md》和《全局规范-前端代码规范.md》。
