# 全局规范-第三方集成规范

> 本文档定义第三方系统集成的架构模式、API客户端设计、熔断降级策略、认证鉴权方式、Webhook处理及日志记录规范，所有涉及外部系统对接的开发任务必须严格遵守。

---

## 1. 集成架构：防腐层模式（ACL）

### 1.1 架构原则

| 原则 | 说明 |
|------|------|
| 隔离外部变化 | 第三方API变更不影响内部业务逻辑 |
| 统一数据模型 | 外部DTO与内部Entity通过映射层转换 |
| 可替换性 | 更换第三方服务商只需修改适配层代码 |
| 可测试性 | 通过Mock/WireMock隔离外部依赖 |

### 1.2 包结构规范

```
com.erp.integration
├── common                          # 集成公共组件
│   ├── IntegrationException.java       # 集成异常基类
│   ├── IntegrationErrorCode.java       # 集成错误码
│   ├── RetryPolicy.java                # 重试策略
│   └── CircuitBreakerConfig.java       # 熔断器配置
├── {provider}                      # 按服务商分包
│   ├── client                          # API客户端
│   │   └── {Provider}Client.java
│   ├── adapter                         # 适配器（防腐层核心）
│   │   └── {Provider}Adapter.java
│   ├── dto                             # 外部DTO（请求/响应）
│   │   ├── {Provider}Request.java
│   │   └── {Provider}Response.java
```

## 2. API客户端设计规范

### 2.1 RestClient配置

```java
@Configuration
public class IntegrationRestClientConfig {

    @Bean("integrationRestClient")
    public RestClient integrationRestClient() {
        return RestClient.builder()
            .requestFactory(clientHttpRequestFactory())
            .defaultHeader("User-Agent", "ERP-Integration/1.0")
            .defaultHeader("Accept", "application/json")
            .build();
    }

    @Bean
    public ClientHttpRequestFactory clientHttpRequestFactory() {
        HttpComponentsClientHttpRequestFactory factory =
            new HttpComponentsClientHttpRequestFactory();
        factory.setConnectTimeout(Duration.ofSeconds(5));    // 连接超时5s
        factory.setReadTimeout(Duration.ofSeconds(30));       // 读超时30s
        factory.setConnectionRequestTimeout(Duration.ofSeconds(3)); // 连接池获取超时3s
        return factory;
    }
}
```

### 2.2 超时配置规范

| 超时类型 | 默认值 | 可配置 | 说明 |
|---------|--------|--------|------|
| 连接超时（connect） | 5s | 按服务商调整 | 建立TCP连接的最大等待时间 |
| 读超时（read） | 30s | 按服务商调整 | 等待响应数据的最大时间 |
| 连接池获取超时 | 3s | 固定 | 从连接池获取连接的最大等待时间 |
| 写超时（write） | 10s | 按服务商调整 | 发送请求数据的最大时间 |

### 2.3 请求/响应日志

```java
@Component
public class IntegrationLogInterceptor implements ClientHttpRequestInterceptor {

    @Autowired
    private IntegrationLogService integrationLogService;

    @Override
    public ClientHttpResponse intercept(HttpRequest request, byte[] body,
            ClientHttpRequestExecution execution) throws IOException {

        long startTime = System.currentTimeMillis();
        String requestBody = new String(body, StandardCharsets.UTF_8);

        // 脱敏处理：移除敏感字段
        String sanitizedRequest = sanitizeSensitiveFields(requestBody);

        ClientHttpResponse response = null;
        String responseBody = null;
        int statusCode = 0;
        String errorMsg = null;

        try {
            response = execution.execute(request, body);
            statusCode = response.getStatusCode().value();
            responseBody = StreamUtils.copyToString(response.getBody(), StandardCharsets.UTF_8);

            // 脱敏响应
            String sanitizedResponse = sanitizeSensitiveFields(responseBody);

            return response;
        } catch (IOException e) {
            errorMsg = e.getMessage();
            throw e;
        } finally {
            long duration = System.currentTimeMillis() - startTime;
            // 异步记录集成日志
            integrationLogService.logAsync(
                request.getURI().toString(),
                sanitizedRequest,
                statusCode,
                sanitizeSensitiveFields(responseBody),
                duration,
                errorMsg
            );
        }
    }

    /**
     * 敏感字段脱敏
     */
    private String sanitizeSensitiveFields(String content) {
        if (content == null) return null;
        // 脱敏规则：密码、Token、密钥、手机号、身份证号
        return content
            .replaceAll("\"password\"\\s*:\\s*\"[^\"]*\"", "\"password\":\"******\"")
            .replaceAll("\"token\"\\s*:\\s*\"[^\"]*\"", "\"token\":\"******\"")
            .replaceAll("\"secret\"\\s*:\\s*\"[^\"]*\"", "\"secret\":\"******\"")
            .replaceAll("\"phone\"\\s*:\\s*\"(\\d{3})\\d{4}(\\d{4})\"", "\"phone\":\"$1****$2\"")
            .replaceAll("\"idCard\"\\s*:\\s*\"(\\d{6})\\d{8}(\\d{4})\"", "\"idCard\":\"$1********$2\"");
    }
}
```

### 2.4 重试策略

```java
@Configuration
public class RetryConfig {

    @Bean("integrationRetryTemplate")
    public RetryTemplate integrationRetryTemplate() {
        return RetryTemplate.builder()
            .maxAttempts(3)                                    // 最多重试3次
            .exponentialBackoff(
                Duration.ofSeconds(1),                         // 初始间隔1s
                2.0,                                           // 倍数因子2.0
                Duration.ofSeconds(4)                          // 最大间隔4s
            )
            .retryOn(HttpClientErrorException.TooManyRequests.class)  // 429 限流
            .retryOn(HttpServerErrorException.class)                  // 5xx 服务端错误
            .retryOn(ResourceAccessException.class)                   // 网络异常
            .noRetryOn(HttpClientErrorException.BadRequest.class)     // 400 不重试
            .noRetryOn(HttpClientErrorException.Unauthorized.class)   // 401 不重试
            .build();
    }
}
```

| 重试参数 | 值 | 说明 |
|---------|---|------|
| 最大尝试次数 | 3 | 首次请求 + 2次重试 |
| 初始间隔 | 1s | 首次重试等待时间 |
| 倍数因子 | 2.0 | 间隔倍增：1s → 2s → 4s |
| 最大间隔 | 4s | 单次等待上限 |
| 可重试异常 | 429、5xx、网络异常 | 临时性故障 |
| 不可重试异常 | 400、401、403、404 | 客户端错误，重试无意义 |

## 3. 熔断器模式（Resilience4j）

### 3.1 熔断器配置

```java
@Configuration
public class CircuitBreakerConfig {

    @Bean
    public io.github.resilience4j.circuitbreaker.CircuitBreakerRegistry circuitBreakerRegistry() {
        CircuitBreakerConfig config = CircuitBreakerConfig.custom()
            .failureRateThreshold(50)                           // 失败率阈值：50%
            .slidingWindowType(SlidingWindowType.COUNT_BASED)   // 计数窗口
            .slidingWindowSize(20)                              // 窗口大小：20次调用
            .minimumNumberOfCalls(10)                           // 最少调用数
            .waitDurationInOpenState(Duration.ofSeconds(60))    // 熔断持续时间：60s
            .permittedNumberOfCallsInHalfOpenState(5)           // 半开状态测试调用数：5
            .recordExceptions(                                  // 记录为失败的异常
                IOException.class,
                TimeoutException.class,
                HttpServerErrorException.class
            )
            .ignoreExceptions(                                  // 忽略的异常（不计入失败率）
                HttpClientErrorException.BadRequest.class,
                HttpClientErrorException.Unauthorized.class
            )
            .build();

        return CircuitBreakerRegistry.of(config);
    }
}
```

### 3.2 熔断器参数规范

| 参数 | 值 | 说明 |
|------|---|------|
| failureRateThreshold | 50% | 在滑动窗口内失败率达到50%时触发熔断 |
| slidingWindowSize | 20 | 统计最近20次调用的失败率 |
| waitDurationInOpenState | 60s | 熔断打开后等待60秒进入半开状态 |
| permittedNumberOfCallsInHalfOpenState | 5 | 半开状态允许5次测试调用 |
| minimumNumberOfCalls | 10 | 至少10次调用后才计算失败率 |

### 3.3 熔断器状态流转

```
  正常调用
    │
    │ 失败率≥50%（20次调用中）
    ▼
 ┌────────┐    60s后     ┌────────┐    5次测试调用    ┌────────┐
 │ CLOSED │ ──────────> │  OPEN  │ ──────────────> │HALF_OPEN│
 │ (正常)  │             │ (熔断)  │                 │ (半开)   │
 └────────┘             └────────┘                 └────┬───┘
    ▲                                                    │
    │              失败率<阈值（恢复正常）                   │
    └────────────────────────────────────────────────────┘
                             │
                      失败率≥阈值 → 回到OPEN
```

### 3.4 降级方法实现

```java
@Service
public class SmsServiceWithFallback {

    @CircuitBreaker(name = "smsService", fallbackMethod = "sendFallback")
    public SmsSendResult send(SmsSendRequest request) {
        return smsAdapter.send(request);
    }

    /**
     * 降级方法：签名必须与原方法一致，额外增加Throwable参数
     */
    private SmsSendResult sendFallback(SmsSendRequest request, Throwable t) {
        log.warn("短信服务熔断降级，手机号={}，原因={}", request.getPhone(), t.getMessage());

        // 降级策略：记录待发送队列，等服务恢复后补发
        pendingSmsRepository.save(PendingSms.builder()
            .phone(request.getPhone())
            .templateCode(request.getTemplateCode())
            .params(request.getParams())
            .retryCount(0)
            .nextRetryTime(LocalDateTime.now().plusMinutes(5))
            .build());

        return SmsSendResult.builder()
            .success(false)
            .errorCode("INTEGRATION_CIRCUIT_OPEN")
            .errorMsg("短信服务暂时不可用，已加入待发送队列")
            .build();
    }
}
```

### 4.3 HMAC签名认证

```java
@Component
public class HmacSignatureInterceptor implements ClientHttpRequestInterceptor {

    @Value("${integration.provider.access-key}")
    private String accessKey;

    @Value("${integration.provider.secret-key}")
    private String secretKey;

    @Override
    public ClientHttpResponse intercept(HttpRequest request, byte[] body,
            ClientHttpRequestExecution execution) throws IOException {

        String timestamp = String.valueOf(System.currentTimeMillis());
        String nonce = UUID.randomUUID().toString().replace("-", "");

        // 构造待签名字符串：accessKey + timestamp + nonce + body
        String stringToSign = accessKey + timestamp + nonce + new String(body, StandardCharsets.UTF_8);

        // HMAC-SHA256签名
        String signature = hmacSha256(stringToSign, secretKey);

        request.getHeaders().set("X-Access-Key", accessKey);
        request.getHeaders().set("X-Timestamp", timestamp);
        request.getHeaders().set("X-Nonce", nonce);
        request.getHeaders().set("X-Signature", signature);

        return execution.execute(request, body);
    }

    private String hmacSha256(String data, String key) {
        try {
            Mac mac = Mac.getInstance("HmacSHA256");
            mac.init(new SecretKeySpec(key.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
            byte[] hash = mac.doFinal(data.getBytes(StandardCharsets.UTF_8));
            return Hex.encodeHexString(hash);
        } catch (Exception e) {
            throw new IntegrationException("HMAC签名失败", e);
        }
    }
}
```

### 4.4 认证方式选择矩阵

| 认证方式 | 适用场景 | 安全等级 | 典型服务商 |
|---------|---------|---------|----------|
| API Key（Header） | 简单接口、低频调用 | 中 | 天气查询、地理编码 |
| OAuth2 Client Credentials | 需要Token刷新、权限控制 | 高 | 企业微信、钉钉 |
| HMAC签名 | 高安全要求、防篡改 | 高 | 支付宝、微信支付 |
| 证书双向认证 | 金融级安全要求 | 极高 | 银行接口、税务接口 |

## 5. Webhook处理规范

### 5.1 Webhook端点规范

| 规范项 | 要求 |
|--------|------|
| 端点路径 | `POST /api/integration/webhook/{provider}` |
| 签名验证 | 必须验证请求签名，防止伪造 |
| 幂等处理 | 基于event_id去重，重复事件直接返回200 |
| 异步处理 | 接收后立即返回200，业务逻辑通过RabbitMQ异步处理 |
| 响应时间 | 必须在5秒内返回响应，超时视为失败 |

### 5.2 Webhook处理流程

```
第三方系统
    │
    │ POST /api/integration/webhook/{provider}
    ▼
┌─────────────────────────────────┐
│  WebhookController              │
│  1. 验证签名（中间件）            │
│  2. 解析请求体                   │
│  3. 幂等检查（Redis event_id）   │
│  4. 发送消息到RabbitMQ           │
│  5. 立即返回200 OK               │
└──────────┬──────────────────────┘
           │
           ▼
┌─────────────────────────────────┐
│  RabbitMQ Queue                 │
│  erp.integration.webhook.{provider} │
└──────────┬──────────────────────┘
           │
           ▼
┌─────────────────────────────────┐
│  WebhookConsumer                │
│  1. 幂等消费检查                 │
│  2. 数据转换（外部DTO→内部模型）  │
│  3. 业务处理                     │
│  4. 记录处理日志                 │
│  5. ACK确认                     │
└─────────────────────────────────┘
```

### 5.3 Webhook签名验证

```java
@RestController
@RequestMapping("/api/integration/webhook")
public class WebhookController {

    @PostMapping("/{provider}")
    public ResponseEntity<String> handleWebhook(
            @PathVariable String provider,
            @RequestHeader Map<String, String> headers,
            @RequestBody String rawBody) {

        // 1. 签名验证
        WebhookProvider webhookProvider = WebhookProviderFactory.getProvider(provider);
        if (!webhookProvider.verifySignature(headers, rawBody)) {
            log.warn("Webhook签名验证失败，provider={}", provider);
            return ResponseEntity.status(401).body("Invalid signature");
        }

        // 2. 解析事件
        WebhookEvent event = webhookProvider.parseEvent(rawBody);

        // 3. 幂等检查
        String deduplicateKey = "erp:webhook:received:" + event.getEventId();
        Boolean isNew = redisTemplate.opsForValue()
            .setIfAbsent(deduplicateKey, "1", 48, TimeUnit.HOURS);
        if (!Boolean.TRUE.equals(isNew)) {
            log.info("Webhook重复事件，eventId={}", event.getEventId());
            return ResponseEntity.ok("OK");
        }

        // 4. 异步处理
        rabbitTemplate.convertAndSend(
            "erp.integration",
            "integration.webhook." + provider,
            event);

        // 5. 立即返回
        return ResponseEntity.ok("OK");
    }
}
```

```java
@Component
public class AliyunSmsConverter {

    /**
     * 内部模型 → 阿里云短信请求
     */
    public AliyunSmsSendRequest toExternalRequest(SmsSendRequest internalRequest) {
        AliyunSmsSendRequest external = new AliyunSmsSendRequest();
        external.setPhoneNumbers(internalRequest.getPhone());
        external.setSignName(internalRequest.getSignName());
        external.setTemplateCode(internalRequest.getTemplateCode());
        external.setTemplateParam(JSON.toJSONString(internalRequest.getParams()));
        external.setOutId(internalRequest.getBizId());
        return external;

     * 阿里云响应 → 内部模型

        return SmsSendResult.builder()
            .success("OK".equals(externalResponse.getCode()))
            .bizId(externalResponse.getBizId())
            .errorCode(externalResponse.getCode())
            .errorMsg(externalResponse.getMessage())
            .build();
    }
}
```

## 8. 限流处理

### 8.1 Token Bucket限流

```java
@Component
public class IntegrationRateLimiter {

    private final ConcurrentHashMap<String, RateLimiter> limiters = new ConcurrentHashMap<>();

    /**
     * 获取或创建限流器
     */
    public RateLimiter getRateLimiter(String providerCode, int permitsPerSecond) {
        return limiters.computeIfAbsent(providerCode,
            key -> RateLimiter.create(permitsPerSecond));
    }

    /**
     * 尝试获取许可（带超时）
     */
    public boolean tryAcquire(String providerCode, int permitsPerSecond, long timeoutMs) {
        RateLimiter limiter = getRateLimiter(providerCode, permitsPerSecond);
        return limiter.tryAcquire(timeoutMs, TimeUnit.MILLISECONDS);
    }
}
```

### 8.3 429响应处理

```java
@Component
public class RateLimitResponseHandler {

    /**
     * 处理429 Too Many Requests响应
     */
    public void handleRateLimitResponse(HttpHeaders responseHeaders) {
        // 解析Retry-After头
        String retryAfter = responseHeaders.getFirst("Retry-After");
        long waitSeconds = retryAfter != null ? Long.parseLong(retryAfter) : 5;

        log.warn("触发服务商限流，等待{}秒后重试", waitSeconds);

        try {
            Thread.sleep(waitSeconds * 1000);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new IntegrationException("限流等待被中断", e);
        }
    }
}
```

```java
public class IntegrationException extends RuntimeException {

    private final String errorCode;
```
