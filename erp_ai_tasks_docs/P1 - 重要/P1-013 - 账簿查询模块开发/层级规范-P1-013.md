## 1. 模块架构约束

### 1.1 模块定位
总账、明细账、余额表、多栏账查询，为财务核算和审计提供完整的账簿查询体系。属于财务层模块（阶段八），是纯查询模块，不新建业务数据表，所有数据来源于凭证和科目余额等已有表。

### 1.2 依赖关系
- 前置依赖：P0-001~P0-005（基础框架层）、P0-011（会计科目）、P1-012（凭证数据）
- 后续依赖：P1-014（财务报表——账簿数据作为报表取数基础）

### 1.3 技术约束
- 技术栈：Spring Boot + MyBatis-Plus + PostgreSQL；复杂聚合查询需优化SQL性能
- 性能约束：总账/余额表查询跨12个会计期间时需优化聚合性能；科目余额表使用行级锁确保过账一致性
- 安全约束：账簿数据仅取已过账凭证（可配置包含未过账）；导出格式需符合财务打印标准

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| fin_account_balance | 科目余额汇总表 | account_id, period_id, begin_debit/credit(期初), period_debit/credit(本期), year_debit/credit(年累计), end_debit/credit(期末) |
| fin_account_balance_aux | 辅助核算余额表 | account_id, period_id, aux_type, aux_item_id, begin_balance, period_debit/credit, end_balance |
| fin_posting_log | 过账日志表 | voucher_id, operator_id, posting_time, status, affected_accounts(JSONB) |
| fin_ledger_query_config | 账簿查询配置表 | user_id, config_type, config_name, config_json(JSONB), is_default |

注：账簿查询模块本身为纯查询模块，上述表为扩展数据表，核心数据来源为 fin_voucher/fin_voucher_detail/fin_account/fin_account_balance。

### 2.2 表关系图
- fin_account_balance 通过 account_id 关联 fin_account（会计科目表）
- fin_account_balance 通过 period_id 关联 fin_accounting_period（会计期间表）
- fin_account_balance_aux 扩展辅助核算维度余额
- fin_voucher_detail 通过 voucher_id 关联 fin_voucher，提供明细账数据源
- fin_posting_log 记录凭证过账操作对科目余额的影响
- fin_ledger_query_config 存储用户自定义查询方案

### 2.3 数据流转
1. 凭证过账 → 更新 fin_account_balance（期初→本期→期末重算）→ 级联更新后续期间期初余额
2. 总账查询：从 fin_account_balance 按科目级别汇总各期间借贷方和余额
3. 明细账查询：从 fin_voucher_detail JOIN fin_voucher 按科目+期间查询凭证明细
4. 余额表查询：从 fin_account_balance 汇总科目余额
5. 多栏账查询：从 fin_voucher_detail 按科目下级栏目展开
6. 日记账查询：从 fin_voucher_detail 按日期顺序展示现金/银行科目逐笔收支

## 3. 业务流程

### 3.1 核心业务流程
1. 总账查询：选择期间范围+科目级别 → 按科目汇总各期借方/贷方/余额 → 支持下钻明细账
2. 明细账查询：选择科目+期间 → 展示借方/贷方/余额三栏式 → 支持从总账下钻
3. 余额表查询：选择期间+科目级别 → 汇总期初/本期借贷/期末余额 → 支持导出
4. 多栏账查询：选择父科目 → 展开子科目为独立栏目 → 展示各栏借贷方金额
5. 日记账查询：选择现金/银行科目+期间 → 按日期逐笔展示收支明细
6. 辅助核算余额查询：选择科目+辅助核算类型 → 按辅助项维度查询余额

### 3.2 业务规则
- 总账仅取已过账凭证（includeUnposted=false为默认值）
- 单次查询最多跨12个会计期间（一个完整会计年度）
- 支持跨年度查询，期初取起始期间期初值
- 未结账期间数据为实时计算值，页面提示"含未结账期间数据"
- 年度结转后新年度期初=上年度期末
- 三账核对一致：总账合计=明细账合计=余额表合计
- 科目余额表通过凭证过账实时更新，反过账为逆操作
- 导出格式需符合财务打印标准

### 3.3 状态流转
账簿查询模块为纯查询模块，不涉及业务状态流转。
关键依赖状态：凭证必须为已过账状态才参与账簿汇总。

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **账簿查询后端开发（P1-013-001）**必须先完成：
   - 科目余额表（fin_account_balance）设计与过账更新机制
   - 总账查询服务
   - 明细账查询服务
   - 余额表查询服务
   - 多栏账查询服务
   - 日记账查询服务
   - 辅助核算余额查询服务
   - 各账簿导出服务
2. **账簿查询前端页面（P1-013-002）**依赖后端完成：
   - 总账页面（科目树+报表+下钻）
   - 明细账页面（三栏式）
   - 余额表页面
   - 多栏账页面

### 5.2 可并行执行的任务
- 总账查询与余额表查询可并行开发（数据来源相同，聚合逻辑不同）
- 明细账查询与日记账查询可并行开发
- 多栏账查询与辅助核算余额查询可并行开发
- 各账簿导出服务可并行开发
- 前端各页面可在对应后端API完成后并行开发
