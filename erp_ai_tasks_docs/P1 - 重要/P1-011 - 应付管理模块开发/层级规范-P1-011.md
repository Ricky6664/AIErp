## 1. 模块架构约束

### 1.1 模块定位
应付全链路管理，覆盖应付款→应付票→付款→核销→发票→账龄分析，是系统财务应付业务的核心模块。属于财务层模块（阶段八），从采购/委外业务自动产生应付数据，并提供完整的付款核销与账龄分析能力。

### 1.2 依赖关系
- 前置依赖：P0-001~P0-005（基础框架层）、P0-009（供应商）、P0-011（财务基础）、P1-001（审核引擎）、P1-004（流转引擎）、P1-006（采购入库/对账）、P1-009（委外）
- 后续依赖：P1-012（凭证管理——应付单/付款单生成凭证）

### 1.3 技术约束
- 技术栈：Spring Boot + MyBatis-Plus + PostgreSQL；金额计算使用BigDecimal；多币种汇率换算
- 性能约束：账龄分析聚合查询需按供应商+账龄区间分组计算，需优化索引
- 安全约束：应付款由系统自动生成；核销金额严格校验防止超核销；付款操作需严格权限控制

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| ap_payable | 应付款表 | 供应商ID, 来源类型/单据ID/编号, 应付日期, 币种/汇率, 应付金额, 已付金额, 已核销金额, 未付金额, 到期日期 |
| ap_invoice_plan | 应付票/收票计划表 | 供应商ID, 来源类型/单据ID, 计划收票日期, 应付票金额, 已收票金额, 未收票金额, 发票类型 |
| ap_payment / _detail | 付款单主/从表 | 供应商ID, 付款日期, 付款类型, 币种/汇率, 付款总额, 银行账户ID |
| ap_payment_writeoff / _detail | 付款核销单主/从表 | 付款单ID, 核销日期, 核销总额, 应付款ID, 核销金额 |
| ap_input_invoice / _detail | 进项发票主/从表 | 供应商ID, 发票号码, 开票日期, 发票类型, 税率, 不含税金额, 税额 |
| ap_input_invoice_writeoff / _detail | 进项发票核销单主/从表 | 发票ID, 核销日期, 应付款ID, 核销金额 |
| ap_other_payable | 其他应付单 | 供应商ID, 应付日期, 应付类型, 应付金额 |
| ap_other_payment | 其他付款单 | 供应商ID, 来源其他应付单ID, 付款金额, 银行账户ID |

### 2.2 表关系图
- ap_payable 独立表：由采购入库/对账/委外入库自动生成，通过来源单据ID关联采购/委外模块
- ap_payment 1:N ap_payment_detail：付款单主从结构，明细关联应付款
- ap_payment 1:1 ap_payment_writeoff 1:N ap_payment_writeoff_detail：核销单主从结构
- ap_input_invoice 1:N ap_input_invoice_detail：发票主从结构
- ap_input_invoice 1:1 ap_input_invoice_writeoff 1:N ap_input_invoice_writeoff_detail：发票核销
- 单据结构与 ar_*（应收管理）完全对称，区别在于关联供应商维度

### 2.3 数据流转
1. 应付款自动生成：采购入库/对账/委外入库审核 → 根据 finance.ap_source 参数 → 自动创建 ap_payable
2. 应付票自动生成：审核时根据 finance.invoice_ap_source 参数 → 创建 ap_invoice_plan
3. 付款流程：创建付款单 → 选择应付款 → 录入付款金额 → 审核
4. 核销流程：创建核销单 → 匹配付款单与应付款 → 校验核销金额 → 更新已核销金额
5. 发票管理：录入进项发票 → 发票核销 → 关联应付款
6. 凭证联动：应付单/付款单审核后根据凭证模板自动生成会计凭证（联动P1-012）

## 3. 业务流程

### 3.1 核心业务流程
1. 应付款管理：系统自动从采购入库/对账/委外生成 → 查看应付款列表
2. 应付票管理：系统自动生成收票计划 → 查看应付票列表
3. 付款管理：创建付款单 → 关联应付款 → 审核
4. 核销管理：创建核销单 → 匹配付款与应付 → 校验金额 → 审核 → 更新已核销金额
5. 发票管理：录入进项发票 → 发票核销
6. 其他应付/付款：手工录入其他应付款 → 付款 → 核销
7. 账龄分析：按供应商/账龄区间（0-30/31-60/61-90/90+天）汇总

### 3.2 业务规则
- 应付款自动生成：finance.ap_source 控制来源（采购入库审核/采购对账审核/手工录入）
- 应付票自动生成：finance.invoice_ap_source 控制来源
- 付款核销：核销金额 ≤ 应付款未核销金额；核销单删除时回滚已核销金额
- 账龄分析：按供应商/账龄区间汇总应付+已付+未付金额
- 凭证联动：应付单/付款单审核后根据凭证模板自动生成会计凭证
- 多币种处理：应付款/付款单支持多币种，核销时按汇率换算
- 与应收管理对称：结构完全对称，应付关联供应商维度

### 3.3 状态流转
应付款状态：未付 → 部分付款 → 已付
付款单审核状态（P1-001管理）：草稿(0) → 已审核(2)
核销单状态：草稿 → 已审核（核销生效）

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **应付管理后端开发（P1-011-001）**必须先完成：
   - 应付款自动生成服务
   - 应付票自动生成服务
   - 付款单CRUD
   - 付款核销单CRUD（含金额校验与回滚）
   - 进项发票与发票核销CRUD
   - 其他应付/付款CRUD
   - 账龄分析
   - 凭证联动集成
2. **应付管理前端页面（P1-011-002）**依赖后端完成

### 5.2 可并行执行的任务
- 应付款自动生成与应付票自动生成可并行开发
- 付款单CRUD与进项发票CRUD可并行开发
- 付款核销与发票核销可并行开发
- 其他应付/付款与账龄分析可并行开发
- 前端各页面可在对应后端API完成后并行开发
