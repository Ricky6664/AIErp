## 五、详细开发规格
> **本任务模块上下文**
> - 涉及数据表：ar_receivable(应收单), ar_receipt(收款单), ar_invoice(应收发票), ar_bad_debt(坏账处理表)
> - 涉及API：/api/ar/receivable/*, /api/ar/receipt/*, /api/ar/invoice/*, /api/ar/bad-debt/*, /api/ar/aging/*

### 5.1 核心功能
1. 实现应收管理接口的Service主流程方法，包含参数校验→业务规则校验→数据持久化→结果返回
2. 主从表操作使用@Transactional保证事务一致性，异常时回滚
3. 业务关键数值（金额/数量）使用BigDecimal，保留6位小数，禁止double运算
4. 关键操作写入操作日志（biz_log表），记录操作人/操作类型/前后快照

### 5.2 数据交互
1. Controller层通过DTO入参，Service层调用Mapper执行DB操作，返回VO结构
2. 跨模块调用通过对应模块的XxxService接口（如应收管理关联库存时调用InventoryService）
3. 分页查询使用MyBatis-Plus Page对象，避免内存分页

### 5.3 关键逻辑
1. 业务规则校验：单据号唯一(tenant_id+order_no)、状态流转合规、关联外键存在性
2. 金额计算：单价×数量=金额，主表合计=∑明细金额，误差≤0.01
3. 数量累计：已生产数/已领料数/已入库数按单行累加，超额时抛BusinessException
4. 并发控制：关键更新操作使用乐观锁@Version，避免超卖/超领

### 5.4 验证
1. 接口返回VO结构与Swagger文档一致，字段类型正确
2. 主从表事务一致性：任一表失败则全部回滚
3. 异常场景有明确中文错误提示，不暴露SQL/堆栈信息
4. 单元测试覆盖：正常流程+边界值+异常分支≥80%
