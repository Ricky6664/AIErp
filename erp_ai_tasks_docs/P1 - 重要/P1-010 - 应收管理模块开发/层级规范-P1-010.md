## 1. 模块架构约束

### 1.1 模块定位
应收全链路管理，覆盖应收款→应开票→收款→核销→发票→账龄分析，是系统财务应收业务的核心模块。属于财务层模块（阶段八），从销售业务自动产生应收数据，并提供完整的收款核销与账龄分析能力。

### 1.2 依赖关系
- 前置依赖：P0-001~P0-005（基础框架层）、P0-008（客户）、P0-011（财务基础）、P1-001（审核引擎）、P1-004（流转引擎）、P1-005（销售出库/对账）
- 后续依赖：P1-012（凭证管理——应收单/收款单生成凭证）

### 1.3 技术约束
- 技术栈：Spring Boot + MyBatis-Plus + PostgreSQL；金额计算使用BigDecimal；多币种汇率换算
- 性能约束：账龄分析聚合查询需按客户+账龄区间分组计算，需优化索引
- 安全约束：应收款由系统自动生成，不提供手工新增入口（但支持手工调整）；核销金额严格校验防止超核销

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| ar_receivable | 应收款表 | 客户ID, 来源类型/单据ID/编号, 应收日期, 币种/汇率, 应收金额, 已收金额, 已核销金额, 未收金额, 到期日期 |
| ar_invoice_plan | 应开票计划表 | 客户ID, 来源类型/单据ID, 计划开票日期, 应开票金额, 已开票金额, 未开票金额, 发票类型 |
| ar_receipt / _detail | 收款单主/从表 | 客户ID, 收款日期, 收款类型(现收/票收), 币种/汇率, 收款总额, 银行账户ID |
| ar_receipt_writeoff / _detail | 收款核销单主/从表 | 收款单ID, 核销日期, 核销总额, 应付款ID, 核销金额 |
| ar_output_invoice / _detail | 销项发票主/从表 | 客户ID, 发票号码, 开票日期, 发票类型, 税率, 不含税金额, 税额, 价税合计 |
| ar_output_invoice_writeoff / _detail | 销项发票核销单主/从表 | 发票ID, 核销日期, 应收款ID, 核销金额 |
| ar_other_receivable | 其他应收单 | 客户ID, 应收日期, 应收类型, 应收金额 |
| ar_other_receipt | 其他收款单 | 客户ID, 来源其他应收单ID, 收款金额, 银行账户ID |

### 2.2 表关系图
- ar_receivable 独立表：由销售出库/对账自动生成，通过来源单据ID关联销售模块
- ar_receipt 1:N ar_receipt_detail：收款单主从结构，明细关联应收款
- ar_receipt 1:1 ar_receipt_writeoff 1:N ar_receipt_writeoff_detail：核销单主从结构
- ar_output_invoice 1:N ar_output_invoice_detail：发票主从结构
- ar_output_invoice 1:1 ar_output_invoice_writeoff 1:N ar_output_invoice_writeoff_detail：发票核销
- ar_other_receivable 1:1 ar_other_receipt：其他应收与其他收款配对

### 2.3 数据流转
1. 应收款自动生成：销售出库/对账审核 → 根据 finance.ar_source 参数 → 自动创建 ar_receivable
2. 应开票自动生成：审核时根据 finance.invoice_ar_source 参数 → 创建 ar_invoice_plan
3. 收款流程：创建收款单 → 选择应收款 → 录入收款金额 → 审核
4. 核销流程：创建核销单 → 匹配收款单与应收款 → 校验核销金额 → 更新已核销金额
5. 发票管理：创建销项发票 → 发票核销 → 关联应收款
6. 凭证联动：应收单/收款单审核后根据凭证模板自动生成会计凭证（联动P1-012）

## 3. 业务流程

### 3.1 核心业务流程
1. 应收款管理：系统自动从销售出库/对账生成 → 查看应收款列表 → 手工调整（坏账等场景）
2. 应开票管理：系统自动生成开票计划 → 查看应开票列表
3. 收款管理：创建收款单（现收/票收）→ 关联应收款 → 审核
4. 核销管理：创建核销单 → 匹配收款与应收 → 校验金额 → 审核 → 更新已核销金额
5. 发票管理：创建销项发票 → 发票核销
6. 其他应收/收款：手工录入其他应收款 → 收款 → 核销
7. 账龄分析：按客户/账龄区间（0-30/31-60/61-90/90+天）汇总

### 3.2 业务规则
- 应收款自动生成：finance.ar_source 控制来源（销售出库审核/销售对账审核/手工录入）
- 应开票自动生成：finance.invoice_ar_source 控制来源
- 收款核销：核销金额 ≤ 应收款未核销金额；核销单删除时回滚已核销金额
- 账龄分析：按客户/账龄区间汇总应收+已收+未收金额
- 凭证联动：应收单/收款单审核后根据凭证模板自动生成会计凭证
- 多币种处理：应收款/收款单支持多币种，核销时按汇率换算
- 与应付管理对称：结构完全对称，应收关联客户维度

### 3.3 状态流转
应收款状态：未收 → 部分收款 → 已收清
收款单审核状态（P1-001管理）：草稿(0) → 已审核(2)
核销单状态：草稿 → 已审核（核销生效）

### 4.2 依赖接口

- P0-008 客户管理：客户信息查询
- P0-011 财务基础：币种/汇率/银行账户信息

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **应收管理后端开发（P1-010-001）**必须先完成：
   - 应收款自动生成服务
   - 应开票自动生成服务
   - 收款单CRUD
   - 收款核销单CRUD（含金额校验与回滚）
   - 销项发票与发票核销CRUD
   - 其他应收/收款CRUD
   - 账龄分析
   - 凭证联动集成
2. **应收管理前端页面（P1-010-002）**依赖后端完成

### 5.2 可并行执行的任务
- 应收款自动生成与应开票自动生成可并行开发
- 收款单CRUD与销项发票CRUD可并行开发
- 收款核销与发票核销可并行开发
- 其他应收/收款与账龄分析可并行开发
- 前端各页面可在对应后端API完成后并行开发
