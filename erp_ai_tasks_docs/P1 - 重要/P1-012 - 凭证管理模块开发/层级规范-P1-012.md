## 1. 模块架构约束

### 1.1 模块定位
凭证录入、凭证模板、自动生成凭证、凭证过账/红冲，是系统会计核算的核心模块。属于财务层模块（阶段八），接收来自应收/应付/成本等模块的业务数据，生成标准化的会计凭证，是账簿查询和财务报表的数据基础。

### 1.2 依赖关系
- 前置依赖：P0-001~P0-005（基础框架层）、P0-011（会计科目/凭证字）、P1-010（应收）、P1-011（应付）
- 后续依赖：P1-013（账簿查询——凭证数据作为账簿查询数据源）、P1-014（财务报表——凭证数据作为报表取数基础）、P1-015（成本核算——成本调整凭证生成）

### 1.3 技术约束
- 技术栈：Spring Boot + MyBatis-Plus + PostgreSQL；金额计算使用BigDecimal，借贷平衡严格校验
- 性能约束：凭证过账需同步更新科目余额表，使用行级锁确保一致性；凭证号按凭证字+期间+流水号生成需保证唯一连续
- 安全约束：过账后凭证不可修改，需红冲后重新制证；凭证号不可重复；借贷必须平衡

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| fin_voucher | 凭证主表 | 凭证字ID, 凭证字, 凭证号, 凭证日期, 会计期间ID, 附件张数, 借方合计, 贷方合计, 状态 |
| fin_voucher_detail | 凭证明细表 | 凭证ID, 行号, 会计科目ID, 借方金额, 贷方金额, 币种/汇率, 原币金额, 摘要, 辅助核算项, 现金流量项目ID |
| fin_voucher_template | 凭证模板表 | 模板名称, 模板编码, 业务类型, 模板配置JSON, 启用状态 |
| fin_voucher_template_detail | 凭证模板明细表 | 模板ID, 行号, 会计科目ID, 摘要, 借方金额, 贷方金额, 辅助核算类别ID |

### 2.2 表关系图
- fin_voucher 1:N fin_voucher_detail：凭证主从结构，每行明细对应一个会计科目
- fin_voucher_template 1:N fin_voucher_template_detail：模板主从结构，定义标准凭证的科目和金额规则
- fin_voucher_detail 关联 fin_account（会计科目表，P0-011）：通过会计科目ID关联
- fin_voucher 关联 fin_accounting_period（会计期间表，P0-011）：通过会计期间ID关联
- fin_voucher_detail 辅助核算项：通过辅助核算类别ID+对象ID关联客户/供应商/部门/员工/项目

### 2.3 数据流转
1. 手工制证：选择凭证字 → 录入凭证日期/期间 → 逐行录入科目/借方/贷方/摘要 → 借贷平衡校验 → 保存
2. 自动生成凭证：业务单据审核 → 匹配凭证模板（finance.auto_voucher参数）→ 按模板填充科目和金额 → 自动创建凭证
3. 凭证过账：凭证审核通过 → 执行过账 → 更新 fin_account_balance 科目余额表 → 标记已过账
4. 凭证红冲：已过账凭证需修改 → 生成反向凭证（借贷方向相反、金额相同）→ 原凭证标记已红冲

## 3. 业务流程

### 3.1 核心业务流程
1. 凭证录入：三栏式录入（借方/贷方/金额）→ 实时借贷平衡校验 → 保存
2. 凭证模板管理：创建模板 → 配置科目和取数规则 → 启用
3. 自动生成凭证：业务单据审核触发 → 匹配模板 → 自动填充 → 创建凭证
4. 凭证审核：凭证提交 → 审核（P1-001审核引擎）
5. 凭证过账：已审核凭证 → 过账 → 更新科目余额表 → 标记已过账
6. 凭证红冲：已过账凭证 → 红冲 → 生成反向凭证 → 原凭证标记已红冲

### 3.2 业务规则
- 借贷平衡校验：保存和提交时严格校验借方合计=贷方合计，不平衡阻止保存并提示差额
- 凭证自动生成：finance.auto_voucher 参数控制，单据审核后自动按模板生成凭证
- 凭证过账：过账后不可修改，过账操作更新科目余额表
- 凭证红冲：自动生成反向凭证，原凭证标记已红冲
- 凭证编号：按凭证字+会计期间+流水号自动生成，同凭证字同期间内唯一连续
- 辅助核算：明细支持客户/供应商/部门/员工/项目等辅助核算项
- 现金流量项目：明细支持关联现金流量项目ID

### 3.3 状态流转
凭证审核状态（P1-001管理）：草稿(0) → 待审核(1) → 已审核(2)
凭证过账状态：未过账 → 已过账（过账后不可修改）
凭证红冲状态：正常 → 已红冲（红冲后不可再操作）

| /api/voucher/auto-generate | POST | 凭证自动生成 |

### 4.2 依赖接口
- P1-001 审核引擎：凭证审核操作
- P0-011 财务基础：会计科目、凭证字、会计期间数据
- P1-010 应收管理：应收单/收款单审核后触发自动生成凭证
- P1-011 应付管理：应付单/付款单审核后触发自动生成凭证
- P1-015 成本核算：成本调整后触发自动生成调整凭证

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **凭证管理后端开发（P1-012-001）**必须先完成：
   - 凭证CRUD（含借贷平衡校验）
   - 凭证编号自动生成
   - 凭证模板CRUD
   - 凭证自动生成服务（模板匹配+字段填充）
   - 凭证过账服务（更新科目余额表）
   - 凭证红冲服务（生成反向凭证）
   - 辅助核算与现金流量项目集成
2. **凭证管理前端页面（P1-012-002）**依赖后端完成：
   - 三栏式凭证录入表单（实时借贷平衡校验）
   - 凭证模板管理页面

### 5.2 可并行执行的任务
- 凭证CRUD与凭证模板CRUD可并行开发
- 凭证过账服务与凭证红冲服务可并行开发
- 自动生成凭证服务可在模板CRUD完成后并行集成
- 前端凭证录入页面与模板管理页面可并行开发
