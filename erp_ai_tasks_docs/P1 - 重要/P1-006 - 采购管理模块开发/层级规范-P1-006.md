## 1. 模块架构约束

### 1.1 模块定位
采购全链路业务管理，覆盖询价→请购→采购订单→入库→退货→对账→统计，是系统采购业务的核心模块。属于业务层模块（阶段七），通过引擎层提供的审核和流转能力实现完整的采购业务闭环。

### 1.2 依赖关系
- 前置依赖：P0-001~P0-005（基础框架层）、P0-007（商品）、P0-009（供应商）、P0-010（仓库）、P0-011（财务基础）、P1-001（审核引擎）、P1-004（流转引擎）
- 后续依赖：P1-007（库存管理——采购入库/退货触发库存变动）、P1-011（应付管理——采购入库/对账产生应付款）、P1-015（成本核算——采购成本核算）

### 1.3 技术约束
- 技术栈：Spring Boot + MyBatis-Plus + PostgreSQL；金额计算使用BigDecimal（金额保留4位小数，单价保留6位小数）
- 性能约束：聚合查询（未采购/未入库/未对账清单）需优化索引；入库操作库存增加需行级锁
- 安全约束：订单变更记录不可删除；多单位换算精度严格保证；采购订单商务字段需与供应商主数据联动回填

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| pur_inquiry / _detail | 询价单主/从表 | 询价单号, 供应商ID, 商品ID, 数量, 报价单价, 报价交期 |
| pur_requisition / _detail | 请购单主/从表 | 请购单号, 申请人/部门ID, 请购类型, 商品ID, 数量, 已采购数量 |
| pur_order / _detail | 采购订单主/从表 | 订单编号, 供应商ID, 采购员, 发票类型, 税率, 币种, 汇率, 结算方式, 账期, 商品ID, 不含税/含税单价 |
| pur_order_change | 订单变更记录表 | 原订单ID, 变更类型/原因, 变更前后内容 |
| pur_inbound / _detail | 采购入库单主/从表 | 入库单号, 供应商ID, 采购订单ID, 仓库ID, 商品ID, 数量, 单位成本, 对账状态 |
| pur_inbound_return / _detail | 入库退货单主/从表 | 退货单号, 原入库单ID, 商品ID, 退货数量 |
| pur_reconciliation / _detail | 采购对账单主/从表 | 对账单号, 供应商ID, 对账期间, 商品ID, 对账金额 |
| doc_detail_serial | 序列号子表 | 明细ID, 序列号, 序列号状态 |

### 2.2 表关系图
- pur_order 1:N pur_order_detail 1:N doc_detail_serial：订单→明细→序列号三层结构
- pur_order 1:N pur_order_change：订单审核后修改自动创建变更记录
- pur_inquiry → pur_requisition → pur_order → pur_inbound → pur_inbound_return → pur_reconciliation：通过P1-004流转引擎的doc_relation表建立上下游关联
- pur_inbound_detail 1:N doc_detail_location/batch/serial：入库明细→库位/批次/序列号三表处理
- pur_order_detail 关联 pur_requisition_detail（请购明细ID）和 pur_inquiry_detail（询价明细ID）

### 2.3 数据流转
1. 询价单创建 → 审核 → 可下推请购单/采购订单
2. 请购单创建 → 审核 → 查看未采购清单 → 下推采购订单
3. 采购订单创建 → 审核 → 查看未入库清单 → 下推入库单
4. 入库单 → 审核 → 库存增加（调用P1-007）→ 应付款生成（联动P1-011）
5. 入库退货 → 审核 → 库存扣减
6. 入库对账 → 审核 → 应付款生成（联动P1-011）

## 3. 业务流程

### 3.1 核心业务流程
1. 询价管理：创建询价单 → 供应商报价回复 → 审核 → 可下推请购/采购
2. 请购管理：创建请购单 → 审核 → 查看未采购清单 → 下推采购订单
3. 采购订单管理：创建订单 → 审核 → 订单变更记录 → 下推入库单
4. 入库管理：查看未入库清单 → 创建入库单（库位/批次/序列号录入）→ 审核 → 库存增加
5. 退货管理：创建退货单 → 审核 → 库存扣减
6. 对账管理：查看未对账清单 → 创建对账单 → 审核 → 应付联动
7. 统计分析：采购统计（按供应商/商品/采购员/时间维度）

### 3.2 业务规则
- 单据流转路径由系统参数 purchase.order_flow_path 控制，支持强制流转跳过中间环节
- 金额计算统一调用金额计算引擎，金额保留4位小数，单价保留6位小数
- 入库单审核后自动增加库存，库位/批次/序列号三表统一通过通用子表处理
- 序列号管理：入库时需扫描/录入序列号
- 未采购/未入库/未对账清单为只读视图，支持下推快捷操作和导出
- 订单审核后修改自动创建变更记录，变更原因必填
- 应付联动：入库单/对账单审核后根据 finance.ap_source 参数自动生成应付款
- 多单位换算：所有明细行支持 is_multi_unit 多单位模式
- 采购订单包含完整商务字段，与供应商主数据（P0-009）联动回填

### 3.3 状态流转
各采购单据通用审核状态（由P1-001审核引擎管理）：
```
草稿(0) → 待审核(1) → 已审核(2) → 已作废(4)
                           ↓
                      全部入库后标记"已转单"
```
入库单对账状态：未对账 → 部分对账 → 已对账

## 4. 接口契约

### 4.1 对外接口
| 接口路径 | 方法 | 说明 |
|---------|------|------|
| /api/purchase/inquiry | GET/POST | 询价单列表/新增 |
| /api/purchase/requisition | GET/POST | 请购单列表/新增 |
| /api/purchase/order | GET/POST | 采购订单列表/新增 |
| /api/purchase/order/{id} | GET/PUT/DELETE | 采购订单详情/修改/删除 |
| /api/purchase/inbound | GET/POST | 入库单列表/新增（含库位/批次/序列号） |
| /api/purchase/inbound-return | GET/POST | 退货单列表/新增 |
| /api/purchase/reconciliation | GET/POST | 对账单列表/新增 |
| /api/purchase/unbuy | GET | 未采购清单聚合查询 |
| /api/purchase/un-inbound | GET | 未入库清单聚合查询 |
| /api/purchase/un-reconciliation | GET | 未对账清单聚合查询 |
| /api/purchase/statistics | GET | 采购统计 |
| /api/purchase/flow/push | POST | 采购单据流转 |

### 4.2 依赖接口
- P1-001 审核引擎：所有单据的审核/反审/作废操作
- P1-004 流转引擎：询价→请购→采购→入库→退货→对账的单据流转
- P1-007 库存管理：入库单审核增加库存、退货单审核扣减库存
- P1-011 应付管理：入库/对账审核后自动生成应付款
- P0-007 商品管理：商品信息查询
- P0-009 供应商管理：供应商信息查询与联动回填
- P0-010 仓库管理：仓库/库位信息查询

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **采购管理后端开发（P1-006-001）**必须先完成：
   - 询价单CRUD → 请购单CRUD → 采购订单CRUD → 入库单CRUD → 退货单CRUD → 对账单CRUD
   - 金额计算引擎集成（含多单位换算）
   - 库存联动集成（P1-007）
   - 应付联动集成（P1-011）
   - 聚合查询与统计
2. **采购管理前端页面（P1-006-002）**依赖后端完成

### 5.2 可并行执行的任务
- 询价单与请购单可并行开发
- 入库单（含库位/批次/序列号）与退货单可并行开发
- 三个聚合查询（未采购/未入库/未对账）可并行开发
- 采购统计与订单变更记录可并行开发
- 前端各单据页面可在对应后端API完成后并行开发
