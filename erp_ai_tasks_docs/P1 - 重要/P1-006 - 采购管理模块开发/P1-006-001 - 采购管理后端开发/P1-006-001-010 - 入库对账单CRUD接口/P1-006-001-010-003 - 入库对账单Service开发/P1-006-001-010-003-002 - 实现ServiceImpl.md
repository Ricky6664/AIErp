### 5.1 ServiceImpl核心结构
```java
@Service
@RequiredArgsConstructor
public class PurchaseOrderServiceImpl extends ServiceImpl<PurchaseOrderMapper, PurchaseOrderEntity> implements IPurchaseOrderService {
    private final PurchaseOrderMapper purchaseMapper;
    private final IAuditEngineService auditEngineService;
    private final ICodeGeneratorService codeGeneratorService;

    @Override
    @Transactional(rollbackFor = Exception.class)
    public Long create(PurchaseOrderCreateDTO dto) {
        // 1. 业务校验
        validateCreate(dto);
        // 2. 生成编码
        String code = codeGeneratorService.generate("purchase");
        // 3. 构建Entity并保存
        PurchaseOrderEntity entity = BeanUtil.copyProperties(dto, PurchaseOrderEntity.class);
        entity.setNo(code);
        entity.setStatus(0); // 草稿
        save(entity);
        // 4. 保存明细行
        saveDetails(entity.getId(), dto.getDetails());
        return entity.getId();
    }
}
```

### 5.2 业务校验规则
1. 名称唯一性校验：同一租户下名称不重复
2. 明细行非空校验：至少包含一条明细行
3. 金额计算校验：单价×数量=金额，精度保留4位小数
4. 状态流转校验：仅草稿状态(0)可提交审核

## 八、易错警示

> ⚠️ @Transactional(rollbackFor=Exception.class)必须加在public方法上

> ⚠️ 避免大事务：仅包含数据库操作，远程调用/RPC放在事务外

> ⚠️ 编码生成调用要幂等（重试时不产生重复编码）

> ⚠️ 异常统一抛出BusinessException，携带错误码+中文提示

> ⚠️ 乐观锁@Version字段在update时通过WHERE version=#{oldVersion}实现

> ⚠️ 多表操作注意操作顺序：先主表后从表(新增)，先从表后主表(删除)
