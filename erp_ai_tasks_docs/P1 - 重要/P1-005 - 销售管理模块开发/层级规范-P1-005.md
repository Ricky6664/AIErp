## 1. 模块架构约束

### 1.1 模块定位
销售全链路业务管理，覆盖报价→订单→发货通知→出库→退货→对账→统计，是系统销售业务的核心模块。属于业务层模块（阶段七），通过引擎层提供的审核和流转能力实现完整的销售业务闭环。

### 1.2 依赖关系
- 前置依赖：P0-001~P0-005（基础框架层）、P0-007（商品）、P0-008（客户）、P0-010（仓库）、P0-011（财务基础）、P1-001（审核引擎）、P1-004（流转引擎）
- 后续依赖：P1-007（库存管理——销售出库/退货触发库存变动）、P1-010（应收管理——销售出库/对账产生应收款）、P1-015（成本核算——销售订单/出库成本核算）

### 1.3 技术约束
- 技术栈：Spring Boot + MyBatis-Plus + PostgreSQL；金额计算使用BigDecimal（保留4位小数）
- 性能约束：聚合查询（未发货/未出库/未对账清单）需优化索引，支持分页；出库操作库存扣减需行级锁
- 安全约束：订单变更记录不可删除；出库操作需校验库存充足性；金额计算精度严格保证

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| sale_quotation / sale_quotation_detail | 报价单主/从表 | 报价单号, 客户ID, 有效期, 商品ID, 数量, 单价, 税率, 折扣 |
| sale_order / sale_order_detail | 销售订单主/从表 | 订单编号, 客户ID, 商品ID, 数量, 单价, 已发货数, 已出库数 |
| sale_order_detail_serial | 订单序列号子表 | 订单明细ID, 序列号, 序列号状态 |
| sale_order_change | 订单变更记录表 | 订单ID, 变更前后对比, 变更原因 |
| sale_delivery_notice / _detail | 发货通知单主/从表 | 通知单号, 来源订单, 商品ID, 发货数量, 已出库数 |
| sale_outbound / _detail | 出库单主/从表 | 出库单号, 仓库ID, 商品ID, 出库数量, 单价, 金额 |
| doc_detail_location / batch / serial | 库位/批次/序列号子表 | 明细ID, 仓库/库位/批次/序列号, 数量 |
| sale_outbound_return / _detail | 出库退货单主/从表 | 退货单号, 来源出库单, 退货数量, 退货原因 |
| sale_reconciliation / _detail | 出库对账单主/从表 | 对账单号, 来源出库单, 对账数量, 对账金额 |

### 2.2 表关系图
- sale_quotation 1:N sale_quotation_detail：报价单主从结构
- sale_order 1:N sale_order_detail 1:N sale_order_detail_serial：订单→明细→序列号三层结构
- sale_order 1:N sale_order_change：订单审核后修改自动创建变更记录
- sale_order → sale_delivery_notice → sale_outbound → sale_outbound_return → sale_reconciliation：通过P1-004流转引擎的doc_relation表建立上下游关联
- sale_outbound_detail 1:N doc_detail_location/batch/serial：出库明细→库位/批次/序列号三表处理

### 2.3 数据流转
1. 报价单创建 → 审核 → 下推销售订单
2. 销售订单创建 → 审核 → 下推发货通知单（或直接从报价单流转到订单）
3. 发货通知单 → 审核 → 下推出库单
4. 出库单 → 审核 → 库存扣减（调用P1-007）→ 应收款生成（联动P1-010）
5. 出库退货 → 审核 → 库存增加
6. 出库对账 → 审核 → 应收款生成（联动P1-010）

## 3. 业务流程

### 3.1 核心业务流程
1. 报价管理：创建报价单 → 审核 → 可下推订单
2. 订单管理：创建/引入订单 → 审核 → 订单变更记录 → 下推发货通知
3. 发货管理：查看未发货清单 → 创建发货通知单 → 审核 → 下推出库
4. 出库管理：查看未出库清单 → 创建出库单（库位/批次/序列号录入）→ 审核 → 库存扣减
5. 退货管理：创建退货单 → 审核 → 库存增加
6. 对账管理：查看未对账清单 → 创建对账单 → 审核 → 应收联动
7. 统计分析：销售统计（多维度汇总）+ 毛利分析

### 3.2 业务规则
- 单据流转路径由系统参数 sale.order_flow_path 控制，支持强制流转跳过中间环节
- 金额计算统一调用金额计算引擎，金额保留4位小数
- 出库单审核后自动扣减库存，库存不足时阻止出库
- 序列号管理：出库时需扫描/录入序列号
- 未发货/未出库/未对账清单为只读视图，支持下推快捷操作
- 订单审核后修改自动创建变更记录，变更原因必填
- 应收联动：出库单/对账单审核后根据 finance.ar_source 参数自动生成应收款

### 3.3 状态流转
各销售单据通用审核状态（由P1-001审核引擎管理）：
```
草稿(0) → 待审核(1) → 已审核(2) → 已作废(4)
                           ↓
                      全部下推后标记"已转单"
```

| /api/sale/delivery-notice | GET/POST | 发货通知单列表/新增 |
| /api/sale/outbound | GET/POST | 出库单列表/新增（含库位/批次/序列号） |
| /api/sale/outbound-return | GET/POST | 退货单列表/新增 |
| /api/sale/reconciliation | GET/POST | 对账单列表/新增 |

| /api/sale/un-reconciliation | GET | 未对账清单聚合查询 |
| /api/sale/statistics | GET | 销售统计 |
| /api/sale/profit | GET | 销售毛利分析 |
| /api/sale/flow/push | POST | 销售单据流转 |

### 4.2 依赖接口
- P1-001 审核引擎：所有单据的审核/反审/作废操作
- P1-004 流转引擎：报价→订单→发货→出库→退货→对账的单据流转
- P1-007 库存管理：出库单审核扣减库存、退货单审核增加库存
- P1-010 应收管理：出库/对账审核后自动生成应收款
- P0-007 商品管理：商品信息查询
- P0-008 客户管理：客户信息查询
- P0-010 仓库管理：仓库/库位信息查询

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **销售管理后端开发（P1-005-001）**必须先完成：
   - 报价单CRUD → 销售订单CRUD → 发货通知单CRUD → 出库单CRUD → 退货单CRUD → 对账单CRUD（按流转顺序开发）
   - 金额计算引擎集成
   - 库存联动集成（P1-007）
   - 应收联动集成（P1-010）
   - 聚合查询（未发货/未出库/未对账清单）
   - 统计与毛利分析
2. **销售管理前端页面（P1-005-002）**依赖后端完成：
   - 按业务流转顺序开发各单据页面

### 5.2 可并行执行的任务
- 报价单与订单变更记录可并行开发
- 出库单（含库位/批次/序列号）与退货单可并行开发
- 三个聚合查询（未发货/未出库/未对账）可并行开发
- 销售统计与毛利分析可并行开发
- 前端各单据页面可在对应后端API完成后并行开发
