## 1. 模块架构约束

### 1.1 模块定位
通用单据引入/下推/复制/追溯引擎，为所有业务单据链路流转提供统一能力，是系统单据流转体系的核心基础设施。属于引擎层模块（阶段六），为上层所有业务模块提供标准化的单据流转服务。

### 1.2 依赖关系
- 前置依赖：P0-001（后端框架）、P0-002（前端框架）、P0-003（数据库）、P0-004（认证与权限）、P0-005（公共组件含引入/下推组件）、P1-001（审核引擎）
- 后续依赖：P1-005~P1-009（销售/采购/库存/生产/委外所有业务模块的单据流转）

### 1.3 技术约束
- 技术栈：Spring Boot + MyBatis-Plus + PostgreSQL；字段映射使用SpEL表达式引擎；流转配置使用JSONB存储
- 性能约束：下推操作使用行级锁防止同一源单明细行被重复下推；数量回写采用"先校验-再写入-后回写"三阶段事务
- 安全约束：流转操作日志（sys_doc_flow_log）不可修改或删除；下推数量严格校验防止超推

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| doc_relation | 单据关联关系表 | 源单据类型/ID/明细ID, 目标单据类型/ID/明细ID, 关联类型(引入/下推/复制), 关联数量 |
| sys_doc_flow_config | 流转配置表 | source_doc_type, target_doc_type, flow_direction(下推/引入), field_mapping_json(JSONB), is_enabled |
| sys_doc_flow_push_rule | 下推规则表 | flow_config_id, push_mode(按行/按单), auto_close_source, quantity_field, max_push_times |
| sys_doc_flow_qty_writeback | 数量回写记录表 | relation_id, source_detail_id, writeback_field, writeback_qty, writeback_time |
| sys_doc_flow_log | 流转操作日志表 | operation_type(下推/引入/复制/反下推/回滚), source/target_doc_type/id, operator_id |

### 2.2 表关系图
- sys_doc_flow_config 1:N sys_doc_flow_push_rule：一个流转配置对应一条或多条下推规则
- sys_doc_flow_config 通过 source_doc_type + target_doc_type 唯一定义一条流转路径
- doc_relation 通过 source_detail_id 关联源单明细行，target_detail_id 关联目标单明细行
- sys_doc_flow_qty_writeback 通过 relation_id 关联 doc_relation，记录每次数量回写
- sys_doc_flow_log 记录所有流转操作，与 doc_relation 通过 source/target 单据关联

### 2.3 数据流转
1. 流转配置初始化：管理员配置 sys_doc_flow_config（字段映射JSON）+ sys_doc_flow_push_rule
2. 下推操作：校验源单状态(已审核) → 校验可下推数量 → 行级锁锁定源单明细 → 创建目标单 → 记录 doc_relation → 回写源单已推数量 → 记录日志
3. 引入操作：查询可引入源单 → 明细行勾选 → 按字段映射填充目标单
4. 复制操作：深拷贝主表+从表 → 重新生成单据编号 → 状态重置为草稿
5. 追溯操作：正向/反向递归查询 doc_relation → 组装追溯链路树
6. 回滚操作：校验目标单状态(草稿) → 删除目标单 → 反写源单已推数量 → 删除关联关系

## 3. 业务流程

### 3.1 核心业务流程
1. 下推：源单(已审核) → 校验可推数量 → 创建目标单 → 建立关联关系 → 回写已推数量
2. 引入：目标单新建 → 选择源单 → 勾选明细行 → 自动填充目标单数据
3. 复制：源单 → 深拷贝全部数据 → 新编号 → 草稿状态
4. 追溯：指定单据 → 上下游递归查询 → 形成追溯链路树
5. 回滚：目标单(草稿) → 删除 → 反写源单数量 → 删除关联

### 3.2 业务规则
- 下推前源单必须为已审核状态（FR-001）
- 下推数量不得超过可下推数量（明细行数量-已下推数量）（FR-002）
- 流转配置必须存在且启用（FR-003）
- 目标单必填字段校验（FR-004）
- 回滚仅限草稿状态目标单，已审核需先反审（FR-005）
- 回滚前目标单不能有下游单据（FR-006）
- 字段映射支持三种类型：direct（直接复制）、default（默认值）、expression（SpEL表达式）

### 3.3 状态流转
流转引擎本身不管理单据状态，但影响源单状态：
- 下推后：源单 pushed_qty 累加 → 全部推完后可能标记"已转单"（由 push_rule.auto_close_source 控制）
- 回滚后：源单 pushed_qty 扣减 → 恢复可推数量

## 4. 接口契约

### 4.1 对外接口
| 接口路径 | 方法 | 说明 |
|---------|------|------|
| /api/engine/flow/push | POST | 通用下推服务（校验+创建目标单+关联+回写） |
| /api/engine/flow/rollback | POST | 下推回滚（删除目标单+反写源单数量） |
| /api/engine/flow/copy | POST | 通用复制服务（深拷贝+新编号+草稿状态） |
| /api/engine/flow/trace/{docType}/{docId} | GET | 单据追溯（正向+反向递归查询） |
| /api/doc-flow/import | POST | 通用引入服务 |
| /api/doc-flow/import/source | GET | 查询可引入源单列表 |
| /api/doc-flow/push/target-type | GET | 查询可下推目标单类型 |
| /api/doc-flow/relation/{docType}/{docId} | GET | 查询单据关联关系 |

### 4.2 依赖接口
- P1-001 审核引擎：下推前校验源单审核状态；回滚时可能需要反审目标单
- P0-005 公共组件：编码生成服务（复制时重新生成单据编号）
- 各业务模块：提供单据数据表和CRUD服务，流转引擎通过配置调用

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **流转引擎后端开发（P1-004-001）**必须先完成：
   - 流转配置表/下推规则表设计与初始化
   - 核心下推服务（三阶段事务：校验→写入→回写）
   - 引入/复制/追溯服务
   - 回滚服务
   - 并发控制（行级锁）
2. **流转引擎前端集成（P1-004-002）**依赖后端完成：
   - 引入/下推/复制/追溯弹窗组件
   - 关联关系展示组件

### 5.2 可并行执行的任务
- 下推服务与引入服务可并行开发
- 复制服务与追溯服务可并行开发
- 流转配置管理CRUD可与核心流转逻辑并行开发
- 各业务模块的流转集成可在API稳定后并行实施
