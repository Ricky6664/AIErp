# P1-004 通用单据流转引擎开发 - 模块开发指南

## 一、模块概述

- **模块定位**：通用单据引入/下推/复制/追溯引擎，为所有业务单据链路流转提供统一能力，是系统单据流转体系的核心基础设施
- **前置依赖**：P0-001（后端框架）、P0-002（前端框架）、P0-003（数据库）、P0-004（认证与权限）、P0-005（公共组件含引入/下推组件）、P1-001（审核引擎）
- **被依赖方**：P1-005~P1-009（销售/采购/库存/生产/委外所有业务模块的单据流转）
- **开发阶段**：阶段六（引擎层）

## 四、模块级专属约束

1. **引入服务**：源单查询需支持按客户/供应商/日期/编号等多维度筛选，明细行勾选支持全选/部分选/反选。引入数据自动填充目标单主表/明细，支持字段映射配置。
2. **下推服务**：下推操作需记录doc_relation关联关系，源单已下推数量需实时更新。下推时源单状态可配置（如"全部下推后自动标记已转单"）。
3. **复制服务**：深拷贝包含主表+所有从表数据，单据编号重新生成（调用编码生成服务），状态重置为草稿，审核记录不复制。
4. **追溯服务**：上下游递归查询形成追溯链路树，支持正向追溯（从源单到最终单据）和反向追溯（从目标单到最初源单）。追溯结果以树形结构返回。
5. **流转路径控制**：各业务模块的流转路径（如报价→订单→发货→出库→对账）由系统参数控制，参数缺失时提示用户或提供强制流转选项。
6. **并发控制**：下推操作需使用行级锁防止同一源单明细行被重复下推，已下推数量需与源单明细行数量进行校验。

### 5.2 流转配置表字段映射规则

sys_doc_flow_config.field_mapping_json存储源单到目标单的字段映射规则，JSON结构示例：

```json
{
  "header_mapping": [
    {"source_field": "customer_id", "target_field": "customer_id", "mapping_type": "direct"},
    {"source_field": "order_date", "target_field": "source_date", "mapping_type": "direct"},
    {"source_field": "dept_id", "target_field": "dept_id", "mapping_type": "direct"},
    {"source_field": "", "target_field": "delivery_date", "mapping_type": "default", "default_value": "CURRENT_DATE"}
  ],
  "detail_mapping": [
    {"source_field": "material_id", "target_field": "material_id", "mapping_type": "direct"},
    {"source_field": "qty", "target_field": "source_qty", "mapping_type": "direct"},
    {"source_field": "unit_price", "target_field": "unit_price", "mapping_type": "direct"},
    {"source_field": "qty", "target_field": "push_qty", "mapping_type": "expression", "expression": "source.qty - source.pushed_qty"}
  ]
}
```

**映射类型说明**：
- `direct`：直接复制源字段值到目标字段
- `default`：目标字段使用默认值（支持常量、当前日期、当前用户等）
- `expression`：通过SpEL表达式计算目标字段值，可引用源单字段

### 5.4 流转校验规则

| 校验规则编号 | 校验项 | 校验时机 | 校验逻辑 | 失败处理 |
|------------|--------|---------|---------|---------|
| FR-001 | 源单状态校验 | 下推前 | 源单audit_status必须为已审核(2)，草稿/待审核/已驳回/已作废状态不允许下推 | 返回错误码FLOW_SOURCE_NOT_AUDITED |
| FR-002 | 可下推数量校验 | 下推前 | 对每个明细行：可下推数量=明细行数量-已下推数量，本次下推数量不得超过可下推数量 | 返回错误码FLOW_QTY_EXCEEDED+具体行号 |
| FR-003 | 关联完整性校验 | 下推前 | 检查流转配置是否存在且启用(is_enabled=1) | 返回错误码FLOW_CONFIG_NOT_FOUND |
| FR-004 | 目标单必填字段校验 | 下推时 | 映射后的目标单必须满足目标单据类型的必填字段要求 | 返回错误码FLOW_TARGET_FIELD_REQUIRED+字段名 |
| FR-005 | 回滚状态校验 | 回滚前 | 目标单audit_status必须为草稿(0)，已审核的目标单需先反审才能回滚 | 返回错误码FLOW_TARGET_NOT_DRAFT |
| FR-006 | 回滚关联校验 | 回滚前 | 目标单不存在下游单据，若存在需先回滚下游单据 | 返回错误码FLOW_TARGET_HAS_DOWNSTREAM |

### 5.5 数量回写算法

下推操作的数量回写采用"先校验-再写入-后回写"三阶段事务流程：

```
阶段一：校验（SELECT ... FOR UPDATE）
  FOR each detailId IN detailIds:
    sourceDetail = SELECT * FROM source_detail WHERE id = detailId FOR UPDATE
    availableQty = sourceDetail.qty - sourceDetail.pushed_qty
    IF pushQtyMap[detailId] > availableQty THEN ROLLBACK + 抛出异常

阶段二：写入目标单（INSERT）
  targetDocId = 创建目标单主表（INSERT INTO target_doc_header）
  FOR each detailId IN detailIds:
    INSERT INTO target_doc_detail (字段来自映射配置)
    INSERT INTO doc_relation (source_detail_id, target_detail_id, relation_qty)
    INSERT INTO sys_doc_flow_log (operation_type='下推')

阶段三：回写源单（UPDATE）
  FOR each detailId IN detailIds:
    UPDATE source_detail SET pushed_qty = pushed_qty + pushQtyMap[detailId] WHERE id = detailId
    INSERT INTO sys_doc_flow_qty_writeback (writeback_qty = pushQtyMap[detailId])
  
  IF 所有明细行 pushed_qty == qty THEN
    UPDATE source_doc_header SET flow_status = '已转单'（如push_rule.auto_close_source=1）
  
COMMIT
```

回滚操作的数量回写为下推的逆操作：从sys_doc_flow_qty_writeback读取原始回写数量，反向更新源单pushed_qty。

## 八、Service层业务逻辑规格

### 8.1 DocFlowPushService

| 方法 | 事务 | 业务逻辑要点 |
|------|------|------------|
| push(FlowPushDTO) | @Transactional(编程式事务) | **阶段一(校验)**：①行级锁锁定源单明细行(SELECT...FOR UPDATE) ②校验源单audit_status=已审核(2) ③校验流转配置存在且启用 ④逐行校验可下推数量(明细行数量-已下推数量)。**阶段二(写入)**：⑤创建目标单主表 ⑥按字段映射创建目标单明细行 ⑦记录doc_relation ⑧记录sys_doc_flow_log。**阶段三(回写)**：⑨更新源单明细行pushed_qty ⑩记录sys_doc_flow_qty_writeback ⑪全部下推后标记源单已转单(若auto_close_source=true) |
| rollback(FlowRollbackDTO) | @Transactional | ①校验目标单status=草稿(0) ②校验目标单无下游单据 ③删除目标单(逻辑删除) ④从sys_doc_flow_qty_writeback读取原始回写数量 ⑤反向更新源单pushed_qty ⑥删除doc_relation ⑦记录sys_doc_flow_log |
| copy(FlowCopyDTO) | @Transactional | ①深拷贝源单主表+所有从表数据 ②调用编码服务重新生成单据编号 ③状态重置为草稿(0) ④清空审核记录 ⑤记录sys_doc_flow_log(operation_type='copy') |

### 8.2 DocFlowImportService
