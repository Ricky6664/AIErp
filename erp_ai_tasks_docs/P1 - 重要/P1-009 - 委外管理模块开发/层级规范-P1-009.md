## 1. 模块架构约束

### 1.1 模块定位
委外全链路业务管理，覆盖委外通知→领退料→入库退库→工序移交接收→统计，是系统委外业务的核心模块。属于业务层模块（阶段七），与生产管理模块结构高度对称，但关联供应商维度而非生产部门维度。

### 1.2 依赖关系
- 前置依赖：P0-001~P0-005（基础框架层）、P0-007（商品含BOM）、P0-009（供应商）、P0-010（仓库）、P1-001（审核引擎）、P1-004（流转引擎）、P1-007（库存引擎）
- 后续依赖：P1-011（应付管理——委外产生应付款）、P1-015（成本核算——委外成本）

### 1.3 技术约束
- 技术栈：Spring Boot + MyBatis-Plus + PostgreSQL；单据结构与生产管理对称设计
- 性能约束：聚合查询（未委外/未领料/未入库清单）需优化索引；库存操作统一调用P1-007库存引擎
- 安全约束：通知变更记录不可删除；加工费数据需保密；工序接收合格/不合格数量严格校验

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| sub_notice / _detail | 委外通知单主/从表 | 通知单号, 供应商ID, 来源销售订单, 计划日期, 商品ID, 数量, 加工单价, 加工费 |
| sub_notice_change | 委外通知变更记录表 | 原通知单ID, 变更类型/原因, 变更前后内容 |
| sub_picking / _detail | 委外领料单主/从表 | 通知单ID, 仓库ID, 商品ID, 数量, 需求数量, 库位/批次/批次号 |
| sub_over_picking / _detail | 委外超领单主/从表 | 通知单ID, 超领原因, 标准用量 |
| sub_return / _detail | 委外退料单主/从表 | 通知单ID, 仓库ID, 商品ID, 数量 |
| sub_receipt / _detail | 委外入库单主/从表 | 通知单ID, 仓库ID, 商品ID, 数量 |
| sub_receipt_return / _detail | 委外退库单主/从表 | 原入库单ID, 商品ID, 数量 |
| sub_process_handover / _detail | 委外工序移交单主/从表 | 通知单ID, 商品工序ID, 移交数量 |
| sub_process_accept / _detail | 委外工序接收单主/从表 | 移交单ID, 接收/合格/不合格数量 |

### 2.2 表关系图
- sub_notice 1:N sub_notice_detail：通知单主从结构
- sub_notice 1:N sub_notice_change：通知单审核后修改自动创建变更记录
- sub_notice 1:N sub_picking/sub_receipt/sub_process_handover：通知单下推生成各类型单据
- sub_process_handover 1:1 sub_process_accept：移交单与接收单配对
- 单据结构与 prod_*（生产管理）高度对称，区别在于 sub_notice 关联供应商（srm_supplier）

### 2.3 数据流转
1. 委外通知单创建 → 审核 → BOM展开 → 查看未委外清单
2. 领料流程：未领料清单 → 领料单 → 超领单 → 退料单 → 库存增减
3. 入库流程：未入库清单 → 入库单 → 退库单 → 库存增减
4. 工序管理：移交单 → 接收单（合格/不合格拆分）
5. 加工费汇总：入库时自动汇总加工费 → 为应付管理和成本核算提供数据
6. 应付联动：入库单审核后自动生成应付款（联动P1-011）

## 3. 业务流程

### 3.1 核心业务流程
1. 委外通知：创建通知单（关联供应商）→ 审核 → BOM展开 → 变更管理
2. 委外领料：未领料清单 → 领料单 → 超领单（超量时）→ 退料单
3. 委外入库：未入库清单 → 入库单 → 退库单
4. 工序管理：移交单 → 接收单（合格/不合格数量拆分）
5. 统计分析：按供应商/时间维度汇总
6. 看板管理：委外进度+供应商产能汇总

### 3.2 业务规则
- 委外与生产结构对称：单据结构与生产管理高度对称，但关联供应商维度
- 加工费管理：通知单明细包含加工单价和加工费，入库时自动汇总
- 库存联动：领料扣减、退料增加、入库增加、退库扣减（统一调用P1-007）
- 应付联动：入库单审核后根据系统参数自动生成应付款（联动P1-011）
- 通知变更后修改自动创建变更记录，变更原因必填
- 未委外/未领料/未入库清单为只读视图，支持下推快捷操作和导出
- 工序移交接收配对：接收单记录合格和不合格数量

### 3.3 状态流转
各委外单据审核状态（由P1-001管理）：草稿(0) → 已审核(2)
委外通知单扩展状态：草稿 → 已审核 → 已完成 → 已关闭

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **委外管理后端开发（P1-009-001）**必须先完成：
   - 委外通知单CRUD + BOM展开
   - 领料单/超领单/退料单CRUD
   - 入库单/退库单CRUD
   - 工序移交/接收单CRUD
   - 加工费汇总与应付联动
   - 聚合查询与统计
2. **委外管理前端页面（P1-009-002）**依赖后端完成

### 5.2 可并行执行的任务
- 领料单与退料单可并行开发
- 入库单与退库单可并行开发
- 工序移交与工序接收可并行开发
- 三个聚合查询（未委外/未领料/未入库）可并行开发
- 委外统计与委外看板可并行开发
- 前端各页面可在对应后端API完成后并行开发
