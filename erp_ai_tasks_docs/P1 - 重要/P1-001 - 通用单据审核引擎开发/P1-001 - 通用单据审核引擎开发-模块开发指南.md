# P1-001 通用单据审核引擎开发 - 模块开发指南

## 一、模块概述

- **模块定位**：通用单据审核/反审/作废/撤销作废引擎，为所有业务单据提供统一的审核状态流转能力，是系统审核体系的核心基础设施
- **前置依赖**：P0-001（后端框架）、P0-002（前端框架）、P0-003（数据库）、P0-004（认证与权限）、P0-005（公共组件含审核组件）
- **被依赖方**：P1-002（审批流程）、P1-004（流转引擎）、P1-005~P1-015（所有业务模块的单据审核）
- **开发阶段**：阶段六（引擎层）

## 四、模块级专属约束

1. **审核引擎与审批流程集成**：approval.enabled参数判断——=false直接审核通过，=true走审批流程（P1-002）。审核引擎需在审核接口中预留审批流程触发入口。
2. **系统参数联动**：sale.auto_confirm/purchase.auto_confirm等自动确认参数，控制各业务单据是否在创建时自动审核通过。参数变更后仅对新单据生效，不影响已有单据。
3. **反审约束**：反审前须校验该单据是否存在已审核的下游关联单据（如销售订单已审核后需先反审出库单才能反审订单），若存在则阻止反审并提示用户先处理下游单据。
4. **作废约束**：作废前须校验该单据不存在任何下游单据关联（无论下游单据状态），若存在则阻止作废。作废后单据数据保留但标记为已作废状态，不参与业务流转。
5. **审核记录不可篡改**：所有审核/反审/作废/撤销作废操作均记录到sys_audit_log表，记录不可修改或删除，作为审计追溯依据。
6. **并发控制**：审核操作需使用行级锁防止并发审核，确保同一单据同一时刻只能有一个审核操作成功。

| 状态码 | 状态名称 | 英文标识 | 颜色标识 | 说明 |

| 0 | 草稿 | DRAFT | #909399(灰色) | 单据刚创建或从已审核反审回来，可编辑、可提交审核、可删除 |
| 1 | 待审核 | PENDING | #E6A23C(橙色) | 已提交审核等待审核人处理，不可编辑、可撤回(回退到草稿) |

### 5.7 并发控制实现

审核操作使用PostgreSQL行级锁（SELECT ... FOR UPDATE）实现并发控制：

```sql
-- 审核操作加锁流程
BEGIN;
  -- 1. 行级锁锁定单据主表记录
  SELECT * FROM {doc_table} WHERE id = :docId FOR UPDATE;
  
  -- 2. 校验当前审核状态（双重检查，防止锁等待期间状态已被修改）
  -- 3. 更新审核状态
  UPDATE {doc_table} SET audit_status = :newStatus WHERE id = :docId;
  
  -- 4. 插入审核日志
  INSERT INTO sys_audit_log (doc_type, doc_id, operation_type, ...);
COMMIT;
```

Redis分布式锁作为辅助手段：Key格式为`audit:lock:{docType}:{docId}`，TTL=10秒，防止同一单据的审核请求被多实例同时处理。

## 八、Service层业务逻辑规格

### 8.1 AuditEngineService

| 方法 | 事务 | 业务逻辑要点 |
|------|------|------------|
| submit(AuditSubmitDTO) | @Transactional | ①查询sys_audit_config获取配置 ②行级锁锁定单据(SELECT...FOR UPDATE) ③校验当前状态为草稿(0)或已驳回(3) ④判断approval_enabled：=false直接→已审核(2)，=true→待审核(1) ⑤更新单据审核状态 ⑥记录sys_audit_log ⑦若启用审批则触发P1-002审批流程 |
| approve(AuditApproveDTO) | @Transactional | ①行级锁锁定单据 ②校验当前状态为待审核(1) ③校验审核人与提交人不能为同一人 ④状态→已审核(2) ⑤记录审核人/时间/意见到sys_audit_log ⑥触发下游自动操作(如自动下推) |
| reject(AuditRejectDTO) | @Transactional | ①行级锁锁定单据 ②校验当前状态为待审核(1) ③驳回原因必填校验(≥5字) ④状态→rejectTo指定值(0或3) ⑤记录sys_audit_log |
| unconfirm(AuditOperationDTO) | @Transactional | ①行级锁锁定单据 ②校验当前状态为已审核(2) ③校验下游单据是否已审核（若存在已审核的下游单据则阻止反审） ④状态→草稿(0) ⑤记录sys_audit_log |
| void(AuditVoidDTO) | @Transactional | ①行级锁锁定单据 ②校验当前状态为已审核(2) ③若void_check_downstream=true则校验无下游单据关联 ④状态→已作废(4) ⑤记录作废原因到sys_audit_log |
| cancelVoid(AuditOperationDTO) | @Transactional | ①行级锁锁定单据 ②校验当前状态为已作废(4) ③状态→草稿(0) ④记录sys_audit_log |
| withdraw(AuditOperationDTO) | @Transactional | ①行级锁锁定单据 ②校验当前状态为待审核(1) ③校验操作人为提交人 ④状态→草稿(0) ⑤记录sys_audit_log |
| getStatus(String docType, Long docId) | 无(只读) | 查询单据当前审核状态 + 允许的操作列表(供前端按钮状态联动) |
| getLogs(String docType, Long docId) | 无(只读) | 查询指定单据的全部审核操作日志，按operate_time倒序返回 |
