### 5.1 核心Service — AuditEngineService.voidDocument

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class AuditEngineService {

    private final AuditLogMapper auditLogMapper;
    private final DocumentStatusMapper documentStatusMapper;
    private final ApplicationEventPublisher eventPublisher;
    private final RedissonClient redissonClient;

    @Transactional(rollbackFor = Exception.class)
    public void voidDocument(AuditVoidDTO dto) {
        // 1. voidReason必填校验
        if (StringUtils.isBlank(dto.getVoidReason())) {
            throw new BusinessException("作废原因不能为空");
        }

        // 2. Redis分布式锁
        String lockKey = String.format("audit:lock:%s:%d", dto.getDocType(), dto.getDocId());
        RLock lock = redissonClient.getLock(lockKey);
        if (!lock.tryLock(0, 10, TimeUnit.SECONDS)) {
            throw new BusinessException("单据正在处理中，请稍后重试");
        }
        try {
            // 3. 行级锁获取单据状态
            DocumentStatusEntity docStatus = documentStatusMapper
                .selectForUpdate(dto.getDocType(), dto.getDocId());
            if (docStatus == null) {
                throw new BusinessException("单据不存在");
            }

            // 4. 状态校验：仅 Draft(0)、Submitted(1)、Approved(2) 可作废
            int currentStatus = docStatus.getStatus();
            if (currentStatus != 0 && currentStatus != 1 && currentStatus != 2) {
                throw new BusinessException(
                    "当前状态不允许作废操作，仅草稿/已提交/已审核状态可作废，当前状态：" + currentStatus);
            }

            // 5. 状态变更 -> Voided(4)
            documentStatusMapper.updateStatus(dto.getDocType(), dto.getDocId(), 4);

            // 6. 插入作废日志
            SysAuditLogEntity logEntity = new SysAuditLogEntity();
            logEntity.setDocType(dto.getDocType());
            logEntity.setDocId(dto.getDocId());
            logEntity.setOperationType("VOID");
            logEntity.setOperatorId(UserContext.getCurrentUserId());
            logEntity.setFromStatus(currentStatus);
            logEntity.setToStatus(4);
            logEntity.setOpinion(dto.getVoidReason());
            logEntity.setCreatedAt(LocalDateTime.now());
            auditLogMapper.insert(logEntity);

            // 7. 发布资源释放事件（事务提交后异步消费）
            eventPublisher.publishEvent(new VoidResourceReleaseEvent(
                dto.getDocType(), dto.getDocId(), currentStatus));
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }
}
```

### 5.2 资源释放事件 — VoidResourceReleaseEvent

```java
@Getter
public class VoidResourceReleaseEvent extends ApplicationEvent {
    private final String docType;
    private final Long docId;
    private final int fromStatus;  // 作废前的状态，下游据此判断需释放哪些资源

    public VoidResourceReleaseEvent(Object source, String docType, Long docId, int fromStatus) {
        super(source);
        this.docType = docType;
        this.docId = docId;
        this.fromStatus = fromStatus;
    }
}

@Component
@Slf4j
public class InventoryResourceReleaseListener {
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void onVoidResourceRelease(VoidResourceReleaseEvent event) {
        if ("sale_order".equals(event.getDocType()) && event.getFromStatus() == 2) {
            inventoryReservationService.releaseByDocId(event.getDocId());
            log.info("已释放销售订单库存预留: docId={}", event.getDocId());
        }
    }
}
```

### 5.4 关键业务规则

1. **状态约束**：仅Draft(0)、Submitted(1)、Approved(2)三种状态可执行作废，已驳回(3)和已作废(4)状态不允许
2. **voidReason必填**：作废原因为空时抛出BusinessException，前端需做表单校验配合
3. **资源释放**：通过Spring事件机制(VoidResourceReleaseEvent)通知下游模块，使用@TransactionalEventListener(phase=AFTER_COMMIT)确保事务提交后才消费
4. **fromStatus传递**：事件携带作废前状态，下游模块据此判断需释放哪些资源（如仅Approved(2)状态的订单需释放库存预留）
5. **并发控制**：PostgreSQL行级锁 + Redis分布式锁双重保障

### 5.5 数据交互

- 涉及DTO：AuditVoidDTO(docType, docId, voidReason)
- 涉及事件：VoidResourceReleaseEvent（下游模块消费）

## 八、易错警示

> ⚠️ voidReason必填校验需在Service层和DTO @NotBlank注解双重保障

> ⚠️ VoidResourceReleaseEvent必须使用@TransactionalEventListener(phase=AFTER_COMMIT)，避免事务回滚但资源已释放

> ⚠️ 事件消费者异常不应影响作废事务本身（事件在事务提交后消费，消费者异常独立处理）

> ⚠️ 作废前状态(fromStatus)必须正确传递，下游模块依赖此值判断资源释放策略

> ⚠️ 行级锁SELECT FOR UPDATE确保并发作废时仅一个请求成功

> ⚠️ 多租户隔离：tenant_id由拦截器自动附加，业务代码勿手动处理
