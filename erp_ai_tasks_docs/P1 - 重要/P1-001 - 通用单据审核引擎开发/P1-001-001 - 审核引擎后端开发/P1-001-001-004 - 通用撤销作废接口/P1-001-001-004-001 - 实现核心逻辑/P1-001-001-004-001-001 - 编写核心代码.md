### 5.1 核心Service — AuditEngineService.cancelVoid

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class AuditEngineService {

    private final AuditLogMapper auditLogMapper;
    private final DocumentStatusMapper documentStatusMapper;
    private final ApplicationEventPublisher eventPublisher;
    private final RedissonClient redissonClient;

    /**
     * 撤销作废操作
     * 状态流转：Voided(4) -> 作废前原始状态（从sys_audit_log.from_status恢复）
     * 这是最简单的审核操作——无需下游检查
     */
    @Transactional(rollbackFor = Exception.class)
    public void cancelVoid(AuditOperationDTO dto) {
        // 1. Redis分布式锁
        String lockKey = String.format("audit:lock:%s:%d", dto.getDocType(), dto.getDocId());
        RLock lock = redissonClient.getLock(lockKey);
        if (!lock.tryLock(0, 10, TimeUnit.SECONDS)) {
            throw new BusinessException("单据正在处理中，请稍后重试");
        }
        try {
            // 2. 行级锁获取单据状态
            DocumentStatusEntity docStatus = documentStatusMapper
                .selectForUpdate(dto.getDocType(), dto.getDocId());
            if (docStatus == null) {
                throw new BusinessException("单据不存在");
            }
            if (docStatus.getStatus() != 4) {
                throw new BusinessException("仅已作废状态单据可撤销作废，当前状态：" + docStatus.getStatus());
            }

            // 3. 从sys_audit_log中获取作废前的原始状态
            Integer previousStatus = auditLogMapper
                .findPreviousStatusBeforeVoid(dto.getDocType(), dto.getDocId());
            if (previousStatus == null) {
                throw new BusinessException("无法获取作废前状态，数据异常");
            }

            // 4. 恢复至作废前状态
            documentStatusMapper.updateStatus(dto.getDocType(), dto.getDocId(), previousStatus);

            // 5. 插入撤销作废日志
            SysAuditLogEntity logEntity = new SysAuditLogEntity();
            logEntity.setDocType(dto.getDocType());
            logEntity.setDocId(dto.getDocId());
            logEntity.setOperationType("UNVOID");
            logEntity.setOperatorId(UserContext.getCurrentUserId());
            logEntity.setFromStatus(4);
            logEntity.setToStatus(previousStatus);
            logEntity.setOpinion("撤销作废，恢复至状态：" + previousStatus);
            logEntity.setCreatedAt(LocalDateTime.now());
            auditLogMapper.insert(logEntity);

            // 6. 发布资源重新获取事件
            eventPublisher.publishEvent(new CancelVoidResourceRestoreEvent(
                dto.getDocType(), dto.getDocId(), previousStatus));
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }
}
```

### 5.2 Mapper层 — 查询作废前状态

```java
@Mapper
public interface AuditLogMapper {
    @Select("SELECT from_status FROM sys_audit_log " +
            "WHERE doc_type = #{docType} AND doc_id = #{docId} " +
            "AND operation_type = 'VOID' " +
            "ORDER BY created_at DESC LIMIT 1")
    Integer findPreviousStatusBeforeVoid(@Param("docType") String docType,
                                          @Param("docId") Long docId);
}
```

### 5.3 资源恢复事件 — CancelVoidResourceRestoreEvent

```java
@Getter
public class CancelVoidResourceRestoreEvent extends ApplicationEvent {
    private final String docType;
    private final Long docId;
    private final int restoredStatus;

    public CancelVoidResourceRestoreEvent(Object source, String docType,
                                           Long docId, int restoredStatus) {
        super(source);
        this.docType = docType;
        this.docId = docId;
        this.restoredStatus = restoredStatus;
    }
}
```

### 5.4 Controller层

```java
@RestController
@RequestMapping("/api/engine/audit")
@RequiredArgsConstructor
public class AuditEngineController {
    private final AuditEngineService auditEngineService;

    @PostMapping("/cancel-void")
    public Result<Void> cancelVoid(@Valid @RequestBody AuditOperationDTO dto) {
        auditEngineService.cancelVoid(dto);
        return Result.ok();
    }
}
```

### 5.5 关键业务规则

1. **状态约束**：仅Voided(4)状态单据可执行撤销作废，其他状态抛出BusinessException
2. **状态恢复**：从sys_audit_log中查找最近一次VOID操作的from_status，恢复到该状态（可能是0/1/2中任意一个）
3. **无需下游检查**：撤销作废是最简单的操作，不需要检查下游单据（因为作废时下游资源已释放）
4. **资源恢复**：通过CancelVoidResourceRestoreEvent通知下游模块重新获取资源，事件在事务提交后消费
5. **并发控制**：PostgreSQL行级锁 + Redis分布式锁

### 5.6 数据交互

- 涉及数据表：sys_audit_log（查询VOID日志获取from_status，写入UNVOID日志）, 业务单据状态表（更新status字段）
- 涉及API：POST /api/engine/audit/cancel-void（撤销作废）
- 涉及DTO：AuditOperationDTO(docType, docId)
- 涉及事件：CancelVoidResourceRestoreEvent

## 八、易错警示

> ⚠️ findPreviousStatusBeforeVoid查询必须在事务内执行，确保读取到最新日志数据

> ⚠️ 如果sys_audit_log中无VOID记录（数据异常），必须抛出BusinessException而非恢复至默认状态

> ⚠️ 资源恢复事件需携带restoredStatus，下游模块据此判断需恢复哪些资源

> ⚠️ 撤销作废无需下游检查——作废时资源已释放，不存在下游关联问题

> ⚠️ 多租户隔离：tenant_id由拦截器自动附加，业务代码勿手动处理
