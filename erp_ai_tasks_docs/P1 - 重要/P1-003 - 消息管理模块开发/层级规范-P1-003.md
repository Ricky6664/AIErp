## 1. 模块架构约束

### 1.1 模块定位
消息中心、消息模板、单据待办、消息推送、业务预警、单据沟通、协作讨论，为系统提供实时通知与协作能力，是系统消息体系的核心基础设施。属于引擎层模块（阶段六），为上层所有业务模块提供消息推送与待办管理能力。

### 1.2 依赖关系
- 前置依赖：P0-001（后端框架含WebSocket配置）、P0-002（前端框架）、P0-003（数据库）、P0-004（认证与权限）、P0-005（公共组件）
- 后续依赖：P1-002（审批流程催办/通知）、P1-004~P1-015（所有业务模块的消息推送与待办）

### 1.3 技术约束
- 技术栈：Spring Boot + WebSocket + Redis（消息队列/连接管理）+ PostgreSQL；前端使用WebSocket客户端 + 消息铃铛组件
- 性能约束：WebSocket连接池管理，单用户仅维护一个有效连接；消息推送延迟 < 1秒；业务预警定时扫描支持cron表达式配置频率
- 安全约束：消息数据仅对接收人可见；已读状态按接收人维度独立管理；消息删除仅标记已删除不物理删除

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| msg_message | 消息中心表 | 消息标题, 消息内容, 消息类型, 发送人, 接收人, 已读状态, 已读时间, 来源单据, 来源模块 |
| msg_template | 消息模板表 | 模板编码, 模板名称, 模板内容, 模板变量列表, 消息类型, 启用状态 |
| msg_type | 消息类型表 | 类型编码, 类型名称, 图标, 排序, 启用状态 |
| msg_todo | 单据待办表 | 待办标题, 待办类型, 来源单据类型/ID, 处理人, 处理状态(待处理/已处理), 创建/完成时间 |
| msg_push_config | 消息推送配置表 | 推送方式(站内信/邮件/短信), 推送时间/对象/频率, 启用状态 |
| msg_alert_rule | 业务预警规则表 | 预警规则名称, 条件表达式, 阈值, 频率, 触发动作配置, 启用状态 |
| msg_doc_comment | 单据沟通表 | 单据类型/ID, 留言内容, 留言人, 回复ID, @提及人列表, 附件URL |
| msg_discussion | 协作讨论主题表 | 讨论标题, 讨论内容, 发起人, 参与人列表 |
| msg_discussion_reply | 协作讨论回复表 | 讨论主题ID, 回复内容, 回复人, 回复时间, 回复对象 |

### 2.2 表关系图
- msg_type 1:N msg_message：消息类型与消息实例一对多关联
- msg_template 独立表：模板被业务模块引用，通过模板编码调用
- msg_todo 通过 source_doc_type + source_doc_id 多态关联各业务单据
- msg_doc_comment 通过 doc_type + doc_id 多态关联各业务单据
- msg_discussion 1:N msg_discussion_reply：讨论主题与回复一对多关联
- msg_alert_rule 独立配置表：触发生成的预警消息写入 msg_message

### 2.3 数据流转
1. 业务事件触发 → 匹配 msg_template 变量替换 → 创建 msg_message → WebSocket推送 + 创建 msg_todo
2. 单据审核/审批 → 自动创建 msg_todo（待处理）→ 操作完成后标记已办
3. 定时任务扫描 msg_alert_rule → 匹配业务数据 → 生成预警消息 → 推送通知
4. 单据沟通 → 新增 msg_doc_comment → @提及/回复触发 msg_message 通知
5. 协作讨论 → 新增 msg_discussion_reply → 推送通知给所有参与人

## 3. 业务流程

### 3.1 核心业务流程
1. 消息发送：业务模块调用消息服务 → 模板变量替换 → 创建消息记录 → WebSocket实时推送
2. 待办管理：单据审核/审批自动创建待办 → 处理完成自动标记已办
3. 业务预警：配置预警规则 → 定时扫描 → 条件匹配 → 自动生成预警消息
4. 单据沟通：在单据详情页留言 → @提及通知 → 回复通知
5. 协作讨论：发起讨论主题 → 参与人回复 → 新回复推送通知

### 3.2 业务规则
- WebSocket连接管理：支持连接池、断线重连、心跳检测；多设备登录时同步推送
- 消息模板变量替换：支持 ${变量名} 格式，变量值由业务模块传入
- 待办自动创建与自动完成：与P1-002审批流程联动
- 业务预警引擎：支持cron表达式配置扫描频率，条件表达式支持配置
- 消息通知联动：@提及和回复自动触发消息通知

### 3.3 状态流转
消息状态：未读 → 已读（标记已读时间）
待办状态：待处理 → 已处理（标记完成时间）
预警规则：启用 → 停用（管理员手动控制）

## 4. 接口契约

### 4.1 对外接口
| 接口路径 | 方法 | 说明 |
|---------|------|------|
| /api/message/message | GET/POST | 消息列表查询/新增消息 |
| /api/message/message/{id}/read | PUT | 标记消息已读 |
| /api/message/message/read-all | PUT | 全部标记已读 |
| /api/message/todo | GET/POST | 待办列表查询/创建待办 |
| /api/message/todo/{id}/done | PUT | 标记待办已办 |
| /api/message/template | GET/POST/PUT/DELETE | 消息模板CRUD |
| /api/message/ws | WebSocket | WebSocket消息推送服务 |
| /api/message/alert-rule | GET/POST/PUT/DELETE | 预警规则CRUD |
| /api/message/alert | GET | 预警触发记录查询 |
| /api/message/doc-comment | GET/POST | 单据沟通列表/新增留言 |
| /api/message/discussion | GET/POST | 协作讨论列表/新增主题 |

### 4.2 依赖接口
- P0-001 后端框架：WebSocket配置、定时任务调度（Spring Schedule）
- P0-004 认证与权限：获取当前用户信息、消息可见性控制
- 外部通道：邮件发送服务（SMTP）、短信发送服务（SMS API）

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **消息管理后端开发（P1-003-001）**必须先完成：
   - 消息中心/模板/类型数据模型
   - WebSocket推送服务（连接管理、心跳检测）
   - 待办管理服务（自动创建/标记已办）
   - 业务预警引擎（定时扫描+条件匹配）
   - 单据沟通与协作讨论服务
2. **消息管理前端页面（P1-003-002）**依赖后端完成：
   - 消息管理工作台
   - 全局消息通知弹窗（WebSocket客户端）
   - 单据沟通嵌入式组件
   - 协作讨论页面

### 5.2 可并行执行的任务
- 消息中心CRUD与消息模板管理可并行开发
- WebSocket推送服务与待办管理服务可并行开发
- 业务预警引擎与单据沟通功能可并行开发
- 推送配置管理与协作讨论可并行开发
