# P1-002 审批流程模块开发 - 模块开发指南

## 一、模块概述

- **模块定位**：审批流程定义、审批实例与审批记录管理，为所有单据审核提供流程支撑，支持多级审批、条件分支、催办、委托、预置流程等完整审批能力
- **前置依赖**：P0-001（后端框架）、P0-002（前端框架）、P0-003（数据库）、P0-004（认证与权限）、P0-005（公共组件）、P1-001（审核引擎）、P1-003（消息管理——审批催办/通知依赖消息推送能力）
- **被依赖方**：P1-004（流转引擎）、P1-005~P1-015（所有业务模块的单据审批）
- **开发阶段**：阶段六（引擎层）

## 四、模块级专属约束

1. **审批流程运行时引擎**：支持完整的状态机（提交→审核→驳回→转办→加签→撤回），状态流转需使用乐观锁防止并发冲突。
2. **催办机制**：审批催办依赖P1-003消息管理模块的消息推送通道（站内信/邮件/短信），催办频率可配置（如每天/每周），自动催办通过定时任务实现。
3. **委托机制**：审批委托配置后，委托期间内的审批任务自动转交被委托人处理，委托到期后自动恢复。委托规则支持按业务类型细分。
4. **预置审批流程**：按单据类型（销售/采购/报销等）预置默认审批流程，支持多级审批节点+条件分支。首次使用时自动加载预置流程，用户可自定义修改或覆盖。
5. **审批节点配置**：使用JSON格式存储流程配置，支持节点拖拽编排。条件分支节点需支持表达式配置（如金额>10000走总经理审批）。
6. **多人审批模式**：多人审批节点支持或签（任一人通过即通过）和会签（所有人通过才通过）两种并行模式。

| delete(Long) | @Transactional | 存在性校验 → 关联实例检查 → 逻辑删除 |

### 8.2 ApprovalInstanceService

| 方法 | 事务 | 业务逻辑要点 |
|------|------|------------|
| page(InstanceQueryDTO) | 无(只读) | 支持businessType/status/applicantId筛选 + 时间范围 |
| getById(Long) | 无(只读) | 返回InstanceDetailVO，含审批日志列表(按action_time倒序) |
| submit(InstanceSubmitDTO) | @Transactional | 查找businessType对应的审批定义 → 创建实例(status='pending') → 设置current_node为第一个审批节点 → 自动创建待办(msg_todo) → 记录审批日志(action='submit') |
| approve(ApprovalActionDTO) | @Transactional | 校验实例status='pending' → 委托检查(若审批人已委托则转交被委托人) → 记录审批日志(action='approve') → 判断当前节点是否完成(或签:任一人通过; 会签:所有人通过) → 流转到下一节点或标记实例status='approved' → 更新待办状态 |
| reject(ApprovalActionDTO) | @Transactional | 校验实例status='pending' → 驳回意见必填校验 → 记录审批日志(action='reject') → 实例status='rejected' → 更新待办状态 |
| withdraw(Long instanceId) | @Transactional | 校验操作人为申请人 → 校验status='pending' → 实例status='withdrawn' → 记录审批日志(action='withdraw') → 更新待办状态 |
