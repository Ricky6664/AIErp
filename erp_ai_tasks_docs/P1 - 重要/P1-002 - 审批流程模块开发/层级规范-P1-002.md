## 1. 模块架构约束

### 1.1 模块定位
审批流程定义、审批实例与审批记录管理，为所有单据审核提供流程支撑，支持多级审批、条件分支、催办、委托、预置流程等完整审批能力。属于引擎层模块（阶段六），是审核引擎（P1-001）的流程扩展层。

### 1.2 依赖关系
- 前置依赖：P0-001（后端框架）、P0-002（前端框架）、P0-003（数据库）、P0-004（认证与权限）、P0-005（公共组件）、P1-001（审核引擎）、P1-003（消息管理——审批催办/通知依赖消息推送能力）
- 后续依赖：P1-004（流转引擎）、P1-005~P1-015（所有业务模块的单据审批）

### 1.3 技术约束
- 技术栈：Spring Boot + MyBatis-Plus + PostgreSQL，流程配置使用JSONB存储；前端审批设计器使用拖拽编排组件
- 性能约束：审批运行时引擎状态流转使用乐观锁防止并发冲突；催办定时任务需支持集群调度（防重复执行）
- 安全约束：审批节点配置JSON需防注入攻击；委托机制需在委托到期后自动恢复；审批记录不可篡改

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| approval_definition | 审批定义表 | 定义名称, 定义编码, 业务类型, 流程配置JSON, 是否启用 |
| approval_node | 审批节点表 | 审批定义ID, 节点顺序, 节点类型(审批/知会/条件分支), 审批人类型, 审批人ID列表, 条件表达式, 并行模式, 超时时间 |
| approval_instance | 审批实例表 | 审批定义ID, 业务类型, 业务单据ID, 申请人ID, 当前节点, 状态(待审批/已通过/已驳回/已撤回) |
| approval_record | 审批记录表 | 审批实例ID, 节点名称, 审批人ID, 动作(通过/驳回/转审/撤回), 审批意见, 操作时间 |
| approval_urge | 审批催办记录表 | 审批实例ID, 催办方式, 催办时间, 催办频率配置, 自动催办开关 |
| approval_delegate | 审批委托配置表 | 委托人ID, 被委托人ID, 委托开始/结束时间, 委托业务类型, 启用状态 |
| approval_preset | 预置审批流程表 | 单据类型, 默认审批流程配置, 多级节点, 条件分支 |

### 2.2 表关系图
- approval_definition 1:N approval_node：一个审批定义包含多个审批节点，按节点顺序编排
- approval_definition 1:N approval_instance：一个审批定义可创建多个审批实例（不同业务单据）
- approval_instance 1:N approval_record：一个审批实例产生多条审批记录（每个节点操作一条）
- approval_instance 1:N approval_urge：一个审批实例可有多条催办记录
- approval_delegate 独立表：按委托人+业务类型配置委托规则

### 2.3 数据流转
1. 管理员配置审批定义 → 编排审批节点（拖拽设计器）→ 保存 approval_definition + approval_node
2. 业务单据提交审核 → 匹配 approval_preset 或 approval_definition → 创建 approval_instance → 状态=待审批
3. 审批人操作 → 写入 approval_record → 推进当前节点 → 判断多人审批模式（或签/会签）→ 流转下一节点或结束
4. 催办触发 → 创建 approval_urge → 调用 P1-003 消息推送
5. 委托生效 → 审批任务自动转交被委托人

## 3. 业务流程

### 3.1 核心业务流程
1. 审批定义配置：管理员通过设计器拖拽编排审批节点，设置条件分支和审批人
2. 预置流程加载：首次使用时自动加载 approval_preset 中的默认流程
3. 审批发起：业务单据提交 → 创建审批实例 → 通知第一节点审批人
4. 审批执行：审批人通过/驳回/转审 → 推进节点 → 通知相关人员
5. 审批完成：所有节点通过 → 回调审核引擎（P1-001）执行审核通过
6. 催办处理：定时任务扫描超时审批 → 发送催办通知
7. 委托处理：委托期间内审批任务自动转交被委托人

### 3.2 业务规则
- 多人审批支持或签（任一人通过即通过）和会签（所有人通过才通过）两种并行模式
- 条件分支节点支持SpEL表达式配置（如金额>10000走总经理审批）
- 催办频率可配置（每天/每周），自动催办通过定时任务实现
- 委托规则支持按业务类型细分，委托到期后自动恢复
- 审批记录包含完整审计信息（审批人/时间/动作/意见），不可修改

### 3.3 状态流转
审批实例状态流转：
```
待审批 → 已通过（所有节点通过）
待审批 → 已驳回（任一审批人驳回）
待审批 → 已撤回（申请人撤回）
已驳回 → 待审批（重新提交）
```

## 4. 接口契约

### 4.1 对外接口
| 接口路径 | 方法 | 说明 |
|---------|------|------|
| /api/approval/definition | GET/POST | 审批定义列表查询/新增 |
| /api/approval/definition/{id} | GET/PUT/DELETE | 审批定义详情/修改/删除 |
| /api/approval/instance | POST | 提交审批（创建审批实例） |
| /api/approval/instance/{id}/withdraw | POST | 撤回审批 |
| /api/approval/record | POST | 审批操作（通过/驳回/转审+审批意见） |
| /api/approval/runtime/{instanceId} | POST | 运行时引擎操作（状态机） |
| /api/approval/my | GET | 我的审批（待审/已审/待提交） |
| /api/approval/urge | POST | 审批催办 |
| /api/approval/delegate | GET/POST/PUT/DELETE | 审批委托CRUD |
| /api/approval/preset/{id}/apply | POST | 一键应用预置审批流程 |
| /api/approval/statistics | GET | 审批统计 |

### 4.2 依赖接口
- P1-001 审核引擎：审批完成后回调审核引擎执行审核通过/驳回
- P1-003 消息管理：催办通知、审批任务通知通过消息推送通道（站内信/邮件/短信）
- P0-004 认证与权限：获取当前用户信息、校验审批权限

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **审批流程后端开发（P1-002-001）**必须先完成：
   - 审批定义/节点数据模型设计
   - 审批运行时引擎（状态机实现）
   - 催办/委托/预置流程功能
   - 与审核引擎（P1-001）的回调集成
   - 与消息管理（P1-003）的推送集成
2. **审批流程前端页面（P1-002-002）**依赖后端完成：
   - 审批设计器页（节点拖拽编排）
   - 我的审批页面
   - 催办/委托/预置配置页面

### 5.2 可并行执行的任务
- 审批定义CRUD与审批实例管理可并行开发
- 催办机制与委托机制可并行开发
- 预置流程配置与审批统计可并行开发
- 前端审批设计器与后端运行时引擎可适度并行（需提前约定接口契约）
