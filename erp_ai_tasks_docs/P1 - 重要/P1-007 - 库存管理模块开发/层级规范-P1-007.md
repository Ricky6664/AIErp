## 1. 模块架构约束

### 1.1 模块定位
库存全功能管理，包括库存引擎（出入库/成本/批次序列号/预警）和业务单据（其他出入库/盘点/调拨/报损报溢/组装拆卸/库存查询/预警/成本查询），是系统库存数据的核心管理模块。属于业务层模块（阶段七），包含库存引擎和库存业务两层架构。

### 1.2 依赖关系
- 前置依赖：P0-001~P0-005（基础框架层）、P0-007（商品）、P0-010（仓库库位）、P1-001（审核引擎）、P1-004（流转引擎）、P1-005（销售出库）、P1-006（采购入库）
- 后续依赖：P1-008（生产管理——领料/入库触发库存变动）、P1-009（委外管理——领料/入库触发库存变动）、P1-015（成本核算——库存成本）

### 1.3 技术约束
- 技术栈：Spring Boot + MyBatis-Plus + PostgreSQL；库存增减使用行级锁+版本号乐观锁；成本计算支持移动加权平均/FIFO/手工指定
- 性能约束：库存增减原子操作必须使用行级锁确保一致性；库存核心表建立联合唯一索引保证数据唯一性
- 安全约束：所有出入库单据审核必须通过库存引擎Service执行；反审时必须反向冲回；库存数据不允许负库存（可配置）

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| inv_stock | 库存总账表（核心表） | 商品ID, 仓库ID, 库存数量, 锁定数量, 可用数量, 单位成本, 成本金额 |
| inv_stock_location | 库位库存表（核心表） | 商品ID, 仓库ID, 库位ID, 库位数量, 锁定数量, 可用数量 |
| inv_batch_trace | 批次跟踪表（核心表） | 商品ID, 仓库ID, 批次号, 批次数量, 生产日期, 有效期 |
| inv_serial_trace | 序列号跟踪表（核心表） | 商品ID, 仓库ID, 序列号, 状态(在库/已出库/已锁定/已报废), 库位ID |
| inv_other_outbound / _detail | 其他出库单 | 出库类型(领用/赠品/报废/其他), 商品ID, 数量, 库位/批次/序列号 |
| inv_other_inbound / _detail | 其他入库单 | 入库类型(赠品/退回/盘盈/其他), 商品ID, 数量 |
| inv_stocktake / _detail | 盘点单 | 盘点类型(全盘/抽盘/动盘), 账面数量, 实盘数量, 差异数量 |
| inv_transfer / _detail | 调拨单 | 调出/调入仓库, 商品ID, 数量, 调出/调入库位 |
| inv_damage / _detail | 报损单 | 商品ID, 数量, 报损原因 |
| inv_surplus / _detail | 报溢单 | 商品ID, 数量, 报溢原因 |
| inv_assembly / _detail | 组装单 | BOM ID, 成品商品ID, 子件商品ID, 用量 |
| inv_disassembly / _detail | 拆卸单 | BOM ID, 成品商品ID, 子件商品ID, 预期/实际数量 |

### 2.2 表关系图
- inv_stock 唯一索引(product_id, warehouse_id, tenant_id)：每个仓库每个商品一条库存记录
- inv_stock_location 唯一索引(product_id, warehouse_id, location_id, tenant_id)：库位级库存
- inv_batch_trace 唯一索引(product_id, warehouse_id, batch_no, tenant_id)：批次级跟踪
- inv_serial_trace 唯一索引(serial_no, product_id, tenant_id)：序列号级跟踪
- 四个核心表形成"总账→库位→批次→序列号"四层库存数据体系
- 所有业务单据审核后通过库存引擎统一操作四个核心表

### 2.3 数据流转
1. 库存引擎层：
   - 出库操作：行级锁锁定inv_stock → 扣减数量 → 更新库位/批次/序列号 → 重算成本
   - 入库操作：行级锁锁定inv_stock → 增加数量 → 更新库位/批次/序列号 → 重算加权平均成本
   - 可用量计算：可用量 = 现存量 - 占用量 + 在途量

2. 业务单据层：
   - 其他出库/入库 → 审核 → 调用库存引擎增减
   - 盘点 → 完成 → 盘盈生成报溢单 + 盘亏生成报损单 → 库存调整
   - 调拨 → 审核 → 调出仓扣减 + 调入仓增加
   - 组装 → 审核 → 子件扣减 + 成品增加（BOM校验）
   - 拆卸 → 审核 → 成品扣减 + 子件增加（BOM校验）

## 3. 业务流程

### 3.1 核心业务流程
1. 库存引擎：提供统一的库存增减原子操作接口，所有出入库单据必须通过引擎执行
2. 其他出入库：创建单据 → 审核 → 库存增减
3. 盘点管理：创建盘点单（全盘/抽盘/动盘）→ 录入实盘数量 → 审核 → 自动生成报溢/报损单
4. 调拨管理：创建调拨单 → 审核 → 调出仓扣减 + 调入仓增加
5. 报损/报溢：创建单据 → 审核 → 库存扣减/增加
6. 组装/拆卸：创建单据 → 审核 → BOM校验 → 子件/成品库存变动
7. 库存查询：多维度查询（仓库+商品+库位+批次+序列号）
8. 库存预警：安全库存检测 + 批次有效期检测
9. 库存成本查询：按成本方法展示商品库存成本

### 3.2 业务规则
- 库存增减原子操作：inv_stock行级锁 + 版本号乐观锁，所有出入库必须通过库存引擎Service
- 成本计算方法：inv.cost_method 控制全局成本方法（移动加权平均/FIFO/手工指定），按商品可覆盖
- 库位/批次/序列号三表处理：审核后自动更新对应跟踪表
- 盘点联动：盘盈→报溢单→库存增加，盘亏→报损单→库存扣减
- 组装/拆卸BOM校验：组装需子件库存充足，拆卸按BOM展开增加子件
- 反审冲回：所有出入库反审时库存数据反向冲回（含四个核心表）

### 3.3 状态流转
各库存单据审核状态（由P1-001管理）：草稿(0) → 已审核(2)
库存核心表状态：
- inv_serial_trace：在库 → 已出库 / 已锁定 / 已报废
- inv_batch_trace：有效期内 → 已过期（预警标记）

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. **库存引擎后端开发（P1-007-001）**必须最先完成：
   - 四个核心表（inv_stock/inv_stock_location/inv_batch_trace/inv_serial_trace）设计
   - 库存增减原子操作（行级锁+乐观锁）
   - 成本计算引擎（移动加权平均/FIFO/手工指定）
   - 批次/序列号管理服务
   - 可用量/占用量/在途量计算
   - 库存预警服务
2. **库存管理后端开发（P1-007-002）**依赖引擎完成：
   - 各业务单据CRUD（其他出入库/盘点/调拨/报损报溢/组装拆卸）
   - 库存查询/成本查询
3. **库存管理前端页面（P1-007-003）**依赖后端完成

### 5.2 可并行执行的任务
- 其他出库单与其他入库单可并行开发
- 报损单与报溢单可并行开发
- 组装单与拆卸单可并行开发
- 库存查询/库位查询/批次查询/序列号查询/成本查询可并行开发
- 盘点单与调拨单可并行开发
- 前端各页面可在对应后端API完成后并行开发
