# 全局规范-权限体系规范

> 本文档为独立规范文档，内容自包含，无需参照外部设计文档。
>
> **适用范围**：系统全部菜单、数据、字段、按钮、接口权限的设计与实现。

---

## 9.1 权限体系总览

系统权限采用**五层权限体系**：

| 权限层级 | 说明 | 配置入口 |
|---------|------|---------|
| 菜单权限 | 控制用户可见菜单与页面 | 菜单权限配置页 |
| 数据权限 | 控制用户可操作的数据范围 | 数据权限配置页 |
| 字段权限 | 控制用户可见/可编辑的字段 | 字段权限配置页 |
| 按钮权限 | 控制用户可操作的按钮 | 菜单权限配置页（按钮级） |
| 接口权限 | 控制后端API接口的访问权限，按钮权限在后端映射为接口权限，每个按钮对应一个或多个API接口，后端接口独立校验权限，前端按钮隐藏不替代后端鉴权 | 由按钮权限自动关联，后端拦截器统一校验 |

---

## 9.2 菜单权限

- 按角色配置菜单可见性
- 支持菜单级+按钮级权限控制
- 菜单权限与侧边栏导航联动，无权限菜单不展示
- **平台授权机制**：sys_menu和mobile_menu表均含`is_authorized`字段，由平台超级管理员控制哪些功能菜单授权给租户使用。菜单可见性判定逻辑：`is_authorized=true`（平台已授权） **且** 角色权限已分配 **且** `enable_flag=true` **且** `visible_flag=true`，四项同时满足才展示。未授权菜单在租户侧完全不可见，无法通过角色权限分配

---

## 9.3 数据权限

- 按角色配置数据可见范围
- 数据权限维度：本人、本部门、本部门及下级部门、全部、**自定义**（支持自定义选择部门/人员列表）
- 基于owner_dept_id和owner_id字段实现数据过滤
- 权限部门与组织架构部门分离

---

## 9.4 字段权限

- 按角色配置字段权限：可见/可编辑/隐藏
- 字段权限与字段配置规则联动
- 支持按页面状态（新增/编辑/详情）配置不同权限

## 9.5 权限配置页（P13配置页变体）

> **专业修正说明**：原需求文档在4.39权限配置功能点中使用"P14 | 权限配置页"作为页面类型，但依据第四章页面类型体系定义，P14 = AI对话页。权限配置页本质上是配置页（P13）的特定变体，采用左右分栏布局（左侧权限树+右侧配置矩阵）。因此，本设计将权限配置页统一归入P13配置页类型，交互规则遵循5.13配置类页面规范，并扩展以下权限配置专属交互。

采用左右分栏式布局：

- **左侧权限树**：角色/用户组树形导航
- **右侧配置矩阵**：选中角色后展示权限配置矩阵

## 9.6 RBAC数据模型

### 9.6.1 核心表结构

**sys_role 角色表**：

| 字段名 | 数据类型 | 非空 | 说明 |
|--------|---------|:----:|------|
| id | BIGINT | 是 | 雪花ID主键 |
| role_name | VARCHAR(64) | 是 | 角色名称 |
| role_code | VARCHAR(64) | 是 | 角色编码（唯一） |
| data_scope | SMALLINT | 是 | 数据权限范围：1=全部 2=本部门及下级 3=本部门 4=本人 5=自定义 |
| status | SMALLINT | 是 | 状态：0=停用 1=启用 |
| sort_order | INT | 是 | 排序号 |
| remark | VARCHAR(512) | 否 | 备注 |
| tenant_id | BIGINT | 是 | 租户ID |
| creator_id / create_time / updater_id / update_time / is_deleted | — | — | 公共字段 |

**sys_role_menu 角色菜单关联表**：

| 字段名 | 数据类型 | 说明 |
|--------|---------|------|
| role_id | BIGINT | 角色ID |
| menu_id | BIGINT | 菜单ID |
| PRIMARY KEY | (role_id, menu_id) | 联合主键 |

**sys_user_role 用户角色关联表**：

| 字段名 | 数据类型 | 说明 |
|--------|---------|------|
| user_id | BIGINT | 用户ID |
| role_id | BIGINT | 角色ID |
| PRIMARY KEY | (user_id, role_id) | 联合主键 |

**sys_user_dept 用户部门关联表**（数据权限自定义范围）：

| 字段名 | 数据类型 | 说明 |
|--------|---------|------|
| user_id | BIGINT | 用户ID |
| dept_id | BIGINT | 可见部门ID |
| PRIMARY KEY | (user_id, dept_id) | 联合主键 |

**sys_role_data_scope 角色数据权限自定义范围表**：

| 字段名 | 数据类型 | 说明 |
|--------|---------|------|
| role_id | BIGINT | 角色ID |
| dept_id | BIGINT | 可见部门ID |
| PRIMARY KEY | (role_id, dept_id) | 联合主键，data_scope=5时使用 |

**sys_role_field_permission 角色字段权限表**：

| 字段名 | 数据类型 | 说明 |
|--------|---------|------|
| role_id | BIGINT | 角色ID |
| page_code | VARCHAR(64) | 页面编码 |
| field_code | VARCHAR(64) | 字段编码 |
| permission_type | SMALLINT | 0=隐藏 1=只读 2=可编辑 |
| page_state | SMALLINT | 0=新增 1=编辑 2=详情 |
| PRIMARY KEY | (role_id, page_code, field_code, page_state) | 联合主键 |

## 9.7 权限判定流程

### 9.7.1 菜单权限判定

```
用户请求菜单列表
  → 查询 sys_user_role 获取用户角色列表
  → 查询 sys_role_menu 获取角色关联的菜单ID集合
  → 过滤：is_authorized=true AND enable_flag=true AND visible_flag=true
  → 返回用户可见菜单树
```

### 9.7.2 数据权限判定（SQL注入方式）

```java
// MyBatis-Plus DataPermissionInterceptor 自动注入WHERE条件
switch (dataScope) {
    case 1: // 全部数据 → 不追加条件
        break;
    case 2: // 本部门及下级
        sql += " AND dept_id IN (SELECT id FROM sys_dept WHERE id={deptId} OR path LIKE '{deptPath}%')";
        break;
    case 3: // 本部门
        sql += " AND dept_id = {deptId}";
        break;
    case 4: // 仅本人
        sql += " AND creator_id = {userId}";
        break;
    case 5: // 自定义部门
        sql += " AND dept_id IN (SELECT dept_id FROM sys_role_data_scope WHERE role_id IN ({roleIds}))";
        break;
}
```

### 9.7.3 字段权限判定

```
页面渲染前：
  → 根据当前用户角色+页面编码+页面状态(新增/编辑/详情)
  → 查询 sys_role_field_permission
  → 返回字段权限Map<fieldCode, permissionType>
  → 前端根据permissionType控制字段显示/隐藏/只读/可编辑
```

## 9.8 Sa-Token权限注解使用规范

| 注解 | 用途 | 示例 |
|------|------|------|
| @SaCheckPermission | 检查权限标识 | `@SaCheckPermission("sale:order:add")` |
| @SaCheckRole | 检查角色标识 | `@SaCheckRole("admin")` |
| @SaCheckSafe | 检查二级认证 | `@SaCheckSafe` （敏感操作需二次验证） |
| @SaCheckLogin | 检查已登录 | `@SaCheckLogin` |

### 9.8.1 使用规范

- **Controller层**必须使用`@SaCheckPermission`注解标注权限
- 权限标识与sys_menu表的permission字段一一对应
- 禁止仅依赖前端按钮隐藏，后端接口必须独立校验权限
- 超级管理员（role_code=super_admin）跳过权限检查

### 9.8.2 权限标识命名规范

```
格式：模块:功能:操作

示例：
  sale:order:add       销售订单新增
  sale:order:edit      销售订单编辑
  sale:order:delete    销售订单删除
  sale:order:audit     销售订单审核
  sale:order:unaudit   销售订单反审核
  sale:order:export    销售订单导出
  sale:order:print     销售订单打印
  purchase:order:add   采购订单新增
  inventory:stock:in   库存入库
  finance:voucher:add  凭证新增
```

### 9.8.3 Controller使用示例

```java
@RestController
@RequestMapping("/api/sale/order")
public class SaleOrderController {

    @PostMapping
    @SaCheckPermission("sale:order:add")
    public R<Void> add(@RequestBody @Validated SaleOrderDTO dto) { ... }

    @PutMapping("/{id}")
    @SaCheckPermission("sale:order:edit")
    public R<Void> update(@PathVariable Long id, @RequestBody SaleOrderDTO dto) { ... }

    @DeleteMapping("/{id}")
    @SaCheckPermission("sale:order:delete")
    public R<Void> delete(@PathVariable Long id) { ... }

    @PostMapping("/{id}/audit")
    @SaCheckPermission("sale:order:audit")
    @SaCheckSafe  // 审核操作需二级认证
    public R<Void> audit(@PathVariable Long id, @RequestBody AuditDTO dto) { ... }

    @GetMapping("/export")
    @SaCheckPermission("sale:order:export")
    public void export(HttpServletResponse response, SaleOrderQueryDTO query) { ... }

    // 多权限关系：拥有其中一个即可
    @GetMapping("/detail/{id}")
    @SaCheckPermission(value = {"sale:order:view", "sale:order:edit"}, mode = SaMode.OR)
    public R<SaleOrderVO> detail(@PathVariable Long id) { ... }
}
```

### 9.8.4 Sa-Token权限数据加载实现

```java
@Component
public class StpInterfaceImpl implements StpInterface {

    @Autowired
    private SysMenuService sysMenuService;
    @Autowired
    private SysRoleService sysRoleService;

    @Override
    public List<String> getPermissionList(Object loginId, String loginType) {
        Long userId = Long.parseLong(loginId.toString());
        // 超级管理员返回全部权限
        if (sysRoleService.isSuperAdmin(userId)) {
            return List.of("*");
        }
        return sysMenuService.getUserPermissionCodes(userId);
    }

    @Override
    public List<String> getRoleList(Object loginId, String loginType) {
        Long userId = Long.parseLong(loginId.toString());
        return sysRoleService.getUserRoleCodes(userId);
    }
}
```

## 9.9 权限分层模型

| 角色类型 | role_code | 说明 | 权限范围 |
|---------|-----------|------|---------|
| 超级管理员 | `super_admin` | 平台级，管理所有租户 | 全部菜单+全部数据+全部字段+跨租户 |
| 平台管理员 | `platform_admin` | 平台运营管理人员 | 平台侧全部菜单+全部数据（不含租户业务数据） |
| 租户管理员 | `tenant_admin` | 租户级，管理本租户 | 本租户已授权菜单+全部数据+全部字段 |
| 部门管理员 | `dept_admin` | 管理本部门及下级 | 已分配菜单+本部门及下级数据+自定义字段权限 |
| 普通角色 | 自定义 | 按配置授权 | 按角色配置的菜单+数据+字段权限 |
| 默认角色 | `default` | 新用户自动分配 | 仅基础查看权限 |

**分层约束规则**：
1. 超级管理员可管理平台管理员和租户管理员，租户管理员无法看到平台管理员
2. 租户管理员创建角色时，菜单选择范围受限于平台已授权菜单（`is_authorized=true`）
3. 租户管理员无法分配超出自身权限范围的权限给其他角色
4. 每个租户创建时自动初始化 `tenant_admin` 角色，并赋予平台已授权全部菜单权限
5. `default` 角色由系统预置，仅包含个人中心、修改密码等基础功能

## 9.10 权限缓存策略

| 缓存项 | Key模式 | TTL | 清除时机 |
|--------|---------|:---:|---------|
| 用户菜单 | `erp:sys:menu:{userId}` | 2h | 角色/菜单变更时清除相关用户 |
| 用户权限集合 | `erp:sys:permission:{userId}` | 2h | 同上 |
| 角色列表 | `erp:sys:role:{tenantId}` | 12h | 角色增删改时清除 |

**权限变更实时生效机制**：修改角色权限后，通过Redis Pub/Sub通知所有后端实例清除相关用户的权限缓存，下次请求时重新加载。

### 9.10.1 多级缓存架构

```
请求 → 权限拦截器
         │
         ├─ 命中一级缓存（JVM本地Caffeine，容量1000，过期5min）→ 直接放行
         │
         ├─ 未命中一级 → 查二级缓存（Redis，过期2h）→ 命中则回填一级缓存
         │
         └─ 未命中二级 → 查数据库 → 回填一级+二级缓存
```

### 9.10.2 权限变更通知实现

```java
// 权限变更时清除相关缓存
public void onPermissionChanged(Long userId, Long roleId) {
    // 1. 清除Redis缓存
    redisTemplate.delete("erp:sys:menu:" + userId);
    redisTemplate.delete("erp:sys:permission:" + userId);
    redisTemplate.delete("erp:sys:role:" + tenantId);

    // 2. 发布Redis消息通知（多实例同步清除本地JVM缓存）
    redisTemplate.convertAndSend("erp:auth:permission:change",
        JSON.toJSONString(Map.of("userId", userId, "roleId", roleId, "tenantId", tenantId)));
}

// Redis消息监听器（每个实例监听）
@Component
public class PermissionChangeListener implements MessageListener {
    @Override
    public void onMessage(Message message, byte[] pattern) {
        PermissionChangeDTO dto = JSON.parseObject(message.getBody(), PermissionChangeDTO.class);
        // 清除本地JVM缓存
        localCache.invalidate("user:menus:" + dto.getUserId());
        localCache.invalidate("user:permissions:" + dto.getUserId());
    }
}
```

### 9.10.3 JWT兜底机制

JWT Token中嵌入权限版本号字段 `permissionVersion`：
- 用户登录时写入当前权限版本号
- 每次权限变更时，该用户/角色的 `permissionVersion` +1
- 每次请求时比对Token中的版本号与Redis中最新版本号
- 版本号不一致 → 强制刷新权限缓存（无需重新登录）
