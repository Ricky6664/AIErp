## 1. 模块架构约束

### 1.1 模块定位
借用管理模块是ERP系统中的业务辅助模块，负责完成借用申请→出库→归还及借入→归还全链路管理。模块包含借用申请单、借用出库单、借用归还单、借入单、借入归还单，实现对外借出和对内借入的双向物品流转管理。

### 1.2 依赖关系
- 前置依赖：
  - P0-007（商品）：提供商品/物品基础数据，借用关联具体物品信息
  - P0-010（仓库）：提供仓库基础数据，借用出库/归还关联具体仓库
- 后续依赖：无（本模块为终端消费模块，不被其他模块直接依赖）

### 1.3 技术约束
- 技术栈约束：后端基于Spring Boot + MyBatis-Plus，前端基于Vue3 + Element Plus；库存操作使用乐观锁防止并发冲突
- 性能约束：借用出库/归还操作含库存更新响应时间不超过3秒
- 安全约束：借用出库前必须先有审核通过的借用申请单；所有库存变更操作需完整审计日志

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| borrow_application | 借用申请单主表 | id, application_no, applicant_id, borrower, purpose, expected_return_date, audit_status |
| borrow_application_detail | 借用申请单明细表 | id, application_id, product_id, qty, remark |
| borrow_apply | 借用出库单主表 | id, outbound_no, application_id, warehouse_id, outbound_date, status |
| borrow_apply_detail | 借用出库单明细表 | id, outbound_id, product_id, qty |
| borrow_return | 借用归还单主表 | id, return_no, outbound_id, return_date, warehouse_id, status |
| borrow_in | 借入单主表 | id, inbound_no, supplier_id, warehouse_id, expected_return_date, status |
| borrow_in_detail | 借入单明细表 | id, inbound_id, product_id, qty, remark |
| borrow_in_return | 借入归还单主表 | id, return_no, inbound_id, return_date, status |

### 2.2 表关系图
- borrow_application（主表）→ borrow_application_detail（从表）：一对多关系，通过 application_id 关联
- borrow_application → borrow_apply：一对一/多关系，通过 application_id 关联（出库依赖申请）
- borrow_apply（主表）→ borrow_apply_detail（从表）：一对多关系，通过 outbound_id 关联
- borrow_apply → borrow_return：一对一/多关系，通过 outbound_id 关联（归还依赖出库）
- borrow_in（主表）→ borrow_in_detail（从表）：一对多关系，通过 inbound_id 关联
- borrow_in → borrow_in_return：一对一/多关系，通过 inbound_id 关联（借入归还依赖借入）

### 2.3 数据流转
1. 借用申请流程：创建借用申请单 → 录入借用明细 → 提交审核 → 审核通过后可执行出库
2. 借用出库流程：关联借用申请单 → 创建出库单 → 审核通过后扣减库存
3. 借用归还流程：关联借用出库单 → 创建归还单 → 审核通过后增加库存
4. 借入流程：创建借入单 → 录入借入明细 → 审核通过后增加库存
5. 借入归还流程：关联借入单 → 创建归还单 → 审核通过后扣减库存并完成供应商归还确认

## 3. 业务流程

### 3.1 核心业务流程
1. **借用申请**：填写借用人、借用目的、预计归还日期，提交审核
2. **借用出库**：审核通过后从仓库出库，记录出库物品明细
3. **借用归还**：借用人归还物品，验收后入库
4. **借入管理**：向供应商借入物品，入库登记
5. **借入归还**：归还供应商物品，出库登记

### 3.2 业务规则
- 借用出库单审核前必须先有借用申请单且审核通过
- 借用归还单审核后自动增加库存
- 借入归还单审核后自动扣减库存并完成供应商归还确认
- 借用归还数量不得超过出库的未归还数量
- 借入归还数量不得超过借入的未归还数量
- 系统自动提醒即将超过预计归还日期的借用单

### 3.3 状态流转
借用申请单状态流转：
- 草稿(0) → 待审核(1) → 已通过(3) / 已驳回(4)

借用出库单状态流转：
- 草稿(0) → 待审核(1) → 已出库(3) / 已驳回(4) → 部分归还(5) → 已归还(6)

借入单状态流转：
- 草稿(0) → 待审核(1) → 已入库(3) / 已驳回(4) → 部分归还(5) → 已归还(6)

- P0-010 仓库接口：获取仓库列表、执行库存扣减/增加操作

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. 借用申请单CRUD接口 → 借用出库单CRUD接口（出库依赖申请单）
2. 借用出库单CRUD接口 → 借用归还单CRUD接口（归还依赖出库单）
3. 借入单CRUD接口 → 借入归还单CRUD接口（归还依赖借入单）
4. 后端接口全部完成 → 前端页面开发

### 5.2 可并行执行的任务
- 借用申请单CRUD接口与借入单CRUD接口可并行开发（两者相互独立）
- 前端页面中，借用申请列表页、借用出库列表页、借用归还列表页、借入列表页、借入归还列表页可并行开发
- 借用管理工作台页可与其他前端页面并行开发
