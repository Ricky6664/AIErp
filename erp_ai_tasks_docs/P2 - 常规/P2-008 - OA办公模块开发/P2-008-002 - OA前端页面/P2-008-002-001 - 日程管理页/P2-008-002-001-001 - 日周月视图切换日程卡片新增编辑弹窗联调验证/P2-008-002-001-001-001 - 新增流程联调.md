### 5.1 表单字段定义

| 字段名 | 组件类型 | 是否必填 | 校验规则 | 说明 |
|--------|---------|---------|---------|------|
| title | el-input | 是 | required, max 100字符 | 日程标题 |
| scheduleDate | el-date-picker | 是 | required, 不早于今天 | 日程日期, value-format="YYYY-MM-DD" |
| startTime | el-time-picker | 是 | required | 开始时间, format="HH:mm" |
| endTime | el-time-picker | 是 | required, 必须>startTime | 结束时间, format="HH:mm" |
| location | el-input | 否 | max 200字符 | 日程地点 |
| remindFlag | el-select | 否 | — | 提醒方式: 不提醒/提前15分钟/提前30分钟/提前1小时 |
| color | el-color-picker | 否 | — | 日程卡片显示颜色, 默认#409EFF |

### 5.2 新增流程

1. 用户点击FullCalendar空白区域或[新增日程]按钮→打开ScheduleFormDialog(mode='create')
2. 表单初始化：scheduleDate默认选中日期, startTime默认当前时间后30分钟, remindFlag默认"提前15分钟"
3. 填写表单→实时校验(startTime变化时自动校验endTime)
4. [保存]→formRef.validate()→调用scheduleApi.create(form)
5. 成功→ElMessage.success('日程创建成功')+关闭弹窗+emit('refresh')→FullCalendar refetchEvents()
6. 失败→定位第一个错误字段scrollIntoView

### 5.3 关键校验规则

```typescript
const validateEndTime = (rule: any, value: any, callback: any) => {
  if (form.startTime && form.endTime && form.endTime <= form.startTime) {
    callback(new Error('结束时间必须晚于开始时间'))
  } else {
    callback()
  }
}
```

### 5.4 错误处理

- 字段校验失败：滚动到第一个错误字段，红色高亮
- 400：后端返回字段级错误信息，映射到对应el-form-item的error属性
- 500：ElMessage.error('系统异常，请稍后重试')

## 八、易错警示

> ⚠️ 代码提交前确保无敏感信息硬编码（密码/密钥/token）

> ⚠️ 多租户隔离(tenant_id)必须正确——所有SQL查询需自动注入tenant_id

> ⚠️ 逻辑删除字段(is_deleted)正确处理——查询追加is_deleted=false，删除使用UPDATE

> ⚠️ el-time-picker的value-format需要统一为"HH:mm"，避免前后端时间格式不一致

> ⚠️ FullCalendar日期点击传入的date需要正确格式化为YYYY-MM-DD

> ⚠️ 提醒选项remindFlag默认值"提前15分钟"需要与后端枚举值完全匹配

> ⚠️ 按钮loading防重复提交

> ⚠️ [OA模块] 日程创建不允许选择过去的日期，需前端+后端双重校验
