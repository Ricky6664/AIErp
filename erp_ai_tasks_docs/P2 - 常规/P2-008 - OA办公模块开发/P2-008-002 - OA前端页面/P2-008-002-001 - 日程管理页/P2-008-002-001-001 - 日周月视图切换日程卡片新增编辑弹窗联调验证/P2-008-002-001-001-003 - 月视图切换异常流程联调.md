### 5.1 通用异常场景

| 场景 | 处理方式 | 提示信息 |
|------|---------|---------|
| 网络断开 | axios拦截器捕获，ElMessage.error | "网络连接异常，请检查网络" |
| 接口超时(>30s) | axios timeout配置，取消请求 | "请求超时，请重试" |
| 服务端500 | 拦截器统一处理，展示traceId | "系统异常(traceId:xxx)，请联系管理员" |
| 乐观锁冲突(409) | 提示用户刷新后重试 | "该日程已被其他用户修改，请刷新后重试" |
| 未保存离开 | beforeRouteLeave+ElMessageBox.confirm | "有未保存的修改，确定离开吗？" |
| 重复提交 | submitButton loading状态 | 按钮disabled直到请求返回 |

### 5.2 日程特有异常场景

| 场景 | 处理方式 | 提示信息 |
|------|---------|---------|
| 选择过去日期创建日程 | el-date-picker禁用过去日期+提交前校验 | "不能创建过去日期的日程" |
| FullCalendar视图切换加载失败 | 显示空状态+重试按钮 | "日程数据加载失败，点击重试" |
| 日程数据量过大(>500条/月) | 分页加载+loading骨架屏 | 月度日程超过500条时提示"当月日程较多，建议缩小查看范围" |
| 月/周/日视图切换时请求取消 | AbortController取消上一次请求 | 避免旧请求覆盖新数据 |

### 5.3 实现要点

```typescript
// 脏状态追踪
const isDirty = ref(false)
watch(() => form, () => { isDirty.value = true }, { deep: true })

// 未保存离开拦截
onBeforeRouteLeave((to, from, next) => {
  if (isDirty.value) {
    ElMessageBox.confirm('有未保存的修改，确定离开吗？', '提示', {
      confirmButtonText: '确定离开',
      cancelButtonText: '继续编辑'
    }).then(() => next()).catch(() => next(false))
  } else {
    next()
  }
})

// 视图切换取消旧请求
const abortController = ref<AbortController | null>(null)
const fetchScheduleList = async (dateRange: DateRange) => {
  abortController.value?.abort()
  abortController.value = new AbortController()
  const data = await scheduleApi.list(dateRange, { signal: abortController.value.signal })
}
```

## 八、易错警示

> ⚠️ 代码提交前确保无敏感信息硬编码（密码/密钥/token）

> ⚠️ 多租户隔离(tenant_id)必须正确——所有SQL查询需自动注入tenant_id

> ⚠️ 逻辑删除字段(is_deleted)正确处理——查询追加is_deleted=false，删除使用UPDATE

> ⚠️ axios拦截器统一处理异常，避免每个组件重复写try-catch

> ⚠️ FullCalendar视图切换(日/周/月)时务必取消前一次请求，避免竞态条件

> ⚠️ dirty状态追踪需要在保存成功后重置为false

> ⚠️ [OA模块] 过去日期的日程仅允许查看，不允许新增和编辑
