## 五、详细开发规格

> **本任务模块上下文**
> - 数据表：oa_vehicle（用车表）
> - 专属字段：purpose, applicant_id, car_id, start_time, end_time, destination, passenger_count, status
> - 公共字段：id, created_by, created_at, updated_by, updated_at, is_deleted, tenant_id, version
> - API基础路径：/api/oa/vehicle

### 5.1 create 方法
- 接收 `OaVehicleCreateDTO`，字段：purpose(NotBlank), applicantId(NotNull), startTime(NotNull), endTime(NotNull), destination(NotBlank), passengerCount(NotNull,Min=1)
- 校验 endTime > startTime
- status 默认 0(pending)，carId 为 null（待派车）
- 创建后触发 P1-002 审批流程（调用 ApprovalService.submit）

### 5.2 update 方法
- 仅 status=0(pending) 允许修改
- 乐观锁：WHERE id=? AND version=?

### 5.3 delete 方法
- 仅 status=0(pending) 允许删除
- 软删除 + 撤销审批流程

### 5.4 getPage 方法
- 查询字段：purpose(模糊), applicantId, status, startTime(范围), destination(模糊)
- 关联查询：申请人姓名、分配车辆车牌号
- 默认按 created_at DESC 排序

### 5.5 getDetail 方法
- 查询完整 Entity -> VO
- 关联查询：申请人姓名、审批状态、分配车辆信息（车牌号/车型）
- 包含审批记录列表

### 5.6 approve/dispatch 方法（专属）
- approve：校验 status==0 -> SET status=1(approved)；由 P1-002 审批回调触发
- dispatch：校验 status==1 -> 校验 carId 对应车辆在 startTime~endTime 无冲突（查 oa_vehicle WHERE car_id=? AND status IN (1,2) AND 时间重叠）-> SET status=2(dispatched), car_id=?
- 车辆冲突时抛 BusinessException(409, "该车辆在此时段已被派出")

### 5.7 错误码规范
- 400: 参数错误（@Valid 校验失败）
- 404: 记录不存在
- 409: 资源冲突（如时间冲突、唯一性冲突）
- 422: 业务规则不允许（如状态不允许操作、余额不足）
- 500: 服务端异常

## 八、易错警示

> ⚠️ 代码提交前确保无敏感信息硬编码（密码/密钥/token）

> ⚠️ 多租户隔离(tenant_id)必须正确——所有SQL查询需自动注入tenant_id

> ⚠️ 逻辑删除字段(is_deleted)正确处理——查询追加is_deleted=false，删除使用UPDATE

> ⚠️ @TableField 注解勿遗漏，特别是 created_at/updated_at 自动填充

> ⚠️ 事务边界准确避免大事务，仅在写操作加 @Transactional

> ⚠️ 异常统一使用 BusinessException，禁止抛出 RuntimeException

> ⚠️ [用车] 审批流程集成 P1-002 审批模块，approve 由审批回调触发

> ⚠️ [用车] dispatch 时必须校验车辆时段不冲突
