## 1. 模块架构约束

### 1.1 模块定位
OA办公模块是ERP系统中的协同办公模块，负责完成日程、公告、会议、用车、请假、新闻等OA办公功能。该模块为组织内部提供日常办公协同能力，提升企业内部管理效率和信息传递效率。

### 1.2 依赖关系
- 前置依赖：
  - P0-004（用户/权限）：提供用户信息、部门信息、权限控制基础
  - P1-002（审批流程）：提供请假、用车等需要审批的流程引擎
- 后续依赖：无（本模块为终端消费模块，不被其他模块直接依赖）

### 1.3 技术约束
- 技术栈约束：后端基于Spring Boot + MyBatis-Plus，前端基于Vue3 + Element Plus；日程视图使用FullCalendar组件
- 性能约束：日程/会议/公告列表查询响应时间不超过2秒；会议室冲突检测响应时间不超过1秒
- 安全约束：公告发布需@RequiresPermissions("oa:announcement:publish")权限；新闻发布需编辑审核流程

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| oa_schedule | 日程表 | id, user_id, title, start_time, end_time, reminder_type, repeat_rule, status |
| oa_announcement | 公告表 | id, title, content, publisher_id, publish_date, expire_date, status, scope |
| oa_meeting | 会议表 | id, meeting_no, title, meeting_room_id, organizer_id, start_time, end_time, attendees, status |
| oa_meeting_room | 会议室表 | id, room_name, location, capacity, equipment, status |
| oa_vehicle | 用车申请表 | id, vehicle_no, applicant_id, purpose, destination, start_time, end_time, audit_status |
| oa_leave | 请假申请表 | id, leave_no, applicant_id, leave_type, start_date, end_date, days, reason, audit_status |
| oa_news | 新闻表 | id, title, content, author_id, category, publish_date, status |

### 2.2 表关系图
- oa_schedule：独立表，通过 user_id 关联用户
- oa_announcement：独立表，通过 publisher_id 关联发布人
- oa_meeting_room → oa_meeting：一对多关系，通过 meeting_room_id 关联（一个会议室可安排多场会议）
- oa_meeting：通过 organizer_id 关联组织者，通过 attendees (JSON) 关联参会人
- oa_vehicle：独立表，通过 applicant_id 关联申请人
- oa_leave：独立表，通过 applicant_id 关联申请人
- oa_news：独立表，通过 author_id 关联作者

### 2.3 数据流转
1. 日程管理流程：创建日程 → 设置提醒规则 → 到时提醒 → 完成/取消
2. 公告管理流程：创建公告 → 设置发布范围 → 发布 → 到期自动下架
3. 会议管理流程：预约会议室（校验冲突）→ 创建会议 → 通知参会人 → 召开 → 完成
4. 用车管理流程：提交用车申请 → 审批通过 → 派车 → 用车完成
5. 请假管理流程：提交请假申请（校验假期余额）→ 审批通过 → 请假执行 → 完成
6. 新闻管理流程：创建新闻 → 编辑审核 → 发布

## 3. 业务流程

### 3.1 核心业务流程
1. **日程管理**：个人或团队日程安排，支持日/周/月视图切换
2. **公告管理**：企业内部公告的发布、查看、下架管理
3. **会议管理**：会议室预约、会议安排、参会人通知
4. **用车管理**：企业公务用车的申请、审批、派车管理
5. **请假管理**：员工请假申请、审批、假期余额管理
6. **新闻管理**：企业新闻的编辑、审核、发布管理

### 3.2 业务规则
- 日程支持日/周/月视图切换与重复规则配置（每日/每周/每月/自定义）
- 会议需校验会议室时间冲突并通知参会人
- 请假管理需校验假期余额并关联审批流程
- 请假天数根据起止日期自动计算（排除周末和法定假日）
- 公告发布后可设置有效期，到期自动下架

### 3.3 状态流转
会议状态流转：
- 待召开(0) → 进行中(1) → 已完成(2) / 已取消(3)

请假申请状态流转：
- 草稿(0) → 待审核(1) → 已通过(3) / 已驳回(4) → 已销假(5)

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. 会议室CRUD接口 → 会议CRUD接口（会议依赖会议室数据）
2. 后端接口全部完成 → 前端页面开发

### 5.2 可并行执行的任务
- 日程CRUD接口、公告CRUD接口、会议室CRUD接口、用车CRUD接口、请假管理CRUD接口、新闻管理CRUD接口可并行开发（大部分相互独立）
- 前端页面中，日程管理页、公告管理页、会议管理页、用车管理页、请假申请页、新闻管理页可并行开发
- OA办公工作台页可与其他前端页面并行开发
