## 五、详细开发规格

> **📦 本任务模块上下文**（来源：P2-007模块开发指南）
> - 本模块涉及数据表：参见模块开发指南
> - 本模块涉及API：/api/after-sale/order, /api/after-sale/remote-service, /api/after-sale/onsite-service, /api/after-sale/return, /api/after-sale/exchange
> - 本模块业务规则：本模块无模块级专属约束，遵循全局规范。售后退货单审核后库存自动增加且退款金额联动应收；售后换货单审核后旧品入库与新品出库同步执行并处理差价；维修领料单关联维修单执行领料出库与库存扣减。
>
> 💡 开发本任务时，请结合上述模块上下文理解业务场景和数据关系。

### 5.1 核心功能
1. 继承IServiceX<Entity>，声明CRUD+业务方法
2. ServiceImpl实现核心业务逻辑+数据校验+联动计算
3. @Transactional管理事务边界，只读方法加readOnly=true
4. 业务异常统一抛出BusinessException(ErrorCode, message)
5. 编码生成调用编码引擎，审核流转调用审核引擎

### 5.2 数据交互
1. Controller接收DTO，调用Service处理业务逻辑
2. Service通过Mapper操作数据库，使用LambdaQueryWrapper构建查询
3. 跨模块调用通过其他模块的Service接口，禁止直接Mapper操作他模块表
4. 编码生成调用CodeGenerateService，审核流转调用ApprovalFlowService
5. 事务内多表操作使用同一@Transactional，失败整体回滚

### 5.3 关键逻辑
1. @Transactional事务边界准确，避免大事务
2. 业务规则校验前置：状态机、权限、数据完整性
3. 编码生成调用编码引擎，保证唯一性和连续性
4. 审核状态流转调用审核引擎，触发回调更新业务数据
5. 异常统一BusinessException，GlobalExceptionHandler捕获

### 5.4 验证
1. Service接口+Impl编译通过
2. CRUD功能完整，查询/新增/修改/删除可用
3. @Transactional事务一致性验证
4. 业务异常正确抛出，前端收到明确错误码
5. 编码生成/审核流转等引擎调用正确
