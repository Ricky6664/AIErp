## 1. 模块架构约束

### 1.1 模块定位
售后管理模块是ERP系统中的业务核心模块之一，负责完成售后全链路管理。模块包含售后单、远程/上门服务、退货/换货/维修、送修/接修及客户回访等功能，覆盖从售后受理到服务完成再到客户回访的完整售后服务链。

### 1.2 依赖关系
- 前置依赖：
  - P0-007（商品）：提供商品基础数据，售后关联具体商品信息
  - P0-008（客户）：提供客户基础数据，售后关联具体客户
  - P0-010（仓库）：提供仓库基础数据，退货入库/换货出库关联仓库
  - P1-001（审核引擎）：提供退货/换货/维修单的审批流程能力
- 后续依赖：无（本模块为终端消费模块，不被其他模块直接依赖）

### 1.3 技术约束
- 技术栈约束：后端基于Spring Boot + MyBatis-Plus，前端基于Vue3 + Element Plus；保修规则引擎基于策略模式实现
- 性能约束：售后单列表查询响应时间不超过2秒；维修领料出库操作响应时间不超过3秒
- 安全约束：退货退款金额不得超过原订单金额；换货操作需同步处理旧品入库与新品出库的事务一致性

### 2.3 数据流转
1. 售后受理流程：创建售后单 → 选择服务类型 → 分配处理人
2. 远程服务流程：创建远程服务单 → 远程处理 → 记录解决方案 → 完成服务
3. 上门服务流程：创建上门服务单 → 指派工程师 → 上门服务 → 完成服务
4. 退货流程：创建退货单 → 审核通过 → 退货入库 → 退款处理
5. 换货流程：创建换货单 → 审核通过 → 旧品入库+新品出库 → 处理差价
6. 维修流程：创建维修单 → 领料出库 → 维修完成 → 返回客户
7. 接修流程：接收客户送修品 → 接修登记 → 维修完成 → 返回客户
8. 送修流程：送修至外部厂商 → 送修登记 → 维修完成返回 → 送修返回
9. 回访流程：服务完成后创建回访单 → 执行回访 → 记录满意度

## 3. 业务流程

### 3.1 核心业务流程
1. **售后单管理**：受理客户售后请求，分类派工
2. **远程/上门服务**：提供远程技术支持或上门现场服务
3. **退货/换货/维修**：处理客户退货、换货和维修需求
4. **送修/接修**：处理外发维修和客户送修业务
5. **客户回访**：售后完成后进行客户满意度回访
6. **保修规则配置**：配置产品保修策略

### 3.2 业务规则
- 售后退货单审核后库存自动增加且退款金额联动应收
- 售后换货单审核后旧品入库与新品出库同步执行并处理差价
- 维修领料单关联维修单执行领料出库与库存扣减
- 保修期内的维修免费，保修期外收取维修费用
- 客户回访需在售后服务完成后7天内执行

### 3.3 状态流转
售后单状态流转：
- 待处理(0) → 处理中(1) → 已完成(2) → 已回访(3) / 已关闭(4)

维修单状态流转：
- 待维修(0) → 维修中(1) → 已完成(2) / 已取消(3)

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. 售后单CRUD接口 → 远程服务单/上门服务单/退货单/换货单/维修单CRUD接口（各服务单依赖售后单）
2. 接修单CRUD接口 → 接修返回单CRUD接口（返回依赖接修单）
3. 送修单CRUD接口 → 送修返回单CRUD接口（返回依赖送修单）
4. 售后维修单CRUD接口 → 维修领料单CRUD接口（领料依赖维修单）
5. 后端接口全部完成 → 前端页面开发

### 5.2 可并行执行的任务
- 远程服务单、上门服务单、退货单、换货单、维修单CRUD接口可并行开发（均仅依赖售后单）
- 接修单CRUD接口与送修单CRUD接口可并行开发（两者相互独立）
- 客户回访单CRUD接口与保修规则配置CRUD接口可并行开发
- 前端页面中，所有列表页可并行开发
