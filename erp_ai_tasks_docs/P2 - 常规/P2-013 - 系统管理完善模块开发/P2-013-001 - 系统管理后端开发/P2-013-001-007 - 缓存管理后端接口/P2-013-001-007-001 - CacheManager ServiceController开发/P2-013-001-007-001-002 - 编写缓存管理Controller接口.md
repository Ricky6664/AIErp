## 五、详细开发规格

> **📦 本任务模块上下文**（来源：P2-013模块开发指南）
> - 本模块涉及数据表：sys_param(系统参数表), sys_dict(字典表), sys_dict_item(字典项表), sys_role(角色表), sys_role_permission(角色权限表)
> - 本模块涉及API：/api/sys/param/*, /api/sys/dict/*, /api/sys/role/*, /api/sys/menu/*, /api/sys/dept/*
> - 本模块业务规则：系统参数优先级链：租户级参数>全局默认参数，参数变更即时生效但仅对新操作生效；字典数据缓存至Redis（TTL 24h），字典项变更时自动清除缓存；角色权限变更后需通知在线用户重新加载权限；菜单数据按角色缓存，权限变更后清除对应用户菜单缓存。
>
> 💡 开发本任务时，请结合上述模块上下文理解业务场景和数据关系。

### 5.2 Controller代码结构

```java
@RestController
@RequestMapping("/api/sys/param")
@Tag(name = "系统管理")
public class SysController {
    @PostMapping("/create")
    @Operation(summary = "新增")
    @SaCheckPermission("sys:add")
    public Result<Long> create(@RequestBody @Valid SysCreateDTO dto) {
        return R.ok(sysService.create(dto));
    }
}
```

## 八、易错警示

> ⚠️ 代码提交前确保无敏感信息硬编码（密码/密钥/token）

> ⚠️ 多租户隔离(tenant_id)必须正确——所有SQL查询需自动注入tenant_id条件

> ⚠️ 逻辑删除字段(is_deleted)正确处理——查询追加is_deleted=false，删除使用UPDATE而非DELETE

> ⚠️ 接口路径必须符合 `/api/{module}/{resource}` 规范，复数形式

> ⚠️ @RequestBody必须配合@Valid使用，否则DTO校验不生效

> ⚠️ GET请求复杂查询参数使用@ModelAttribute而非@RequestParam

> ⚠️ [系统管理模块] 系统参数优先级链：租户级参数 > 全局默认参数，查询时先查租户级再回退全局

> ⚠️ [系统管理模块] 参数变更后仅对新操作生效，不影响已有业务单据，需在参数值中记录生效时间

> ⚠️ [系统管理模块] 字典数据缓存至Redis（TTL 24h），字典项增删改时必须清除对应dict_type的缓存
