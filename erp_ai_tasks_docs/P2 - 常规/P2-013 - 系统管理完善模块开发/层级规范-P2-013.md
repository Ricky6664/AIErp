## 1. 模块架构约束

### 1.1 模块定位
系统管理完善模块是ERP系统中的系统管理增强模块，负责完善系统管理功能。模块包含系统管理工作台、编码规则管理、数据视图管理、单据配置、操作日志查询、登录日志、缓存管理及系统公告等功能。注意：数据字典管理与系统参数管理已在V10.0迁移至P0-005-016/017，本阶段仅提供增强功能。

### 1.2 依赖关系
- 前置依赖：
  - P0-004（认证权限基础）：提供用户认证、权限控制、角色管理基础
- 后续依赖：无（本模块为终端消费模块，但编码规则管理能力被各业务模块的单据编号生成调用）

### 1.3 技术约束
- 技术栈约束：后端基于Spring Boot + MyBatis-Plus，前端基于Vue3 + Element Plus；缓存管理基于Redis SCAN命令实现
- 性能约束：操作日志查询（10万条以内）响应时间不超过3秒；编码规则生成编号响应时间不超过100ms
- 安全约束：缓存管理需@RequiresPermissions("system:cache:manage")权限控制；操作日志不可修改/删除；系统公告发布需管理员权限

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| sys_code_rule | 编码规则表（完整定义参见层级规范-P0-001，此处仅列出本模块扩展字段） | rule_code, target_table, target_field, reset_cycle, is_enabled |
| sys_code_rule_segment | 编码规则段配置表（完整定义参见层级规范-P0-001，此处仅列出本模块扩展字段） | rule_id, segment_type, segment_order, fixed_value, date_format, seq_digits, step |
| sys_data_view | 数据视图表（完整定义参见层级规范-P0-001，此处仅列出本模块扩展字段） | view_code, main_table, query_sql_template |
| sys_data_view_field | 数据视图字段表 | id, view_id, field_name, field_label, field_type, is_visible, sort_order |
| sys_operation_log | 操作日志表 | id, user_id, operation_type, module, description, request_url, request_params, ip, create_time |
| sys_login_log | 登录日志表 | id, user_id, login_type, login_ip, login_device, login_browser, login_time, status |
| sys_notice | 系统公告表 | id, title, content, notice_type, publisher_id, publish_date, expire_date, scope, status |
| sys_doc_config | 单据配置表 | id, doc_type, doc_name, config_json, status |

### 2.2 表关系图
- sys_code_rule（主表）→ sys_code_rule_segment（从表）：一对多关系，通过 rule_id 关联
- sys_data_view（主表）→ sys_data_view_field（从表）：一对多关系，通过 view_id 关联
- sys_operation_log：独立表，通过 user_id 关联操作用户
- sys_login_log：独立表，通过 user_id 关联登录用户
- sys_notice：独立表，通过 publisher_id 关联发布人
- sys_doc_config：独立配置表，按单据类型配置

### 2.3 数据流转
1. 编码规则流程：创建编码规则 → 配置段（固定值/日期/流水号等段类型）→ 启用 → 业务模块调用生成编号
2. 数据视图流程：创建数据视图 → 配置字段 → 启用 → 前端按视图渲染表格
3. 操作日志流程：用户操作 → AOP拦截器自动记录 → 日志持久化 → 管理员查询
4. 系统公告流程：创建公告 → 设置发布范围和时间 → 定时发布（XXL-JOB）→ 到期自动下架

## 3. 业务流程

### 3.1 核心业务流程
1. **系统管理工作台**：汇总系统运行状态、在线用户数、今日操作统计等
2. **编码规则管理**：配置各业务单据的编号生成规则
3. **数据视图管理**：配置前端表格的数据视图（列定义/排序/过滤）
4. **操作日志查询**：查询用户操作审计日志
5. **登录日志查询**：查询用户登录记录
6. **缓存管理**：查看和管理Redis缓存（按前缀搜索/清除/刷新）
7. **系统公告管理**：发布/管理/下架系统公告
8. **单据配置**：配置各业务单据的显示/必填/默认值等属性

### 3.2 业务规则
- 编码规则支持多段组合：前缀+日期+流水号+自定义段
- 编码规则流水号支持自动递增，跨日/月/年自动重置
- 缓存管理使用Redis SCAN按前缀搜索，避免KEYS命令阻塞
- 系统公告支持定时发布（XXL-JOB调度）与发布范围控制（全员/指定部门/指定角色）
- 操作日志记录粒度：增/删/改操作，记录请求参数和响应结果
- 登录日志记录登录IP/设备/浏览器/时间/登录结果

### 3.3 状态流转
编码规则状态流转：
- 启用(1) / 禁用(0)

系统公告状态流转：
- 草稿(0) → 待发布(1) → 已发布(2) → 已下架(3)
- 定时发布：待发布(1) → [到达发布时间] → 已发布(2)

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. 编码规则CRUD接口 → 编码规则段配置（段配置依赖规则主表）
2. 数据视图CRUD接口 → 数据视图字段配置（字段配置依赖视图主表）
3. 后端接口全部完成 → 前端页面开发

### 5.2 可并行执行的任务
- 编码规则CRUD接口、数据视图CRUD接口、操作日志查询接口、系统参数增强接口、缓存管理接口、系统公告接口、单据配置CRUD接口可并行开发（各接口相互独立）
- 前端页面中，编码规则管理页、数据视图管理页、操作日志页、系统参数配置页、缓存管理页、系统公告管理页、单据配置页可并行开发
- 数据字典增强接口与系统参数增强接口可并行开发
