## 1. 模块架构约束

### 1.1 模块定位
移动端适配模块是ERP系统中的多终端扩展模块，负责完成移动端首页、审批、消息、报表、单据操作及关键业务查询功能。该模块基于UniApp实现跨平台（iOS/Android/H5）适配，为管理人员和业务员提供移动办公能力。

### 1.2 依赖关系
- 前置依赖：
  - P0-004（移动端菜单）：提供移动端菜单配置基础
  - 各业务模块前端完成：移动端需调用各业务模块的后端接口
- 后续依赖：无（本模块为终端消费模块，不被其他模块直接依赖）

### 1.3 技术约束
- 技术栈约束：后端基于Spring Boot + MyBatis-Plus，移动端基于UniApp（Vue3语法）；消息推送集成APNs(iOS)/FCM(Android)；离线存储使用SQLite + IndexedDB
- 性能约束：移动端API接口响应时间不超过2秒；首页加载时间不超过3秒（4G网络）；离线数据同步响应时间不超过5秒
- 安全约束：AppID/AppSecret等敏感配置加密存储；移动端接口独立鉴权，与PC端Token体系隔离；支持强制版本更新机制

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| mobile_menu | 移动端菜单表 | id, menu_name, menu_icon, route_path, permission_code, parent_id, sort_order, status |
| mobile_version | 移动版本管理表 | id, version_code, version_name, platform, download_url, force_update, release_notes, status |
| mobile_config | 移动端配置表 | id, config_key, config_value, config_type, description, status |
| mobile_push_message | 移动推送消息表 | id, user_id, title, content, push_type, target_platform, push_status, push_time |

### 2.2 表关系图
- mobile_menu：树形结构自关联表，通过 parent_id 实现多级菜单
- mobile_version：独立表，按 platform（iOS/Android）分别管理版本
- mobile_config：独立配置表，存储移动端全局配置（推送开关/离线策略等）
- mobile_push_message → 用户表：通过 user_id 关联推送目标用户

### 2.3 数据流转
1. 移动端菜单流程：配置菜单项 → 设置路由和权限 → 前端加载用户有权限的菜单
2. 版本管理流程：发布新版本 → 配置强制更新策略 → 客户端启动时检查版本 → 提示/强制更新
3. 消息推送流程：业务事件触发 → 构建推送消息 → 选择推送通道（APNs/FCM）→ 发送到设备
4. 离线操作流程：离线时操作暂存本地SQLite → 网络恢复 → 自动同步数据至服务端

## 3. 业务流程

### 3.1 核心业务流程
1. **移动端首页**：快捷功能入口、待办提醒、KPI卡片展示
2. **移动端审批**：待审/已审/待提交列表、审批详情、审批意见输入
3. **移动端消息中心**：系统消息、审批通知、业务提醒
4. **移动端关键业务查询**：客户/供应商/库存/订单等核心业务数据查询
5. **移动端报表**：关键报表的移动端适配展示
6. **移动端单据操作**：常用单据的移动端创建和编辑
7. **移动端配置管理**：基础配置、版本管理、推送配置

### 3.2 业务规则
- 移动端页面基于UniApp开发，需同时适配iOS、Android与H5三种平台
- 集成APNs（iOS）与FCM（Android）推送通道，支持即时/定时/批量推送策略
- 消息模板支持变量占位符（如：{单据编号}、{客户名称}）
- 移动端单据操作支持离线暂存，网络恢复后自动同步数据至服务端
- 支持版本号管理与强制更新机制，客户端启动时检查版本
- 移动端审批支持审批意见输入、签名附件、催办通知与审批委托功能
- 移动端接口独立鉴权，与PC端Token体系隔离

### 3.3 状态流转
推送消息状态流转：
- 待推送(0) → 推送中(1) → 已推送(2) / 推送失败(3)

移动版本状态流转：
- 草稿(0) → 已发布(1) → 已下架(2)

离线数据同步状态流转：
- 离线暂存(0) → 同步中(1) → 已同步(2) / 同步失败(3)

## 4. 接口契约

### 4.1 对外接口
| 接口路径 | 方法 | 说明 |
|---------|------|------|
| /api/mobile/menu/* | POST/PUT/DELETE/GET | 移动端菜单CRUD操作 |
| /api/mobile/approval/* | POST/GET | 移动端审批操作（待审列表/审批提交） |
| /api/mobile/push/* | POST/GET | 移动端消息推送（发送/查询） |
| /api/mobile/business/* | GET | 移动端关键业务查询 |
| /api/mobile/report/* | GET | 移动端报表数据 |
| /api/mobile/document/* | POST/PUT/GET | 移动端单据操作 |

### 4.2 依赖接口
- P0-004 用户/权限接口：获取移动端菜单权限、用户认证
- 各业务模块后端接口：审批/业务查询/报表/单据操作调用各模块已有后端接口

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. 移动端菜单CRUD接口 → 移动端审批接口（审批依赖菜单导航）
2. 后端接口全部完成 → 移动端前端页面开发

### 5.2 可并行执行的任务
- 移动端菜单CRUD接口、移动端消息推送接口、移动端关键业务查询接口、移动端报表数据接口、移动端单据操作接口可并行开发（各接口相互独立）
- 移动端前端页面中，移动端首页、审批列表页、消息中心页、业务查询页、报表页、单据操作页可并行开发
- 移动端配置管理页与版本管理页可并行开发
- 管理工作台页可与其他前端页面并行开发
