## 1. 模块架构约束

### 1.1 模块定位
期末处理模块是ERP系统中的财务核心模块之一，负责完成期末结账/反结账、期末调汇、期末结转等财务期末处理功能。该模块确保会计期间的正确关闭与结转，是财务核算周期中不可或缺的环节，保障财务数据的完整性和准确性。

### 1.2 依赖关系
- 前置依赖：
  - P1-012（凭证）：提供凭证数据支撑，结账前需校验所有凭证已审核
  - P1-013（账簿）：提供账簿数据支撑，结转前需确保账簿数据平衡
  - P1-014（报表）：提供报表数据验证，结账后报表数据锁定
- 后续依赖：无（本模块为终端消费模块，不被其他模块直接依赖）

### 1.3 技术约束
- 技术栈约束：后端基于Spring Boot + MyBatis-Plus，前端基于Vue3 + Element Plus；期末结转操作使用事务保证数据一致性
- 性能约束：期末结转操作（含生成结转凭证）响应时间不超过30秒；结账校验操作响应时间不超过10秒
- 安全约束：结账/反结账操作必须由财务主管权限执行（@RequiresPermissions("fin:period:close")）；同一期间不可并发结账（分布式锁保护）

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| fin_accounting_period | 会计期间表 | id, period_year, period_month, start_date, end_date, status, closed_by, closed_at |
| fin_period_close | 结账记录表 | id, period_id, closed_by, closed_at, close_remark, status |
| fin_exchange_gain_loss | 期末调汇表 | id, exchange_no, period_id, currency_id, exchange_rate, total_gain_loss |
| fin_exchange_gain_loss_detail | 期末调汇明细表 | id, exchange_id, account_id, original_amount, original_rate, current_rate, gain_loss |
| fin_period_carry_forward | 期末结转表 | id, carry_forward_no, period_id, carry_forward_type, voucher_id, status |
| fin_period_revaluation | 期末调汇记录表 | id, period_id, currency_id, revaluation_date, rate_before, rate_after |

### 2.2 表关系图
- fin_accounting_period（主表）：核心期间信息表，所有操作基于期间执行
- fin_accounting_period → fin_period_close：一对一关系，每个期间最多一条结账记录
- fin_accounting_period → fin_exchange_gain_loss：一对多关系，通过 period_id 关联
- fin_exchange_gain_loss（主表）→ fin_exchange_gain_loss_detail（从表）：一对多关系，通过 exchange_id 关联
- fin_accounting_period → fin_period_carry_forward：一对多关系，通过 period_id 关联
- fin_period_carry_forward → 凭证表：逻辑关联，结转操作生成结转凭证

### 2.3 数据流转
1. 期末结账流程：检查本期所有凭证已审核 → 检查试算平衡 → 执行结账操作 → 锁定本期数据 → 开启下一期间
2. 反结账流程：验证反结账权限 → 检查下期未结账 → 执行反结账 → 解锁本期数据
3. 期末调汇流程：选择外币科目 → 录入期末汇率 → 系统自动计算汇兑损益 → 生成调汇凭证
4. 期末结转流程：选择结转类型 → 系统自动计算结转金额 → 生成结转凭证 → 更新科目余额

## 3. 业务流程

### 3.1 核心业务流程
1. **期末结账**：关闭当前会计期间，禁止本期新增/修改凭证，确保数据完整性
2. **反结账**：重新打开已关闭的会计期间，允许修正本期数据
3. **期末调汇**：对外币账户按期末汇率重新计量，计算汇兑损益
4. **期末结转**：将损益类科目余额结转至本年利润，处理增值税结转等

### 3.2 业务规则
- 期末结转类型包含五种：损益结转、成本结转、增值税结转、所得税结转、利润分配结转
- 结账前校验条件：本期所有凭证已审核、试算平衡、无未记账单据
- 反结账前提：下一期间未结账（需从最后一个已结账期间开始反结账）
- 同一期间不可并发结账操作（分布式锁互斥）
- 调汇仅针对设置了外币核算的科目

### 3.3 状态流转
会计期间状态流转：
- 未结账(0) → 已结账(1) → 已反结账(0)

期末结转状态流转：
- 待结转(0) → 结转中(1) → 已完成(2) / 失败(3)
- 失败(3) → 待结转(0)（可重新执行）

## 4. 接口契约

### 4.1 对外接口
| 接口路径 | 方法 | 说明 |
|---------|------|------|
| /api/fin/period/close/* | POST/GET | 期末结账操作与结账状态查询 |
| /api/fin/period/reverse/* | POST | 期末反结账操作 |
| /api/fin/exchange/* | POST/GET | 期末调汇操作与调汇记录查询 |
| /api/fin/carryforward/* | POST/GET | 期末结转操作与结转记录查询 |

### 4.2 依赖接口
- P1-012 凭证接口：查询本期凭证列表、校验凭证审核状态、生成结转凭证
- P1-013 账簿接口：查询科目余额表、校验试算平衡
- P1-014 报表接口：获取报表数据、结账后锁定报表数据

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. 期末结账接口 → 期末反结账接口（反结账依赖结账功能的实现）
2. 后端接口全部完成 → 前端页面开发

### 5.2 可并行执行的任务
- 期末结账接口、期末调汇接口、期末结转接口可并行开发（三者相互独立）
- 前端页面中，期末结账页、期末调汇页、期末结转页可并行开发
- 期末处理工作台页可与其他前端页面并行开发
