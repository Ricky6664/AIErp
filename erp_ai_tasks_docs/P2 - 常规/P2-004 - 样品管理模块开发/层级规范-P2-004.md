## 1. 模块架构约束

### 1.1 模块定位
样品管理模块是ERP系统中的业务辅助模块，负责完成样品申请→发货→归还全链路管理。模块包含样品申请、样品发货、样品采购、样品入库、样品归还及样品库存查询功能，实现样品从申请到回收的完整生命周期管控。

### 1.2 依赖关系
- 前置依赖：
  - P0-007（商品）：提供商品基础数据，样品关联具体商品信息
  - P0-008（客户）：提供客户基础数据，样品发货关联目标客户
  - P0-010（仓库）：提供仓库基础数据，样品入库/出库关联具体仓库
- 后续依赖：无（本模块为终端消费模块，不被其他模块直接依赖）

### 1.3 技术约束
- 技术栈约束：后端基于Spring Boot + MyBatis-Plus，前端基于Vue3 + Element Plus；库存操作使用乐观锁防止超卖
- 性能约束：样品库存查询响应时间不超过2秒；发货/归还操作含库存更新响应时间不超过3秒
- 安全约束：样品发货/归还操作需审核通过后才能执行库存变更；库存操作记录完整审计日志

### 2.2 表关系图
- sample_application（主表）→ sample_application_detail（从表）：一对多关系，通过 application_id 关联
- sample_application → sample_shipment：一对多关系，通过 application_id 关联（一个申请可多次发货）
- sample_shipment（主表）→ sample_shipment_detail（从表）：一对多关系，通过 shipment_id 关联
- sample_purchase（主表）→ sample_purchase_detail（从表）：一对多关系，通过 purchase_id 关联
- sample_purchase → sample_inbound：一对多关系，通过 purchase_id 关联
- sample_inbound（主表）→ sample_inbound_detail（从表）：一对多关系，通过 inbound_id 关联
- sample_shipment → sample_return：一对多关系，通过 shipment_id 关联

### 2.3 数据流转
1. 样品申请流程：创建申请单 → 录入样品明细 → 提交审核 → 审核通过后允许发货
2. 样品发货流程：关联申请单 → 创建发货单 → 审核通过后扣减库存并关联出库单
3. 样品采购流程：创建采购单 → 录入采购明细 → 审核通过后等待入库
4. 样品入库流程：关联采购单 → 创建入库单 → 审核通过后增加库存
5. 样品归还流程：关联发货单 → 创建归还单 → 审核通过后增加库存并执行出库冲回

## 3. 业务流程

### 3.1 核心业务流程
1. **样品申请**：业务员为客户申请样品，明确样品种类、数量和用途
2. **样品发货**：审核通过后从仓库发出样品，自动扣减库存
3. **样品采购**：样品库存不足时发起采购，向供应商订购样品
4. **样品入库**：采购到货后验收入库，增加样品库存
5. **样品归还**：客户归还样品，验收后入库增加库存
6. **样品库存查询**：实时查询各仓库各样品的库存情况

### 3.2 业务规则
- 样品发货审核后自动扣减库存并关联出库单
- 样品归还审核后自动增加库存并执行出库冲回
- 发货数量不得超过申请单的未发货数量
- 入库数量不得超过采购单的未入库数量
- 归还样品需记录样品状态（完好/损坏/部分损坏）

### 3.3 状态流转
样品申请单状态流转：
- 草稿(0) → 待审核(1) → 已通过(3) / 已驳回(4)

样品发货单状态流转：
- 草稿(0) → 待审核(1) → 已发货(3) / 已驳回(4) → 部分归还(5) → 已归还(6)

样品归还单状态流转：
- 草稿(0) → 待审核(1) → 已完成(3) / 已驳回(4)

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. 样品申请CRUD接口 → 样品发货CRUD接口（发货依赖申请单数据）
2. 样品采购CRUD接口 → 样品入库CRUD接口（入库依赖采购单数据）
3. 样品发货CRUD接口 → 样品归还CRUD接口（归还依赖发货单数据）
4. 后端接口全部完成 → 前端页面开发

### 5.2 可并行执行的任务
- 样品申请CRUD接口与样品采购CRUD接口可并行开发（两者相互独立）
- 样品库存查询接口可与其他后端接口并行开发
- 前端页面中，样品申请列表页、样品发货列表页、样品采购列表页、样品入库列表页、样品归还列表页可并行开发
