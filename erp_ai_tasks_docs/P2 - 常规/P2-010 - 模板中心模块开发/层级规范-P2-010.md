## 1. 模块架构约束

### 1.1 模块定位
模板中心模块是ERP系统中的基础支撑模块，负责完成模板管理、模板分类、打印模板、导入/导出模板及模板设计器功能。该模块为全系统提供统一的模板管理能力，支撑各业务模块的打印输出、数据导入导出等场景。

### 1.2 依赖关系
- 前置依赖：
  - P0-005（公共组件含打印组件）：提供前端打印组件基础、文件上传下载能力
- 后续依赖：无（本模块为终端消费模块，但其模板能力被各业务模块的打印/导入/导出功能调用）

### 1.3 技术约束
- 技术栈约束：后端基于Spring Boot + MyBatis-Plus，前端基于Vue3 + Element Plus；打印模板设计器基于Canvas/konva.js实现拖拽编辑；模板内容以JSON格式存储
- 性能约束：模板设计器渲染帧率不低于30fps；模板列表查询响应时间不超过2秒
- 安全约束：模板设计器生成的模板内容需XSS过滤；模板文件上传限制文件类型和大小

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| template | 模板主表 | id, template_code, template_name, template_type, category_id, content_json, status |
| template_category | 模板分类表 | id, category_name, parent_id, sort_order, status |
| print_template | 打印模板表 | id, template_id, paper_size, orientation, layout_json, bind_data_fields, status |
| import_template | 导入模板表 | id, template_id, target_table, field_mapping_json, validation_rules, status |
| export_template | 导出模板表 | id, template_id, source_table, export_fields_json, export_format, status |

### 2.2 表关系图
- template_category：树形结构自关联表，通过 parent_id 实现多级分类
- template_category → template：一对多关系，通过 category_id 关联
- template → print_template：一对一/多关系，通过 template_id 关联
- template → import_template：一对一/多关系，通过 template_id 关联
- template → export_template：一对一/多关系，通过 template_id 关联

### 2.3 数据流转
1. 模板创建流程：选择模板类型 → 创建模板 → 配置模板内容（JSON）→ 保存发布
2. 打印模板流程：创建打印模板 → 打开设计器 → 拖拽组件编排 → 绑定数据字段 → 保存预览 → 发布
3. 导入模板流程：创建导入模板 → 配置目标表 → 设置字段映射 → 配置校验规则 → 保存发布
4. 导出模板流程：创建导出模板 → 选择数据源 → 配置导出字段 → 设置导出格式 → 保存发布

## 3. 业务流程

### 3.1 核心业务流程
1. **模板管理**：统一的模板CRUD管理，支持多种模板类型
2. **模板分类**：树形结构的模板分类管理
3. **打印模板管理**：可视化设计器创建和编辑打印模板
4. **导入模板管理**：配置数据导入的字段映射和校验规则
5. **导出模板管理**：配置数据导出的字段和格式
6. **模板设计器**：拖拽式组件编排的可视化模板设计工具

### 3.2 业务规则
- 模板分类支持树形结构（无限级嵌套）
- 模板内容以JSON格式存储，支持版本管理
- 打印模板设计器支持拖拽式组件编排与数据绑定
- 导入模板需配置字段映射与校验规则（必填/格式/范围）
- 导出模板需配置导出字段与格式（Excel/CSV/PDF）
- 模板删除前需检查是否被业务模块引用

### 3.3 状态流转
模板状态流转：
- 草稿(0) → 已发布(1) → 已停用(2)
- 已停用(2) → 已发布(1)（可重新启用）

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. 模板CRUD接口 → 打印模板CRUD接口（打印模板依赖基础模板）
2. 模板CRUD接口 → 导入模板CRUD接口（导入模板依赖基础模板）
3. 模板CRUD接口 → 导出模板CRUD接口（导出模板依赖基础模板）
4. 模板CRUD接口 → 模板设计器引擎接口（设计器依赖基础模板）
5. 后端接口全部完成 → 前端页面开发

### 5.2 可并行执行的任务
- 模板CRUD接口与模板分类CRUD接口可并行开发
- 打印模板CRUD接口、导入模板CRUD接口、导出模板CRUD接口可并行开发（均仅依赖基础模板接口）
- 模板设计器引擎接口可与其他后端接口并行开发
- 前端页面中，模板管理列表页、模板分类树形列表页、打印模板列表页、导入模板列表页、导出模板列表页可并行开发
