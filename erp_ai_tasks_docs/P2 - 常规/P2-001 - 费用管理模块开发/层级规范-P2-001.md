## 1. 模块架构约束

### 1.1 模块定位
费用管理模块是ERP系统中的财务核心模块之一，负责完成费用报销与费用预算管理全流程。模块包含费用预算单、费用申请单、费用报销单的全流程CRUD，以及费用预算执行率查询与费用统计报表功能，实现从预算编制到费用报销的闭环管理。

### 1.2 依赖关系
- 前置依赖：
  - P0-011（财务基础）：提供会计科目、币种、汇率等基础数据支撑
  - P1-001（审核引擎）：提供费用申请单、报销单的审批流程能力
- 后续依赖：无（本模块为终端消费模块，不被其他模块直接依赖）

### 1.3 技术约束
- 技术栈约束：后端基于Spring Boot + MyBatis-Plus，前端基于Vue3 + Element Plus；费用报销单附件上传使用MinIO对象存储
- 性能约束：费用统计报表查询响应时间不超过3秒；费用预算执行率实时计算需在1秒内返回
- 安全约束：费用报销金额修改需留痕审计；费用数据按部门权限隔离，用户只能查看本部门及下级部门费用数据

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| expense_budget | 费用预算单主表 | id, budget_no, budget_year, budget_month, dept_id, total_amount, status |
| expense_budget_detail | 费用预算单明细表 | id, budget_id, expense_type_id, budget_amount, used_amount |
| expense_application | 费用申请单主表 | id, application_no, applicant_id, dept_id, total_amount, audit_status |
| expense_application_detail | 费用申请单明细表 | id, application_id, expense_type_id, apply_amount, remark |
| expense_reimbursement | 费用报销单主表 | id, reimbursement_no, applicant_id, dept_id, total_amount, audit_status |
| expense_reimbursement_detail | 费用报销单明细表 | id, reimbursement_id, expense_type_id, amount, receipt_no, attachment_url |

### 2.2 表关系图
- expense_budget（主表）→ expense_budget_detail（从表）：一对多关系，通过 budget_id 关联
- expense_application（主表）→ expense_application_detail（从表）：一对多关系，通过 application_id 关联
- expense_reimbursement（主表）→ expense_reimbursement_detail（从表）：一对多关系，通过 reimbursement_id 关联
- expense_application → expense_reimbursement：逻辑关联，报销单可关联申请单编号
- expense_budget_detail → expense_application_detail：逻辑关联，通过费用类型统计已用金额

### 2.3 数据流转
1. 费用预算编制流程：创建预算单 → 录入预算明细 → 提交审核 → 审核通过后预算生效
2. 费用申请流程：创建申请单 → 关联预算项 → 校验预算余额 → 提交审核 → 审核通过后占用预算
3. 费用报销流程：创建报销单 → 关联申请单（可选）→ 上传票据附件 → 校验预算余额 → 提交审核 → 审核通过后确认费用并更新预算执行率

## 3. 业务流程

### 3.1 核心业务流程
1. **费用预算管理**：按年度/月度/部门编制费用预算，预算审核通过后作为费用控制上限
2. **费用申请管理**：员工提交费用申请，经审批后形成费用申请单，占用对应预算额度
3. **费用报销管理**：员工提交报销单并附票据，经审批后确认费用并更新预算执行数据
4. **预算执行率查询**：实时展示各部门/各费用类型的预算使用情况
5. **费用统计报表**：按时间/部门/费用类型维度统计费用数据

### 3.2 业务规则
- 费用申请金额不得超过对应预算项的剩余可用金额
- 费用报销金额不得超过对应申请单金额（若关联申请单）
- 报销单必须上传至少一张票据附件
- 预算执行率 = 已使用金额 / 预算金额 × 100%
- 超预算申请/报销需走超额审批流程（额外审批节点）

### 3.3 状态流转
费用申请单/报销单状态流转：
- 草稿(0) → 待审核(1) → 审核中(2) → 已通过(3) / 已驳回(4)
- 已驳回(4) → 草稿(0)（重新编辑后可再次提交）

费用预算单状态流转：
- 草稿(0) → 待审核(1) → 已生效(3) / 已驳回(4)

## 4. 接口契约

### 4.1 对外接口
| 接口路径 | 方法 | 说明 |
|---------|------|------|
| /api/expense/claim/* | POST/PUT/DELETE/GET | 费用报销单CRUD操作 |
| /api/expense/application/* | POST/PUT/DELETE/GET | 费用申请单CRUD操作 |
| /api/expense/budget/* | POST/PUT/DELETE/GET | 费用预算单CRUD操作 |
| /api/expense/budget/execution/* | GET | 费用预算执行率查询 |

### 4.2 依赖接口
- P0-011 财务基础接口：获取会计科目列表、币种列表、汇率数据
- P1-001 审核引擎接口：提交审核、撤回审核、获取审核状态、审核回调

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. 费用报销Entity/DTO/VO定义 → 费用报销Mapper开发 → 费用报销Service开发 → 费用报销Controller开发
2. 费用申请Entity/DTO/VO定义 → 费用申请Mapper开发 → 费用申请Service开发 → 费用申请Controller开发
3. 费用预算Entity/DTO/VO定义 → 费用预算Mapper开发 → 费用预算Service开发 → 费用预算Controller开发
4. 费用预算CRUD接口完成后 → 费用预算执行率查询接口开发
5. 后端接口全部完成 → 前端页面开发

### 5.2 可并行执行的任务
- 费用报销CRUD接口、费用申请CRUD接口、费用预算CRUD接口可并行开发
- 前端页面中，费用申请列表页、费用报销列表页、费用预算列表页可并行开发
- 费用预算执行率页面与费用统计报表页面可并行开发
