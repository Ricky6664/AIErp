## 1. 模块架构约束

### 1.1 模块定位
运维管理模块是ERP系统中的系统运维保障模块，负责完成定时任务管理、任务执行日志、数据备份与恢复、运维告警、服务器监控、在线用户管理及服务监控功能。该模块覆盖监控、备份、恢复、告警四大运维领域，为系统稳定运行提供保障能力。

### 1.2 依赖关系
- 前置依赖：
  - P0-001（后端框架）：提供Spring Boot基础框架、Actuator端点、Redis连接等基础设施
- 后续依赖：无（本模块为终端消费模块，不被其他模块直接依赖）

### 1.3 技术约束
- 技术栈约束：后端基于Spring Boot + MyBatis-Plus + XXL-JOB，前端基于Vue3 + Element Plus；服务器监控使用Spring Boot Actuator + OSHI采集
- 性能约束：服务器监控数据采集间隔不低于10秒；告警检测间隔不低于30秒；在线用户列表查询响应时间不超过2秒
- 安全约束：数据恢复操作需@RequiresPermissions("ops:recovery:execute")权限控制与二次确认；备份文件需MD5校验完整性；Actuator端点需配置安全访问（IP白名单+认证）

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| ops_scheduled_task | 定时任务表 | id, task_name, task_group, cron_expression, handler_name, status, last_execute_time |
| ops_task_execution_log | 任务执行日志表 | id, task_id, execute_time, duration, result, error_message |
| ops_data_backup | 数据备份表 | id, backup_name, backup_type, file_path, file_size, md5_check, status, create_time |
| ops_alert_rule | 运维告警规则表 | id, rule_name, metric_type, threshold, operator, notify_type, status |
| ops_alert_log | 运维告警日志表 | id, rule_id, alert_time, metric_value, alert_message, handle_status |
| ops_server_monitor | 服务器监控数据表 | id, server_ip, cpu_usage, memory_usage, disk_usage, jvm_usage, db_connections, collect_time |
| ops_module_auth | 模块授权表 | id, module_code, customer_id, license_key, expire_date, status |

### 2.2 表关系图
- ops_scheduled_task → ops_task_execution_log：一对多关系，通过 task_id 关联（一个任务多条执行日志）
- ops_alert_rule → ops_alert_log：一对多关系，通过 rule_id 关联（一条规则可触发多次告警）
- ops_server_monitor：独立时序表，按 collect_time 排列监控数据
- ops_data_backup：独立表，按 create_time 排列备份记录
- ops_module_auth：独立授权表

### 2.3 数据流转
1. 定时任务流程：创建任务 → 配置Cron表达式 → 启用 → XXL-JOB调度执行 → 自动记录执行日志
2. 数据备份流程：创建备份任务 → 执行数据库备份 → 计算MD5校验值 → 存储备份文件 → 记录备份信息
3. 数据恢复流程：选择备份文件 → 校验MD5完整性 → 二次确认 → 执行恢复 → 记录恢复日志
4. 运维告警流程：配置告警规则 → 定时检测指标 → 超阈值触发告警 → 推送通知（站内信/邮件/短信）
5. 服务器监控流程：定时采集指标 → 存储历史数据 → 展示实时/趋势图表

## 3. 业务流程

### 3.1 核心业务流程
1. **定时任务管理**：基于XXL-JOB的任务CRUD、Cron配置、手动触发
2. **任务执行日志**：查看任务执行历史、执行结果、错误详情
3. **数据备份与恢复**：数据库手动/定时备份、备份文件管理、数据恢复
4. **运维告警**：配置告警规则、查看告警历史、处理告警
5. **服务器监控**：CPU/内存/磁盘/JVM/数据库连接池实时监控
6. **在线用户管理**：查看在线用户、强制下线、会话信息查看
7. **服务监控**：Spring Boot Actuator健康检查、指标展示
8. **模块授权管理**：管理客户模块授权许可证

### 3.2 业务规则
- 集成XXL-JOB调度框架，支持Cron表达式配置与手动触发
- 备份文件需MD5校验完整性，恢复前自动校验
- 恢复操作需二次确认，恢复过程需记录完整日志并支持回滚
- 告警规则支持阈值配置，超阈值自动触发告警通知推送（站内信/邮件/短信）
- CPU/内存/磁盘/JVM/数据库连接池实时采集并存储历史趋势数据
- 在线用户管理基于Sa-Token会话列表实现，支持强制下线

### 3.3 状态流转
定时任务状态流转：
- 启用(1) / 禁用(0)
- 执行状态：等待执行(0) → 执行中(1) → 成功(2) / 失败(3)

备份任务状态流转：
- 待备份(0) → 备份中(1) → 已完成(2) / 失败(3)

告警处理状态流转：
- 未处理(0) → 处理中(1) → 已处理(2) / 已忽略(3)

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. 定时任务CRUD接口 → 任务执行日志查询接口（日志依赖任务定义）
2. 数据备份CRUD接口 → 数据恢复接口（恢复依赖备份文件）
3. 后端接口全部完成 → 前端页面开发

### 5.2 可并行执行的任务
- 定时任务CRUD接口、数据备份CRUD接口、运维告警CRUD接口、服务器监控数据接口、在线用户管理接口可并行开发（各接口相互独立）
- 前端页面中，定时任务管理页、数据备份页、运维告警页、服务器监控页、在线用户管理页可并行开发
- 服务监控仪表盘页与数据恢复页可并行开发
