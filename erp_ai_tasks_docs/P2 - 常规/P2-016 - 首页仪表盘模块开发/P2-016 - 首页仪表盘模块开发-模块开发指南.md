## 四、模块级专属约束

本模块为轻量级模块，以后端数据聚合与前端展示为主。仪表盘配置采用布局JSON+组件配置JSON存储，支持用户个性化配置；KPI数据聚合覆盖销售/采购/库存/财务/生产多维KPI汇总；图表数据聚合按时间维度与分类维度提供趋势数据与对比数据。

## 五、数据表完整字段定义

> **本模块无专属数据表**。首页仪表盘为纯聚合展示模块，所有KPI数据和图表数据均从各业务模块已有表实时聚合查询或从定时任务预计算的统计表读取。仪表盘布局配置和小组件定义复用sys_dashboard_layout和sys_dashboard_widget表（已在P0-005公共组件中定义）。详细的数据源表和布局配置设计见第九节补充说明。

### 5.4 图表数据聚合SQL

以下为图表数据的核心聚合逻辑，在PostgreSQL数据库层以物化视图或存储过程实现预计算：

**销售趋势折线图（按月/日维度）**：

```sql
SELECT stat_date,
       SUM(order_amount) AS total_sales,
       SUM(delivery_amount) AS total_delivery,
       SUM(order_amount) - SUM(delivery_amount) AS pending_delivery
FROM rpt_sales_daily_stats
WHERE stat_date BETWEEN :startDate AND :endDate
GROUP BY stat_date
ORDER BY stat_date;
```

**采购金额柱状图（按供应商TOP10）**：

```sql
SELECT supplier_id, s.supplier_name,
       SUM(order_amount) AS total_purchase
FROM rpt_purchase_daily_stats p
LEFT JOIN pur_supplier s ON p.supplier_id = s.id
WHERE stat_date BETWEEN :startDate AND :endDate
GROUP BY supplier_id, s.supplier_name
ORDER BY total_purchase DESC
LIMIT 10;
```

**库存分布饼图（按物料分类）**：

```sql
SELECT mc.category_name,
       SUM(total_qty) AS qty,
       SUM(total_amount) AS amount
FROM rpt_inventory_stats i
LEFT JOIN inv_material_category mc ON i.material_category_id = mc.id
WHERE stat_date = CURRENT_DATE
GROUP BY mc.category_name
ORDER BY amount DESC;
```

**财务收支对比柱状图（按会计期间）**：

```sql
SELECT fp.period_name,
       SUM(CASE WHEN account_category = '收入' THEN credit_amount ELSE 0 END) AS income,
       SUM(CASE WHEN account_category = '成本' THEN debit_amount ELSE 0 END) AS cost,
       SUM(CASE WHEN account_category = '费用' THEN debit_amount ELSE 0 END) AS expense
FROM rpt_finance_period_stats r
LEFT JOIN fin_period fp ON r.period_id = fp.id
WHERE r.period_id BETWEEN :startPeriod AND :endPeriod
GROUP BY fp.period_name
ORDER BY fp.period_name;
```

### 5.5 数据聚合与缓存策略

| 数据类型 | 聚合方式 | 聚合频率 | 缓存策略 | 备注 |
|---------|---------|---------|---------|------|
| KPI卡片数据 | SQL聚合查询 | 按业务类型3~10分钟 | Redis String缓存，Key格式：`dashboard:kpi:{kpi_code}:{user_id}` | 支持手动刷新按钮强制更新缓存 |
| 趋势图表数据 | SQL聚合查询 | 每日凌晨预计算 | Redis Hash缓存，Key格式：`dashboard:chart:{chart_code}:{date_range}` | 数据量大时使用物化视图预计算 |
| 快捷入口 | 静态配置 | 无（读取配置表） | Redis缓存TTL=1小时 | 按用户权限过滤后缓存 |
| 待办事项 | 实时查询 | 实时 | 不缓存，直接查库 | 待办数据变化频繁且对实时性要求高 |
| 统计数据源 | 定时任务聚合 | 每日凌晨02:00 | 写入统计表后直接查表 | 使用Spring Schedule @Scheduled(cron="0 0 2 * * ?") |

### 5.6 实时刷新WebSocket推送

系统通过WebSocket实现仪表盘数据的实时推送，技术实现要点：

- **连接端点**：`ws://{host}/ws/dashboard`，通过JWT Token进行身份认证
- **心跳机制**：客户端每30秒发送PING帧，服务端回复PONG帧；超过90秒无心跳则断开连接
- **消息格式**：JSON结构包含`type`(事件类型)、`data`(事件数据，含kpi_code/value/change_rate/update_time)、`timestamp`(服务端时间戳)

**推送事件类型**：

| 事件类型 | 触发条件 | 推送内容 | 目标用户 |
|---------|---------|---------|---------|
| KPI_UPDATE | KPI数据缓存更新时 | KPI编码+新值+变化率 | 所有在线用户 |
| TODO_NEW | 新待办事项产生时 | 待办类型+标题+来源单据 | 指定用户 |
| TODO_COMPLETE | 待办事项处理完成时 | 待办ID+处理结果 | 指定用户 |
| CHART_REFRESH | 图表缓存数据更新时 | 图表编码+新数据集 | 所有在线用户 |
| LAYOUT_SYNC | 布局配置被修改时 | 新布局JSON | 当前用户 |

**多实例部署方案**：使用Redis Pub/Sub作为消息总线，各Spring Boot实例订阅`dashboard:broadcast`频道，收到消息后推送给本实例的WebSocket连接用户。

### 5.7 首页布局配置JSON结构

layout_json采用Vue Grid Layout格式，每个组件节点包含`i`(组件ID)、`x`/`y`(坐标)、`w`/`h`(宽高栅格数)、`widget_type`(组件类型)。布局栅格采用12列制，行高固定80px，默认布局依次为：4个KPI卡片(w=3,h=2)→销售趋势折线图(w=6,h=4)+库存分布饼图(w=6,h=4)→快捷入口(w=12,h=2)→待办事项(w=12,h=4)。每个用户最多保存5套布局方案，其中1套为默认方案（is_default=1）。
