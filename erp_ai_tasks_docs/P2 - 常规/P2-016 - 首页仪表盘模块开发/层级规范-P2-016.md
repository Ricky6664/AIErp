## 1. 模块架构约束

### 1.1 模块定位
首页仪表盘模块是ERP系统的数据可视化入口模块，负责完成系统首页仪表盘配置、KPI卡片展示、多类型图表展示及用户个性化配置。该模块为系统提供统一的首页数据可视化入口，通过聚合各业务模块数据，为管理层提供一目了然的经营概览。

### 1.2 依赖关系
- 前置依赖：
  - P0-005（P01仪表盘组件）：提供前端仪表盘布局组件基础（Vue Grid Layout、图表容器）
- 后续依赖：无（本模块为终端消费模块，不被其他模块直接依赖）

### 1.3 技术约束
- 技术栈约束：后端基于Spring Boot + MyBatis-Plus + Redis缓存，前端基于Vue3 + ECharts + Vue Grid Layout；WebSocket实时推送使用Spring WebSocket + Redis Pub/Sub
- 性能约束：KPI数据查询（Redis缓存命中）响应时间不超过100ms；图表数据查询响应时间不超过3秒；WebSocket消息推送延迟不超过1秒
- 安全约束：KPI数据按用户权限过滤（仅展示有权查看的数据维度）；WebSocket连接通过JWT Token认证

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| sys_dashboard_layout | 仪表盘布局配置表 | id, user_id, layout_name, layout_json(JSONB), is_default, sort_order, status |
| sys_dashboard_widget | 仪表盘小组件定义表 | id, layout_id, widget_type, widget_config(JSONB), data_source, refresh_interval, sort_order |
| rpt_sales_daily_stats | 销售日统计表 | stat_date, customer_id, product_category_id, order_count, order_amount, delivery_amount |
| rpt_purchase_daily_stats | 采购日统计表 | stat_date, supplier_id, material_category_id, order_count, order_amount, receipt_amount |
| rpt_inventory_stats | 库存统计表 | stat_date, warehouse_id, material_category_id, total_qty, total_amount, warning_count |
| rpt_finance_period_stats | 财务期间统计表 | period_id, account_category, debit_amount, credit_amount, balance |
| rpt_production_daily_stats | 生产日统计表 | stat_date, workshop_id, plan_count, completed_count, in_progress_count, yield_rate |
| sys_dashboard_todo | 首页待办事项表 | id, user_id, todo_type, todo_title, source_doc_type, source_doc_id, priority, status |

### 2.2 表关系图
- sys_dashboard_layout（主表）→ sys_dashboard_widget（从表）：一对多关系，通过 layout_id 关联
- sys_dashboard_layout → 用户表：通过 user_id 关联（每用户最多5套布局方案）
- rpt_sales_daily_stats：独立统计表，由定时任务每日凌晨聚合销售数据
- rpt_purchase_daily_stats：独立统计表，由定时任务每日凌晨聚合采购数据
- rpt_inventory_stats：独立统计表，聚合库存数据
- rpt_finance_period_stats：独立统计表，按会计期间汇总财务数据
- rpt_production_daily_stats：独立统计表，聚合生产工单数据
- sys_dashboard_todo：独立待办表，聚合各模块待办事项

### 2.3 数据流转
1. KPI数据展示流程：定时任务预计算统计表 → 查询KPI接口 → Redis缓存（5分钟TTL）→ 前端KPI卡片展示
2. 图表数据展示流程：定时任务预计算统计表 → 查询图表接口 → Redis缓存 → 前端ECharts渲染
3. 布局配置流程：用户拖拽布局 → 保存layout_json → 加载时读取用户默认布局
4. 实时推送流程：数据变更 → Redis Pub/Sub发布 → WebSocket推送到在线用户 → 前端更新
5. 待办事项流程：各模块产生待办 → 写入sys_dashboard_todo → 实时推送到指定用户

## 3. 业务流程

### 3.1 核心业务流程
1. **仪表盘配置**：管理员/用户自定义仪表盘布局（拖拽式Vue Grid Layout）
2. **KPI卡片展示**：展示今日销售额、本月采购额、库存预警数、应收/应付款总额等核心KPI
3. **图表数据展示**：销售趋势折线图、采购金额柱状图、库存分布饼图、财务收支对比图
4. **快捷入口**：提供常用功能快捷跳转（新建销售订单/采购订单/库存查询/待审单据等）
5. **待办事项**：聚合各模块待审核/待处理/待发货等待办
6. **实时数据推送**：WebSocket推送KPI更新/待办通知/图表刷新

### 3.2 业务规则
- 仪表盘配置采用布局JSON+组件配置JSON存储，layout_json使用Vue Grid Layout格式
- 布局栅格采用12列制，行高固定80px
- 每个用户最多保存5套布局方案，其中1套为默认方案
- KPI数据使用Redis缓存（Key: dashboard:kpi:{kpi_code}:{user_id}，TTL 5分钟）
- 趋势图表数据使用Redis Hash缓存（Key: dashboard:chart:{chart_code}:{date_range}）
- 统计数据由定时任务每日凌晨02:00聚合（Spring Schedule @Scheduled）

### 3.3 状态流转
仪表盘布局状态流转：
- 启用(1) / 禁用(0)，每个用户最多1个默认布局（is_default=1）

待办事项状态流转：
- 待处理(0) → 已处理(1) / 已忽略(2)

## 4. 接口契约

### 4.1 对外接口
| 接口路径 | 方法 | 说明 |
|---------|------|------|
| /api/dashboard/config/* | POST/PUT/DELETE/GET | 仪表盘配置CRUD操作 |
| /api/dashboard/kpi/* | GET | KPI数据聚合查询（支持多种KPI类型参数） |
| /api/dashboard/chart/* | GET | 图表数据聚合查询（支持时间/分类维度） |

### 4.2 依赖接口
- P0-005 公共组件接口：获取P01仪表盘组件（Vue Grid Layout、图表容器）
- 各业务模块数据接口：为统计图表提供数据来源（通过统计表间接依赖）

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. 仪表盘配置CRUD接口 → KPI数据聚合接口（KPI依赖配置确定展示哪些指标）
2. 仪表盘配置CRUD接口 → 图表数据聚合接口（图表依赖配置确定展示哪些图表）
3. 后端接口全部完成 → 前端页面开发

### 5.2 可并行执行的任务
- KPI数据聚合接口与图表数据聚合接口可并行开发（两者相互独立）
- 仪表盘配置页与首页仪表盘页可并行开发（配置页不依赖首页数据展示逻辑）
- WebSocket推送功能可与数据接口并行开发
