### 5.1 接口实现结构

```java
@PostMapping("/create")
@Operation(summary = "新增报表中心")
@SaCheckPermission("report:add")
@OperLog(module = "报表中心管理", action = "新增")
public Result<Long> create(@RequestBody @Valid ReportCreateDTO dto) {
    return R.ok(reportService.create(dto));
}
```

### 5.2 参数处理

1. @RequestBody接收JSON请求体
2. @Valid触发DTO校验注解
3. 校验失败抛MethodArgumentNotValidException由全局处理器捕获

### 5.3 响应包装

- 成功：Result<T>(code=200, data=业务数据)
- 失败：Result<T>(code=错误码, message=错误提示)

### 5.4 验证

1. 接口调用返回预期Result结构
2. 参数校验失败返回400
3. 异常由GlobalExceptionHandler统一处理

## 八、易错警示

> ⚠️ 代码提交前确保无敏感信息硬编码（密码/密钥/token）

> ⚠️ 多租户隔离(tenant_id)必须正确——所有SQL查询需自动注入tenant_id条件

> ⚠️ 逻辑删除字段(is_deleted)正确处理——查询追加is_deleted=false，删除使用UPDATE而非DELETE

> ⚠️ 接口路径必须符合 `/api/{module}/{resource}` 规范，复数形式

> ⚠️ @RequestBody必须配合@Valid使用，否则DTO校验不生效

> ⚠️ GET请求复杂查询参数使用@ModelAttribute而非@RequestParam

> ⚠️ [报表中心模块] SQL查询必须经过白名单校验，禁止INSERT/UPDATE/DELETE/DROP/ALTER/TRUNCATE等写操作

> ⚠️ [报表中心模块] 所有动态SQL必须自动注入tenant_id和is_deleted条件，确保多租户隔离和逻辑删除

> ⚠️ [报表中心模块] 报表查询必须设置30秒超时限制，超时自动终止并返回友好提示
