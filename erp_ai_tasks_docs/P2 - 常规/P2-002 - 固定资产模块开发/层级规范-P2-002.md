## 1. 模块架构约束

### 1.1 模块定位
固定资产模块是ERP系统中的财务核心模块之一，负责完成固定资产全生命周期管理。模块包含资产卡片录入、资产折旧计提、资产变动管理、资产清理处置及资产统计报表功能，覆盖从资产入账到报废处置的完整管理链路。

### 1.2 依赖关系
- 前置依赖：
  - P0-011（财务基础含会计科目）：提供会计科目、资产分类科目映射、币种等基础数据
- 后续依赖：无（本模块为终端消费模块，不被其他模块直接依赖）

### 1.3 技术约束
- 技术栈约束：后端基于Spring Boot + MyBatis-Plus，前端基于Vue3 + Element Plus；折旧计算采用批量计算模式，单次折旧处理上限10000条资产
- 性能约束：折旧批量计提操作（1000条以内）响应时间不超过10秒；资产卡片列表查询响应时间不超过2秒
- 安全约束：资产处置操作需@RequiresPermissions("fa:disposal:execute")权限控制；折旧计提操作需财务主管权限

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| fa_card (fa_asset) | 资产卡片表 | id, asset_code, asset_name, category_id, original_value, net_value, depreciation_method, useful_life, purchase_date, status |
| fa_depreciation | 资产折旧计提表 | id, depreciation_no, period_id, total_amount, total_count, status |
| fa_depreciation_detail | 折旧明细表 | id, depreciation_id, asset_id, depreciation_amount, accumulated_amount, net_value |
| fa_change (fa_asset_change) | 资产变动表 | id, change_no, asset_id, change_type, change_date, original_value_change, useful_life_change |
| fa_disposal (fa_asset_disposal) | 资产清理处置表 | id, disposal_no, asset_id, disposal_type, disposal_date, disposal_amount, gain_loss |
| fa_asset_disposal_detail | 资产处置明细表 | id, disposal_id, asset_id, book_value, disposal_amount, gain_loss |

### 2.2 表关系图
- fa_card（主表）：核心资产信息表，所有其他表通过 asset_id 关联
- fa_depreciation（主表）→ fa_depreciation_detail（从表）：一对多关系，通过 depreciation_id 关联
- fa_card → fa_depreciation_detail：一对多关系，一个资产可有多条折旧历史记录
- fa_card → fa_change：一对多关系，一个资产可有多次变动记录
- fa_disposal（主表）→ fa_asset_disposal_detail（从表）：一对多关系，通过 disposal_id 关联
- fa_card → fa_disposal：一对多关系，一个资产可有多次处置记录

### 2.3 数据流转
1. 资产入账流程：创建资产卡片 → 填写资产信息（原值/使用年限/折旧方法）→ 审核通过后资产生效
2. 折旧计提流程：选择会计期间 → 批量执行折旧计算 → 生成折旧明细 → 更新资产净值 → 生成折旧凭证
3. 资产变动流程：选择变动类型（原值调整/部门调拨/使用人变更）→ 录入变动信息 → 审核通过后更新资产卡片
4. 资产处置流程：选择处置类型（报废/出售/捐赠）→ 录入处置信息 → 审核通过后更新资产状态为已处置并计算处置损益

## 3. 业务流程

### 3.1 核心业务流程
1. **资产卡片管理**：录入、编辑、查询固定资产卡片，记录资产的基本信息、价值信息、折旧信息
2. **资产折旧计提**：按会计期间批量执行折旧计算，支持四种折旧方法
3. **资产变动管理**：处理资产原值调整、部门调拨、使用人变更、使用年限调整等变动事项
4. **资产清理处置**：处理资产报废、出售、捐赠等处置事项，计算处置损益
5. **资产统计报表**：按资产分类/部门/状态维度统计资产数据

### 3.2 业务规则
- 折旧方法支持四种：平均年限法（直线法）、双倍余额递减法、年数总和法、工作量法
- 已提足折旧的资产不再计提折旧（净值=残值时停止）
- 当月新增资产从次月开始计提折旧，当月减少资产当月仍计提折旧
- 资产处置前必须确认该资产无未完成的变动业务
- 资产清理处置后，资产状态变更为"已处置"且不可恢复

### 3.3 状态流转
资产卡片状态流转：
- 在用(1) → 已处置(2) / 已报废(3)
- 在用(1) → 停用(4) → 在用(1)

折旧计提状态流转：
- 未计提(0) → 计提中(1) → 已完成(2) / 失败(3)
- 失败(3) → 未计提(0)（可重新执行）

## 4. 接口契约

### 4.1 对外接口
| 接口路径 | 方法 | 说明 |
|---------|------|------|
| /api/fa/asset/* | POST/PUT/DELETE/GET | 固定资产卡片CRUD操作 |
| /api/fa/depreciation/* | POST/GET | 资产折旧计算（批量计提/查询折旧记录） |
| /api/fa/change/* | POST/PUT/DELETE/GET | 资产变动CRUD操作 |
| /api/fa/disposal/* | POST/PUT/DELETE/GET | 资产清理处置CRUD操作 |

### 4.2 依赖接口
- P0-011 财务基础接口：获取会计科目列表（固定资产类/累计折旧类/折旧费用类科目）、资产分类科目映射

## 5. 开发顺序约束

### 5.1 必须顺序执行的任务
1. 固定资产卡片CRUD接口 → 资产折旧计算接口（折旧依赖资产卡片数据）
2. 固定资产卡片CRUD接口 → 资产变动CRUD接口（变动依赖资产卡片数据）
3. 固定资产卡片CRUD接口 → 资产清理处置CRUD接口（处置依赖资产卡片数据）
4. 后端接口全部完成 → 前端页面开发

### 5.2 可并行执行的任务
- 资产折旧计算接口、资产变动CRUD接口、资产清理处置CRUD接口可并行开发（均仅依赖资产卡片接口）
- 前端页面中，资产卡片列表页、资产折旧列表页、资产变动列表页、资产清理处置列表页可并行开发
- 资产统计报表页面可与其他前端页面并行开发
