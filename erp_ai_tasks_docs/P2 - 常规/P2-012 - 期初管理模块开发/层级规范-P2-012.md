## 1. 模块架构约束

### 1.1 模块定位
期初管理模块是ERP系统中的数据初始化模块，负责完成系统初始化数据管理。模块包含期初库存、期初应收、期初应付、期初应开票、期初应收票、期初固定资产、期初科目余额的录入与审核写入，确保系统上线或切换时业务数据的完整衔接。

### 1.2 依赖关系
- 前置依赖：
  - P0-007（商品）：提供商品基础数据，期初库存关联具体商品
  - P0-010（仓库）：提供仓库基础数据，期初库存关联具体仓库
  - P1-010（应收）：提供应收款管理基础，期初应收写入应收表
  - P1-011（应付）：提供应付款管理基础，期初应付写入应付表
  - P1-012（凭证）：提供凭证管理基础，期初科目余额写入科目余额表
- 后续依赖：无（本模块为终端消费模块，不被其他模块直接依赖）

### 1.3 技术约束
- 技术栈约束：后端基于Spring Boot + MyBatis-Plus，前端基于Vue3 + Element Plus；期初数据写入使用事务保证一致性
- 性能约束：期初科目余额批量导入（1000条以内）响应时间不超过10秒；试算平衡校验响应时间不超过3秒
- 安全约束：期初数据审核通过后自动写入业务表，操作不可逆需严格权限控制；已启用（存在业务单据）的仓库/客户/供应商/科目不可修改期初数据

## 2. 数据模型关系

### 2.1 核心数据表
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| init_inventory | 期初库存主表 | id, warehouse_id, init_date, total_amount, audit_status, write_status |
| init_inventory_detail | 期初库存明细表 | id, init_id, product_id, qty, unit_price, amount, batch_no |
| init_ar | 期初应收表 | id, customer_id, init_date, total_amount, audit_status, write_status |
| init_ap | 期初应付表 | id, supplier_id, init_date, total_amount, audit_status, write_status |
| init_ar_invoice | 期初应开票表 | id, customer_id, init_date, invoice_amount, audit_status, write_status |
| init_ap_invoice | 期初应收票表 | id, supplier_id, init_date, invoice_amount, audit_status, write_status |
| init_fa_asset | 期初固定资产表 | id, asset_name, category_id, original_value, accumulated_depreciation, net_value, audit_status |
| init_account_balance | 期初科目余额表 | id, account_id, period_id, debit_balance, credit_balance, audit_status, write_status |

### 2.2 表关系图
- init_inventory（主表）→ init_inventory_detail（从表）：一对多关系，通过 init_id 关联
- init_ar：独立表，通过 customer_id 关联客户
- init_ap：独立表，通过 supplier_id 关联供应商
- init_ar_invoice：独立表，通过 customer_id 关联客户
- init_ap_invoice：独立表，通过 supplier_id 关联供应商
- init_fa_asset：独立表，通过 category_id 关联资产分类
- init_account_balance：独立表，通过 account_id 关联会计科目
- 各期初表 → 对应业务表：审核通过后数据写入（init_inventory → inv_material, init_ar → fin_receivable 等）

### 2.3 数据流转
1. 期初库存录入流程：选择仓库 → 录入商品/数量/单价 → 校验 → 提交审核 → 审核通过后写入库存表
2. 期初应收/应付录入流程：选择客户/供应商 → 录入金额 → 提交审核 → 审核通过后写入应收/应付表
3. 期初固定资产录入流程：录入资产信息 → 设置折旧方法 → 提交审核 → 审核通过后写入资产卡片表
4. 期初科目余额录入流程：录入科目借贷方余额 → 试算平衡校验 → 提交审核 → 审核通过后写入科目余额表

## 3. 业务流程

### 3.1 核心业务流程
1. **期初库存管理**：录入各仓库的初始库存数量和金额
2. **期初应收管理**：录入客户的初始应收款余额
3. **期初应付管理**：录入供应商的初始应付款余额
4. **期初应开票管理**：录入待开具发票的初始数据
5. **期初应收票管理**：录入待收取发票的初始数据
6. **期初固定资产管理**：录入初始固定资产卡片数据
7. **期初科目余额管理**：录入会计科目的初始余额

### 3.2 业务规则
- 期初数据审核通过后自动写入对应业务表（库存表/应收表/应付表/资产卡片表/科目余额表）
- 已启用（已存在业务单据）的仓库/客户/供应商/科目不可修改期初数据
- 期初科目余额必须通过试算平衡校验（全部借方合计=全部贷方合计）方可提交
- 期初固定资产支持四种折旧方法公式自动计算月折旧额
- 期初数据写入后不可重复写入（write_status标记）

### 3.3 状态流转
期初数据状态流转：
- 草稿(0) → 待审核(1) → 已审核并写入(3) / 已驳回(4)
- 已审核并写入(3)：终态，不可回退
