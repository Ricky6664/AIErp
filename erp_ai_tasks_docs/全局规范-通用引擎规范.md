## 0.7.5 编码引擎详细规范

### 段类型配置表（sys_code_rule_segment）

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | bigint | 是 | 主键 |
| rule_id | bigint | 是 | 所属编码规则ID，关联 sys_code_rule.id |
| segment_type | varchar(20) | 是 | 段类型：`fixed`/`date`/`serial`/`custom` |
| segment_value | varchar(50) | 否 | 段值，fixed时为固定字符串，date时为日期格式 |
| segment_length | int | 否 | 段长度，serial时用于序号补零位数 |
| sort_order | int | 是 | 段排序序号 |
| serial_reset_type | varchar(10) | 否 | 序号重置周期：`year`/`month`/`day`/`never`，仅serial段有效 |
| serial_start | int | 否 | 序号起始值，默认1 |
| custom_expression | varchar(200) | 否 | 自定义表达式，custom段使用，支持SpEL |

**段类型说明**：

| 段类型 | 说明 | 示例 |
|--------|------|------|
| fixed | 固定字符串 | `SO`、`PO`、`-` |
| date | 日期变量段 | `yyyyMMdd` → `20260525`，`yyyyMM` → `202605` |
| serial | 自增序号段 | length=4 → `0001`、`0002` |
| custom | 自定义段 | 支持SpEL表达式，如 `#dept.code` 取部门编码 |

**示例**：编码规则 `SO-20260525-0001` 由3段组成：
- 段1：fixed = `SO`
- 段2：date = `yyyyMMdd`（分隔符 `-` 可通过附加fixed段实现）
- 段3：serial = length 4, reset `day`

### 并发控制机制

```
编码生成并发控制流程：
1. 根据 rule_id + 当前日期周期 拼接 Redis Key
   Key格式: code:serial:{ruleId}:{datePattern}
   示例:    code:serial:1001:20260525

2. 使用 Redis INCR 原子递增获取序号
   Long seq = redisTemplate.opsForValue().increment(key);

3. 若 seq == 1（首次创建Key），设置过期时间
   - 日重置：expire 48h
   - 月重置：expire 35d
   - 年重置：expire 400d
   - 不重置：不设过期时间

4. 补零格式化
   String serial = String.format("%0" + segmentLength + "d", seq);

5. 拼接所有段，返回最终编码
```

**降级策略**：
- Redis不可用时降级为数据库行级锁：`SELECT current_value FROM sys_code_serial WHERE rule_id=? AND period=? FOR UPDATE`
- 更新序号：`UPDATE sys_code_serial SET current_value = current_value + 1 WHERE rule_id=? AND period=?`

### 编码生成API接口

| 方法 | 路径 | 说明 | 请求参数 | 响应 |
|------|------|------|---------|------|
| POST | `/api/sys/code/generate` | 生成编码（消耗序号） | `{ "ruleCode": "sale_order" }` | `{ "code": "SO-20260525-0001" }` |
| GET | `/api/sys/code/preview` | 预览编码（不消耗序号） | `?ruleCode=sale_order` | `{ "preview": "SO-20260525-0043" }` |
| GET | `/api/sys/code/rule/list` | 查询编码规则列表 | 分页参数 | 编码规则分页列表 |
| PUT | `/api/sys/code/rule/update` | 更新编码规则 | 规则完整JSON | 操作结果 |

**编码回退规则**：
- 删除单据 **不回退** 已使用的序号（防止编码复用导致关联混乱）
- 仅在编码生成后、单据保存前发生异常时，通过补偿机制回退：`redisTemplate.opsForValue().decrement(key)`

**审核状态机流转规则**：

```
草稿(0) ──提交──> 待审核(1) ──审核通过──> 已审核(3) ──反审──> 草稿(0)
  │                  │                      │
  │                  ├──驳回──> 已驳回(6)    ├──作废──> 已作废(5) ──撤销作废──> 已审核(3)
  │                  │            │          │
  │                  └──撤回──> 草稿(0)      └──关闭──> 已关闭(4)
  │
  └──删除──> 物理/逻辑删除
```

## 0.7.7 流转引擎详细规范

### 字段映射配置表（sys_flow_mapping）

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | bigint | 是 | 主键 |
| mapping_name | varchar(100) | 是 | 映射名称，如"销售订单→发货单" |
| source_business_type | varchar(50) | 是 | 源单业务类型，如 `sale_order` |
| target_business_type | varchar(50) | 是 | 目标单业务类型，如 `sale_ship` |
| source_table | varchar(100) | 是 | 源单主表名 |
| target_table | varchar(100) | 是 | 目标单主表名 |
| field_mappings | json | 是 | 主表字段映射配置 |
| detail_field_mappings | json | 否 | 从表字段映射配置（从表→从表） |
| quantity_field_mapping | json | 否 | 数量字段映射，用于回写控制 |
| pre_validations | json | 否 | 下推前校验规则 |
| status | tinyint | 是 | 状态：0=禁用，1=启用 |
| tenant_id | bigint | 是 | 租户ID |

**字段映射JSON格式**：

```json
{
  "field_mappings": [
    { "source_field": "customer_id", "target_field": "customer_id", "mapping_type": "direct" },
    { "source_field": "order_no", "target_field": "source_order_no", "mapping_type": "direct" },
    { "source_field": "order_date", "target_field": "source_order_date", "mapping_type": "direct" },
    { "source_field": "", "target_field": "ship_date", "mapping_type": "default", "default_value": "${today}" },
    { "source_field": "aux_prop1", "target_field": "aux_prop1", "mapping_type": "aux" }
  ]
}
```

**mapping_type 枚举**：

| 类型 | 说明 |
|------|------|
| direct | 直接映射，源字段值直接赋给目标字段 |
| default | 默认值，使用 `default_value` 填充 |
| expression | 表达式，使用SpEL计算 |
| aux | 辅助属性映射，含辅助属性1~10的映射 |
| constant | 常量值 |

### 下推前校验规则

```json
{
  "pre_validations": [
    {
      "type": "status_check",
      "required_status": [3],
      "message": "源单必须为已审核状态才能下推"
    },
    {
      "type": "quantity_check",
      "quantity_field": "qty",
      "pushed_quantity_field": "pushed_qty",
      "message": "可下推数量不足"
    },
    {
      "type": "relation_check",
      "check_table": "sale_ship",
      "check_condition": "source_order_id = #{sourceId} AND status = 3",
      "message": "存在已审核的下游单据，不允许重复下推"
    }
  ]
}
```

### 数量回写逻辑

下推成功后，需回写源单的已下推数量：

```sql
-- 回写源单明细行的已下推数量
UPDATE sale_order_detail
SET pushed_qty = pushed_qty + #{pushedQty}
WHERE id = #{sourceDetailId};

-- 当所有明细行的 pushed_qty >= qty 时，更新源单整体状态
UPDATE sale_order
SET flow_status = 'fully_pushed'
WHERE id = #{sourceOrderId}
  AND NOT EXISTS (
    SELECT 1 FROM sale_order_detail
    WHERE order_id = #{sourceOrderId}
      AND pushed_qty < qty
  );
```

### 条件分支规则

条件节点（`node_type=condition`）根据表达式决定走哪个分支：

```json
[
  {
    "branch_name": "金额>10万",
    "condition_expression": "#amount > 100000",
    "next_node_id": 2003
  },
  {
    "branch_name": "金额<=10万",
    "condition_expression": "#amount <= 100000",
    "next_node_id": 2004
  },
  {
    "branch_name": "默认分支",
    "condition_expression": "default",
    "next_node_id": 2005
  }
]
```

**表达式上下文变量**：
- `#amount` — 单据金额
- `#dept` — 发起人部门信息
- `#initiator` — 发起人信息
- 表单中任意字段可通过 `#fieldName` 引用

### 超时处理规则

| timeout_action | 说明 |
|----------------|------|
| remind | 发送催办通知（站内信+钉钉/企微推送） |
| auto_approve | 超时自动通过（需系统参数 `approval.auto_approve_on_timeout=true`） |
| auto_reject | 超时自动驳回 |
| escalate | 超时自动转交给上级审批人 |

**超时检测机制**：
- 使用定时任务扫描：每5分钟扫描一次 `sys_approval_task` 表中状态为 `pending` 且已超时的记录
- 定时任务Key：`job:approval:timeout:check`
- 使用分布式锁防止多实例重复处理：`lock:approval:timeout:{taskId}`
