# 全局规范-缓存使用规范

> 本文档定义ERP系统Redis缓存的Key命名规则、过期策略、一致性保障、防护机制及使用禁止项，所有缓存相关开发必须严格遵守。

---

## 1. Redis Key命名规则

### 1.1 格式定义

统一格式：`erp:{模块}:{资源}:{标识}`

- 全部小写，各层级使用冒号`:`分隔
- `{模块}`为业务模块缩写（如sys/sale/purchase/inv）
- `{资源}`为缓存数据类型（如dict/config/menu/token）
- `{标识}`为具体业务标识（如typeCode/tenantId/userId）

### 1.2 各模块缓存Key清单

#### 系统管理模块（sys）

| Key模式 | 数据类型 | 说明 | 示例 |
|---------|---------|------|------|
| `erp:sys:dict:{typeCode}` | Hash | 字典缓存，field=code，value=名称 | `erp:sys:dict:order_status` |
| `erp:sys:config:{tenantId}` | Hash | 系统参数缓存，field=configKey | `erp:sys:config:1001` |
| `erp:sys:menu:{userId}` | String(JSON) | 用户菜单树缓存 | `erp:sys:menu:1001` |
| `erp:sys:permission:{userId}` | Set | 用户权限标识集合 | `erp:sys:permission:1001` |
| `erp:sys:role:{userId}` | Set | 用户角色标识集合 | `erp:sys:role:1001` |
| `erp:sys:user:{userId}` | Hash | 用户基本信息缓存 | `erp:sys:user:1001` |
| `erp:sys:dept:{deptId}` | Hash | 部门信息缓存 | `erp:sys:dept:2001` |
| `erp:sys:tenant:{tenantId}` | Hash | 租户信息缓存 | `erp:sys:tenant:1001` |

#### 认证授权模块（auth）

| Key模式 | 数据类型 | 说明 | 示例 |
|---------|---------|------|------|
| `erp:auth:token:{token}` | Hash | Sa-Token会话信息 | Sa-Token自动管理 |
| `erp:auth:login:fail:{username}` | String(int) | 登录失败次数（防暴力破解） | `erp:auth:login:fail:admin` |
| `erp:auth:captcha:{uuid}` | String | 图形验证码 | `erp:auth:captcha:a1b2c3d4` |
| `erp:auth:sms:{phone}` | String | 短信验证码 | `erp:auth:sms:13800138000` |
| `erp:auth:online:{userId}` | Set | 用户在线Token集合 | `erp:auth:online:1001` |

#### 商品管理模块（prod）

| Key模式 | 数据类型 | 说明 | 示例 |
|---------|---------|------|------|
| `erp:prod:product:{productId}` | Hash | 商品基本信息缓存 | `erp:prod:product:5001` |

#### 销售管理模块（sale）

| Key模式 | 数据类型 | 说明 | 示例 |

#### 库存管理模块（inv）

| Key模式 | 数据类型 | 说明 | 示例 |
|---------|---------|------|------|

## 2. 缓存过期策略表

| 缓存类型 | Key模式 | TTL | 淘汰策略 | 说明 |
|---------|---------|-----|---------|------|
| 字典缓存 | `erp:sys:dict:{typeCode}` | 24h | 主动失效+TTL兜底 | 修改字典时删除对应typeCode的缓存 |
| 系统参数 | `erp:sys:config:{tenantId}` | 12h | 主动失效+TTL兜底 | 修改参数时删除对应租户的缓存 |
| 用户菜单 | `erp:sys:menu:{userId}` | 2h | 权限变更时主动清除 | 用户菜单/角色变更时清除 |
| 用户权限 | `erp:sys:permission:{userId}` | 2h | 权限变更时主动清除 | 与菜单缓存联动清除 |
| 用户角色 | `erp:sys:role:{userId}` | 2h | 角色变更时主动清除 | 角色分配变更时清除 |
| 用户信息 | `erp:sys:user:{userId}` | 4h | 主动失效+TTL兜底 | 用户信息修改时清除 |
| 部门信息 | `erp:sys:dept:{deptId}` | 12h | 主动失效+TTL兜底 | 部门信息修改时清除 |
| 租户信息 | `erp:sys:tenant:{tenantId}` | 24h | 主动失效+TTL兜底 | 租户配置变更时清除 |
| 登录失败次数 | `erp:auth:login:fail:{username}` | 30min | 登录成功后清除 | 超过5次锁定账号 |
| 图形验证码 | `erp:auth:captcha:{uuid}` | 5min | 验证成功后清除 | 一次性使用 |
| 短信验证码 | `erp:auth:sms:{phone}` | 5min | 验证成功后清除 | 60秒内不可重复发送 |
| 商品信息 | `erp:prod:product:{productId}` | 6h | 主动失效+TTL兜底 | 商品信息修改时清除 |
| 客户商品价格 | `erp:sale:price:{customerId}:{productId}` | 12h | 主动失效+TTL兜底 | 价格变更时清除 |
| 供应商商品价格 | `erp:pur:price:{supplierId}:{productId}` | 12h | 主动失效+TTL兜底 | 价格变更时清除 |
| 实时库存 | `erp:inv:stock:{warehouseId}:{productId}` | 1h | 库存变动时更新 | 高并发场景以DB为准 |
| 分布式锁 | `erp:lock:*` | 30s | 自动过期 | 防止死锁，配合看门狗续期 |
| 限流计数 | `erp:rate:limit:*` | 按窗口 | 窗口到期自动清除 | 如1分钟/1小时窗口 |

## 3. 缓存一致性策略

### 3.1 Cache-Aside模式（标准策略）

**读操作：**

```java
public DictTypeVO getDictType(String typeCode) {
    String key = "erp:sys:dict:" + typeCode;
    // 1. 先查缓存
    DictTypeVO cached = (DictTypeVO) redisTemplate.opsForHash().get(key, "data");
    if (cached != null) {
        return cached;
    }
    // 2. 缓存未命中，查DB
    DictTypeVO data = dictTypeMapper.selectByTypeCode(typeCode);
    // 3. 写入缓存（设置TTL）
    if (data != null) {
        redisTemplate.opsForHash().put(key, "data", data);
        redisTemplate.expire(key, 24, TimeUnit.HOURS);
    }
    return data;
}
```

**写操作（先更新DB再删缓存）：**

```java
@Transactional
public void updateDictType(DictTypeDTO dto) {
    String key = "erp:sys:dict:" + dto.getTypeCode();
    // 1. 先更新数据库
    dictTypeMapper.updateById(dto);
    // 2. 再删除缓存
    redisTemplate.delete(key);
    // 3. 延迟双删（兜底一致性，可选）
    CompletableFuture.runAsync(() -> {
        try {
            Thread.sleep(500);
            redisTemplate.delete(key);
        } catch (InterruptedException ignored) {}
    });
}
```

### 3.2 双写一致规范

| 场景 | 策略 | 说明 |
|------|------|------|
| 字典/系统参数等低频变更 | 先更新DB -> 删缓存 -> 延迟500ms再删缓存 | 延迟双删兜底 |
| 用户菜单/权限 | 更新DB -> 批量删除相关用户缓存 | 权限变更影响范围可控 |
| 库存数量 | 仅缓存做辅助展示，核心扣减走DB事务 | 缓存与DB允许短暂不一致 |
| 高频读取/低频写入 | 更新DB -> 删缓存 -> 发布MQ广播清除各节点缓存 | 多实例部署一致性保障 |

## 4. 缓存穿透/击穿/雪崩防护

### 4.1 缓存穿透防护（查询不存在的数据）

```java
/**
 * 布隆过滤器方案 — 适用于大量ID查询场景
 * 启动时预加载所有有效ID到布隆过滤器
 */
public ProductVO getProduct(Long productId) {
    // 1. 布隆过滤器判断（不存在则一定不存在）
    if (!productBloomFilter.mightContain(productId)) {
        return null;
    }
    // 2. 查缓存
    String key = "erp:prod:product:" + productId;
    ProductVO cached = (ProductVO) redisTemplate.opsForHash().get(key, "data");
    if (cached != null) return cached;
    // 3. 查DB
    ProductVO data = productMapper.selectVoById(productId);
    if (data != null) {
        redisTemplate.opsForHash().put(key, "data", data);
        redisTemplate.expire(key, 6, TimeUnit.HOURS);
    } else {
        // 缓存空对象，防止穿透（短TTL）
        redisTemplate.opsForHash().put(key, "data", new ProductVO());
        redisTemplate.expire(key, 5, TimeUnit.MINUTES);
    }
    return data;
}
```

### 4.2 缓存击穿防护（热点Key过期瞬间大量请求穿透到DB）

```java
/**
 * 互斥锁方案 — 使用Redis分布式锁防止同一时间大量请求穿透到DB
 */
public ProductVO getProductWithLock(Long productId) {
    String key = "erp:prod:product:" + productId;
    ProductVO cached = getFromCache(key);
    if (cached != null) return cached;

    String lockKey = "erp:lock:cache:" + key;
    try {
        // 获取分布式锁，最多等待3秒
        boolean locked = redisLock.tryLock(lockKey, 3, 10, TimeUnit.SECONDS);
        if (locked) {
            // 双重检查
            cached = getFromCache(key);
            if (cached != null) return cached;
            // 查DB并回填缓存
            ProductVO data = productMapper.selectVoById(productId);
            putCache(key, data);
            return data;
        } else {
            // 未获取到锁，短暂休眠后重试缓存
            Thread.sleep(50);
            return getFromCache(key);
        }
    } finally {
        redisLock.unlock(lockKey);
    }
}
```

### 4.3 缓存雪崩防护（大量缓存同时过期导致DB压力骤增）

| 防护措施 | 实现方式 | 说明 |
|---------|---------|------|
| TTL加随机偏移 | `baseTTL + random(0, 300)` 秒 | 避免同一批Key同时过期 |
| 多级缓存 | 本地缓存(Caffeine) + Redis | 本地缓存兜底，降低Redis压力 |
| 限流降级 | Sentinel/自定义限流 | DB压力过大时返回兜底数据 |
| 热点Key永不过期 | 逻辑过期 + 后台异步刷新 | 如字典、系统参数等基础数据 |

```java
/**
 * 随机TTL工具方法
 */
public static long randomTTL(long baseSeconds) {
    return baseSeconds + ThreadLocalRandom.current().nextLong(0, 300);
}
```

## 5. Redis使用禁止项

### 5.1 禁止清单

| 禁止项 | 说明 | 替代方案 |
|--------|------|---------|
| 禁止使用`KEYS`命令 | `KEYS *`会阻塞Redis，生产环境绝对禁止 | 使用`SCAN`命令替代 |
| 禁止大Key（>1MB） | 单个Key的value超过1MB严重影响性能 | 拆分为多个小Key或使用Hash分片 |
| 禁止不设TTL | 不设TTL的Key永不过期，最终撑爆内存 | 所有业务Key必须设置TTL |
| 禁止使用`FLUSHALL`/`FLUSHDB` | 清空整个Redis实例 | 按Key模式精确删除 |
| 禁止在循环中调用Redis | N+1查询模式，网络开销巨大 | 使用Pipeline批量操作或`MGET` |
| 禁止存储敏感原文 | 密码、密钥等不得明文存储 | 加密后存储或脱敏处理 |
| 禁止用Redis做持久化存储 | Redis是缓存，数据可能丢失 | 重要数据必须落DB，Redis仅做加速 |
| 禁止O(N)复杂度命令在大集合上使用 | `SMEMBERS`/`HGETALL`在大集合上会阻塞 | 使用`SSCAN`/`HSCAN`分批读取 |

### 5.2 Redis使用最佳实践

```java
// 正确：Pipeline批量写入
List<Object> results = redisTemplate.executePipelined((RedisCallback<Object>) connection -> {
    for (DictItem item : dictItems) {
        connection.hashCommands().hSet(key.getBytes(), item.getCode().getBytes(), item.getName().getBytes());
    }
    return null;
});

// 错误：循环中逐条写入
for (DictItem item : dictItems) {
    redisTemplate.opsForHash().put(key, item.getCode(), item.getName());
}
```

```java
// 正确：MGET批量读取
List<String> keys = productIds.stream().map(id -> "erp:prod:product:" + id).collect(Collectors.toList());
List<Object> results = redisTemplate.opsForValue().multiGet(keys);

// 错误：循环中逐条读取
for (Long productId : productIds) {
    redisTemplate.opsForValue().get("erp:prod:product:" + productId);
}
```

### 5.3 Key删除工具类

```java
@Component
public class CacheManager {

    @Autowired
    private StringRedisTemplate redisTemplate;

    /** 删除指定Key */
    public void evict(String key) {
        redisTemplate.delete(key);
    }

    /** 按前缀批量删除（使用SCAN，禁止KEYS） */
    public void evictByPrefix(String prefix) {
        Set<String> keys = new HashSet<>();
        ScanOptions options = ScanOptions.scanOptions().match(prefix + "*").count(1000).build();
        try (Cursor<String> cursor = redisTemplate.scan(options)) {
            while (cursor.hasNext()) {
                keys.add(cursor.next());
            }
        }
        if (!keys.isEmpty()) {
            redisTemplate.delete(keys);
        }
    }
}
```
