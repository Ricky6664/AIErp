## 2. Dockerfile标准规范

### 2.1 后端Dockerfile（多阶段构建）

```dockerfile
# ===== 阶段1：构建 =====
FROM maven:3.9-eclipse-temurin-17 AS builder
WORKDIR /build
COPY pom.xml .
RUN mvn dependency:go-offline -B
COPY src ./src
RUN mvn clean package -DskipTests -B

# ===== 阶段2：运行 =====
FROM eclipse-temurin:17-jre-alpine
LABEL maintainer="erp-team"
WORKDIR /app

# 安全：非root用户运行
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
USER appuser

COPY --from=builder /build/target/*.jar app.jar

# JVM参数通过环境变量注入
ENV JAVA_OPTS="-Xms512m -Xmx1024m -XX:+UseG1GC -XX:MaxGCPauseMillis=200"
ENV SPRING_PROFILES_ACTIVE=prod
ENV TZ=Asia/Shanghai

EXPOSE 8080

# 健康检查
HEALTHCHECK --interval=30s --timeout=10s --start-period=60s --retries=3 \
  CMD wget -q --spider http://localhost:8080/actuator/health || exit 1

ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar app.jar --spring.profiles.active=$SPRING_PROFILES_ACTIVE"]
```

### 2.2 前端Dockerfile

```dockerfile
# ===== 阶段1：构建 =====
FROM node:20-alpine AS builder
WORKDIR /build
COPY package.json pnpm-lock.yaml ./
RUN corepack enable && pnpm install --frozen-lockfile
COPY . .
RUN pnpm build

# ===== 阶段2：运行 =====
FROM nginx:1.25-alpine
COPY --from=builder /build/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
HEALTHCHECK --interval=30s --timeout=5s CMD wget -q --spider http://localhost/ || exit 1
```

### 2.3 Dockerfile强制规范

| 规范项 | 要求 |
|--------|------|
| 基础镜像 | 后端统一`eclipse-temurin:17-jre-alpine`，前端统一`nginx:1.25-alpine` |
| 多阶段构建 | 必须使用，构建阶段与运行阶段分离，减小产物体积 |
| 非root运行 | 后端必须创建非root用户运行，禁止以root身份启动Java进程 |
| 层缓存优化 | `COPY pom.xml` → `mvn dependency:go-offline` → `COPY src`，利用Docker缓存层 |
| 健康检查 | 必须配置HEALTHCHECK，后端检查`/actuator/health`，前端检查`/` |
| 时区设置 | 统一设置`TZ=Asia/Shanghai` |
| .dockerignore | 必须配置，排除`.git/`、`node_modules/`、`target/`、`*.log`等 |

## 3. docker-compose标准配置

### 3.1 开发环境（docker-compose.dev.yml）

```yaml
version: '3.8'
services:
  postgres:
    image: postgres:15-alpine
    environment:
      POSTGRES_DB: erp_dev
      POSTGRES_USER: erp
      POSTGRES_PASSWORD: ${DB_PASSWORD:-erp_dev_2024}
    ports: ["5432:5432"]
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U erp -d erp_dev"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    command: redis-server --requirepass ${REDIS_PASSWORD:-redis_dev_2024}
    ports: ["6379:6379"]
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "${REDIS_PASSWORD:-redis_dev_2024}", "ping"]
      interval: 10s

  elasticsearch:
    image: elasticsearch:8.12.0
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=false
      - ES_JAVA_OPTS=-Xms512m -Xmx512m
    ports: ["9200:9200"]

  minio:
    image: minio/minio:RELEASE.2024-11-07T00-52-20Z
    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: ${MINIO_USER:-minioadmin}
      MINIO_ROOT_PASSWORD: ${MINIO_PASSWORD:-minioadmin}
    ports:
      - "9000:9000"
      - "9001:9001"

  rabbitmq:
    image: rabbitmq:3.12-management-alpine
    environment:
      RABBITMQ_DEFAULT_USER: ${RABBITMQ_USER:-erp}
      RABBITMQ_DEFAULT_PASS: ${RABBITMQ_PASSWORD:-erp_dev_2024}
    ports:
      - "5672:5672"
      - "15672:15672"

volumes:
  pgdata:
```

### 3.2 生产环境关键差异

| 配置项 | 开发环境 | 生产环境 |
|--------|---------|---------|
| PostgreSQL | 单节点 | 主从复制，连接池PgBouncer |
| Redis | 单节点 | Sentinel哨兵模式（3节点） |
| Elasticsearch | 单节点，安全关闭 | 3节点集群，安全开启，业务ES与ELK日志ES分离 |
| RabbitMQ | 单节点 | 镜像队列集群（3节点） |
| MinIO | 单节点 | 纠删码模式（4节点） |
| 后端服务 | 1副本 | 2+副本，Nginx负载均衡 |
| 密码管理 | `.env`文件 | 环境变量/Vault/K8s Secret |

## 5. CI/CD Pipeline标准流程

### 5.1 标准流水线阶段

```
代码提交 → 代码扫描 → 单元测试 → 构建打包 → 镜像推送 → 部署
   │          │          │          │          │         │
   │       ESLint     Vitest     Maven      Docker    Docker
   │       SonarQube  JaCoCo     Package    Push      Compose/K8s
   │                  覆盖率>80%
```

### 5.2 各阶段详细规范

| 阶段 | 工具 | 通过条件 | 超时 |
|------|------|---------|------|
| 代码扫描 | ESLint + SonarQube | 0个Critical/Blocker，代码异味<50 | 5min |
| 单元测试 | Vitest(前端) + JUnit(后端) | 通过率100%，覆盖率≥80% | 10min |
| 构建打包 | Maven(后端) + pnpm build(前端) | 构建成功，产物完整 | 10min |
| 镜像构建 | Docker Build | 镜像构建成功，体积<500MB | 5min |
| 镜像推送 | Docker Push | 推送至私有Registry成功 | 5min |
| 部署 | Docker Compose / K8s | 健康检查通过，服务可访问 | 10min |

### 5.3 分支策略

| 分支 | 用途 | 触发部署 |
|------|------|---------|
| `main` | 生产代码 | 合并触发→生产部署 |
| `develop` | 开发集成 | 推送触发→测试环境部署 |
| `feature/*` | 功能开发 | PR触发→CI检查 |
| `release/*` | 发布准备 | 创建触发→预生产部署 |
| `hotfix/*` | 紧急修复 | 合并触发→生产热修复 |

## 6. 健康检查与监控

### 6.1 健康检查端点

```yaml
# application.yml 配置
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,prometheus
  endpoint:
    health:
      show-details: when-authorized
      show-components: when-authorized
```

| 端点 | 用途 | 访问权限 |
|------|------|---------|
| `/actuator/health` | 健康状态（UP/DOWN） | 公开（Docker健康检查用） |
| `/actuator/info` | 应用信息（版本/构建时间） | 公开 |
| `/actuator/metrics` | JVM/业务指标 | 需认证 |
| `/actuator/prometheus` | Prometheus采集端点 | 内网可访问 |

### 6.2 监控指标规范

| 指标类别 | 采集工具 | 关键指标 |
|---------|---------|---------|
| JVM指标 | Micrometer + Prometheus | 堆内存、GC次数/耗时、线程数 |
| HTTP指标 | Spring Boot Actuator | QPS、响应时间P95/P99、错误率 |
| 数据库指标 | HikariCP + Prometheus | 连接池使用率、慢查询数量 |
| 业务指标 | 自定义Counter/Gauge | 单据创建数、审核通过率、编码生成次数 |
| 系统指标 | Node Exporter | CPU、内存、磁盘、网络IO |

### 6.3 告警规则

| 告警项 | 阈值 | 级别 | 通知方式 |
|--------|------|------|---------|
| 服务宕机 | health=DOWN持续1min | P0-紧急 | 短信+钉钉 |
| CPU使用率 | >80%持续5min | P1-重要 | 钉钉 |
| 内存使用率 | >85%持续5min | P1-重要 | 钉钉 |
| 磁盘使用率 | >90% | P1-重要 | 钉钉 |
| HTTP错误率 | 5xx>1%持续3min | P1-重要 | 钉钉 |
| 响应时间P99 | >3s持续5min | P2-常规 | 钉钉 |
| 连接池耗尽 | active>=max-2 | P1-重要 | 钉钉 |

## 7. Nginx反向代理规范

### 7.1 标准配置模板

```nginx
upstream erp_backend {
    least_conn;
    server backend-1:8080 max_fails=3 fail_timeout=30s;
    server backend-2:8080 max_fails=3 fail_timeout=30s;
}

server {
    listen 443 ssl http2;
    server_name erp.example.com;

    # SSL配置
    ssl_certificate /etc/ssl/certs/erp.crt;
    ssl_certificate_key /etc/ssl/private/erp.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # 前端静态资源
    location / {
        root /usr/share/nginx/html;
        try_files $uri $uri/ /index.html;
        expires 30d;
    }

    # 后端API代理
    location /api/ {
        proxy_pass http://erp_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 10s;
        proxy_read_timeout 60s;
        client_max_body_size 50m;
    }

    # WebSocket代理
    location /ws/ {
        proxy_pass http://erp_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
    }
}

# HTTP重定向HTTPS
server {
    listen 80;
    server_name erp.example.com;
    return 301 https://$host$request_uri;
}
```

## 8. 环境变量管理规范

| 规范项 | 要求 |
|--------|------|
| 敏感信息 | 数据库密码、Redis密码、API Key等**禁止硬编码**，必须通过环境变量注入 |
| 命名规范 | 全大写下划线分隔，前缀标识模块：`DB_PASSWORD`、`REDIS_HOST`、`MINIO_ACCESS_KEY` |
| 环境隔离 | 各环境使用独立的`.env.{profile}`文件，生产环境禁止使用`.env`文件 |
| 默认值 | 非敏感配置项可在Dockerfile中设置合理默认值 |
| 文档化 | 所有环境变量必须在`docs/env-reference.md`中登记说明 |

### 8.1 标准环境变量清单

| 变量名 | 说明 | 示例值 |
|--------|------|--------|
| `SPRING_PROFILES_ACTIVE` | 运行环境 | dev/test/staging/prod |
| `DB_HOST` / `DB_PORT` / `DB_NAME` | 数据库连接 | postgres / 5432 / erp_prod |
| `DB_USERNAME` / `DB_PASSWORD` | 数据库认证 | erp / (环境变量注入) |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` | Redis连接 | redis-sentinel / 26379 / (注入) |
| `RABBITMQ_HOST` / `RABBITMQ_USER` / `RABBITMQ_PASSWORD` | RabbitMQ连接 | rabbitmq / erp / (注入) |
| `MINIO_ENDPOINT` / `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | MinIO连接 | minio:9000 / (注入) |
| `JAVA_OPTS` | JVM参数 | -Xms512m -Xmx1024m |

## 10. 数据库备份与恢复

| 策略 | 频率 | 保留期 | 工具 |
|------|------|--------|------|
| 全量备份 | 每日凌晨2:00 | 30天 | pg_dump + cron |
| 增量备份(WAL) | 实时归档 | 7天 | pgBackRest / WAL-G |
| Redis快照 | 每6小时 | 7天 | redis-cli BGSAVE |
| MinIO版本 | 对象版本控制 | 30天 | MinIO版本控制功能 |

### 10.1 备份验证

- **每月**执行一次备份恢复演练
- 验证恢复后数据完整性（表数量、记录数、关键业务数据）
- 记录恢复耗时，确保RTO（恢复时间目标）<4小时
