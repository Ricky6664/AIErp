# 全局规范-错误码体系规范

> 本文档定义ERP系统错误码编码规则、统一异常响应结构、前后端错误处理规范，所有模块的错误码定义与使用必须严格遵守。

---

## 1. 错误码编码规则

### 1.1 格式定义

错误码采用**6位纯数字**编码，格式：`{分类前缀}{模块编号}{序号}`

| 位数 | 含义 | 说明 |
|------|------|------|
| 第1~2位 | 错误分类 | 标识错误所属层级（系统/参数/业务/认证） |
| 第3~4位 | 模块编号 | 标识错误所属业务模块 |
| 第5~6位 | 序号 | 模块内错误序号，从01开始递增 |

### 1.2 分类前缀分配

| 前缀范围 | 分类 | 说明 |
|---------|------|------|
| `10xxxx` | 系统级错误 | 系统基础设施错误（网络/中间件/框架/数据库等） |
| `20xxxx` | 参数级错误 | 请求参数校验失败（格式/范围/必填/类型等） |
| `30xxxx`~`60xxxx` | 业务级错误 | 业务逻辑错误（按模块分段分配） |
| `90xxxx` | 认证级错误 | 认证授权相关错误（登录/Token/权限等） |

**编码规则要点：**

- 每个错误码全系统唯一，不允许重复
- 新增错误码时必须在对应模块的错误码枚举类中统一定义
- 废弃的错误码标记`@Deprecated`，不得复用给新错误
- 序号`00`保留为模块通用错误（如"操作失败"），业务序号从`01`开始

## 3. 统一异常响应结构

### 3.1 响应JSON格式

全系统所有错误统一通过`R.fail(code, message)`返回，HTTP状态码始终为200（业务错误码由`code`字段承载）。

**成功响应：**

```json
{
  "code": 200,
  "message": "success",
  "data": { "id": 1001 },
  "timestamp": 1716800000000
}
```

**参数错误响应：**

```json
{
  "code": 200001,
  "message": "客户名称不能为空",
  "data": null,
  "timestamp": 1716800000000
}
```

**业务错误响应：**

```json
{
  "code": 310001,
  "message": "销售订单数量超出可用库存",
  "data": null,
  "timestamp": 1716800000000
}
```

**认证错误响应：**

```json
{
  "code": 900001,
  "message": "未登录或登录已过期，请重新登录",
  "data": null,
  "timestamp": 1716800000000
}
```

### 3.2 异常抛出规范

```java
// 方式一：通过ErrorCode枚举抛出（推荐）
throw new BusinessException(ErrorCode.SALE_ORDER_QTY_EXCEED);

// 方式二：带动态参数的错误消息
throw new BusinessException(ErrorCode.SALE_ORDER_QTY_EXCEED, "可用库存=" + availableQty);

// 方式三：自定义code和message（仅临时场景使用）
throw new BusinessException(310099, "自定义业务错误描述");
```

### 4.2 业务异常类定义

```java
@Getter
public class BusinessException extends RuntimeException {
    private final int code;

    public BusinessException(ErrorCode errorCode) {
        super(errorCode.getMessage());
        this.code = errorCode.getCode();
    }

    public BusinessException(ErrorCode errorCode, String detail) {
        super(errorCode.getMessage() + "：" + detail);
        this.code = errorCode.getCode();
    }

    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
    }
}
```

### 4.3 全局异常处理器

```java
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    /** 业务异常 */
    @ExceptionHandler(BusinessException.class)
    public R<Void> handleBusiness(BusinessException e) {
        log.warn("业务异常 code={}, message={}", e.getCode(), e.getMessage());
        return R.fail(e.getCode(), e.getMessage());
    }

    /** 参数校验异常（@Valid / @Validated） */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public R<Void> handleValid(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
            .map(f -> f.getField() + ": " + f.getDefaultMessage())
            .collect(Collectors.joining("; "));
        return R.fail(ErrorCode.PARAM_FORMAT_ERROR.getCode(), msg);
    }

    /** Sa-Token权限异常 */
    @ExceptionHandler(NotLoginException.class)
    public R<Void> handleNotLogin(NotLoginException e) {
        return R.fail(ErrorCode.AUTH_NOT_LOGIN.getCode(), ErrorCode.AUTH_NOT_LOGIN.getMessage());
    }

    @ExceptionHandler(NotPermissionException.class)
    public R<Void> handleNotPermission(NotPermissionException e) {
        return R.fail(ErrorCode.AUTH_NO_PERMISSION.getCode(), ErrorCode.AUTH_NO_PERMISSION.getMessage());
    }

    /** 未知异常兜底 */
    @ExceptionHandler(Exception.class)
    public R<Void> handleException(Exception e) {
        log.error("系统异常", e);
        return R.fail(ErrorCode.SYS_ERROR.getCode(), ErrorCode.SYS_ERROR.getMessage());
    }
}
```

## 5. 前端错误码处理规范

### 5.1 Axios响应拦截器

```typescript
// src/utils/request.ts
import axios from 'axios';
import { ElMessage } from 'element-plus';
import { useUserStore } from '@/stores/user';

const service = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 30000,
});

service.interceptors.response.use(
  (response) => {
    const { code, message, data } = response.data;

    // 成功
    if (code === 200) return data;

    // 认证级错误 -> 跳转登录
    if (code >= 900000 && code < 910000) {
      const userStore = useUserStore();
      userStore.logout();
      ElMessage.error(message || '登录已过期，请重新登录');
      return Promise.reject(new Error(message));
    }

    // 参数级错误 -> 表单字段高亮提示
    if (code >= 200000 && code < 210000) {
      ElMessage.warning(message);
      return Promise.reject(new Error(message));
    }

    // 业务级错误 -> 普通错误提示
    if (code >= 300000 && code < 700000) {
      ElMessage.error(message);
      return Promise.reject(new Error(message));
    }

    // 系统级错误 -> 严重错误提示
    if (code >= 100000 && code < 200000) {
      ElMessage.error('系统繁忙，请稍后重试');
      return Promise.reject(new Error(message));
    }

    // 未知错误
    ElMessage.error(message || '未知错误');
    return Promise.reject(new Error(message));
  },
  (error) => {
    // 网络级错误
    if (error.response) {
      const status = error.response.status;
      const msgMap: Record<number, string> = {
        401: '未授权，请重新登录',
        403: '拒绝访问',
        404: '请求资源不存在',
        500: '服务器内部错误',
      };
      ElMessage.error(msgMap[status] || `请求失败(${status})`);
    } else {
      ElMessage.error('网络连接异常，请检查网络');
    }
    return Promise.reject(error);
  }
);

export default service;
```

### 5.2 错误码常量管理

```typescript
// src/constants/errorCode.ts
export const ErrorCode = {
  // 系统级
  SYS_ERROR: 100000,
  SYS_DB_ERROR: 100001,

  // 参数级
  PARAM_MISSING: 200001,
  PARAM_FORMAT_ERROR: 200002,

  // 认证级
  AUTH_NOT_LOGIN: 900001,
  AUTH_TOKEN_EXPIRED: 900002,
  AUTH_NO_PERMISSION: 900004,
} as const;

/** 判断是否为认证错误（需要跳转登录） */
export function isAuthError(code: number): boolean {
  return code >= 900000 && code < 910000;
}

/** 判断是否为参数错误（需要表单提示） */
export function isParamError(code: number): boolean {
  return code >= 200000 && code < 210000;
}
```

### 5.3 业务层错误码处理示例

```typescript
// 提交销售订单，针对特定错误码做特殊处理
async function submitOrder(data: SaleOrderDTO) {
  try {
    await api.post('/api/sale/order', data);
    ElMessage.success('提交成功');
  } catch (err: any) {
    // 特定业务错误码 -> 弹窗提示并引导操作
    if (err.code === ErrorCode.SALE_ORDER_QTY_EXCEED) {
      ElMessageBox.confirm('库存不足，是否跳转到库存查询？', '提示', {
        confirmButtonText: '查看库存',
        cancelButtonText: '取消',
      }).then(() => router.push('/inv/stock'));
    }
    // 其他错误已由拦截器统一处理，此处可不再重复提示
  }
}
```
