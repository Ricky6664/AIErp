# 全局规范 - 末端任务文档编写规范

> **适用范围**：本文档规定所有末端（叶子）任务文档的标准化编写模板与质量要求。
> **文档定位**：确保每一份末端任务文档包含足够具体的信息，使AI仅凭当前任务文档+对应层级规范即可独立完成开发。

---

## 1. 核心原则

| 原则 | 说明 |
|------|------|
| 自包含 | 每份任务文档必须包含完成任务所需的全部信息，禁止出现"参见设计文档"、"根据设计文档确定"等外部引用 |
| 具体化 | 禁止使用占位文本（如"相关源代码文件"、"按任务要求开发"），所有内容必须具体到文件名、字段名、方法名 |
| 可验证 | 验收标准必须包含可量化或可检查的具体指标，禁止使用"所有功能点已实现且通过验证"等模糊描述 |
| 类型适配 | 不同任务类型使用对应模板，禁止套用错误类型的模板内容 |

---

## 2. 任务类型分类

所有末端任务按以下6种类型分类，每种类型使用专属模板：

| 类型编码 | 任务类型 | 典型任务示例 |
|---------|---------|------------|
| DDL | 数据库建表任务 | 编写CREATE TABLE语句、编写索引、编写Flyway迁移脚本 |
| ENTITY | 实体/模型定义任务 | 定义Entity类、定义DTO类、定义VO类 |
| MAPPER | 数据访问层任务 | 编写Mapper接口、编写XML映射文件 |
| SERVICE | 业务逻辑层任务 | 编写Service接口、编写ServiceImpl、编写业务校验逻辑 |
| CONTROLLER | 接口层任务 | 编写Controller类、实现具体API接口 |
| FRONTEND | 前端页面/组件任务 | 编写列表页、编写表单页、编写组件 |
| DEVOPS | 部署/配置/DevOps任务 | 编写Dockerfile、配置Nginx、配置CI/CD |
| CONFIG | 配置/规范文档任务 | 编写配置文件、编写规范文档 |

编写OrgCompanyMapper接口：继承BaseMapper<OrgCompanyEntity>，@Mapper注解，定义selectPageWithDeptCount(Page,CompanyQueryDTO)自定义分页查询(关联org_department统计部门数量)、selectByCreditCode(String)按信用代码精确查询，使用LambdaQueryWrapper构造动态条件
```

### 5.2 Section 5 详细开发规格

```markdown
### 5.1 接口定义

| 属性 | 值 |
|------|-----|
| 接口名 | OrgCompanyMapper |
| 注解 | @Mapper |
| 继承 | BaseMapper<OrgCompanyEntity> |
| 泛型实体 | OrgCompanyEntity |

### 5.2 自定义SQL

| 方法签名 | SQL类型 | 实现方式 | 说明 |
|---------|---------|---------|------|
| selectByCreditCode(String creditCode) | @Select | 注解SQL | 按信用代码精确查询 |
| selectPageWithDeptCount(Page, CompanyQueryDTO) | SELECT | XML映射 | 关联部门表统计 |
| batchUpdateStatus(List<Long> ids, Boolean enabled) | @Update | 注解SQL | 批量更新状态 |

### 5.3 复杂查询

| 查询类型 | 实现方式 | 关键要点 |
|---------|---------|---------|
| 多表JOIN | XML映射文件 | JOIN不超过5张表，明确ON条件 |
| 动态条件 | LambdaQueryWrapper | 链式调用，eq/like/between组合 |
| 分页查询 | Page<Entity>参数 | MyBatis-Plus分页插件自动处理 |
| 动态SQL | XML中<if>/<where>/<foreach> | 使用#{param}防注入 |

### 5.4 类型处理器

| TypeHandler | 适用场景 | 注册方式 |
|------------|---------|---------|
| JacksonTypeHandler | JSON字段(List/Map存储) | @TableField(typeHandler=...) |
| EnumTypeHandler | 枚举字段 | MyBatis-Plus全局配置 |
```

### 5.3 Section 6 交付物清单

**正确示例**：
```
| 1 | src/main/java/com/erp/module/org/mapper/OrgCompanyMapper.java | Mapper接口 |
| 2 | src/main/resources/mapper/org/OrgCompanyMapper.xml | XML映射文件(如有自定义SQL) |
```

### 5.4 Section 7 验收标准

**正确示例**：
```
| 1 | 继承BaseMapper | 泛型为对应Entity类型 |
| 2 | @Mapper注解 | 接口类上@Mapper注解存在 |
| 3 | 自定义SQL语法正确 | SQL无语法错误，使用#{param}参数占位符 |
| 4 | 无SQL注入风险 | 所有动态参数使用#{}而非${} |
| 5 | 分页查询正确 | 使用Page对象，分页插件生效 |
| 6 | LambdaQueryWrapper | 条件构造正确，空值条件判空处理 |
| 7 | XML命名空间一致 | namespace与Mapper接口全限定名一致 |
```

### 5.5 Section 8 易错警示

```
> ⚠️ 禁止在Mapper中写业务逻辑，Mapper只负责数据访问
> ⚠️ 多表JOIN不超过5张表，超过应拆分查询或使用ES
> ⚠️ 动态SQL使用#{param}而非${param}防注入
> ⚠️ XML映射文件namespace必须与Mapper接口全限定名一致
> ⚠️ 分页查询必须使用Page对象，不要手动LIMIT/OFFSET
> ⚠️ LambdaQueryWrapper条件注意空值判断，避免空条件全表扫描
```

## 9. DEVOPS类型任务模板

### 9.1 Section 2 任务目标（必须具体）

编写后端Dockerfile：使用maven:3.9-eclipse-temurin-17构建阶段+eclipse-temurin:17-jre运行阶段、JAR分层、创建非root用户(erp:1001)、暴露8080端口、设置JVM参数(-Xms512m -Xmx1024m)、HEALTHCHECK配置
```

### 9.2 Section 5 详细开发规格

```markdown
### 5.1 文件内容

```dockerfile
# Stage 1: Build
FROM maven:3.9-eclipse-temurin-17 AS builder
WORKDIR /build
COPY pom.xml .
RUN mvn dependency:go-offline -B
COPY src ./src
RUN mvn package -DskipTests -B

# Stage 2: Runtime
FROM eclipse-temurin:17-jre
RUN groupadd -r erp && useradd -r -g erp -u 1001 erp
WORKDIR /app
COPY --from=builder /build/target/*.jar app.jar
RUN chown -R erp:erp /app
USER erp
EXPOSE 8080
HEALTHCHECK --interval=30s --timeout=3s CMD curl -f http://localhost:8080/actuator/health || exit 1
ENTRYPOINT ["java", "-Xms512m", "-Xmx1024m", "-jar", "app.jar"]
```

### 5.2 关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 基础镜像 | eclipse-temurin:17 | 与项目JDK17一致，体积小 |
| 分层构建 | 依赖层+代码层分离 | 利用Docker缓存加速构建 |
| 非root用户 | erp:1001 | 安全最佳实践 |
| 健康检查 | /actuator/health | Spring Boot原生支持 |

### 5.3 验证

1. `docker build -t erp-server .` 构建成功
2. `docker run -p 8080:8080 erp-server` 启动成功
3. `curl http://localhost:8080/actuator/health` 返回UP
4. 容器内进程以erp用户运行（非root）
```

| Environment | 运行时动态获取 | env.getProperty("erp.app.app-name") |

### 5.3 环境差异

| 环境 | Profile | 差异项 |
|------|---------|--------|
| dev | application-dev.yml | 调试日志开启、AI功能全开、上传限制50MB |
| test | application-test.yml | 测试数据库、Mock外部服务 |
| staging | application-staging.yml | 接近生产配置、性能测试参数 |
| prod | application-prod.yml | 生产日志级别、安全配置、限流参数 |

### 5.4 校验规则

| 校验项 | 校验注解 | 校验逻辑 |
|--------|---------|---------|
| appName非空 | @NotBlank | 应用名称不能为空 |
| maxUploadSize范围 | @Min(1048576) @Max(104857600) | 1MB~100MB之间 |
| 自定义校验 | @ConfigurationProperties + @Validated | 配置类上添加@Validated启用校验 |
```

## 13. 易错警示规范

### 13.1 通用必含警示（所有任务默认携带）

```
> ⚠️ 代码中禁止硬编码密码、密钥、数据库连接串等敏感信息
> ⚠️ 所有查询必须包含tenant_id条件（由MyBatis-Plus插件自动注入）
> ⚠️ 所有删除操作使用逻辑删除（is_deleted=true），禁止物理DELETE
```

### 13.2 类型专属警示

**DDL任务追加**：
```
> ⚠️ 唯一索引必须加WHERE is_deleted = false条件（部分唯一索引）
> ⚠️ 金额/单价/数量字段统一使用decimal(18,8)
> ⚠️ 时间字段统一使用timestamp类型
> ⚠️ Flyway迁移文件一旦发布禁止修改，只能通过新迁移文件修正
```

**Entity任务追加**：
```
> ⚠️ 使用LocalDateTime而非Date
> ⚠️ 必须实现Serializable接口
> ⚠️ @TableField注解不可遗漏，确保Java驼峰与DB下划线正确映射
> ⚠️ 通用字段通过继承BaseEntity获取，不要在Entity中重复定义
```

**Service任务追加**：
```
> ⚠️ @Transactional加在具体实现方法上，不要加在接口方法上
> ⚠️ 避免大事务：只读查询方法加readOnly=true，或使用@Transactional(propagation=NOT_SUPPORTED)
> ⚠️ 业务异常统一使用throw new BusinessException(ErrorCode.XXX, "具体提示")
> ⚠️ 编码引擎调用必须幂等，防止重复生成
```

**Controller任务追加**：
```
> ⚠️ 所有接口必须添加@SaCheckPermission注解进行权限校验
> ⚠️ 使用@Valid触发DTO校验，不要在Controller中手动校验
> ⚠️ 返回统一使用Result<T>包装，禁止直接返回Entity
> ⚠️ @Operation(summary="...") Knife4j文档注解不可遗漏
```

**Frontend任务追加**：
```
> ⚠️ 操作按钮必须使用v-permission指令控制权限可见性
> ⚠️ API调用统一使用useApi composable，不要直接调用axios
> ⚠️ 表格数据加载使用useTable composable统一管理分页/排序/筛选
> ⚠️ 表单提交前使用validate()方法校验，不要跳过校验直接提交
```

**DevOps任务追加**：
```
> ⚠️ Docker镜像使用非root用户运行
> ⚠️ 敏感配置通过环境变量注入，不要写入Dockerfile或配置文件

**Mapper任务追加**：

> ⚠️ 禁止在Mapper中写业务逻辑
> ⚠️ 多表JOIN不超过5张表
> ⚠️ 动态SQL使用#{param}而非${param}防注入
> ⚠️ XML命名空间与Mapper接口全限定名一致

**Config任务追加**：

## 14. 跨任务类型处理指南

当一个末端任务涉及多个层级的代码变更（例如同时需要Service + Mapper + Controller修改），按以下原则处理：

### 14.1 识别主任务类型和辅任务类型

| 判断依据 | 说明 |
|---------|------|
| 任务目标核心 | 任务目标描述中最核心的变更对象所属类型为主类型 |
| 代码量占比 | 代码变更量最大的层级所属类型为主类型 |
| 交付物主体 | 主要交付物所属的类型为主类型 |

**示例**：任务"为订单审核功能添加审核意见字段"涉及DDL加字段 + Entity加属性 + Mapper适配 + Service加逻辑 + Controller改接口，主任务类型为SERVICE（业务逻辑是核心），辅任务类型为DDL/ENTITY/MAPPER/CONTROLLER。

### 14.2 模板选用原则

- **以主任务类型的模板为主框架**：Section 2任务目标、Section 5详细开发规格以主任务类型模板格式编写
- **辅任务类型的交付物在交付物清单中完整列出**：Section 6交付物清单包含所有涉及层级的文件
- **验收标准覆盖所有涉及的层级**：Section 7验收标准逐层验证，确保端到端正确

### 14.3 跨类型任务文档结构示例

```markdown
