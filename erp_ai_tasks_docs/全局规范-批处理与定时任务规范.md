# 全局规范-批处理与定时任务规范

## 3. 任务参数规范

### 3.1 JSON参数格式

所有JobHandler的任务参数统一使用JSON格式：

```json
{
  "tenantId": 1001,
  "dateRange": {
    "start": "2025-05-01",
    "end": "2025-05-26"
  },
  "batchSize": 1000,
  "extraParams": {
    "status": "pending",
    "warehouseId": 201
  }
}
```

### 3.2 参数定义

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| tenantId | Long | 否 | 租户ID，为空时遍历所有租户 |
| dateRange | Object | 否 | 日期范围（start/end），为空时使用默认范围 |
| batchSize | Integer | 否 | 每批次处理条数，默认1000，可通过sys_param配置 |
| extraParams | Object | 否 | 业务自定义参数 |

### 3.3 参数解析工具

```java
/**
 * Job参数解析工具
 */
public class JobParamParser {

    /**
     * 解析Job参数为标准化上下文
     */
    public static JobContext parseContext(String jobParam) {
        JobContext context = new JobContext();
        if (jobParam == null || jobParam.isBlank()) {
            return context.withDefaults();
        }

        try {
            JsonNode json = JsonUtil.readTree(jobParam);

            // 解析tenantId
            if (json.has("tenantId") && !json.get("tenantId").isNull()) {
                context.setTenantId(json.get("tenantId").asLong());
            }

            // 解析dateRange
            if (json.has("dateRange")) {
                JsonNode range = json.get("dateRange");
                context.setStartDate(LocalDate.parse(range.get("start").asText()));
                context.setEndDate(LocalDate.parse(range.get("end").asText()));
            }

            // 解析batchSize
            if (json.has("batchSize")) {
                context.setBatchSize(json.get("batchSize").asInt());
            }

            // 解析extraParams
            if (json.has("extraParams")) {
                context.setExtraParams(JsonUtil.toObject(json.get("extraParams"), Map.class));
            }

        } catch (Exception e) {
            XxlJobHelper.log("任务参数解析失败: " + e.getMessage());
            throw new JobParamException("任务参数格式错误", e);
        }

        return context.withDefaults();
    }
}
```

### 3.4 默认参数值

```java
@Data
public class JobContext {
    private Long tenantId;
    private LocalDate startDate;
    private LocalDate endDate;
    private int batchSize = 1000;
    private Map<String, Object> extraParams = new HashMap<>();

    // 运行时状态
    private long totalCount = 0;
    private long processCount = 0;
    private long successCount = 0;
    private long failCount = 0;
    private List<String> errors = new ArrayList<>();

    public JobContext withDefaults() {
        if (batchSize <= 0) batchSize = 1000;
        if (startDate == null) startDate = LocalDate.now().minusDays(1);
        if (endDate == null) endDate = LocalDate.now();
        return this;
    }

    public void incrementSuccess() { this.successCount++; this.processCount++; }
    public void incrementFail() { this.failCount++; this.processCount++; }
}
```

## 4. BaseJobHandler模板方法

### 4.1 抽象基类

```java
/**
 * 批处理任务基类 — 模板方法模式
 * 所有JobHandler必须继承此类，实现processChunk方法
 */
public abstract class BaseJobHandler {

    protected final Logger log = LoggerFactory.getLogger(getClass());

    @Autowired
    private SysJobExecutionMapper jobExecutionMapper;

    @Autowired
    private TenantService tenantService;

    /**
     * XXL-JOB入口方法（子类通过@XxlJob注解标记）
     */
    public ReturnT<String> execute() {
        String jobParam = XxlJobHelper.getJobParam();
        String jobHandler = XxlJobHelper.getGlueType();
        long jobId = XxlJobHelper.getJobId();

        // 1. 解析参数
        JobContext context = JobParamParser.parseContext(jobParam);

        // 2. 记录执行日志
        SysJobExecution execution = createExecution(jobId, jobHandler, context);
        jobExecutionMapper.insert(execution);

        try {
            // 3. 前置处理
            preProcess(context);

            // 4. 获取租户列表
            List<Long> tenantIds = resolveTenantIds(context);

            // 5. 遍历租户执行
            for (Long tenantId : tenantIds) {
                context.setTenantId(tenantId);
                TenantContext.setTenantId(tenantId);

                try {
                    executeForTenant(context);
                } catch (Exception e) {
                    log.error("租户{}执行失败", tenantId, e);
                    context.getErrors().add("租户" + tenantId + ": " + e.getMessage());
                } finally {
                    TenantContext.clear();
                }
            }

            // 6. 后置处理
            postProcess(context);

            // 7. 更新执行日志
            execution.setStatus(context.getFailCount() > 0 ? "PARTIAL" : "SUCCESS");
            execution.setEndTime(LocalDateTime.now());
            execution.setProcessCount(context.getProcessCount());
            execution.setFailCount(context.getFailCount());
            execution.setErrorMsg(context.getErrors().isEmpty() ? null :
                String.join("\n", context.getErrors()));
            jobExecutionMapper.updateById(execution);

            String summary = String.format("处理完成: 总计%d, 成功%d, 失败%d",
                context.getProcessCount(), context.getSuccessCount(), context.getFailCount());
            XxlJobHelper.log(summary);
            return context.getFailCount() > 0
                ? new ReturnT<>(ReturnT.FAIL_CODE, summary)
                : ReturnT.SUCCESS;

        } catch (Exception e) {
            log.error("任务执行异常", e);
            execution.setStatus("FAILED");
            execution.setEndTime(LocalDateTime.now());
            execution.setErrorMsg(e.getMessage());
            jobExecutionMapper.updateById(execution);
            XxlJobHelper.log("任务执行异常: " + e.getMessage());
            return new ReturnT<>(ReturnT.FAIL_CODE, e.getMessage());
        }
    }

    /**
     * 按租户执行（内部分块处理）
     */
    private void executeForTenant(JobContext context) {
        int offset = 0;
        int batchSize = context.getBatchSize();

        while (true) {
            // 分片查询
            LambdaQueryWrapper<?> wrapper = buildQueryWrapper(context);
            List<?> chunk = fetchChunk(wrapper, offset, batchSize);

            if (chunk == null || chunk.isEmpty()) {
                break;
            }

            context.setTotalCount(context.getTotalCount() + chunk.size());
            XxlJobHelper.log("租户{}: 处理第{}批, 本批{}条",
                context.getTenantId(), offset / batchSize + 1, chunk.size());

            // 分块处理（子类实现）
            try {
                processChunk((List) chunk, context);
            } catch (Exception e) {
                log.error("租户{}: 第{}批处理失败",
                    context.getTenantId(), offset / batchSize + 1, e);
                onError(chunk, e, context);
            }

            if (chunk.size() < batchSize) {
                break; // 最后一批
            }
            offset += batchSize;
        }
    }

    // ========== 子类必须/可选实现的方法 ==========

    /**
     * 【必须实现】构建查询条件
     */
    protected abstract LambdaQueryWrapper<?> buildQueryWrapper(JobContext context);

    /**
     * 【必须实现】处理单个分块
     * 注意：每个chunk在独立事务中执行，事务范围不应覆盖整个批次
     */
    protected abstract void processChunk(List<?> chunk, JobContext context);

    /**
     * 【可选覆写】前置处理（如初始化资源、预加载数据）
     */
    protected void preProcess(JobContext context) {
        // 默认空实现
    }

    /**
     * 【可选覆写】后置处理（如汇总统计、发送通知）
     */
    protected void postProcess(JobContext context) {
        // 默认空实现
    }

    /**
     * 【可选覆写】分块处理异常时的处理逻辑
     */
    protected void onError(List<?> chunk, Exception e, JobContext context) {
        context.getErrors().add("批次处理失败: " + e.getMessage());
        context.getFailCount();
        for (int i = 0; i < chunk.size(); i++) {
            context.incrementFail();
        }
    }

    // ========== 工具方法 ==========

    private List<Long> resolveTenantIds(JobContext context) {
        if (context.getTenantId() != null) {
            return List.of(context.getTenantId());
        }
        return tenantService.getAllActiveTenantIds();
    }

    @SuppressWarnings("unchecked")
    private List<?> fetchChunk(LambdaQueryWrapper<?> wrapper, int offset, int limit) {
        // 通过MyBatis-Plus分页查询获取分块数据
        wrapper.last("OFFSET " + offset + " LIMIT " + limit);
        return (List<?>) getBaseMapper().selectList(wrapper);
    }

    protected abstract BaseMapper<?> getBaseMapper();

    private SysJobExecution createExecution(long jobId, String jobHandler, JobContext context) {
        return SysJobExecution.builder()
            .jobId(jobId)
            .jobName(jobHandler)
            .startTime(LocalDateTime.now())
            .status("RUNNING")
            .batchSize(context.getBatchSize())
            .param(JsonUtil.toJson(context))
            .build();
    }
}
```

## 5. 具体JobHandler实现示例

### 5.1 销售订单自动关闭

```java
@Component
public class SaleOrderAutoCloseJobHandler extends BaseJobHandler {

    @Autowired
    private SaleOrderMapper saleOrderMapper;

    @Autowired
    private SaleOrderService saleOrderService;

    @Override
    protected BaseMapper<?> getBaseMapper() {
        return saleOrderMapper;
    }

    @XxlJob("saleOrderAutoCloseJobHandler")
    public ReturnT<String> run() {
        return execute();
    }

    @Override
    protected LambdaQueryWrapper<?> buildQueryWrapper(JobContext context) {
        // 查询超过30天未操作的草稿订单
        return new LambdaQueryWrapper<SaleOrder>()
            .eq(SaleOrder::getStatus, "draft")
            .lt(SaleOrder::getUpdatedAt, LocalDateTime.now().minusDays(30))
            .eq(SaleOrder::getIsDeleted, false);
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void processChunk(List<?> chunk, JobContext context) {
        @SuppressWarnings("unchecked")
        List<SaleOrder> orders = (List<SaleOrder>) chunk;

        for (SaleOrder order : orders) {
            try {
                saleOrderService.autoClose(order.getId(), "系统自动关闭：超过30天未操作");
                context.incrementSuccess();
                XxlJobHelper.log("自动关闭订单: {}", order.getOrderNo());
            } catch (Exception e) {
                log.error("自动关闭订单失败: orderNo={}", order.getOrderNo(), e);
                context.incrementFail();
                context.getErrors().add("订单" + order.getOrderNo() + ": " + e.getMessage());
            }
        }
    }

    @Override
    protected void postProcess(JobContext context) {
        if (context.getSuccessCount() > 0) {
            XxlJobHelper.log("租户{}: 自动关闭订单{}个",
                context.getTenantId(), context.getSuccessCount());
        }
    }
}
```

### 5.2 库存快照生成

```java
@Component
public class InventoryStockSnapshotJobHandler extends BaseJobHandler {

    @Autowired
    private InvStockMapper stockMapper;

    @Autowired
    private InvStockSnapshotMapper snapshotMapper;

    @Override
    protected BaseMapper<?> getBaseMapper() {
        return stockMapper;
    }

    @XxlJob("inventoryStockSnapshotJobHandler")
    public ReturnT<String> run() {
        return execute();
    }

    @Override
    protected LambdaQueryWrapper<?> buildQueryWrapper(JobContext context) {
        return new LambdaQueryWrapper<InvStock>()
            .gt(InvStock::getQty, BigDecimal.ZERO)
            .eq(InvStock::getIsDeleted, false);
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void processChunk(List<?> chunk, JobContext context) {
        @SuppressWarnings("unchecked")
        List<InvStock> stocks = (List<InvStock>) chunk;
        LocalDate snapshotDate = LocalDate.now().minusDays(1); // 昨日快照

        List<InvStockSnapshot> snapshots = stocks.stream().map(stock -> {
            InvStockSnapshot snapshot = new InvStockSnapshot();
            snapshot.setWarehouseId(stock.getWarehouseId());
            snapshot.setProductId(stock.getProductId());
            snapshot.setQty(stock.getQty());
            snapshot.setLockQty(stock.getLockQty());
            snapshot.setAvailableQty(stock.getQty().subtract(stock.getLockQty()));
            snapshot.setSnapshotDate(snapshotDate);
            return snapshot;
        }).collect(Collectors.toList());

        // 批量插入快照记录
        snapshotMapper.insertBatch(snapshots);
        context.getSuccessCount();
        for (int i = 0; i < snapshots.size(); i++) {
            context.incrementSuccess();
        }
    }
}
```

## 6. 分块处理模式（Chunk-Oriented）

### 6.1 处理流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 查询第1批 │──→│ 处理第1批 │──→│ 查询第2批 │──→│ 处理第2批 │──→ ...
│ (1000条)  │    │ (逐条处理)│    │ (1000条)  │    │ (逐条处理)│
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                    │
                    ▼
              ┌──────────┐
              │ 独立事务   │  每个chunk一个事务，失败不影响其他chunk
              │ 提交/回滚  │
              └──────────┘
```

### 6.2 分块大小配置

| 数据类型 | 默认batchSize | 配置Key | 说明 |
|---------|-------------|---------|------|
| 单据类（订单/出入库） | 500 | `job.batch_size.order` | 单据含明细行，处理较重 |
| 主数据类（商品/客户） | 1000 | `job.batch_size.master` | 单条记录较轻 |
| 日志/流水类 | 5000 | `job.batch_size.log` | 简单记录，可大批量处理 |
| 统计汇总类 | 200 | `job.batch_size.stat` | 含复杂计算 |

```java
/**
 * 从系统参数获取批处理大小
 */
public int getConfiguredBatchSize(String configKey, int defaultValue) {
    String value = sysParamService.getParamValue(configKey);
    if (value != null) {
        try {
            int size = Integer.parseInt(value);
            if (size > 0 && size <= 10000) {
                return size;
            }
        } catch (NumberFormatException ignored) {}
    }
    return defaultValue;
}
```

### 6.3 事务管理

**核心原则：每个chunk一个独立事务，禁止整个批次一个大事务。**

```java
/**
 * 分块事务管理 — 每个chunk独立事务
 * 使用Propagation.REQUIRES_NEW确保每个chunk在独立事务中执行
 */
@Service
public class ChunkTransactionManager {

    @Transactional(propagation = Propagation.REQUIRES_NEW, rollbackFor = Exception.class)
    public <T> ChunkResult<T> processChunk(List<T> chunk, Consumer<T> processor) {
        ChunkResult<T> result = new ChunkResult<>();
        for (T item : chunk) {
            try {
                processor.accept(item);
                result.addSuccess(item);
            } catch (Exception e) {
                result.addFail(item, e.getMessage());
            }
        }
        return result;
    }
}
```

**禁止事项：**

| 禁止项 | 原因 | 正确做法 |
|--------|------|---------|
| 整个批次一个大事务 | 锁表时间过长，内存溢出 | 每个chunk独立事务 |
| chunk内N+1查询 | 1000条数据产生1000+次DB查询 | 预加载关联数据，批量查询 |
| chunk内逐条INSERT | 1000次网络往返 | 使用`insertBatch`批量写入 |
| chunk大小不设上限 | 单次处理百万数据OOM | 强制限制chunk上限10000 |

## 7. 失败处理与重试策略

### 7.1 重试策略

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 最大重试次数 | 3 | 单次任务执行内最大重试次数 |
| 重试间隔基数 | 10秒 | 指数退避基数 |
| 退避系数 | 2 | 第N次重试等待：基数 × 系数^(N-1) |
| 最大等待时间 | 300秒 | 重试间隔上限 |

**退避时间表：**

| 重试次数 | 等待时间 |
|---------|---------|
| 第1次 | 10秒 |
| 第2次 | 20秒 |
| 第3次 | 40秒 |

### 7.2 XXL-JOB失败重试配置

```java
/**
 * XXL-JOB任务注册时配置重试策略

 */
```

### 7.3 失败批次死信处理

对于多次重试仍失败的批次，写入死信表供人工处理：

```sql
CREATE TABLE sys_job_dead_letter (
    id              BIGSERIAL       PRIMARY KEY,
    tenant_id       BIGINT          NOT NULL,
    job_id          BIGINT          NOT NULL,       -- XXL-JOB任务ID
    job_name        VARCHAR(100)    NOT NULL,       -- JobHandler名称
    execution_id    BIGINT,                         -- 关联执行日志ID
    chunk_index     INT             NOT NULL,       -- 失败的chunk序号
    chunk_data      JSONB,                          -- 失败的chunk数据快照
    error_msg       TEXT,                           -- 错误信息
    retry_count     INT             NOT NULL DEFAULT 0, -- 已重试次数
    status          VARCHAR(20)     NOT NULL DEFAULT 'PENDING',
    -- PENDING=待处理, RETRYING=重试中, RESOLVED=已处理, DISCARDED=已丢弃
    resolved_by     BIGINT,                         -- 处理人ID
    resolved_at     TIMESTAMP,                      -- 处理时间
    resolve_remark  VARCHAR(500),                   -- 处理备注
    created_at      TIMESTAMP       NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMP       NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_job_dead_letter_status ON sys_job_dead_letter(status, created_at);
CREATE INDEX idx_job_dead_letter_job ON sys_job_dead_letter(job_name, tenant_id);

COMMENT ON TABLE sys_job_dead_letter IS '定时任务死信表（失败批次暂存）';
```

## 8. 幂等执行

### 8.1 幂等性保障原则

所有JobHandler必须保证**幂等执行**：同一任务多次执行的结果与执行一次相同。

| 保障方式 | 适用场景 | 实现方法 |
|---------|---------|---------|
| 状态检查 | 单据状态流转 | 处理前检查当前状态，已完成则跳过 |
| 唯一索引 | 快照/统计记录 | 使用日期+维度作为唯一键，冲突时更新 |
| 执行日志 | 防重复调度 | 检查当天是否已执行成功 |

### 8.2 幂等性检查实现

```java
/**
 * 任务幂等性检查 — 防止同一天重复执行
 */
protected boolean isAlreadyExecutedToday(String jobName) {
    LocalDateTime todayStart = LocalDate.now().atStartOfDay();
    SysJobExecution existing = jobExecutionMapper.selectOne(
        new LambdaQueryWrapper<SysJobExecution>()
            .eq(SysJobExecution::getJobName, jobName)
            .eq(SysJobExecution::getStatus, "SUCCESS")
            .ge(SysJobExecution::getStartTime, todayStart)
            .last("LIMIT 1")
    );
    return existing != null;
}
```

## 9. 并发执行规则

### 9.1 阻塞处理策略

| 策略 | XXL-JOB名称 | 适用场景 | 说明 |
|------|------------|---------|------|
| 丢弃后续 | DISCARD_LATER | 默认策略 | 前一次未执行完，新的调度直接丢弃 |
| 覆盖前者 | COVER_EARLY | 实时性要求高 | 终止前一次，执行新的调度 |
| 串行执行 | SERIAL_EXECUTION | 不可并行 | 排队等待，前一次执行完再执行下一次 |

### 9.2 策略选择指南

| Job类型 | 推荐策略 | 原因 |
|--------|---------|------|
| 数据清理 | 丢弃后续 | 清理任务不需要并发执行 |
| 日报/月报生成 | 丢弃后续 | 同一报表不需要重复生成 |
| 数据同步 | 串行执行 | 保证数据顺序一致性 |
| 实时告警 | 覆盖前者 | 以最新一次调度为准 |
| 库存快照 | 丢弃后续 | 同一日期快照不允许重复 |

### 9.3 分布式锁保障

```java
/**
 * 关键任务分布式锁保障 — 防止多节点并发执行
 */
protected boolean acquireJobLock(String jobName, long timeoutSeconds) {
    String lockKey = "erp:scheduler:lock:" + jobName;
    return redisLock.tryLock(lockKey, timeoutSeconds, TimeUnit.SECONDS);
}

protected void releaseJobLock(String jobName) {
    String lockKey = "erp:scheduler:lock:" + jobName;
    redisLock.unlock(lockKey);
}
```

## 10. 路由策略

### 10.1 路由策略选择

| 策略 | XXL-JOB名称 | 适用场景 | 说明 |
|------|------------|---------|------|
| 第一个 | FIRST | 默认策略 | 始终使用第一个在线节点 |
| 轮询 | ROUND | 负载均衡 | 均匀分配任务到各节点 |
| 故障转移 | FAILOVER | 高可用 | 节点故障时自动切换到其他节点 |
| 一致性Hash | CONSISTENT_HASH | 数据亲和性 | 同一任务始终路由到同一节点 |
| 分片广播 | SHARDING_BROADCAST | 大数据量 | 所有节点同时执行，各自处理分片 |

### 10.2 分片广播模式

```java
/**
 * 分片广播 — 多节点并行处理
 * XXL-JOB将总数据按节点数分片，每个节点处理一个分片
 */
@XxlJob("largeDataProcessJobHandler")
public ReturnT<String> largeDataProcess() {
    int shardIndex = XxlJobHelper.getShardIndex();   // 当前分片序号
    int shardTotal = XxlJobHelper.getShardTotal();   // 总分片数

    XxlJobHelper.log("分片广播: 分片{}/{}", shardIndex + 1, shardTotal);

    // 按分片条件查询数据（使用ID取模分片）
    List<DataItem> items = dataMapper.selectList(
        new LambdaQueryWrapper<DataItem>()
            .apply("MOD(id, {0}) = {1}", shardTotal, shardIndex)
    );

    // 处理本分片数据
    for (DataItem item : items) {
        processItem(item);
    }

    return ReturnT.SUCCESS;
}
```

## 12. 监控与告警

### 12.1 XXL-JOB Admin监控

| 监控维度 | 指标 | 告警阈值 |
|---------|------|---------|
| 任务执行状态 | 失败次数/总次数 | 失败率 > 5% |
| 执行时长 | 单次执行耗时 | 超过预设阈值（如30分钟） |
| 调度延迟 | 实际执行时间与计划时间差 | 延迟 > 5分钟 |
| 执行器在线 | 节点存活状态 | 节点离线 > 1分钟 |

### 12.2 告警通知

```java
/**
 * 任务执行异常告警 — 通过系统消息通知管理员
 */
protected void sendAlert(String jobName, JobContext context) {
    if (context.getFailCount() == 0) return;

    AlertMessage alert = AlertMessage.builder()
        .type("JOB_FAILURE")
        .title("定时任务执行异常")
        .content(String.format("任务: %s\n租户: %d\n成功: %d\n失败: %d\n错误: %s",
            jobName, context.getTenantId(),
            context.getSuccessCount(), context.getFailCount(),
            String.join("\n", context.getErrors())))
        .level("WARNING")
        .build();

    alertService.sendToAdmins(alert);
}
```

## 13. 检查清单

新增定时任务时，必须逐项确认：

| 检查项 | 通过标准 |
|--------|---------|
| 命名规范 | 符合`{Module}{Business}JobHandler`格式 |
| 继承BaseJobHandler | 使用模板方法模式，实现processChunk |
| 参数解析 | 使用JobParamParser解析JSON参数 |
| 幂等性 | 多次执行结果一致，支持状态检查/唯一索引 |
| 事务管理 | 每个chunk独立事务，不使用大事务 |
| 批处理大小 | 使用系统参数配置，不硬编码 |
| 失败处理 | 有重试策略和死信处理机制 |
| 并发控制 | 选择合适的阻塞策略和分布式锁 |
| 执行日志 | 写入sys_job_execution表，记录完整执行信息 |
| 租户隔离 | 正确处理多租户场景 |
| 监控告警 | 失败时触发告警通知 |
| CRON表达式 | 在Admin控制台正确配置，避开业务高峰 |
| 单元测试 | 覆盖正常/异常/边界场景 |
