## Issue #2: getCompanyById 返回类型标注错误

**严重程度**: 🟡 中  
**文件**: `erp-ai-web/src/api/org/company.ts:20`  
**描述**: `getCompanyById` 函数返回类型标注为 `Promise<{ code: number; data: CompanyListVO }>`，但后端 `OrgCompanyController.getById()` 返回的是 `RT<CompanyDetailVO>`。`CompanyListVO` 缺少 `address` 字段，而 `CompanyDetailVO` 包含此字段。CompanyForm.vue 第96行使用 `(data as unknown as Record<string, unknown>).address` 类型强转来绕过此问题。

**当前代码**:

```typescript
export function getCompanyById(id: number): Promise<{ code: number; data: CompanyListVO }> {
```

**修复建议**: 将返回类型改为 `CompanyDetailVO`，或在 types.ts 中定义独立的 `CompanyDetailVO` 接口（含 address 字段）。

## Issue #3: 前后端字段长度校验不一致

**严重程度**: 🟢 低  
**文件**: `CompanyForm.vue` vs `CompanyCreateDTO.java`

## Issue #4: 信用代码重复错误码映射待验证

**严重程度**: 🟢 低  
**文件**: `CompanyForm.vue:179-184`, `OrgCompanyServiceImpl.java:130-138`  
**描述**: 后端 `checkCreditCodeUnique()` 抛出 `BusinessException(ErrorCode.DATA_ALREADY_EXISTS)`，前端 `handleSaveError(400)` 检查 `code === 400`。需要确认全局异常处理器将 `DATA_ALREADY_EXISTS` 正确映射为 HTTP 400。如果映射为其他状态码（如 409 Conflict），前端将显示通用 `saveFailed` 而非 `creditCodeDuplicate` 提示。

**修复建议**: 验证 `GlobalExceptionHandler` 中 `DATA_ALREADY_EXISTS` → HTTP 400 的映射；或在前端增加对该错误码的精确匹配。
